# GFIELD 그래프 가독성·정답 검수

그래프 문제는 계산식이 맞아도 축 눈금이나 격자선이 읽히지 않으면 출제하지 않는다. 막대그래프, 꺾은선그래프, 그림그래프, 띠그래프, 원그래프는 아래 기준을 모두 만족해야 생성 가능으로 표시한다.

## 공통 통과 조건

1. 축의 수치 눈금 글자와 격자선을 함께 그린다.
2. 눈금 한 칸의 값이 주어진 문제는 지문과 읽기 설명에 그 값과 단위를 명시한다. 한 칸의 값을 찾아야 하는 문제는 합계와 막대 칸 수처럼 답을 하나로 정할 조건을 주고, 화면·읽기 설명·그림 속 `data-*`에는 찾아야 할 값을 미리 넣지 않는다.
3. 모든 데이터 값은 눈금 단위의 정확한 배수로 생성한다.
4. 축 끝은 `눈금 단위 × 격자 칸 수`와 일치하게 만든다. 일반 그래프는 읽기 쉬운 눈금 수를 유지하고, 원문 구조에 촘촘한 격자가 필요한 막대그래프는 최대 24칸까지 허용하되 숫자를 쓰는 주요 눈금은 8개 이하로 나눈다.
5. 그래프에 사용한 데이터에서 SVG 좌표를 계산하며, 감사기는 SVG 좌표를 다시 값으로 환산해 원자료와 비교한다.
6. 합·차·비교 문제는 필요한 모든 막대, 선, 범례, 시점 이름을 분명하게 표시한다.
   묶음 막대는 두 자료의 막대가 같은 항목 안에서 겹치지 않게 나란히 두고, 색뿐 아니라 무늬와 글자 범례로 구분한다.
7. 원그래프·띠그래프는 비율의 합이 100%인지, 그림그래프는 그림 한 개가 나타내는 수가 지문과 일치하는지 독립 계산한다.
8. 가려진 값이나 눈금 사이 값을 읽어야만 답이 나오는 문제는 생성하지 않는다.

## 화면 가독성 조건

- 눈금 글자와 단위가 다른 글자와 겹치지 않아야 한다.
- 막대·점·선이 축 또는 격자선에 가려지지 않아야 한다.
- 범례 색과 무늬는 색각 이상이 있어도 구별할 수 있게 글자 라벨을 함께 둔다.
- 375px 화면에서 축 제목, 눈금, 범례, 문제 문장이 잘리거나 페이지 전체의 가로 스크롤을 만들지 않아야 한다. 여섯 항목 또는 두 그래프처럼 최소 글자 크기를 지키기 어려운 경우에는 그래프 영역 안에서만 가로 스크롤을 허용한다.
- 데이터가 많아질수록 축을 무작정 촘촘하게 만들지 말고 눈금 단위를 키워 읽기 쉬운 범위를 유지한다.

## 필수 감사

- `graph-audit.js`: 4-1 막대그래프와 4-2 꺾은선그래프의 눈금·격자선·단위·SVG 좌표를 독립 검산한다.
- `source-4-1-bar-1-audit.js`: 4-1 막대그래프의 이해 개념탐구 1의 11개 원문 구조를 33,000회 생성하고, 공개 조건의 단일답·최대 24칸 격자·숨긴 막대와 눈금값·가로와 세로 좌표를 역검사한다.
- `source-4-1-bar-2-audit.js`: 4-1 막대그래프의 활용 개념탐구 2의 공개 7개 원문 구조를 21,000회 생성하고, 원문 기준 답·세로 눈금·막대 좌표·빈 막대와 묶음 막대 위치를 독립 검산한다. 답이 확인되지 않거나 하나로 정해지지 않는 4개 항목은 실행 경로에서도 잠금인지 검사한다.
- 막대그래프 이해 화면 검수: 데스크톱·375px 문제와 풀이 44상태, A4 PDF 22개·52쪽을 확인한다. 최종 증거는 2026-08-28 비공개 검수 보관소에 둔다.
- 막대그래프 활용 화면 검수: 데스크톱·375px 문제와 풀이 28상태, A4 PDF 14개·34쪽, 잠금 직접 URL 4개를 확인한다. 최종 증거는 2026-08-28 비공개 검수 보관소에 둔다.
- `advanced-graphs-audit.js`: 6-1 그림그래프·띠그래프·원그래프의 비율, 도수, 조합 조건을 독립 검산한다.
- 그래프 생성기를 바꾸면 두 감사를 모두 실행하고, 데스크톱과 375px 화면에서 실제 SVG를 다시 확인한다.

이 계약은 원본 교재 페이지를 복제하지 않는다. 원본에서 확인한 그래프 구조를 새 수치와 새 자료로만 재구성한다.
