# GFIELD 그래프 가독성·정답 검수

그래프 문제는 계산식이 맞아도 축 눈금이나 격자선이 읽히지 않으면 출제하지 않는다. 막대그래프, 꺾은선그래프, 그림그래프, 띠그래프, 원그래프는 아래 기준을 모두 만족해야 생성 가능으로 표시한다.

## 공통 통과 조건

1. 축의 수치 눈금 글자와 격자선을 함께 그린다.
2. 지문에 눈금 한 칸의 단위와 단위를 명시한다.
3. 모든 데이터 값은 눈금 단위의 정확한 배수로 생성한다.
4. 최댓값은 `눈금 단위 × (눈금 수 - 1)`과 일치하게 만들고, 눈금 수는 2~10개로 제한한다.
5. 그래프에 사용한 데이터에서 SVG 좌표를 계산하며, 감사기는 SVG 좌표를 다시 값으로 환산해 원자료와 비교한다.
6. 합·차·비교 문제는 필요한 모든 막대, 선, 범례, 시점 이름을 분명하게 표시한다.
7. 원그래프·띠그래프는 비율의 합이 100%인지, 그림그래프는 그림 한 개가 나타내는 수가 지문과 일치하는지 독립 계산한다.
8. 가려진 값이나 눈금 사이 값을 읽어야만 답이 나오는 문제는 생성하지 않는다.

## 화면 가독성 조건

- 눈금 글자와 단위가 다른 글자와 겹치지 않아야 한다.
- 막대·점·선이 축 또는 격자선에 가려지지 않아야 한다.
- 범례 색과 무늬는 색각 이상이 있어도 구별할 수 있게 글자 라벨을 함께 둔다.
- 375px 화면에서 축 제목, 눈금, 범례, 문제 문장이 잘리거나 가로 스크롤을 만들지 않아야 한다.
- 데이터가 많아질수록 축을 무작정 촘촘하게 만들지 말고 눈금 단위를 키워 읽기 쉬운 범위를 유지한다.

## 필수 감사

- `graph-audit.js`: 4-1 막대그래프와 4-2 꺾은선그래프의 눈금·격자선·단위·SVG 좌표를 독립 검산한다.
- `advanced-graphs-audit.js`: 6-1 그림그래프·띠그래프·원그래프의 비율, 도수, 조합 조건을 독립 검산한다.
- 그래프 생성기를 바꾸면 두 감사를 모두 실행하고, 데스크톱과 375px 화면에서 실제 SVG를 다시 확인한다.

이 계약은 원본 교재 페이지를 복제하지 않는다. 원본에서 확인한 그래프 구조를 새 수치와 새 자료로만 재구성한다.
