# 소개(about)·문제은행(drill) 리디자인 — 구현 설계서

> **작성**: 2026-08-28, 설계 세션(Fable). **구현은 별도 세션(Sonnet)이 이 문서만 보고 진행한다.**
> 원장 지시: "UX나 디자인을 아래를 고려해서 좀 잘 만들자. **너무 AI스러워.**"
> 참고로 받은 것: MengTo/Skills 저장소 · Metal(액체금속) · Beautiful UI Five · Orbs 등.
> → MengTo/Skills(MIT)에서 **13개 스킬을 `.claude/skills/`에 설치**해 뒀다(§7 매핑 참조).
> 구현 세션은 해당 스킬을 Skill 도구로 불러 쓰면 된다.

## 0. 진단 — 무엇이 "AI스러운가" (스크린샷으로 확인함)

**about.html**
- 히어로가 **보라→파랑 그라데이션 + 글로 블롭 + 중앙 정렬 금색 타이틀**. AI 랜딩의 최다 빈출
  클리셰 그 자체다. 게다가 **앱 본체(크림 종이+네이비+골드)와 세계관이 다르다** — 소개
  페이지만 다른 브랜드처럼 보인다.
- 전 섹션이 중앙 정렬, 섹션 구분은 여백뿐, 제목에 이모지(🪄).
- `--purple/--purple-glow` 토큰이 이 페이지에만 존재한다.

**drill.html (문제은행)**
- 흰 카드 + 기본 `<select>` 3개 + 파란 버튼. 부트스트랩 관리자 폼처럼 보인다.
- 제목에 이모지(📝). 159유형·424레벨이라는 **실물 자산이 화면에 전혀 드러나지 않는다** —
  드롭다운을 열기 전엔 뭐가 있는지 알 수 없다.
- 배경이 앱과 무관한 연회색(#f5f6fa 계열). 인쇄 학습지(문제은행의 산출물)와도 인상이 안 이어진다.

**결론: 두 페이지 모두 "덜 꾸며서"가 아니라 "아무 데나 갖다 놓아도 되는 모양이라서" AI스럽다.**
고치는 방향은 장식 추가가 아니라 **이 제품만의 세계로 편입**이다.

## 1. 방향 선언 — 한 세계: "수학 공방(工房)"

앱 본체가 이미 가진 정체성 = **따뜻한 크림 종이 + 잉크 네이비 + 금박**. 스토리 삽화 35장도
이 팔레트다. 소개·문제은행을 **같은 세계의 두 방**으로 만든다.

| 방 | 은유 | 손님 |
|---|---|---|
| about.html | **출판사의 책 소개 페이지** — 잘 조판된 수학 동화책을 펼쳐 보이는 곳 | 학부모·원장 |
| drill.html | **공방의 작업대** — 모눈종이 위에서 문제를 골라 찍어내는 곳 | 교사·학생 |

보라 그라데이션 세계는 **폐기**한다. `--purple`·`--purple-glow` 토큰 삭제.

### 참고 자료 취사(원장 제공 링크에 대한 판단)
- **Liquid Metal(크롬 효과)** — 다크 테크 사이트용이라 **그대로 쓰면 안 맞는다.** 대신 아이디어만
  가져와 **"금박(gold foil)" 버튼**으로 번안한다: 골드 그라데이션 보더 + 호버 시 사선 광택 스윕
  1회. 동화책 금박 장식으로 읽히게. (스킬 `liquid-metal-border`의 기법을 골드로 재조색)
- **Orbs(애니메이션 구)** — AI 챗봇 인상이 강해 **불채택.** 히어로 장식은 대신 §3 히어로 명세의
  "수 성좌(constellation)"로.
- **Beautiful UI Five / screenshot-to-code 류** — 빌드 도구 없는 우리 스택(단일 HTML·vanilla)과
  안 맞아 도구는 불채택, **원칙만 §2·§6에 반영.**

## 2. 공통 토큰 — 앱과 통일 (두 페이지 모두 이걸로 교체)

```css
:root{
  --paper:#FBFAF7; --paper-warm:#F7F5F0; --mist:#F1F0EC; --line:#E4E2DC;
  --ink:#1A2233; --sub:#4a5468;
  --blue:#16417C; --blue-deep:#0E2C57;
  --gold:#C9A063; --gold-soft:#EAC996; --gold-bright:#F5D98B;
  --ok:#2E9E6B; --no:#D9534F;
  /* 그림자: 진한 단일 그림자 금지. 저알파 2겹(beautiful-shadows 원칙) */
  --shadow-1:0 1px 2px rgba(26,34,51,.05), 0 4px 14px rgba(26,34,51,.06);
  --shadow-2:0 2px 4px rgba(26,34,51,.06), 0 10px 30px rgba(26,34,51,.09);
}
```

**타이포그래피**
- 제목(display): **'Gowun Batang'**(구글 폰트, 한글 세리프 — 동화책 인상). weight 700.
- 본문/UI: 기존 **Pretendard** 유지.
- 숫자·코드: `ui-monospace` + `font-variant-numeric: tabular-nums`.
- 본문 폭 ≤ 34em(한글 기준), 제목 `text-wrap: balance` 또는 `keep-all` + 수동 개행.
- 로드: `<link>` 구글폰트(display=swap) + 폴백 `serif`. **폰트 실패 시에도 조판이 성립해야 한다.**

**레이아웃 문법** (container-lines / book-serif-index 차용)
- 콘텐츠 폭 1080px. 좌우에 **1px 헤어라인 세로 괘선**이 페이지 끝까지 이어진다(책의 판면).
- 섹션 구분 = 여백이 아니라 **가로 헤어라인 + 챕터 번호**. 각 섹션 머리에
  `01 / 왜 만들었나` 식 **로마자 대신 타뷸러 숫자** 폴리오. (number-details 차용 — 수학 브랜드니
  숫자 자체가 장식이다)
- **중앙 정렬은 히어로 한 곳만.** 나머지는 전부 좌정렬.

**금지 목록(구현 중 이것이 나오면 잘못 가고 있는 것)**
보라·핑크 그라데이션 / 글로 블롭 / 이모지 섹션 아이콘 / 모든-섹션-중앙정렬 /
`border-radius` 20px 이상 남발 / 진한 단일 box-shadow / 회색 #888 본문 / 스톡 일러스트.

## 3. about.html 설계 (섹션별)

현 구조(hero → 문제의식 → 철학 → ladder → kids → cta → foot)는 유지. 표피와 조판만 교체.

### 3-1. 히어로 — "펼친 책의 첫 장"
- 배경: `--paper`. 상단에 아주 옅은 **모눈**(24px 격자, `--line` 6% 알파)을 깔되 아래로 페이드.
- 중앙(이 페이지 유일의 중앙 정렬):
  - 오버라인: `NUMBERS OF MAGIC — 수의 마법` (letter-spacing .18em, `--gold`)
  - H1: **"수는 마법이다"** Gowun Batang 700, clamp(44px, 7vw, 84px), `--ink`.
    "마법"만 `--blue`. ~~금색 글자~~ 금지 — 금색은 가는 요소 전용(§2).
  - 서브: 한 문장, `--sub`.
- 장식 = **수 성좌**: 히어로 뒤에 우리 스토리 삽화와 같은 문법(원본 도형 SVG, 숫자·기호만)으로
  1·2·4·8·16 점들이 가는 금선으로 이어진 성좌 1개. 정적, 8s 느린 float 1개만. **orbs·파티클 금지.**
- 모션: 제목 어절 단위 staggered reveal 1회(스킬 `staggered-word-reveal`), 60ms 간격,
  `prefers-reduced-motion`이면 즉시 표시.
- SCROLL 표시는 유지하되 텍스트 없애고 가는 화살표만.

### 3-2. 문제의식 · 철학 섹션
- 챕터 폴리오(`01`, `02`) + 좌정렬 2단: 좌 40% 제목(Gowun Batang), 우 60% 본문.
- 인용 문장은 **좌측 2px 골드 괘선** 인용 블록으로.
- 카드 금지 — 괘선과 여백으로만 구분.

### 3-3. 사다리(The Ladder)
- 현재 세로 리스트를 **판면 안의 계단 다이어그램**으로: 좌측 얇은 세로 레일 + 급수 노드(0급~).
  노드는 스토리 삽화 팔레트의 원(네이비 채움/골드 테두리), 각 노드 우측에 급수명·한 줄 설명.
- 스크롤 진입 시 노드가 아래→위로 순차 점등(animation-on-scroll, 1회).
- 숫자 자산 노출: 섹션 머리에 `199 units · 159 threads · 424 levels`를 타뷸러 숫자 대형으로.
  (number-details) — **실데이터와 일치시킬 것. data/threads.js에서 세어 넣는다. 하드코딩 후
  검증 없이 끝내지 말 것.**

### 3-4. 누미와 친구들(kids)
- 제목 이모지 제거. 캐릭터는 기존 `assets/characters/poco-*.png` 실물을 **필름 스트립**(가로
  스크롤 스냅, 각 프레임에 헤어라인 테두리 + 하단 캡션)으로.

### 3-5. CTA + 푸터
- CTA 버튼 = **금박 버튼**(§1 번안): `--ink` 바탕 + 1.5px 골드 그라데이션 보더,
  호버 시 사선 광택 스윕 1회(0.9s, 재호버 시에만 재생). 텍스트 "마을에 들어가기 →" → index.html.
- 푸터: 헤어라인 위 1줄 — 좌측 워드마크(Gowun Batang), 우측 언어 전환(한/EN/中 — 기존 i18n 유지).

### 3-6. 다국어
기존 `data-i18n` 시스템 그대로. **새로 넣는 문구는 반드시 3개 언어 모두** 사전에 추가.
Gowun Batang은 한글 전용이므로 EN/中 제목은 `'Gowun Batang', 'Noto Serif SC', serif` 폴백 체인.

## 4. drill.html(문제은행) 설계 — "공방의 작업대"

**엔진·생성 로직은 손대지 않는다. DOM 구조는 바꾸되 기존 JS 함수·id 계약을 유지하거나
호출부를 같이 옮긴다.**

### 4-1. 배경과 프레임
- 배경: `--paper-warm` + **옅은 모눈**(learning의 산출물인 인쇄 학습지와 같은 인상).
- 콘텐츠는 판면(§2 괘선) 안에. 상단바: 좌 워드마크, 우 "마을로" 텍스트 링크(버튼 아님).
- H1: "문제은행" Gowun Batang + 옆에 작은 타뷸러 카운터 **`159 유형 · 424 레벨`**(실데이터).
  이모지 제거.

### 4-2. 주제 선택 — 드롭다운을 "서랍장"으로
현 `<select>`를 **2열 마스터-디테일**로 교체(모바일은 세로 스택):
- 좌열(서랍장): 대분류 리스트(교과연산/창의연산 탭 유지 → 그 아래 챕터 그룹). 각 항목에
  유형 수를 타뷸러 숫자로. 검색 인풋 1개(입력 시 즉시 필터, JS 10줄 수준).
- 우열(작업대): 선택한 유형의 **실제 견본 문제 3개를 즉석 생성해 미리보기**(기존 생성기 호출).
  이게 이 페이지의 핵심 개선 — 문제은행인데 문제가 보여야 한다.
- 문항 수·타이머는 `<select>` 대신 **세그먼트 컨트롤**(10/20/30 · 없음/3분/5분).

### 4-3. 액션과 티켓
- "연습 시작" = 금박 버튼(§3-5와 동일 컴포넌트). "학습지 인쇄" = 아웃라인 버튼.
- 학습지 코드 박스 → **티켓 모양**(양끝 반원 노치 + 점선 절취선, 코드는 monospace).
  기능 로직은 그대로.

### 4-4. 연습 화면(문제 푸는 뷰)
- 이번 범위에서는 **토큰·타이포만 통일**(배경·버튼·숫자 타뷸러화). 구조 개편은 다음 배치.

## 5. 모션 규칙(두 페이지 공통)
- 스크롤 리빌은 **섹션당 1회, 250ms, translateY 12px + opacity**만. 반복 재생 금지.
- `prefers-reduced-motion: reduce` → 모든 모션 즉시 상태로. **필수.**
- hover 트랜지션 120~180ms. 무한 루프 애니메이션은 히어로 성좌 float 1개 외 금지.

2. 콘솔·페이지 에러 0. 폰트 CDN 차단 환경(이 샌드박스)에서도 폴백 조판 성립.

4. drill: 견본 미리보기가 유형 선택마다 실제 갱신되는 것, 코드 티켓 기능 회귀 없음.
