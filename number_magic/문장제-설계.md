# 문장제(이해편) 설계 — Polya 6단계를 제너레이터로 (2026-08-29)

> 원장 지시: "문장 이해력이 같이 성장해야 하는 거야. 연산만 빠르면 오히려 문장제가 무너져."
> "난 이 부분도 정말 중요하다 생각해."
> 출처 자료: 「유·초등 저학년을 위한 언어사고력 프로그램」(지필드 영재교육) — 이해편 A上·A下 실물,
> 프로그램 소개서. 저자 표기는 **대치 소마 부원장 이주연**.

## 0. 자료 취급 원칙

교재 지면은 **지필드 것**이지만 저자가 외부 인물로 명기돼 있다. 이 저장소의 기존 관례
(CARS·기적의 계산법·두뇌로와 동일)를 그대로 적용한다:

- **방법·구조·용어는 사실로 쓴다.** 6단계 체계, 하위 기능 목록, 연산 신호어 규칙, 의미 유형
  (합병·첨가·구잔·구차)은 수학교육의 공유 자산이다.
- **지문·상황은 전부 새로 쓴다.** 교재의 문장("허수아비 위에 참새가…")을 옮기지 않는다.
  우리는 어차피 **제너레이터**라 상황을 매번 새로 만든다 — 베낄 이유가 없다.
- 삽화·지면 배치도 가져오지 않는다.

## 1. 왜 이게 우리 구조와 잘 맞나

**6단계는 서로 다른 여섯 개의 "묻는 방식"이고, 상황은 하나다.** 이것이 핵심이다.
상황 하나를 만들면 여섯 가지 문항이 전부 파생된다 — 제너레이터에 가장 잘 맞는 형태다.

```
situation = { 주체, 대상, n1, n2, 연산, 의미유형, 단위 }
   ├ 1단계 → 중요한 낱말·숫자는? 주어진 것과 구하는 것은?
   ├ 2단계 → 이 상황에 맞는 그림/수직선은?
   ├ 3단계 → 더해야 하나, 빼야 하나, 곱해야 하나?
   ├ 4단계 → 식으로 쓰면?
   ├ 5단계 → 답이 뜻하는 것은? 답이 n1보다 큰가 작은가? 이 풀이는 맞나?
   └ 6단계 → 이 식에 맞는 문제를 직접 만들어라
```

**이미 갖춰진 것** — 새로 만들 인프라가 거의 없다:
| | |
|---|---|
| 이야기 문장 생성기 | `nl5_story` · `nl15_logic` (`engine/threads/nl.js`) |
| 인쇄 렌더 | `app/exam.js`가 `p.word`를 문장으로 그린다 |
| 화면 위젯 | `storyCard`(🔊 낭독 포함) |
| 수직선 | `numlineSvg` (2단계·4단계에 그대로 쓴다) |
| 그림 셈 | `cubes`·`base10`·`tapCount` (2단계 ○△× 표현) |

**비어 있는 것은 초등 이상 콘텐츠뿐이다.** 유아 6레벨만 있고 그 위가 없다.

## 2. 6단계 — 실물에서 확인한 하위 기능 전량

### Ⅰ. 어떻게 문제를 풀어야 할까? (Polya: 문제 이해)
중요한 낱말 · 중요한 숫자 · 일의 순서 · 글의 내용 · 글의 흐름 · 생각하며 읽기 ·
상황 알아보기 · **주어진 것과 구하고자 하는 것** · 도움이 되는 내용 찾기 · 내용 요약

> 특이한 활동 하나: 문제를 **세 부분으로 끊어 `/` 표시하고 소리 내어 읽기**.
> 쉬는 동안 머릿속으로 장면을 떠올리게 한다. 우리 `storyCard`의 🔊 낭독과 바로 붙는다.

### Ⅱ. 문제의 상황을 우뇌로 그려라 (문제 이해)
장면 찾기 · 덧셈 상황을 그림으로 · 뺄셈 상황을 그림으로 · **미지수(□) 상황을 그림으로** ·
덧뺄 상황을 **수직선**에 · 미지수 상황을 수직선에

### Ⅲ. 상황에 적절한 연산을 찾아라 (계획 수립)
그림을 그려 연산 찾기 ×3 · 주어진 것/구하는 것을 보고 연산 찾기 ×3 ·
**동일한 상황 찾기** ×2 · 세 수의 계산 · 미지수가 있는 문제

### Ⅳ. 식으로 나타내어라 (계획 수립)
그림→식 · 수직선→식 · **말→식** · 적절한 정보를 찾아 식으로 ·
그림→□ 식 · 수직선→□ 식 · 곱셈식

### Ⅴ. 돌다리도 두들겨 보고 건너라 (실행)
문제에 맞는 식 찾기 · 해결 과정 알아보기 · 해결하기 · **결과 해석하기**("답 35가 뜻하는 것은?") ·
**풀이 방법 점검하기**(남의 틀린 생각을 찾아 고치기) · 계산 점검 · **답 점검하기**(어림: "답은 20보다 작다") ·
여러 방법으로 해결 · **문제 확장하기** · **문제 수정하기**

### Ⅵ. 문제를 만들어라 (반성)
식을 말로 나타내기 · 덧셈식 문제 만들기(**합병**) · 덧셈식 문제 만들기(**첨가**) ·
뺄셈식 문제 만들기(**구잔**) · 뺄셈식 문제 만들기(**구차**) · 곱셈식 문제 만들기 · □ 있는 식

## 3. 기계로 옮길 수 있는 두 가지 규칙

### 3-1. 연산 신호어 (교재가 명시한 표)
| 기호 | 신호어 |
|---|---|
| `+` | 더하기 · 합 · ~보다 크다(많다) · ~에게 더 받았다 → **늘어남** |
| `−` | 빼기 · 차 · ~보다 작다(적다) · ~에게 주었다 → **줄어듦** |
| `×` | 곱하기 · 곱 · 배 · **몇씩 몇 묶음 / 몇 상자 / 몇 줄** |
| `=` | ~와 같습니다 · ~입니다 · ~이 되었습니다 |

생성기가 상황을 만들 때 **신호어를 골라 문장을 조립**하면, 3단계(연산 찾기) 문항의 정답이
자동으로 정해지고 채점 근거도 생긴다.

### 3-2. 의미 유형 — 같은 `+`라도 상황이 다르다
- **덧셈**: `합병`(둘을 합친다 — 사과와 배는 모두 몇 개) · `첨가`(더 받는다 — 몇 개를 더 받았다)
- **뺄셈**: `구잔`(남은 것 — 먹고 남은 것은) · `구차`(차이 — ~보다 몇 개 더 많은가)

**6단계(문제 만들기)가 이 네 유형을 각각 따로 훈련시킨다.** 즉 유형은 장식이 아니라
문항 스펙이다. 생성기의 `situation.kind`로 그대로 들어간다.

> `구차`가 특히 중요하다. "몇 개 더 많은가"는 빼는 상황인데 문장에 '주었다·먹었다'가
> 없어서, 신호어만 외운 아이가 반드시 틀리는 자리다. 교재가 `구잔`과 `구차`를 갈라 놓은
> 이유가 이것이고, 우리 오답 설계도 여기에 걸어야 한다.

## 4. 단계 편성 (소개서 표 그대로)

| | A | B | C |
|---|---|---|---|
| 대상 | 7~8세 | 8~9세 | 9~10세 |
| 연산 범위 | 자연수 **+ − ×** | 자연수 **+ − × ÷** | **분수·소수의 + −** |
| 분량 | 3개월 · 12차시 · 주1회 100분 | | |

우리 과정표(`과정-로드맵.md`)와 겹쳐 보면 **A ≈ 과정 3~7, B ≈ 과정 8~12, C ≈ 과정 17~20**이다.
즉 문장제는 별도 트랙이 아니라 **각 연산 과정에 붙는 층**으로 넣는 것이 맞다 —
원장 논리("연산과 문장 이해력이 **같이** 커야 한다") 그대로다.

## 5. 구현 제안

**새 스레드 계열 `WP`(word problem) 신설.** 6단계 = 6개 스레드, 각 3레벨(A/B/C 연산 범위).

| 스레드 | 무엇을 묻나 | 답 형태 | 재사용 |
|---|---|---|---|
| `WP1` 문제 이해 | 주어진 것 / 구하는 것 / 중요한 수 | 정수·선택 | `storyCard` |
| `WP2` 그림으로 그리기 | 상황에 맞는 그림·수직선 고르기 | 선택 | `numlineSvg`·`cubes` |
| `WP3` 연산 찾기 | 더할까 뺄까 곱할까 | 선택(+−×) | — |
| `WP4` 식으로 쓰기 | 식의 빈칸 | 정수 다칸 | `steps` |
| `WP5` 점검하기 | 답의 뜻 · 어림 · 틀린 풀이 찾기 | 선택·정수 | — |
| `WP6` 문제 만들기 | 식에 맞는 상황 고르기/채우기 | 선택·낱말 | `storyCard` |

**지켜야 할 것 (이 저장소가 이미 데인 자리):**
1. **`tex` 하나로 문항이 성립해야 한다** — 문장제는 `tex`가 아니라 `word`를 쓰므로,
   `printAskText`·`fillPrintGrid`가 `p.word`를 제대로 싣는지 **먼저 확인**하고 시작할 것.
   렌더 경로는 있으나 **아직 아무 생성기도 `word`를 채운 적이 없다.**
2. **유일해**를 강제할 것. 선택형이 많아 특히 위험하다.
3. **답 환원 원칙** — 답은 정수 몇 개 또는 선택지 index. 문장을 자유 입력받지 않는다.
4. 3개 언어. 문장제는 번역이 아니라 **각 언어로 자연스러운 상황을 따로 쓰는 것**에 가깝다 —
   단위(마리·송이·자루)가 언어마다 다르므로 기계 번역식으로 만들면 어색해진다.
