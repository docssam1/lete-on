## 0. 한 장 요약

유아 5세부터 미적분Ⅰ까지 **48과정 383회차**의 연산 학습 시스템입니다.
같은 내용이 **종이 학습지**와 **앱 화면** 두 형태로 나가고, 문항은 사람이 쓰는 게 아니라
**생성기(JS 함수)가 매번 새로 만듭니다.** 그래서 "문항을 고친다"가 아니라
"생성기를 고친다"가 이 프로젝트의 기본 동작입니다.

빌드 도구가 없습니다. 순수 HTML·JS·CSS이고 `index.html`이 스크립트를 순서대로 읽습니다.
`main`에 푸시하면 GitHub Actions가 그대로 배포합니다.

## 4. 새 유형·유닛을 추가하는 절차 — 여덟 걸음

**이 순서를 지키지 않으면 검사기는 통과하는데 화면에서 안 보입니다.** 실제로 2026-09-21에
4번과 6번을 각각 한 번씩 빠뜨려 두 번 사고가 났습니다.

| # | 할 일 | 빠뜨리면 |
|---|---|---|
| 1 | `engine/threads/midN.js`에 생성기 작성 — `NM_TGEN['md83_xxx'] = function(params, rng)` | 문제가 안 나옴(바로 티남) |
| 2 | `data/threads.js`에 스레드 등록 — `name` `gen` `prereq` `unit` `concept` `widgets` `levels[]` | 유형 목록에 없음 |
| 3 | `data/units/M-XX.js` 유닛 파일 작성 — `tier` `level` `order` `generator` `title` `subtitle` `practice` `discover` `check` `lab` `arena` `stamp` `voice` | 마법 카드가 비어 있음 |
| 4 | **`index.html`에 `<script src="data/units/M-XX.js">` 추가** | **앱에서 유닛이 통째로 로드 안 됨.** Node 검사기는 폴더를 통째로 읽어서 전부 통과한다 |
| 5 | `data/courses.js`에 편성 — `drills`에 `MD83@2` 식으로, `magic`에 `M-XX`, `minSessions` 재계산(항목 수 ÷ 2, 올림) | 학습지에 안 나옴 |
| 6 | **`data/roadmap.js` 챕터의 `units[]`에 추가** | **앱 지도에서만 안 보임.** 아무 검사기도 안 울린다 |
| 7 | `data/stages.js`의 `weeks`, `landing.html`의 주차 문구, `about.html`의 통계 갱신 | `check-stages` · `check-about-stats`가 잡아 준다 |
| 8 | 검사기 전체 실행 | — |

**생성기를 쓸 때의 계약**

| 규칙 | 내용 |
|---|---|
| 난수 | `Math.random()` 절대 금지. `R(rng,a,b)` · `pick(rng,arr)`만 |
| 답 | 항상 **정수 몇 개**. 수식 문자열을 입력받거나 파싱하지 않는다 |
| 답 환원 | 근호·분수는 정수 둘로 — `4√3`은 `[4,3]`, 근의 공식은 `[D, 2a]` |
| 역산 | 답을 **먼저** 고르고 계수를 거꾸로 맞춘다. 그래야 나눗셈이 늘 떨어진다 |
| 풀이 | `solution[]`의 **마지막 단계 `blank`가 `answer`와 같아야** 한다 |
| 표기 | 계수 1·0과 지수 1을 노출하지 않는다. 음수는 괄호로 감싼다(`(-3)^2`) |
| 말투 | 중등·고등은 **"…합니다"체**, 초등·유아는 **"…해요"체** |
| 언어 | `ko` `en` `zh` 셋 다 채운다 |

## 5. 검사기 — 이걸로 일합니다

`node scripts/<이름>.js`. 전부 `number_magic/` 에서 실행합니다.

**빠른 것(각 수 초)** — 데이터를 고쳤으면 매번

| 검사기 | 무엇을 본다 |
|---|---|
| `check-ladder` | 유형 순서와 선수 관계 |
| `check-stages` | 단계·과정·광고 숫자 일치 |
| `check-about-stats` | about.html 통계 = 실데이터 |
| `check-tex-hygiene` | 계수 1·0, 지수 1 노출, 이중부호 |
| `check-level-concept` | 갈래 바뀌는 레벨에 개념 문장 |
| `check-unit-lang` · `check-new-levels-lang` | 3개국어 누락·혼입 |
| `check-tone` | 중등·고등 합니다체 |
| `check-answerable` | 전 유형이 화면에서 풀리는가 |
| `check-step-equations` | 풀이 단계가 참인 식인가 |
| `check-level-coverage` | 만든 레벨이 실제로 학습지에 나오는가 (보고만, exit 0) |

**느린 것(수 분)** — 커밋 전

| 검사기 | 무엇을 본다 |
|---|---|
| `check-print` | 657레벨 인쇄 레이아웃(실제 브라우저 렌더) |
| `check-print-lang` | 세 언어가 칸 안에 인쇄되는가 |
| `check-solution-steps` | 풀이 모양 + **HEAD와 대조**해 "안 건드린 게 안 바뀌었나" |
| `check-new-levels-math` | 수학 관계 성립(6만 문항대) |

> `check-solution-steps`는 HEAD와 비교하므로 **의도적으로 문구를 바꾸면 커밋 직전까지 실패로 뜹니다.**
> 커밋하면 0이 됩니다. 실패 건수가 나오면 먼저 "prompt만 달라진 것인지"를 확인하십시오.
