## 0. 왜 다시 설계하는가

현재 구조(A-01 → A-02 → A-03 → A-04 순차 진행)의 문제:

1. **직렬 진행** — "덧셈 끝나고 곱셈, 초급 끝나고 중급"식. 참고 팜플렛(두뇌로 영재수학)
   분석 결과, 잘 만든 연산 커리큘럼은 **여러 스킬 실(thread)을 매주 병행**한다.
   새 개념 1개 + 이전 스킬 4~5개가 매 세션 섞여 나선형으로 복습된다.
2. **계산기형 입력** — 문제 보여주고 숫자패드로 최종 답만 입력. 전략(수 이사,
   우선10...)을 배우고도 연습은 그냥 암산 답 맞히기라 전략이 체화되지 않음.
3. **기본 연산 전제 미확인** — "수를 이사시켜요"는 가르기가 먼저 돼야 하는데
   전제 스킬 확인 없이 전략부터 들이밈.
4. **연습량 부족** — 세션당 4~8문항. 범위 확장, 시험 모드, 인쇄 학습지 없음.

## 1. 참고 팜플렛 구조 분석 (설계 원리 추출)

Level 1~3, 각 레벨 = 과정(course) 여러 개, 과정 = 4주차(session).

| 원리 | 내용 | 우리 설계 반영 |
|------|------|----------------|
| **스레드 병행** | 한 주차에 새 개념 1개 + 복습 스레드 3~5개 혼합 | 세션 = 새 마법 1 + 복습 드릴 3~5 |
| **나선형 복습** | 배운 스킬이 이후 수십 주에 걸쳐 계속 재등장 (예: 4d±4d, 2d×2d가 몇 달을 관통) | 스레드별 '유지 주기'로 자동 재출제 |
| **4주차 = Test** | 매 과정 마지막 주는 그 과정 스레드 전체를 시험 | 세션4 = 시험 모드(과정 시험) |
| **동시 다발 발달** | 덧셈이 끝나기 전에 구구단이 시작되고, 뺄셈·나눗셈이 곱셈과 병행 | 과정 설계에서 연산 종류 교차 배치 |
| **표기 체계** | 1d/2d(자리수), 10s(몇십), 보수(5F/10F/100F), twin(두배), 올림/내림/나머지 구분 | §2 스레드 코드 체계로 수용 |
| **특수 기법 스레드** | 19단·99단·기준곱·제곱수·거듭제곱 등 경시형 암산 기법이 고급에서 별도 스레드 | CHALLENGE의 특수곱 스레드 |

> ⚠️ 팜플렛 표를 그대로 복제하지 않는다. 위 **원리**만 가져오고 과정 편성은
> 우리 마법 전략(수 이사·우선10·계단식...)을 중심으로 자체 설계한다.

## 4. 연습 방식 — "계산기 금지" 원칙

**원칙 1: 전략을 배우는 화면에서는 전략의 중간 과정이 곧 입력이다.**
**원칙 2: 수 감각은 손 조작(큐브)이 먼저, 기호(수식)는 그다음이다.**
최종 답만 치는 숫자패드는 아레나(스피드전)에서만 허용.

| 위젯 | 동작 | 적용 스레드 |
|------|------|-------------|
| **큐브 보드(옮기기·가르기)** ★조작 핵심 | 큐브를 더미/텐프레임 사이로 드래그·탭 이동. 가르기(7 → 3+4), 모으기, **수 이사를 손으로**(8+7: 7 더미에서 큐브 2개를 옮겨 10 완성) | NS2, NS3, AD2, SB3 도입부 |
| **배열 보드(직사각형·정사각형 만들기)** ★조작 핵심 | 큐브 N개를 행×열 격자로 배열. 곱셈=직사각형(3×4), 나눗셈=12개를 3줄로→한 줄에 몇 개?, **약수=가능한 직사각형 전부 찾기**, **소수=1×N밖에 안 됨**, **제곱수=정사각형이 되는 수** | ML1~ML2 도입, DV2, DV6~DV8, ML11 |
| **텐프레임** | 10칸 틀에 점 채우기 — 보수를 눈으로 확인 | NS3, AD2 |
| **짝 묶기 타일** | 합10 짝 선택 (기존 selectPairs 유지) | AD8 |
| **단계 채우기(steps-entry)** ★기호 핵심 | `25+9 = 25+10-□ = □-1 = □` — 전략의 중간 빈칸을 순서대로 입력. 한 칸 맞히면 다음 칸 활성화 | AD2~AD6, SB3~SB7, ML6, DC, FR |
| **세로셈 자리 입력** | 일→십→백 자리 순서로 입력, 올림/내림 박스 별도 | AD5~7, SB4~6, ML7~9 |
| **□ 채우기(역산)** | `7 × □ = 42`, `□ - 18 = 25` | ML4, 전 스레드 변형 |
| **숫자패드(최종답)** | 기존 방식 | 아레나 전용 |

큐브·배열 보드는 같은 스레드의 **레벨 1(도입)에서 기본**, 레벨이 오르면 단계 채우기 →
숫자패드 순으로 추상화된다 (구체물 → 기호 → 암산).

기존 6단계 흐름은 유지하되 내용이 바뀜:
`기본연산(드릴 3~5스레드 순환) → 마법노트(개념) → 핵심체크 → 매직랩(단계 채우기) → 아레나(스피드) → 도장`

## 5. 데이터 스키마 (구현 지시서)

```js
// data/threads.js — 스레드 사전
window.NM_THREADS = {
  AD2: {
    name: {ko:'받아올림 덧셈(한 자리)', en:'…', zh:'…'},
    gen: 'addCarry1d',          // engine/generators.js의 함수 키
    prereq: ['NS3','AD1'],
    widgets: ['steps','tenframe','numpad'],  // 허용 위젯(앞이 기본)
    levels: [                    // 수 범위 = 레벨 (시험/인쇄에서 선택 가능)
      {id:1, params:{aMin:5,aMax:9,bMin:2,bMax:9}, label:{ko:'한 자리'}},
      {id:2, params:{twoDigit:true}, label:{ko:'두 자리 섞기'}},
      {id:3, params:{threeDigit:true}, label:{ko:'세 자리까지'}}
    ]
  }, …
};

// data/courses.js — 과정 편성
window.NM_COURSES = {
  P2: {
    tier:'beginner', order:2,
    title:{ko:'수 이사의 마법', …},
    sessions:[
      { magic:'A-02',            // 새 마법(전략 유닛 id) — null이면 드릴만
        drills:[ {t:'NS3',lv:1,n:6}, {t:'AD8',lv:1,n:6}, {t:'AD1',lv:2,n:6}, {t:'NS5',lv:1,n:4} ] },
      { magic:'A-02:deepen',     // 같은 마법의 심화 세션(범위 확대)
        drills:[ … ] },
      { magic:null, drills:[ … ] },
      { test:true,               // 세션4 = 과정 시험
        pool:[ {t:'AD2',lv:1,n:8}, {t:'NS3',lv:1,n:4}, {t:'AD8',lv:1,n:4}, … ],
        passRate:0.8 }
    ]
  }, …
};
```

- 생성기는 전부 `{prompt:{ko,en,zh}, tex, answer, steps:[{tex,blank,answer}...], widget}` 반환.
  `steps`가 있으면 단계 채우기 위젯이 자동 사용.
- **모든 생성기는 시드 지원**: `gen(params, rng)` — 시험/인쇄 재현용 (mulberry32).

## 6. 시험(Exam) 모드 + 인쇄 학습지

  - 진입: 과정 세션4(자동 구성) 또는 자유 시험(스레드·레벨·문항수 직접 선택)
  - 문항수 10~50, 타이머 선택(없음/5분/10분), 범위=스레드 레벨로 확장
  - 채점 → 결과지: 점수·소요시간·오답 목록(문제·내 답·정답·전략 힌트)
  - 오답만 다시 풀기 / 같은 구성 재시험(새 시드)
- **인쇄 학습지**
  - 시험 구성과 동일한 선택 UI → `인쇄` 버튼 → A4 인쇄 뷰
  - 상단: 이름/날짜/시간/점수 기입란, 학습지 코드
  - 문제 페이지(2열×10행, **기본 20문항 — 확정**) + **정답 페이지 분리**(맨 뒤, "정답지" 표기)
  - **학습지 코드 = 시드 해시** (`#P2-AD2L1x20-k3f9z`) — 같은 코드는 항상 같은 문제
    → 학부모·교사가 같은 시험지 재인쇄 가능, URL 해시로 공유
  - `@media print` CSS로 앱 UI 숨김 (도서관 인쇄 방지 가드와 충돌 않게 lib 외 경로만 허용)

## 7. 전제 스킬 확인 (게이트 아님 — 안내)

reading-world의 "자유 선택, 잠금 없음" 원칙 유지:

1. 마법 유닛/과정 진입 시 전제 스레드 목록 확인 (`NM_THREADS[t].prereq`)
2. 학습 기록(`mastery[t]` = 최근 정답률 EMA·속도)이 없거나 낮으면 —
   **막지 않고** 배너 표시: "이 마법엔 ○○ 연습이 도움돼요 → 3분 워밍업 하기 / 그냥 진행"
3. 워밍업 = 해당 스레드 5문항 (통과 시 mastery 갱신, 코인 소액)
4. 부모 대시보드(추후)에서 스레드별 mastery 히트맵 제공

## 8. 구현 파이프라인 계획 (승인됨 — 진행 가능)

Workflow(멀티 에이전트)로 일괄 구현 — 단계별 fan-out + 검수:

1. **생성기 팩토리** — 스레드별 생성기 ~30개 (Sonnet 병렬, 스레드당 1에이전트)
   - 계약: 시드 지원, `{prompt(ko/en/zh), tex, answer, steps, widget}` 반환
2. **위젯 5종** — 가르기 보드·텐프레임·단계 채우기·세로셈·□채우기 (Opus)
3. **데이터** — threads.js, courses.js(B1~5, P1~10, M1~6, H1~9 — **BASIC 포함 확정**), 마법 유닛 신규분(A-05~09, M-01~06, H-01~09 노트) (Sonnet 병렬)
4. **시험+인쇄 모듈** — exam.js, print CSS, 시드 코드, **기본 20문항(2열×10행)** (Opus)
5. **검수 (adversarial)** —
   - 생성기 무차별 대입 검증: 10만 회 생성→답 재계산 일치·범위·중복률
   - i18n 완전성 검사 (ko/en/zh 필드 누락 0)
   - Playwright E2E: 과정 P2 전체 플레이 + 시험 + 인쇄 뷰 스냅샷
   - 별도 리뷰 에이전트가 오답·저품질 문항 패턴 보고
6. **병합·배포** — main 푸시 → Pages

예상 규모: 신규/수정 파일 ~40개. 기존 A-01~04는 마법 유닛으로 재사용(드릴만 스레드 체계로 이관).
