## 0. 사용자 요구 (원문 요지)

1. **개념 설명을 더 쉽고 친절하게** — "2×3+2×4는 사과 2개들이 봉지 3개와 4개를
   더하면 봉지 7개" 같은 **문장(이야기) 설명** 또는 **넓이 그림**으로. 게임처럼 친절하게.
2. **창의수연 난이도가 널뛴다 → 정교하게 조정**. 초급/중급/고급 자유선택은 유지하되,
   **"학습모드" 로드맵**을 신설: 처음엔 수 범위가 작고 → 연산이 확장되고 → 높은 단계로
   자연스럽게 이어지는 하나의 길. 초급·중급 개념이 과정에 따라 **섞여도 좋음**.
3. 배우도록 만들 것 — 문제만 나오는 시험이 아니라, 학습이 되게.

## 2. 발견된 치명적 결함 (구현 시 최우선 수정)

### 2-1. NM_TGEN ↔ 앱 브리지 부재 (버그, ADVANCE 티어 전체가 앱에서 작동 불가)
- `app/main.js:12` → `const GEN=window.NM_GEN` 인데, B/C 유닛의 generator
  (`ml1_double`, `ml_gauss` 등)는 **`window.NM_TGEN`에만** 등록됨(engine/threads/*).
- main.js의 6개 호출부(`786, 812, 953, 981, 1036, 1075`)가 `GEN[cfg.generator]({level})`
  로 직접 호출 → ADVANCE 유닛 진입 시 `undefined is not a function` (origin/main도 동일).
- **또한 유닛의 `params`(mode:'div', target:100, easy:false…)가 전혀 전달되지 않음.**

**수정 설계** — main.js에 헬퍼 하나 추가, 6개 호출부를 교체:
```js
function genProblem(cfg, level){
  const g = GEN[cfg.generator];
  if (g) return g({ level });                       // 레거시 NM_GEN
  const tg = (window.NM_TGEN||{})[cfg.generator];   // 스레드 생성기
  if (tg){
    const rng = NM_RNG.mulberry32((Math.random()*2**31)|0);
    return tg(Object.assign({ level }, cfg.params||{}), rng);
  }
  return null; // + 화면에 "생성기 없음" 안내
}
// 호출부: GEN[cfg.generator]({level:'practice'}) → genProblem(cfg,'practice')
//        GEN[u.lab.generator]({level:'main'})    → genProblem(u.lab,'main')
//        arena 동일. (u.practice/u.lab/u.arena 객체를 그대로 넘긴다)
```
- index.html에서 rng.js가 generators.js보다 늦게 로드되므로 main.js 시점엔 NM_RNG 존재. OK.

### 2-2. 소수점 입력 불가
- `buildNumpad`(main.js & widgets.js 두 곳)에 `.` 키 없음. steps 위젯은
  `parseInt(inp,10)===s.blank` (widgets.js:401) → 소수 blank는 영원히 오답.
- 영향: `ml_decimal_mul`(C-25) mul 모드(답 4.3 등), C-25 check fill(3.8).

**수정 설계**:
1. `buildNumpad(pad, cb, opts)` 에 `opts.decimal` 추가 → 키 배열을
   `['1'..'9','.','0','del','ok']` 아님 — 12칸 유지가 어려우므로 **13키**:
   `['1','2','3','4','5','6','7','8','9','.','0','del','ok']` + CSS에서
   `.nm-numpad.dec{grid-template-columns:repeat(4,1fr)}` 로 4열 전환(13키 → 4×3+1,
   마지막 ok를 `grid-column:span 2`). 두 파일(main.js, widgets.js) 동일 적용.
2. 비교는 `parseFloat(inp)===Number(blank)` 로 통일(정수는 기존과 동일 동작).
3. decimal 필요 여부 판정: `!Number.isInteger(cur.answer)` 또는
   `cur.steps?.some(s=>!Number.isInteger(s.blank))` 또는 `cur.answerType==='decimal'`.
4. C-25의 check fill은 이미 소수 답(3.8) — 넘패드 수정 후 그대로 사용 가능.
   (수정 전 임시 회피가 필요하면 fill을 `3.8÷0.1=38`류 정수 답으로 교체)

### 2-3. `nextStepKey`/unitFlow 는 문제 없음 — flow는 CUR.unitFlow 고정 6단계.

## 4. 디스커버(개념 설명) 친절화 — 이야기+넓이 우선

1. **스테이지 ①은 반드시 구체물 이야기로 시작** — 사과 봉지, 사탕, 피자, 동전, 타일.

3. **스테이지 ③에서 수식 일반화 + 즉시 해보기.**
4. 말투: 시험 아님. "~해요/~해봐!" + 누미의 응원. 실패해도 힌트 먼저.

## 7. 직접 조작(만지는 수학) 위젯 설계 — "가르기는 직접 옮겨본다"

### 현황
`app/widgets.js`의 위젯 6종(cubes·array·tenframe·steps·vertical·missing)은 전부
**"그림 보고 숫자 입력"** 형이다. 아이가 **손으로 옮기고, 묶고, 자르는** 조작형이 없음.
디스커버도 읽기 전용. → 조작형 위젯군을 신설하고, 디스커버에 "해보기" 스테이지를 끼운다.

### 7-1. 신규 조작 위젯 6종 (widgets.js에 추가, pointer 이벤트 기반·모바일 우선)

  problem에 `widget:'dragSplit', manip:{total:7, target:3}` 식 파라미터 추가.

### 7-2. 디스커버에 "해보기(tryIt)" 스테이지

### 8-1b. 구구 3형제 — 덧셈구구·뺄셈구구·곱셈구구
"구구"는 곱셈만이 아니다. 교과는 세 종류의 **사실 암기(구구) 단계**를 거친다:

| 구구 | 내용 | 스레드 | 로드맵 |
|---|---|---|---|
| **덧셈구구** (1-2) | 받아올림 있는 한 자리+한 자리 (8+5, 9+7 … 총 45사실) | AD2 | R2에 "덧셈구구 완성" 유닛 |
| **뺄셈구구** (1-2) | 받아내림 있는 십몇−한 자리 (13−5, 15−8 …) | SB3 level 받아내림 | R3에 "뺄셈구구 완성" 유닛 |
| **곱셈구구** (2-2) | 2~9단 | ML2~ML4 | R6 (기존 구구 A~F) |

- **`factTable` 위젯 신설**(§7 목록에 추가, 7번째): 구구표(덧셈표/뺄셈표/곱셈표)의
  **빈칸을 직접 채우는 표 위젯**. 행×열 격자에서 빈칸 탭→넘패드. 표 전체가
  초록으로 물들면 완성 — "표를 정복하는" 시각적 성취감.
- **아레나 재사용**: 덧셈구구·뺄셈구구도 곱셈구구처럼 타임 배틀(arena)로
  유창성(fluency) 훈련. 스레드 유닛 래퍼(8-2의 2)로 `T-AD2구구`, `T-SB3구구`
  유닛을 만들고 arena count를 12~15로 올려 속도 목표 부여.
- 구구 배지: 세 구구 모두 완성하면 로드맵에 "구구 삼관왕 👑" 특별 도장.

### 8-1c. 시판 연산 교재 벤치마크 (사용자 제공: "기적의 계산법" 구성표 사진, 2026-07-14)
> 목차를 베끼지 말 것(저작물). 아래는 **구조적 교훈**만 추출한 것.

1. **하루 한 걸음(단계) 단위** — 시판 교재는 1일 1단계(앞뒷면), 한 권 10단계,
   전체 120단계로 진도가 아주 잘게 쪼개져 있음. 우리 로드맵 돌 하나 =
   유닛 전체(6스텝)라 너무 큼 → **돌 안에 "오늘의 한 장" 개념**: practice/lab/arena를
   각각 하루 분량으로 카운트하고, 로드맵에서 유닛 돌을 3칸 미니 게이지로 표시.
2. **시간 기록 문화** — 워크시트마다 "분·초" 기록란이 있음(같은 장을 더 빨리).
   → 아레나에 **개인 기록(best time) 저장 + "지난 기록 깨기"** 표시. `S.records[unitId]`.
3. **학년 마무리 = □ 방정식** — 매 학년 권이 "n학년 방정식"(□ 구하기)으로 끝남.
   → 로드맵 각 챕터 마지막에 **"□의 비밀" 캡스톤 돌** 추가: 그 챕터 연산을
   □ 채우기 역산 문제로(기존 `missing` 위젯 재사용, 생성기는 각 스레드의
   식을 □ 위치만 바꿔 출제하는 공용 래퍼 `eq_missing(threadKey)` 신설).
4. **유아 단계(P1~P6) 시퀀스 확인** — 수 알기(10까지) → 5까지 덧뺄 → 10보다 작은
   덧뺄 → 100까지 수 → 10 가르기·모으기 → 10보다 큰 덧뺄 순서.
   → 현재 비어 있는 **BASIC(수의 나라 NL) 티어를 이 순서로 채우는 근거**로 사용.
   가르기·모으기 트리 다이어그램(10을 두/세 가지로 가르기)은 `dragSplit` 위젯의
   화면 구성과 정확히 일치 — 세 갈래 가르기(10=1+3+□)도 지원하도록 manip 확장.
5. **초2 확인** — 두 자리±두 자리, 같은 수 여러 번 더하기(곱셈 도입), 구구단,
   세 자리± 가 한 학년에 공존. §8-1 매핑표·R6.5 신설 방향이 맞음을 재확인.

### 8-2. 설계 반영 3가지
1. **로드맵에 "교과 보충" 챕터 삽입** (구구단 사이·직후에 교과 흐름이 끊기지 않게):
   - `R6.5 📏 네 자리 수의 세계` — units: 스레드 유닛 `T-AD7`, `T-SB6`
   - `R7.5 ➗ 나눗셈 첫걸음` — units: `T-DV2`, `T-DV3` (몫 개념은 `bundle` 위젯 역방향:
     "12개를 3접시에 똑같이 — 접시당 몇 개?" = `dragSplit` 확장)
   - R13에 `T-FR2`(가분수↔대분수), `T-DC1`(소수 ±) 추가.
2. **스레드 유닛 자동 래퍼**: 40개 유닛 파일을 손으로 또 만들지 않는다.
   `data/units/thread-units.js` 하나에서
   `makeThreadUnit('T-AD7', threadKey:'AD7', level:2, icon, title, 짧은 discover 1스테이지)`
   헬퍼로 생성 → `window.NM_UNITS['T-AD7']=…`. practice/lab/arena generator는
   threads.js의 `gen`+`levels[].params`를 그대로 사용(§2-1 브리지로 params 전달 가능).
   discover는 1~2 스테이지 약식(교과 복습 성격) — 창의수연 유닛(C)의 3스테이지와 구별.
3. **교과 배지**: 로드맵 돌과 유닛 헤더에 `edu:'2-2'` 필드 → "🏫 2학년 2학기" 배지 표시.
   부모가 "학교 진도와 어디가 맞는지" 바로 봄. 유닛/챕터 데이터에 `edu` 필드만 추가.
