## 1. 지금 열려 있는 이유와 코드 위치

`app/main.js`의 프로필 기본값이 `status:'active'`라서 신규 사용자도 승인 상태로
시작한다(2026-08-29 지시). 게이트 코드(체험 유닛 제한·잠금 모달·승인번호 입력)는
전부 살아 있고, 기본값 한 줄만 바꾸면 다시 켜진다.

## 2. 코드 형식

```
NM-XXXX-XXXX   (예시 형식 — 실제 코드는 git에 두지 않는다)
```
- X = `23456789ABCDEFGHJKMNPQRSTUVWXYZ` 31자 중 난수. **0·O·1·I·L 제외** —
  학부모가 종이에서 옮겨 적을 때 헷갈리는 글자를 없앴다.
- 8자 난수 = 31⁸ ≈ 8.5×10¹¹ 조합. 익명 키로 존재 여부를 찔러보는 무차별
  대입은 사실상 불가능(코드당 성공 확률 ~10⁻¹²).
- 입력은 대소문자 무관 처리하지 않는다 — 코드 자체가 대문자만 쓰므로
  안내문에 "대문자로 입력"을 명시(현재 입력창 maxlength=24, 별도 변환 없음).

## 3. 저장소 — Supabase `nm_codes`

| 컬럼 | 뜻 |
|---|---|
| `code` (PK) | 승인번호 |
| `label` | 메모(학생 이름·발급처). **발급 전 재고는 `발급용-NN`** |
| `active` | true=유효. false로 바꾸면 그 학생은 다음 재검증 때 체험 모드로 |
| `created_at` | 생성 시각 |

- RLS: **anon·authenticated 는 표에 접근할 수 없다**(2026-09-06 정책·권한 모두 회수).
  발급·회수는 Supabase 대시보드(postgres)에서만. 읽기는 `service_role` 만 가능.
- 앱 검증 흐름(`nmCheckCode`→`applyAccountCode`): 표를 직접 보지 않고
  **Edge Function `nm-auth`** 에 물어본다(아래 §3-1). 유효하면 ok:true, 아니면
  "오타든 비활성이든 없음"으로 동일 처리.
- **하루 1회 재검증**(`reverifyAccountIfNeeded`): active=false로 회수하면
  다음날 앱이 자동으로 체험 모드로 되돌린다. 오프라인이면 잠그지 않는다.
- 기존 사용자(게이트 도입 전 프로필)는 코드 없이 영구 active(grandfather).

## 4. 운영 절차 (원장용)

**재고 확인** — Supabase 대시보드 → Table Editor → nm_codes,
또는 SQL: `select code,label from nm_codes where label like '발급용%' and active;`

**학생에게 발급** — 재고 하나를 골라 label만 학생 이름으로:
```sql
update nm_codes set label='홍길동 (2026-09)' where code='(그 코드)';
```
학생은 앱 잠금 화면(🔑 승인번호 입력)에 코드를 넣으면 즉시 전체 해제.

**회수(퇴원 등)** —
```sql
update nm_codes set active=false where code='(그 코드)';
```

**재고 보충** — 30개 단위 생성(2026-08-31에 1차분 30개 넣어 둠):
`scripts/` 없이 대시보드 SQL로 아래를 실행(lateral로 행마다 새 난수):
```sql
insert into nm_codes (code,label,active)
select gen.code, '발급용-'||lpad((coalesce((select max(substring(label from '\d+')::int)
  from nm_codes where label like '발급용%'),0)+g)::text,2,'0'), true
from generate_series(1,30) g
cross join lateral (
  select 'NM-'||string_agg(ch,'') filter (where s<=4)
       ||'-'||string_agg(ch,'') filter (where s>4) as code
  from (select s, substr('23456789ABCDEFGHJKMNPQRSTUVWXYZ',1+floor(random()*31)::int,1) ch
        from generate_series(1,8) s, (select g) tie) t
) gen on conflict do nothing;
```

## 3-1. 검증 함수 `nm-auth` (2026-09-06 신설)

소스: `supabase/functions/nm-auth/index.ts`

```
POST /functions/v1/nm-auth   { action:'verify'|'recheck', code }
  → 200 { ok:true, label }   유효
  → 200 { ok:false }         없거나 회수됨
  → 429 { error:'rate_limited', retryAfter }   같은 IP 10분에 12회 초과
```
- 헤더는 앱의 `sbHdr()`(apikey + anon Bearer) 그대로. Origin 은
  `docssam1.github.io` · `lete-on.gfieldacademy.net` · 로컬 8767 만 허용.
- 속도 제한 기록은 `nm_auth_attempts`(IP 해시 앞 32자만, 하루 뒤 pg_cron 이 청소).
- 표 접근은 service_role 로만 — 그래서 `grant select on nm_codes to service_role` 이 필요하다
  (없으면 함수가 `lookup_failed` 503 을 낸다. 실제로 처음 배포 때 이 누락으로 실패했다).

## 5. 게이트 — 2026-09-06 켰다

`app/main.js`:
```js
if(!S.account)S.account={status:hadSave?'active':'trial',code:null,checkedAt:0};
function accountActive(){return !!(S.account&&S.account.status==='active');}
```
- **완전 신규 설치만 체험으로 시작**한다. 이미 저장본이 있던 프로필(재원생)은
  승인번호 없이 계속 active — grandfather. 무조건 'trial' 로 두면 재원생이 잠기고,
  무조건 'active' 로 두면 게이트가 없는 것과 같다. 두 줄 다 한쪽을 깨뜨린다.
- 학습지 인쇄·편지함도 같은 게이트(`accountActive()`)를 쓴다.

### 체험 범위 (원장 지시 "유치 초등 중등 고등 2개씩과 게임마을 2개 챕터씩")
`trialUnitSet()` 이 **데이터에서 계산**한다(유닛 목록을 손으로 박지 않는다):
1. **학년 밴드 2유닛씩** — `data/roadmap.js` 의 `chapter.grade` 를 묶어서
   유치(유아) · 초등(초1~초5·창의) · 중등(중1~중3) · 고등(공통수학1·2·대수·미적분Ⅰ).
   현재 결과: 유치 N-01·N-06 / 초등 A-01·A-02 / 중등 M-01·M-02 / 고등 M-21·M-22.
2. **마을 건물마다 앞 2챕터 전체** — `TOWN_SPOTS` 에 실제로 서 있는 4개 등급
   (numberland·beginner·advanced·intermediate)의 열린 레벨 앞 2개.
   curriculum.js 의 11개 tier 를 전부 세면 199유닛 중 70개가 열려 버린다 — 마을 건물만 센다.
- 합계 **31 / 199 유닛**. `screenTier` 는 3번째 챕터부터 자물쇠로 그리고 누르면 게이트 모달.

### 마을 밖(다른 서비스) 차단
`externalBlocked()` = 체험이면 true. 막는 곳:
- 관문 모달의 `url` 링크 — 도형 나라(`../geometry/`) · 탐험대(`../world-explorer/`).
  앱 안 화면(`view`, 예: 수학사 퀴즈)은 그대로 열린다.
- 로드맵 챕터 링크 중 `../` 로 시작하는 것(`../fields-classic/calculus/`).
  `labs/*.html` 같은 앱 안 링크는 열린다.

## 6. 보안 메모

- 실제 코드값은 **절대 git 에 넣지 않는다**(이 문서 포함). 코드는 Supabase 에만.
- ~~anon 키로는 유효 코드의 존재 확인만 가능~~ — **이 전제는 틀렸다(2026-09-06 실측).**
  RLS `USING (active=true)` 는 행 필터일 뿐이라 `/rest/v1/nm_codes?select=code` 한 번이면
  유효 코드 31개가 그대로 200 으로 나왔다. 게이트를 켜기 전에 반드시 막아야 했던 구멍이다.
  → 정책·권한을 모두 회수하고 검증을 `nm-auth` 로 옮겼다. 지금은 같은 요청이 401 이다.
- 남은 할 일 하나: **개발 검증용 코드 1개가 아직 active** 다(label "개발 검증용 (배포 후
  비활성 예정)"). 원장이 새 게이트를 직접 확인한 뒤 `active=false` 로 내릴 것.
