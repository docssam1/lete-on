# 승인번호 체계 설계 (Phase 2B 운영판)

> 2026-08-31, 원장 지시 "승인 페이지 열려면 승인번호 설계가 되어야 해 /
> 우선 승인 풀어놓고 내가 확인해야 하니 차후 잠그자"에 따른 설계.
> **지금 상태: 게이트 열림** — 신규 프로필도 승인 없이 전부 이용 가능.
> 잠그는 방법은 §5 한 줄이다.

---

## 1. 지금 열려 있는 이유와 코드 위치

`app/main.js`의 프로필 기본값이 `status:'active'`라서 신규 사용자도 승인 상태로
시작한다(2026-08-29 지시). 게이트 코드(체험 유닛 제한·잠금 모달·승인번호 입력)는
전부 살아 있고, 기본값 한 줄만 바꾸면 다시 켜진다.

## 2. 코드 형식

```
NM-XXXX-XXXX   (예시 형식 — 실제 코드는 git에 두지 않는다)
```
- X = `23456789ABCDEFGHJKMNPQRSTUVWXYZ` 31자 중 난수. **0·O·1·I·L 제외** —
  학부모가 종이에서 옮겨 적을 때 헷갈리는 글자를 없앴다.
- 8자 난수 = 31⁸ ≈ 8.5×10¹¹ 조합. 익명 키로 존재 여부를 찔러보는 무차별
  대입은 사실상 불가능(코드당 성공 확률 ~10⁻¹²).
- 입력은 대소문자 무관 처리하지 않는다 — 코드 자체가 대문자만 쓰므로
  안내문에 "대문자로 입력"을 명시(현재 입력창 maxlength=24, 별도 변환 없음).

## 3. 저장소 — Supabase `nm_codes`

| 컬럼 | 뜻 |
|---|---|
| `code` (PK) | 승인번호 |
| `label` | 메모(학생 이름·발급처). **발급 전 재고는 `발급용-NN`** |
| `active` | true=유효. false로 바꾸면 그 학생은 다음 재검증 때 체험 모드로 |
| `created_at` | 생성 시각 |

- RLS: 익명(anon)은 **active=true 행만 SELECT** 가능. 쓰기 불가.
  → 발급·회수는 Supabase 대시보드(서비스 롤)에서만 한다.
- 앱 검증 흐름(`nmCheckCode`→`applyAccountCode`): 행이 오면 유효, 안 오면
  "오타든 비활성이든 없음"으로 동일 처리.
- **하루 1회 재검증**(`reverifyAccountIfNeeded`): active=false로 회수하면
  다음날 앱이 자동으로 체험 모드로 되돌린다. 오프라인이면 잠그지 않는다.
- 기존 사용자(게이트 도입 전 프로필)는 코드 없이 영구 active(grandfather).

## 4. 운영 절차 (원장용)

**재고 확인** — Supabase 대시보드 → Table Editor → nm_codes,
또는 SQL: `select code,label from nm_codes where label like '발급용%' and active;`

**학생에게 발급** — 재고 하나를 골라 label만 학생 이름으로:
```sql
update nm_codes set label='홍길동 (2026-09)' where code='(그 코드)';
```
학생은 앱 잠금 화면(🔑 승인번호 입력)에 코드를 넣으면 즉시 전체 해제.

**회수(퇴원 등)** —
```sql
update nm_codes set active=false where code='(그 코드)';
```

**재고 보충** — 30개 단위 생성(2026-08-31에 1차분 30개 넣어 둠):
`scripts/` 없이 대시보드 SQL로 아래를 실행(lateral로 행마다 새 난수):
```sql
insert into nm_codes (code,label,active)
select gen.code, '발급용-'||lpad((coalesce((select max(substring(label from '\d+')::int)
  from nm_codes where label like '발급용%'),0)+g)::text,2,'0'), true
from generate_series(1,30) g
cross join lateral (
  select 'NM-'||string_agg(ch,'') filter (where s<=4)
       ||'-'||string_agg(ch,'') filter (where s>4) as code
  from (select s, substr('23456789ABCDEFGHJKMNPQRSTUVWXYZ',1+floor(random()*31)::int,1) ch
        from generate_series(1,8) s, (select g) tie) t
) gen on conflict do nothing;
```

## 5. 잠그는 날 (차후, 원장 확인 뒤)

`app/main.js`에서 신규 프로필 기본값 한 줄:
```js
if(!S.account)S.account={status:'active',code:null,checkedAt:0};
//                              ↑ 'active' → 'trial' 로 바꾸면 게이트 켜짐
```
- 켜면: 신규 사용자는 체험 유닛 4개(N-01·N-09·A-01·C-06)만 이용 가능,
  나머지는 잠금 모달 → 승인번호 입력.
- 기존 사용자(저장본 있던 프로필)는 영향 없음(grandfather).
- 학습지 인쇄·편지함도 같은 게이트를 쓴다(`accountActive()`).

## 6. 보안 메모

- 실제 코드값은 **절대 git에 넣지 않는다**(이 문서 포함). 코드는 Supabase에만.
- anon 키로는 유효 코드의 존재 확인만 가능하고 목록 열람은 코드를 알아야만
  되므로(PK 등가 조회), 코드 유출 = 그 코드 하나의 유출로 한정된다.
- 개발 검증용 코드 1개가 active로 남아 있다 — **게이트를 켜는 날 함께
  비활성화할 것**(label에 "개발 검증용 (배포 후 비활성 예정)"이라 적혀 있다).
