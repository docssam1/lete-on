## 2. 재설계 원칙

1. **척추는 연산 진도다.** 과정 번호는 계산 능력 순서를 따르고, 창의수연 전략은 그 지점의 "새 마법" 슬롯에 끼운다. (기존: 전략이 척추, 연산이 부록 → 뒤집음)
2. **한 주의 분량은 고정하지 않는다** (원장 지시: 주차별 편성 불필요, 한 주에 하나여도 됨).
   기본 단위는 "노드 1개"(마법 유닛 하나 또는 유형 하나)이고, **누적 복습은 세션에 자동으로 붙는
   드릴 믹스가 담당**한다 — 아이가 무엇을 하든 이전 유형이 조금씩 섞여 나온다. 빠른 아이는
   한 주에 여러 노드, 느린 아이는 하나. 페이스는 기록만 하고 강제하지 않는다.
3. **과정 끝 = Test.** 그 과정 유형 풀에서 80% 통과, 미달 시 재시험(기존 courses.js 규칙 그대로).
4. **정체 감지 → 보강 루프.** 유형별 정답률·속도를 추적, 2회 연속 미달이면 다음 주차에 그 유형 보강 드릴 자동 삽입 + **한 단계 시각화로 내려간다**(십진블록·수직선). 학원은 반 단위 스테이가 최선이지만 앱은 개인 단위로 한다.
5. **페이스 표기.** 상위권 월 1과정 / 표준 1.5~2개월. 잠금 없음(자유 선택 원칙) — 페이스는 안내일 뿐.

## 6. 개념 계보 (세로줄) — 과정은 가로줄일 뿐이다

> 원장 지시(2026-08-24): "단순히 과정으로 보지 마라. 2와 5는 친구 — 그러면 4×25, 8×125도
> 묶이고, 1/5·4/25 같은 것도 소수로 만들 수 있다."

과정표(가로)는 "언제 배우나"만 답한다. **같은 생각이 자라나는 줄기(세로)**를 따로 정의해,
스토리 모드에서 유닛마다 "이 마법의 다음 진화"가 보이게 한다. 유닛 데이터에 `lineage` 필드 추가.

### 계보 1 · 2와 5는 친구 (10의 혈통) — 원장 예시 그대로
```
보수 10 (유아·과정1)
 → 곱해서 10 만들기 (2×5)
 → ×5 = ×10÷2, ÷5 = ×2÷10        "5는 10의 반쪽 친구"
 → 곱해서 100 만들기 (4×25)        "친구가 두 번 만나면 100"
 → ×25 = ×100÷4, ÷25
 → 곱해서 1000 만들기 (8×125) ★신규  "세 번 만나면 1000"
 → 분해곱셈법 (숨은 2·5를 찾아낸다)
 → 분수→소수 변환: 1/5=2/10=0.2, 4/25=16/100=0.16, 3/8=375/1000=0.375
   — 분모를 2·5의 곱으로 보고 10·100·1000으로 부풀리는 것
 → 유한소수 판별 (중2 W9): 분모의 소인수가 2·5뿐이면 유한소수 — 계보의 완성
 → 10ⁿ = 2ⁿ·5ⁿ (지수, 고등)
```

### 계보 2 · 반과 배 (2의 혈통)
두 배 수 → ÷2 → 한쪽으로 모으기(고급 A: ×2와 ÷2로 곱을 옮긴다) → 진법·이진법 곱셈(고급 C)

### 계보 3 · 9는 10의 옆집 (보수의 혈통)
10 이용 9 덧셈(+10−1, 다함식) → ×9 = ×10−1 → 9로 끝나는 수의 곱 → 100 보수 곱셈(고급)
→ 순환소수: 9·99로 나누면 반복된다(고급 D → 중2) → 11=10+1: ×11, 1001 법칙

### 계보 4 · 무지개 덧셈법 (평균의 혈통) — 아이 눈높이 이름 확정(원장, 2026-08-25)
"가우스 짝짓기"의 공식 명칭을 **무지개 덧셈법**으로 한다 — 짝(1↔10, 2↔9…)을 잇는 선이
무지개 아치이기 때문. 가우스 소년 일화는 "전해지는 이야기"로 붙인다.
무지개 덧셈법(첫수+끝수) → 차가 2인 두 수의 곱(중간수²−1) → 평균값 곱셈(평균²−차²)
→ 합차공식 (a+b)(a−b)=a²−b² (중3 W10) — 계보의 완성
- **개념실험실 1호 제작 완료**: `labs/rainbow-sum.html` — ①가우스 이야기(전설 표기·읽어주기)
  ②1~10 무지개 애니메이션(아치 5개 그려지며 합 11, 11×5=55) ③직접 하기(1~10·1~9 홀수
  가운데 수·1~20·1~100 축약, 짝 탭으로 아치 생성 → (첫+끝)×쌍수 입력 채점).
  전부 자체 창작 SVG/JS 단일 파일, 외부 의존 0. 내레이션은 Web Speech 폴백 —
  MP3 파이프라인(generate-audio) 연결은 추후. 스토리 모드 🔬노드의 원형(template).

### 계보 5 · 자리의 마법 (자릿값의 혈통)
자릿값·큰 수 → 자리 이동 곱셈 → 차근차근 곱하기(부분곱) → 분리 제곱법((앞+뒤)² 전개)
→ 다항식 곱셈·곱셈공식 (중2~3) → 지수법칙

### 규칙
1. **모든 유닛은 계보를 하나 이상 가진다** (`lineage:['ten-friends']` 식). 무소속이면 설계 재검토 신호.
2. 스토리 모드 유닛 카드에 계보 문장과 **다음 진화 링크**를 표시: "이 마법은 나중에 ○○로 자라요."
3. 마법 노트(discover)의 개념 문장도 계보 언어로 쓴다 — "4×25가 100이 되는 건 4 속에 2가 두 번, 25 속에 5가 두 번 숨어 있기 때문" 식.
4. 계보 완주 배지: 한 계보의 전 유닛 완료 시 가문 문장(紋章) 획득.

### 이 지시로 생긴 신규·수정 소요
- ★ 곱해서 1000 만들기 (8×125, 2×500, 4×250) — ml_pair10 target:1000 레벨 확장 + 유닛
- 분수→소수(FR8) 개념을 "부풀리기" 관점으로 재서술 (지금은 대응표 암기에 가까움)
- 유한소수 판별 유형(중2 W9)을 계보 1의 종착으로 명시
- 유닛 스키마에 lineage 필드 + 스토리 모드 계보 표시

> 원장 지시(2026-08-24): 개념을 이런 식으로 열어라 — "나눗셈이 먼저일까 분수가 먼저일까",
> "수직선을 다 이으려면 어떤 수가 필요할까", "다 구하려고 무리하지 마, 무리수야",
> "+는 비트만이 만들었을까, 라틴어 et가 만든 걸까", "유한과 무한은 무엇일까". **순서 재배치 허용** —
> 이야기가 자연스러우면 과정 안 유닛 순서를 바꿔도 된다.

### 원칙 3가지
1. **질문으로 연다.** 정의부터 주지 않는다. "수직선에 유리수를 다 찍어도 구멍이 남을까?"처럼
   아이가 궁금해지는 질문 → 탐구 → 이름 붙이기(정의는 맨 뒤).
2. **생활 장면·말장난이 기억 고리다.** 해발/해저, 득점/실점, "무리하지 마 무리수야" —
   교과서 문장보다 농담 한 줄이 오래 남는다. 단, 말장난은 개념의 **본질과 닿아야** 쓴다
   (무리수 = 다 쓸 수 없는 수 → "다 구하려 무리하지 마"는 본질 그대로).
3. **수학사는 검증된 사실만, 전설은 전설이라 말한다.** 연도·인명은 확인된 것만 쓰고,
   히파소스 익사 같은 이야기는 "전해지는 이야기"로 표기. 문구는 전부 자체 서술(교재 인용 없음).

### 훅 뱅크 (유형 ↔ 이야기 ↔ 수학사)
| 개념(어디에) | 친숙한 훅 | 수학사 연결 |
|---|---|---|
| 나눗셈 도입 (초2~3) | **나눗셈이 먼저일까 분수가 먼저일까?** 빵 3개를 4명이 나누면 — 나눗셈을 하는 순간 분수가 태어난다 | 이집트 파피루스(약 3,600년 전)에 이미 분수가 있다 — 빵과 맥주를 나누는 계산. 나누는 **행동**이 먼저, 분수는 그 행동에 붙인 **이름** |
| 나눗셈 두 얼굴 (초3) | 사탕 12개를 **3명에게 똑같이**(등분제: 한 명 몇 개?) vs **3개씩 봉지에**(포함제: 몇 봉지?) — 식은 같은 12÷3, 질문은 다르다 | 문장제에서 아이가 헷갈리는 근본 원인. 두 그림을 다 겪게 한 뒤 "같은 식"임을 발견 |
| 음수 도입 (중1 G03~) | **해발 vs 해저, 득점 vs 실점, 영상 vs 영하** — 0을 기준으로 반대 방향에 이름 붙이기 | 중국 『구장산술』은 2,000년 전에 붉은 산가지(+)·검은 산가지(−)로 계산했다. 유럽은 음수를 "거짓 수"라 부르며 수백 년 의심했다 — 아이가 어색해하는 건 당연한 일 |
| 제곱근 (중3) | **제곱해서 2가 되는 수를 찾아라**: 1.4²=1.96, 1.41²=1.9881, 1.414²=… 좁혀가기 게임 | 손으로 뿌리를 캐는 **개평법**(나눗셈 필산처럼 자리마다 파 내려간다) 체험 유닛 — 계산기 이전 시대의 마법 |
| 무리수 (중3) | **"다 구하려고 무리하지 마 — 무리수야."** 아무리 써도 끝나지 않고 반복도 없는 수 | 피타고라스 학파는 "모든 것은 분수"라 믿었는데 정사각형 대각선 √2가 그 믿음을 깼다. 히파소스가 이 비밀을 누설해 바다에 던져졌다는 **전설**이 전해진다 |
| 실수·수직선 (중3) | **수직선을 빈틈없이 이으려면 어떤 수가 필요할까?** 유리수만 찍으면 √2 자리에 바늘구멍이 남는다 | 구멍을 모두 메운 수의 이름이 **실수** — "수직선 = 실수"가 되는 순간 |
| 연산 기호의 역사 (초등 고학년 쉬어가기) | **+는 누가 만들었을까?** 라틴어 et(그리고)를 빨리 흘려 쓰다 +가 됐다. 비트만(1489)은 그걸 **처음 책에 인쇄**한 사람 — 발명이라기보다 상인들의 손버릇이 굳은 것 | =는 레코드(1557)가 "이보다 더 같은 것은 없다"며 나란한 두 줄로. ×는 오트레드(1631) — 라이프니츠는 "x랑 헷갈린다"고 싫어해서 점(·)을 썼다. ÷는 란(1659) |
| 유한과 무한 (초등 고학년~중등) | **유한 = 세다 보면 끝이 있다. 무한 = 끝이 없다.** 자연수는 끝이 있을까? "가장 큰 수"에 늘 +1이 가능하다 | ∞ 기호는 월리스(1655). 소수점 아래로도 같은 질문 — 0.375는 끝나고(유한소수) 1/3=0.333…은 끝나지 않는다 → **계보 1의 유한소수 판별과 접속** |
| 무지개 덧셈법 (초2~, 계보 4) | 짝을 이으면 **무지개** — 1↔10, 2↔9… 전부 11! 무지개가 5개니까 11×5 | 어린 가우스가 1~100의 합을 몇 초 만에 구한 일화(전설 표기). **개념실험실 1호 `labs/rainbow-sum.html` 완성** — 이야기·애니메이션·직접 하기 3단 구성이 이후 🔬노드의 표준 틀 |

### 데이터 모델
- 유닛 discover에 선택 필드 `story:{ hook, history }` — hook은 여는 질문/말장난 한 줄,
  history는 수학사 한 토막(2~3문장, 3개 언어). 없으면 지금처럼 렌더.
- 쉬어가기 유닛("기호의 역사", "무한 호텔" 등)은 문제 없이 이야기+간단 퀴즈만 있는
  `tier:'story'` 신설 검토 — Phase 2에서 결정.
- 훅 문구는 전부 자체 창작 — 어떤 교재의 서술도 옮기지 않는다(수학사 사실 자체는 공유 자산).

## 8. 도형수 친구들 — 삼각수(구현 완료) · 사각수(실험실 3호 예정)

> 원장 지시(2026-08-25): "55, 66, 78, 91, 5050과 친해지기" → 구현 완료.
> "그러면 사각수도 해야지" → 실험실 3호로 설계.

- **삼각수 친구 수집 ✅** — rainbow-sum ③직접 하기에 1~11·12·13 범위 추가,
  55·66·78·91·5050을 "무지개 친구" 배지로 수집(localStorage 유지, 5개 완집 시 👑).
  이 다섯 수는 이후 과정에서 계속 재등장하므로(합 구하기·평균·수열) 얼굴을 익혀 두는 게 목적.
- **사각수 = 홀수의 합 (실험실 3호 `labs/square-friends.html` 예정)** —
  1, 1+3=4, 1+3+5=9, 1+3+5+7=16… **홀수를 ㄱ자(곱자 모양)로 두르면 정사각형이 자란다**를
  점 애니메이션으로. 친구 배지 1·4·9·16·25·36·49·64·81·100.
  수학사 훅: 고대 그리스인들은 조약돌(calculus!)로 수를 놓아 보며 삼각수·사각수라는
  이름을 붙였다 — "계산(calculate)"이라는 말 자체가 조약돌에서 왔다.
  종착: 제곱수 암기 → 분리 제곱법(계보 5) → 곱셈공식·제곱근(중3)의 밑재료.
  삼각수와의 다리: **사각수 = 이웃한 삼각수 두 개의 합**(55+66=121=11²) — 두 실험실을 잇는 링크로.

## 9. 유아 그래픽 지침 (원장, 2026-08-25)

"유아쪽은 우리 맵처럼 그래픽 신경쓰자" — 유아(N) 유닛의 화면 밀도를 마을 지도 수준으로.
- 위젯마다 장면(배경·소품)을 입힌다: 저울은 과일 가게, 피라미드는 이집트 사막, 동전은 가게 놀이.
- 이모지 나열로 때우지 말 것 — 마을 지도처럼 SVG 장면 + 캐릭터(누미/3/8) 동반 등장.
- 구현 시점: Phase 1 인프라 뒤, 유아 MP3 적용과 같은 묶음으로(화면·소리를 한 번에 업그레이드).

## 10. 주간 학습지 편지함 (학부모 요청, 2026-08-25)

> "어떤 엄마는 매주 해야 할 분량이 학습지로 왔으면 좋겠대. 알람 받기 이런 거 되나,
> 아니면 편지함에 쌓이도록 설계."

**결정: 1단계 = 앱 안 편지함(📬). 알람(푸시)은 2단계.**
- **편지함**: 마을에 우체통 건물/아이콘. 매주 월요일이 되면 그 주의 학습지 봉투가 자동으로
  도착(클라이언트에서 주차 계산 — 서버 불필요). 봉투 = 현재 과정 위치에서 뽑은 생성형
  학습지(제너레이터 시드를 주차로 고정해 **가족 모두 같은 주엔 같은 문제지**) + 인쇄 버튼.
  안 연 봉투는 쌓이고 뱃지 숫자로 표시. 부모는 아이 계정 열고 인쇄만 하면 됨.
- **주간 분량 산출**: courses.js의 과정 위치(현재 세션)에서 마법 1 + 드릴 2~3종을 편성 —
  기존 학습지 모드 생성기를 그대로 재사용. 과정 진도가 없으면 최근 학습 유닛 기준.
- **알람(2단계)**: GitHub Pages는 서버 푸시가 없으므로 ①PWA 설치 + 로컬 알림(제한적) ②이메일
  발송은 Supabase Edge Function + Routine 스케줄로 가능. 학부모 이메일 수집이 선행되므로
  회원제(예정)와 함께 설계. 1단계 편지함만으로도 "매주 쌓이는" 요구는 충족.
- 구현 위치: Phase 2(courses.js 재편)와 같은 턴 — 주간 편성 로직을 공유하기 때문.
