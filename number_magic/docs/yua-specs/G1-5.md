# G1-5호 (9까지의 수 · 양의 수와 순서수) → 앱 유아 단계 이관 명세

대응 유닛: **N-05 생활 서수 문장제**(1:1). 활동 목록 원본: `docs/g1-inventory/G1-5.md`. PDF 쪽을 직접 보고 확인했다.
이 호는 교재 자체가 **글 읽기가 대부분**(상황 문장·안내문·서술형 고쳐 쓰기)이라 5~7세용으로는 거의 전부 '그림 장면 + 한 가지만 묻기'로
다시 짜야 한다. 서술형 "틀린 것 고쳐 쓰기"(4·10쪽)는 앱 입력으로 채점할 수 없어 E(대체안)이다.

## 공통 규약 (G1-4/5/6 세 파일이 같은 문구)

1. **답 계약(코드 확인)**: 위젯은 `onAnswer(숫자 하나)` 만 부르고 채점은 `+val === problem.answer`
   (main.js 3149·4724·5331·6156). 정답이 여러 개인 열린 활동은 **위젯이 스스로 검증**해서 맞으면 `problem.answer`,
   아니면 `-1` 을 보낸다(+`shake`). 배열 입력이 필요해도 숫자 하나로 접는다.
2. **보기 고르기**: 숫자 칩은 `problem.chips`(숫자 배열, 생성기가 `rng` 로 섞어 실음, 답은 그 숫자 값). 글/그림 보기는
   `problem.choices`(배열) + **답 = 1부터 세는 보기 번호**(인쇄 ①②③와 같음). 기존 위젯 다수가 위젯 안에서 `Math.random`
   으로 보기를 만드는데(widgets.js 875·957·1099…) 새 위젯은 따르지 말 것 — 인쇄·재현이 안 된다.
3. **인쇄(exam.js)**: nl 문항은 `nlVisualHtml(p)` 의 widget 별 분기가 그림을 만든다. 모르는 widget 은 **빈 문자열**이 되어
   그림이 통째로 빠진다 → 새 widget 마다 분기 필수. 정답지는 `nlAnswerLabel(p)` 가 말로 바꿔 적는다. **한 줄 패치 권장**:
   `nlAnswerLabel` 맨 앞에 `if(p.answerLabel) return pickL(p.answerLabel)`(문자열 또는 `{ko,en,zh}`) — 열린 활동·글 답을
   생성기가 직접 적게 한다. 화면 말투(톡톡·콕)는 `NL_PRINT_WORDS` 에 새 문구를 추가해 인쇄용으로 바꾼다.
4. **중복 키**: `problemKey()`(exam.js 4899)는 열거된 필드만 본다. 새 필드(`scene cards seat target cats kind animals clues
   rules give ask ahead behind fromBack theme` 등)를 목록에 추가하지 않으면 **서로 다른 문항이 같은 키로 합쳐져** 풀이 줄어든다.
   `choices` 는 이미 키에 있어 보기 순서만 다른 같은 문제가 다른 문항으로 센다 — 풀 크기는 '질문의 개수'로만 셀 것
   (권장: `choices` 를 키에서 빼고 `uq` 문자열 하나를 넣는 패치).
5. **풀 크기**: 한 레벨에서 서로 다른 key 24개 이상(20+예시1+따라풀기3, `docs/unique-shortfall-2026-09-25.json` 기준).
   각 mode 마다 추정 풀을 적었다.
6. **수 범위**: 레벨 규칙은 기존과 같다 — `practice` ≤5, `main` ≤9. 글을 못 읽는 나이라 문장은 짧게, 모든 화면 문구는
   `NM_SAY`로 읽힌다(기호 금지). 서수는 `ORDINAL` 표(nl.js 243)를 재사용, 3언어 한 벌 `{ko,en,zh}`.
   **'양의 수/순서수' 용어는 유아 말로**: 양 = "몇 개인 수", 순서 = "몇째인 수". 교재의 정의 박스는 개념 노트로.
7. **새 스레드 번호**: `NL-?` 는 가칭. 다른 호 명세와 겹치지 않게 통합 때 부여.
8. **검증**: 새 위젯·mode 는 `node scripts/check-answerable.js <스레드>` 와 인쇄 미리보기로 확인.

## 이 호의 새 모듈 (활동별 명세에서 참조)

### M1. `qtyOrd` — 양(몇 개)과 순서(몇째) 구분
- 위젯 `qtyOrd`: 위에 **장면**, 가운데 말풍선(🔊 으로 문장을 읽어 줌), 아래 **숫자 카드 두 장**. 아이는 묻는 쪽 카드를 누른다
  ("몇째를 나타내는 수에 콕!" / "몇 개를 나타내는 수에 콕!"). 누르면 즉시 판정(맞으면 `.on`, 틀리면 shake), `onAnswer(그 카드의 수)`.
  두 수가 같으면 구분이 안 되므로 생성기가 **서로 다른 수**만 뽑는다.
- 스키마
  ```
  { widget:'qtyOrd', answerType:'number',
    scene:{ kind:'line'|'prize'|'coins', total:T, rank:k, e:토큰, q?:n },
    cards:[{n:T,role:'qty'},{n:k,role:'ord'}] (순서 rng), ask:'qty'|'ord',
    prompt:{ko,en,zh}, answer:(ask==='qty'? 양의 수 : 순서수) }
  ```
- 장면 종류: `line` — 친구 T명이 줄을 섰고 하나가 표시됨("모두 T명, 표시된 친구는 앞에서 k째"). `prize` — 시상대(1·2·3) 위 k등과
  그 친구가 받은 선물 q개("2등, 사탕 5개"). `coins` — 동전 T개 한 줄, 하나만 큰 동전(k째).
  교재의 "형우 왼쪽에서 셋째·앞에서 둘째" 같은 두 방향 서수는 `seat`(p3)로, "책 3권을 빌려 4일 만에"는 기간 말이라 유아 개념(양 vs 순서)
  에서 벗어나 **폐기**(E).
- 인쇄: `nlVisualHtml` 에 `qtyOrd` — 장면을 그리고 카드 두 장에 ○표 하라는 말. 정답지 `answerLabel`: `3 (몇째)` / `5 (몇 개)`.
- 풀: `line` 은 T 3~9, k 1~T−1, ask 2 → 70; `prize` k 1~3 × q 2~9 × ask 2 → 48; 충분.
- 3언어: ko `모두 5명이에요. 모자 쓴 친구는 앞에서 셋째예요. 몇째를 나타내는 수에 콕!` / en `There are 5 friends in all. The friend with the hat is third from the front. Tap the number that tells the place.` / zh `一共有5个小朋友，戴帽子的排在前面第3。点一点表示第几的数。`

### M2. `pickCard` (세 호 공유 — G1-4 명세 M5 와 같은 위젯)
큰 보기 단추 2~4개로 고르는 범용 위젯. `stemParts`(`{k:'text',t}`·`{k:'row',total,mark,e}`·`{k:'dots',n,e}`·`{k:'eq',t}`·`{k:'cards',list}`),
`choices`(문자열 배열), 답 = 1부터 센 보기 번호. 즉시 판정, 🔊 다시 듣기. 인쇄: stem + ①②③ + `답 ( )번`.
이 호에서는 `fix`(고쳐 쓰기 대체)와 `rule`(안내문 판단)이 쓴다.

### M3. `chain` — 수 기계 연쇄 (`nl8_machine` 새 mode)
기존 `numberMachine` 위젯을 확장한다(B): `mmode:'chain'`, `rules:['+1','-1','+2']`(기계 칸을 여러 개 이어 놓음), `theme`.
숫자패드 입력(기존). 중간 값은 숨김. **전 구간이 0~9 안**에 머무르게 생성기가 입력을 고른다.
- 스키마 `{widget:'numberMachine', answerType:'number', mmode:'chain', input, rules:[…], theme:'quiz'|'age'|'birds'|'stairs', answer}`
- 테마별 기계 칸 표시: `quiz` ✓(+1) / ✗(−1), `age` 🎂(+1살), `birds` 🐦(+2), `stairs` 이김(+2칸)/짐(−1칸) — 기호는 그림 칩 하나 + 부호.
- 인쇄: `nlMachineHtml` 에 `chain` 이면 칸을 `rules.length` 만큼 이어 그림, 끝 상자만 빈칸.
- 3언어 문구 예(quiz): ko `5점에서 시작! ✓맞음은 +1, ✗틀림은 −1. 맞음, 틀림, 맞음이면 몇 점일까요?` / en `Start at 5 points! Right is +1, wrong is −1. Right, wrong, right — how many points?` / zh `从5分开始！答对+1，答错−1。对、错、对，现在几分？`
- 풀: 입력 0~9 × 규칙 조합(길이 2~3, 증감 1~3) 수백 → 범위 필터 후에도 충분. practice 는 `+1/−1` 2칸.

### M4. `trade` — 주고받기 (`nl15_logic` 새 mode)
위젯 `tradeScene`(C): 두 줄(A·B)에 토큰이 놓이고 아이가 **토큰을 눌러 옮겨 본다**(탭 → 반대 줄로 이동 애니메이션).
- `interaction:'after'` — "A가 B에게 k개 주면 A는 몇 개?" 옮긴 뒤 `chips` 로 고름(`ask:'a'|'b'`).
- `interaction:'equal'` — "몇 개를 옮기면 두 줄이 같아질까?" 아이가 옮기고 ✔; 양쪽 수가 같을 때만 `answer`(= 옮긴 수), 아니면 `-1`.
  차가 홀수면 불가능하므로 생성기는 **차가 짝수인 쌍만**.
- 스키마 `{widget:'tradeScene', answerType:'number', interaction:'after'|'equal', a:{e,n}, b:{e,n}, give?:{from:'a'|'b', n:k}, ask?:'a'|'b', chips?, answer}`
- 범위: 합 ≤9(practice 합 ≤6). 토큰은 구슬 대신 기존 `⚫`(바둑돌)·`🍬`(사탕).
- 인쇄: 두 줄 + 화살표 "A→B k개", 답칸. `equal` 은 정답지 `answerLabel` 로 `2개`.
- 풀: after — a,b 각 1~8 합 ≤9 × give × ask ≈ 100; equal — 차가 짝수인 (a,b) 쌍 ≈ 20 × 토큰 2 = 40.

## 활동별 상세

### p2 양의 수, 순서수 — 결정 **C**
- **교재**: 두 수가 든 상황 문장(달리기 등수·층·식구·시험·사과)에서 밑줄 친 두 수를 양의 수/순서수로 나눠 □에 씀.
- **앱 현황**: 없음. N-05 는 줄서기(`lineup`)·계단(`stairs`)에서 서수를 **찾는** 것뿐이고, 양과 순서를 가르는 문항은 없다.
- **결정**: M1 `qtyOrd`. 문장 속 밑줄 두 수를 쓰는 입력은 문장 읽기+쓰기가 필요해 유아에겐 불가 → **두 수 카드 중 묻는 쪽을 고르기**.
- **들어갈 곳**: 새 스레드 `NL-양순서`(가칭) 레벨 1 `line practice`(T≤6), 2 `line main`, 3 `prize·coins main`. N-05 의 lab 으로 올리는 선택안.
- **소품**: 시상대(새), 큰 동전(기존 `coin` 크기만 키움), 친구 줄은 기존 `FRIEND_EMOJI`(사람 그림은 별도 사람 작화 문서 소관).

### p3 교실 — 결정 **D**
- **교재**: 5×6 자리표(이름 칸)에서 앞·뒤·왼쪽·오른쪽 기준 순서수로 위치를 읽고 누구인지 이름을 씀. 칠판을 보는 학생 기준이라
  **'왼쪽/오른쪽'이 그림과 반대**로 뒤집힌다.
- **결정**: 이름 쓰기(채점 불가)와 방향 반전 둘 다 5~7세에겐 과하다 →
  **자리를 콕 짚기**로 바꾸고 **그림 기준**(칠판 쪽이 위=앞, 왼쪽은 그림의 왼쪽)만 쓴다. 반전은 폐기(교재 3~4번은 이 호의 상위 난이도라 유아에선 제외).
- **위젯 `seatGrid`(C)**: 칠판 막대(위) + `rows×cols` 책상 칸(`occ` 토큰 = 기존 동물 10종, 정체성 불필요).
  - `interaction:'find'` — "앞에서 둘째 줄, 왼쪽에서 셋째 칸 친구를 콕!" 칸을 누르면 즉시 판정, 답 = `r*cols + c`(0부터).
  - `interaction:'read'` — 한 칸을 색으로 표시("이 친구는 앞에서 몇째 줄?") `ask:'row'|'col'`, 칩 3개, 답 = `r+1` 또는 `c+1`.
- 스키마 `{widget:'seatGrid', answerType:'number', interaction, rows, cols, occ:[토큰×rows*cols], target:[r,c], ask?, chips?, answer}`
- 범위: practice 3×3, main 3×4 · 4×4 (순서수 ≤4). 교재 5×6 은 줄을 넘겨 읽기 어려워 축소.
- **들어갈 곳**: N-05 새 스레드 `NL-자리줄`(가칭) 레벨 1 `find practice`, 2 `find main`, 3 `read main`.
- **인쇄**: 격자 그림, `find` 는 ○표, `read` 는 표시된 칸 + 답칸. 정답지 `answerLabel`: `앞에서 2째 줄, 왼쪽에서 3째`.
- **소품(새)**: `blackboard`(칠판, CSS 막대로 충분하나 실사 교체 대상), `desk`(책상 칸, 선택).
- 풀: 격자 3종 × 칸 위치 9~16 × (find 1 + read 2) ≈ 80.

### p4 틀린 부분 찾기 — 결정 **E**
- **교재**: 상황 글에서 틀린 문장을 찾아 바르게 고쳐 씀(서술형 5문항: 카드 순서·층 세기·사탕 나누기·나이 차·계단 시간).
- **앱 입력으로 불가**: 자유 문장 고쳐 쓰기는 채점할 수 없고 유아는 쓰지도 못한다.
- **대체안 — `nl5_story`/`fix`**: 그림 장면 + **틀린 말 하나** + 맞는 수를 `pickCard` 보기 3개에서 고르기.
  `{widget:'pickCard', stemParts:[{k:'row',total,mark,e},{k:'text',t:'틀린 말: …'}], choices:['3','4','5'], answer:번호}`.
  오답 보기 중 하나는 **교재가 흔히 틀리게 하는 수(틀린 말에 쓰인 수)**를 넣어 함정으로 삼는다.
- **유아 템플릿 3개**(교재 문항 중 개념이 유아 범위인 것):
  1. `frontFromBack` — 줄 T명, 표시된 친구는 뒤에서 k째인데 "앞에서 k째"라고 틀리게 말함 → 맞는 앞에서 몇째(= T−k+1). T 3~9, k≠T−k+1.
  2. `floor` — 계단·층 그림(아래에서 몇째 ↔ 위에서 몇째) 틀린 말 고치기. 기존 `stairs` 장면 재사용.
  3. `chainCompare` — "민수보다 1개 많은 영희, 영희보다 1개 많은 철수 → 철수는 민수보다 1개 많다" 틀린 말 → 정답 2(보기 1·2·3). 사탕 토큰.
  교재의 사탕 나누기(같아지게 주기)는 `trade/equal`(p13)로, 층수 퍼즐(엘리베이터)·계단 걸리는 시간은 **폐기**(두 번 이상 연산·시간 개념).
- **들어갈 곳**: `NL-양순서` 레벨 4~6. 풀: 템플릿 1 ≈ 40, 2 ≈ 10, 3 ≈ 8 → 합 ≈ 58 (레벨 4 는 1번만으로 24 확보).
- 인쇄: M2. 3언어: 틀린 말을 그대로 읽어 주고 "어디가 틀렸을까요? 맞는 수를 골라요". **소품** 기존만.

### p5 그래프 — 결정 **C**
- **교재**: 과일 5종 세로 막대그래프를 보고 표 빈칸 채우기·같은 수 찾기·가장 많은 것/수·(가정) 가장 적은 것.
- **앱 현황**: N-10 `nl10_data` 는 섞인 물건을 바구니에 나누어 세는 것뿐. 그래프·표 읽기는 없다.
- **결정**: 새 위젯 `barRead`(C) — **물건 쌓기 그림그래프**(막대 대신 토큰을 칸마다 쌓아 세기 쉽게) + 왼쪽 눈금 1~9.
  - `kind:'count'`(칸 하나의 수를 칩으로, 표 빈칸 채우기 대응), `'most'`/`'least'`(가장 많은/적은 칸을 누름, 답 = 칸 index), `'diff'`(A는 B보다 몇 개 많아요?),
    `'rank'`(둘째로 많은 칸), `'same'`(수가 같은 두 칸을 모두 누름 — 정확히 둘일 때 `answer` 제출).
  - 칸 3개(practice)·4~5개(main), 수 1~9, `most/least/rank` 는 동률 없음.
- 스키마 `{widget:'barRead', answerType:'number', cats:[{e,n}], kind, focus:[i,j]?, rankN?, hidden?, chips?, answer}`
- 5종 과일 대신 기존 토큰: 🍎 🍓 🍌 🍪 🍬(**수박·포도·귤은 새 소품 없이 대체**). 그림에 글자 없이 토큰만(읽기 부담 제거).
- **들어갈 곳**: N-10 스레드 NL15 레벨 4(`count`·`most`), 5(`diff`·`least`), 6(`rank`·`same`) (가칭, `nl10_data`/`graph`).
- **인쇄**: 토큰 열을 격자로(최대 높이 9, 토큰 20px), 눈금 숫자, 답칸/○표. 정답지 `answerLabel`(토큰 이름 또는 숫자).
- **교재 4번(가정 조건 추론)** — "사과를 좋아한다던 미선이가 귤로 바꾸면 가장 적은 것은?" — 두 단계 가정 추론이라 폐기(E).
- 풀: 칸 조합 × 값(서로 다른 3~5개 수) 수천 → 충분.

### p6 체육대회 안내문 — 결정 **D**
- **교재**: 체육대회 안내문(날짜·종목 5개·신청 기한·상품 규칙)을 읽고 종목 수·기한·상품 종목·상품 교환 가능 여부를 답함.
- **결정**: 독해·날짜 계산(10일 전)이 5~7세에겐 과하다. **살릴 개념은 둘**: ① 종목(종류) 수 세기 ② "N보다 큰 번호표는 상품" 규칙 판단.
  - ① 기존 `tapCount` 재사용(A): 안내판에 서로 다른 토큰 k종을 한 번씩 놓고 "몇 가지일까요?" `items` 의 `t:true` 전부 → 답 k.
  - ② `nl3_ordinal`/`rule`: `pickCard` — stem: 번호표 카드(숫자 n) + 규칙 문장("5보다 큰 번호표는 상품!") → 보기 `예`/`아니오`(순서 rng).
    판정은 `n > m`. 규칙 m 1~8, n 1~9, n≠m. 풀 = 약 70. 숫자 크기 비교(N-03 의 '몇째와 크기 비교')와 직결.
  - 날짜·상품 종목 찾기·상품 교환(두 단계)은 **폐기**(E).
- **들어갈 곳**: N-03 스레드 NL8(몇째와 칸 세기)에 레벨 4(`rule`) 추가. **소품(새)**: `ticket`(번호표 종이, 숫자는 위젯이 올림) 1종.
- 인쇄: 번호표 그림 + 규칙 문장 + ○ 예/아니오.

### p9 숫자 이야기 — 결정 **D**
- **교재**: 상자 속 숫자 카드(2·8·6)를 글 흐름에 맞게 빈칸에 채움(남녀 인원·짝 짓고 남는 수, 책 권수 순서, 과일 차이).
- **결정**: 글이 길고 빈칸이 많다 → **그림이 곧 문제**인 `cardFill`(C, 우선순위 낮음)로 두 템플릿만:
  1. `pair` — 남자 a명·여자 b명(a>b) 얼굴 줄 그림 + 카드 `[a, b, a−b]`, 빈칸 3(남자·여자·짝 짓고 남는 남자). 카드를 눌러 칸에 넣는다.
     그림을 세면 보이므로 '세기+분해' 연습이 된다.
  2. `order` — 종류 3개의 개수 카드 `[9,3,7]`, 단서("가장 많은 것은 ○", "가장 적은 것은 ○")로 칸에 배치.
  교재의 "더 많다/더 적다" 두 층 비교(사과가 배보다 N 많고 포도는 사과보다 M 많음)는 **폐기**.
- 스키마 `{widget:'cardFill', answerType:'number', template, cards:[…], slots:[{key,label}], pictures?, clues?, answer}` — 모든 칸이 맞으면 `answer`(=첫 칸 값), 아니면 `-1`.
- **들어갈 곳**: N-15 스레드 NL13 레벨 4(`cards`, 가칭). 인쇄: 카드 상자 + 빈칸 3, 정답지 `answerLabel` 로 `남자 8, 여자 6, 남는 2`.

### p11 매표소 — 결정 **C**
- **교재**: 줄 선 연주(앞에서 넷째·가운데)의 앞 사람 수·뒤 사람 수(○ 그리기)·전체 인원.
- **앱 현황**: `lineup`(몇째 친구 짚기)·`stairs` 뿐. 앞·뒤 사람 수와 합산은 없다.
- **`nl5_story` 새 mode 세 가지**(위젯 `storyCard` 확장):
  1. `around` — 줄(`layout:'row'`, 왼쪽 끝에 매표소 그림) 속 한 친구를 표시(`mark`), `ask:'ahead'|'behind'|'total'`.
     `ahead = mark`, `behind = total−mark−1`, `total` = 전체(앞+뒤+나). 숫자패드(기존 `storyCard` numpad).
     `ask:'total'` 의 변형으로 장면 대신 수만 주는 문항("앞 3명, 뒤 2명 → 모두?", p7 1번) 지원: `ahead`/`behind` 필드.
  2. `behindDraw` — "내 뒤에 b명이 서요. ○를 그려요": 앞부분 줄(`context`) 은 고정으로 그리고 **빈 칸에 토큰을 눌러 b명을 채움**.
     기존 `tapMake` 에 `context:{chars,mark}` 옵션을 더해(B) 위에 앞 줄을 그린다. 답 = b.
  3. `convert` — "뒤에서 k째 친구 → 앞에서 몇째?". practice 는 줄을 다 보여 주고(세어 볼 수 있음), main 은 **표시 없이 T칸 윤곽만**
     보여 주어 방향 바꿔 세기를 하게 한다(`scene:'full'|'silhouette'`). 답 = T−k+1, 숫자패드. (p13 5번, p4 `frontFromBack` 과 같은 수학)
- 스키마(공통) `{widget:'storyCard', interaction:'numpad', layout:'row', total:T, mark:idx0, ask, chars, ahead?, behind?, fromBack?, scene?, answer}`.
  storyCard 의 `row` + numpad 경로는 현재 chars 를 `disabled` 로만 그리므로 `mark` 강조 클래스와 매표소 아이콘을 추가해야 한다.
- 범위 T 3~9. **들어갈 곳**: `NL-자리줄` 레벨 4(`around`) 5(`behindDraw`) 6(`convert`).
- **인쇄**: 줄 그림(`nlOrderStripHtml` 재사용 + 표시) + 답칸. `behindDraw` 는 "○를 그려요" 빈 칸.
- **소품(새)**: `ticket-booth`(매표소). 줄 서는 친구는 기존 사람 토큰.
- 풀: around T 3~9 × mark × ask 3 ≈ 120; convert 40; behindDraw 20+.

### p12 숲속 동물들의 달리기 대회 — 결정 **C**
- **교재**: 달리기 단서(~보다 빠르다·뒤따른다·사이에 있다)로 동물 수·3등·5등·1~5등 순서 말하기(5마리).
- **앱 현황**: 없음.
- **결정**: 새 위젯 `rankClue`(C) — 동물 3마리(practice, 단서 2개)·4마리(main, 단서 3개) 그림이 **섞인 순서**로 놓이고 아래에 **단서 카드**
  (동물 그림 두 개 + 화살표/말: "A는 B보다 앞", "C는 A 바로 뒤", "B는 맨 뒤") 와 🔊. 아이는 "2등은 누구?" 에 해당하는 동물을 **누른다**.
  5마리 전체 순서 말하기는 입력이 길어 폐기(최대 4마리).
- 스키마 `{widget:'rankClue', answerType:'number', animals:[토큰×N], clues:[{k:'ahead',a,b}|{k:'first',a}|{k:'last',a}|{k:'right_after',a,b}|{k:'between',a,b,c}], askRank:r, answer:표시 순서의 index}`
- 생성기는 순위 순열을 정하고 **그 순열이 단서로 유일하게 정해지는** 단서 집합을 만든다(N=3 → 6가지, N=4 → 24가지 열거 검증).
- 동물은 기존 10종(`animal:rabbit … tiger`) — 새 소품 없음. 사나운 동물(`wolf`·`tiger`)은 앱 규칙(순한 표정)을 따른다.
- **들어갈 곳**: `NL-순위`(가칭) 레벨 1 `N=3 practice`, 2 `N=3 main`, 3 `N=4`. **인쇄**: 동물 그림 + 단서 문장(그림 칩) + ○표. 정답지 `answerLabel`(동물 이름).
- 풀: 순열 6~24 × 질문 순위 N × 동물 선택(10 중 N) → 수백.
- 3언어: `곰은 호랑이보다 앞에서 달려요` / `The bear runs ahead of the tiger` / `熊跑在老虎前面`.
