# G1-4호 (9까지의 수) → 앱 유아 단계 이관 명세

대응 유닛: **N-04 기수법 놀이**(1:1). 활동 목록 원본: `docs/g1-inventory/G1-4.md`. PDF 쪽을 직접 보고 확인했다.
이 호의 활동은 '기수법'에 안 담기는 것이 많다(홀짝·조건 수 찾기·도형수·퍼즐). 새 mode 는 **주제가 맞는 유닛**에 두고
(아래 표), N-04 는 제목/소개를 "수의 여러 가지 모습"으로 넓히는 것을 권한다(통합 담당 결정).

## 공통 규약 (G1-4/5/6 세 파일이 같은 문구)

1. **답 계약(코드 확인)**: 위젯은 `onAnswer(숫자 하나)` 만 부르고 채점은 `+val === problem.answer`
   (main.js 3149·4724·5331·6156). 정답이 여러 개인 열린 활동은 **위젯이 스스로 검증**해서 맞으면 `problem.answer`,
   아니면 `-1` 을 보낸다(+`shake`). 배열 입력이 필요해도 숫자 하나로 접는다.
2. **보기 고르기**: 숫자 칩은 `problem.chips`(숫자 배열, 생성기가 `rng` 로 섞어 실음, 답은 그 숫자 값). 글/그림 보기는
   `problem.choices`(배열) + **답 = 1부터 세는 보기 번호**(인쇄 ①②③와 같음). 기존 위젯 다수가 위젯 안에서 `Math.random`
   으로 보기를 만드는데(widgets.js 875·957·1099…) 새 위젯은 따르지 말 것 — 인쇄·재현이 안 된다.
3. **인쇄(exam.js)**: nl 문항은 `nlVisualHtml(p)` 의 widget 별 분기가 그림을 만든다. 모르는 widget 은 **빈 문자열**이 되어
   그림이 통째로 빠진다 → 새 widget 마다 분기 필수. 정답지는 `nlAnswerLabel(p)` 가 말로 바꿔 적는다. **한 줄 패치 권장**:
   `nlAnswerLabel` 맨 앞에 `if(p.answerLabel) return pickL(p.answerLabel)`(문자열 또는 `{ko,en,zh}`) — 열린 활동·글 답을
   생성기가 직접 적게 한다. 화면 말투(톡톡·콕)는 `NL_PRINT_WORDS` 에 새 문구를 추가해 인쇄용으로 바꾼다.
4. **중복 키**: `problemKey()`(exam.js 4899)는 열거된 필드만 본다. 새 필드(`tiles cond clues vals lit figs sys refs skin
   preset cats kind animals rules give ask ahead behind theme` 등)를 목록에 추가하지 않으면 **서로 다른 문항이 같은 키로
   합쳐져** 풀이 줄어든다. `choices` 는 이미 키에 있어 보기 순서만 다른 같은 문제가 다른 문항으로 센다 — 풀 크기는
   '질문의 개수'로만 셀 것(권장: `choices` 를 키에서 빼고 `uq` 문자열 하나를 넣는 패치).
5. **풀 크기**: 한 레벨에서 서로 다른 key 24개 이상(20+예시1+따라풀기3, `docs/unique-shortfall-2026-09-25.json` 기준).
   각 mode 마다 추정 풀을 적었다.
6. **수 범위**: 레벨 규칙은 기존과 같다 — `practice` ≤5, `main` ≤9. 글을 못 읽는 나이라 문장은 짧게, 모든 화면 문구는
   `NM_SAY`로 읽힌다(기호 `<`·`≥` 금지, "보다 큰"으로). 3언어: 문구는 `{ko,en,zh}` 한 벌, 수사는 `ORDINAL` 표
   (nl.js 243)를 재사용.
7. **새 스레드 번호**: 아래 `NL-?` 는 가칭이다. 다른 호 명세와 번호가 겹칠 수 있으니 통합 때 부여한다. 기존 NL1~NL16
   에 레벨을 추가하는 경우는 레벨 id 만 이어 붙인다. 과정 C0 의 해당 주(`perSessionDrills`)에 새 스레드를 넣는다.
8. **검증**: 새 위젯·mode 는 `node scripts/check-answerable.js <스레드>`(풀이 가능성)와 인쇄 미리보기로 확인.

## 이 호의 새 모듈 (활동별 명세에서 참조)

### M1. 조건 수 타일 `tilePick` + 생성기 `nl_numset`
- 위젯 `tilePick` 한 개가 네 가지 interaction 을 한다. 숫자 타일 한 줄(0~9 또는 창).
  - `multi`: 조건에 맞는 타일을 **모두** 눌러 켜고 ✔. 집합이 정확히 `ok` 와 같을 때만 `problem.answer`(= `ok.length`)
    제출, 아니면 `-1`+shake. (교재 2쪽 ○표)
  - `count`: 타일은 연습용 표시(채점 안 함), 아래 `chips` 3개 중 개수를 고름. 답 = `ok.length`. (8쪽·확인학습)
  - `single`: 한 타일을 누르면 즉시 판정(gridPaint single 과 같은 방식), 답 = 그 수. (`who`·`lock`)
  - 타일은 `.nm-tp-tile` 큰 버튼(44px 이상), 켜진 타일은 색, 오답 shake.
- problem 스키마
  ```
  { prompt:{ko,en,zh}, widget:'tilePick', answerType:'number',
    interaction:'multi'|'count'|'single', theme:'tile'|'lock',
    tiles:[0..9 중 연속 창], cond:{gt?,lt?,parity?:'odd'|'even'}   // multi·count
    clues:[{k:'gt'|'lt'|'odd'|'even'|'not'|'between', n?, a?, b?}],   // single
    ok:[숫자…], chips:[3개], answer }
  ```
- 조건 문구 생성(`condText`): ko `3보다 큰 홀수`·`3보다 크고 8보다 작은 짝수` / en `odd numbers greater than 3` /
  zh `比3大的奇数`. 글을 못 읽으니 말로 읽힌다. 홀짝 정의는 개념 노트에 "둘씩 짝지으면 남는 게 없으면 짝수,
  하나 남으면 홀수"로 싣는다(교재의 '1에서 2씩 센 수'는 유아에겐 말이 어렵다).
- 인쇄: `nlVisualHtml` 에 `tilePick` 분기 — 타일 줄을 둥근 칸으로 그리고(`multi`는 ○표 하라는 말, `count`/`single`은 답칸).
  정답지는 `answerLabel` 로 `ok` 를 `3, 5, 7` 로 적음(multi), 숫자(count/single).
- 풀: `multi`/`count` — 조건 종류(홀/짝 2 + gt 9 + lt 9 + 두 조건 조합 약 45) × 타일 창 4 ≈ 100. 충분.
  `practice` 는 조건 한 개짜리 20종 × 창 4 = 80. `single` — 목표 수 10 × 단서 조합 다수.

### M2. 도형수 `cellCode` + 생성기 `nl_cellcode`
칸에 ○를 놓아 수를 나타내는 약속. 교재: 2×2 격자에서 **왼쪽 아래 1, 오른쪽 아래 2, 오른쪽 위 3, 왼쪽 위 4**이고 ○가
놓인 칸의 값을 더한 것이 수(그림 실측: 5 = 왼쪽 위+왼쪽 아래). 세로 4칸은 아래부터 1·2·3·4.
- 위젯 `cellCode`: `layout:{cols,rows}`, `vals:[칸 값…]`(읽는 순서 왼→오, 위→아래), `lit:[켜진 칸 index]`.
  interaction: `read`(켜진 그림의 수를 `chips` 에서 고름), `make`(목표 수가 되게 칸을 눌러 켬 → ✔),
  `make2`(**서로 다른 두 방법**으로 — 첫 방법이 맞으면 판이 비워지고 "다른 방법으로 또!", 둘째가 첫째와 같으면 거부),
  `pickMax`(그림 4장 중 가장 큰 수를 고름, 답 = 1부터 센 번호).
- `showVals:true` 이면 칸마다 값을 옅게 보여 줌(practice). 아니면 맨 위 **범례**(`legend`: 칸 하나만 켠 그림 4장 + 그 수)로
  약속을 가르친다. 칸 값 배치는 생성기가 순열로 섞는다(24가지) → 외워서 풀 수 없음.
- 판정: `make`/`make2` 는 켜진 칸 값의 합 `=== target`(여러 정답). 세로 4칸에서 두 방법이 되는 목표 수는 3~7
  (3={3},{1,2}; 4={4},{1,3}; 5={1,4},{2,3}; 6={2,4},{1,2,3}; 7={3,4},{1,2,4}); 8·9 는 한 방법뿐이라 `make2` 에서 제외.
- 범위: 합 ≤9(네 칸 전부=10 제외). practice 는 1~5 목표.
- 스키마
  ```
  { widget:'cellCode', answerType:'number', interaction:'read'|'make'|'make2'|'pickMax',
    layout:{cols:2,rows:2}|{cols:1,rows:4}, vals:[4,3,1,2], showVals:boolean,
    legend:[{lit:[2],n:1},…], lit:[…] (read), figs:[{lit:[…]}×4] (pickMax),
    target (make), chips:[…] (read), answer }
  ```
- 인쇄: 격자를 SVG 로(칸 40px), `make` 는 빈 격자 + "○를 그려요", `read` 는 ○ 그려진 격자 + 답칸. 정답지 `answerLabel`
  (예: `6 = 4+2 또는 3+2+1`).
- 풀: `read` 값 순열 24 × 켜진 집합 14 ≈ 336; `make` 목표 9 × 순열; `make2` 3~7 × 순열 × 레이아웃 2. 충분.

### M3. 고대 숫자 모듈 (`nl_tallybuild` 의 새 mode 3개 + 헬퍼 `NM_ANCIENT`)
- 새 헬퍼 `NM_ANCIENT.glyph(sys, n, {size})` → SVG 문자열(화면·인쇄·매칭 카드 공용; 파일은 `app/ancient-art.js` 권장,
  index.html 에서 widgets.js 앞에 로드). **직접 그린 선·점·글씨만** 쓴다(원문 기호 베끼기 금지, 교재 사진 트레이스 금지).
  `sys`: `maya`(점=1, 막대=5, 막대 위에 점) · `egypt`(막대 n개, 4개까지 한 줄·5 이상은 두 줄로 나눔) ·
  `greek`(막대 1~4, 5=ㄱ자 표, 6~9=표+막대) · `chinese`(1~5 막대, 6~9=가로선+아래 막대 n−5) ·
  `mesopotamia`(쐐기 y 를 한 줄 3개씩 쌓음) · `roman`(Ⅰ~Ⅸ, 시계에서 보는 글씨). 0 은 안 씀.
- 레벨: practice(≤5) `maya egypt roman mesopotamia` / main(≤9) 전체 6종.
- 세 mode:
  1. `ancientMatch` — **matchLine 확장**(B): `rightType:'ancient'`, `sys` 추가. 오른쪽 카드 = `NM_ANCIENT.glyph`.
     왼쪽 수 3(practice)~4(main)개. 기존 판정(`left[selL]===num`) 그대로.
  2. `ancientRead` — 약속 읽기. **`pickCard`(공통 모듈 M5)** 로: `stemParts:[{k:'refs',list:[{n,sys}…3개]},{k:'glyph',sys,n}]`,
     `chips`/`choices`는 수 3개. 규칙을 스스로 알아내게 `refs` 는 {1,2,3,5} 중 정답이 아닌 3개(정답에 5-기호가 쓰이면 5를 반드시 포함).
  3. `ancientBuild` — 새 위젯 `glyphBuild`(C): 부품 단추(예: 점 · 막대)를 눌러 글자를 쌓고 ↩ 되돌리기, ✔ 제출.
     `parts:[{v:1},{v:5}]`, 한 5묶음 안 점은 4개까지만 눌림(**표준형 강제** — 점 5개로 5를 만들 수 없음). 합 `=== target` 이면 `answer`.
     부품이 하나뿐인 `egypt`/`mesopotamia` 는 최대 9개. `roman` 은 4·9 가 뺄셈형이라 build 에서 제외(read·match 만).
- 스키마 `ancientRead`: `{widget:'pickCard', stemParts:[…], chips:[…], answer:n, sys, n, refs:[…]}`;
  `ancientBuild`: `{widget:'glyphBuild', sys, target, refs:[{n}…], parts:[…], answer:target}`;
  `ancientMatch`: 기존 `matchLine` + `rightType:'ancient', sys`.
- 인쇄: 글자 SVG 를 카드로. build 는 "여기에 그려요" 빈 상자 + `refs`. 정답지 `answerLabel`(build: `점 1개 + 막대 1개`, read: 숫자,
  match: `3→①` 은 기존 `nlAnswerLabel` 이 처리).
- 풀: `ancientRead` sys 6 × n(1·5 제외 7) × refs 변형 ≈ 80; `ancientBuild` target 2~9 × sys 5 ≈ 40; practice 는 (sys 4 × n 2~5 = 16)
  이라 모자람 → **`ancientRead`+`ancientBuild` 를 한 레벨에 섞어** 32 확보하거나 practice 를 maya/egypt/roman/mesopotamia × (read·build) 로 구성.
- 3언어: 수사만 나오므로 거의 중립. 문구 예: ko `점과 막대로 6을 만들어요` / en `Make 6 with dots and bars` / zh `用点和横线做出6`.
  부품 이름은 말 대신 그림 단추(점·막대)로 → 번역 부담 없음.

### M4. 달팽이·뱀 길 수 채우기 (`nl2_seq` 의 `path`)
`seqFill` 에 `layout:'snail'|'snake'` 를 더한다(B/C). `cells:[{x,y,v}]`(0~100 좌표, `v:null` 이면 묻는 칸 또는 가려진 칸),
`ask:index`. 생성기가 상수 `PATH_LAYOUTS`(달팽이 10칸·뱀 9칸 좌표)를 직접 정의. 칸 값은 연속(0..9 또는 1..9), 방향 오름·내림,
보여 주는 칸은 4~5개(시작 칸 포함)이고 묻는 칸 하나가 강조. 칩 3개(`chips`). 인쇄: `nlSeqStripHtml` 옆에 `nlPathSvg(cells, ask)`.
풀 = 레이아웃 2 × 방향 2 × 시작 2 × 묻는 칸 5↑ ≈ 40.
⚠ **기존 버그**: `renderSeqFill` 의 `const blank = problem.blank || 1` — `blank` 가 0 이면 1 로 바뀐다.
첫 칸을 묻는 문항(rule4·path)을 쓰려면 `problem.blank != null ? problem.blank : 1` 로 고칠 것.

### M5. 공통 보기 카드 `pickCard` (세 호가 공유)
큰 단추 2~4개로 고르는 범용 위젯. `stemParts`(그림·글을 조합: `{k:'text',t}`·`{k:'dots',n,e}`·`{k:'pairs',n,e}`·
`{k:'glyph',sys,n}`·`{k:'refs',list}`·`{k:'eq',t}`), `choices`(문자열 또는 `{glyph}`/`{dots}`), 답 = 1부터 센 보기 번호.
누르면 즉시 판정(맞으면 `.on`, 틀리면 shake+`onAnswer(번호)`), 🔊 다시 듣기(storyCard 와 같은 `NM_SAY` 호출).
인쇄: `nlStemHtml(stemParts)` + 보기 ①②③ 목록 + `답 ( )번`. 이 호에서는 `ancientRead`·`parity` 가 쓴다.

## 활동별 상세

### p2 짝수, 홀수 — 결정 **D** (두 부분)
- **교재**: ① 1에서 2씩 뛰어 센 수를 연결 원 5개에 채우고 홀수/짝수 정의 읽기 ② 6개 조건(범위+홀짝)에 맞는 수를 0~9에서 ○.
- **앱 현황**: ① `nl2_seq`/`gap` 의 `skip2` 가 2씩 뛰기를 이미 함(N-02 lab, seqFill 칩 줄). 차이: 시작이 1~12 아무 수, 연결 원이
  아님, 홀수/짝수 이름 없음. ② 없음.
- **① 2씩 뛰어 세기 연결 원 — (B) `nl2_seq`/`hop`**: 위젯 seqFill 재사용, `chain:true`(칩 사이를 선으로 이은 동그라미로 그리는
  CSS 변형). `{kind:'hop', seq:[1,3,5,7,9], blank, chain:true, hopStep:2, answer}`. 시작 수는 0·1(practice)
  /0~3, 내림차 포함(main), 길이 4~5, 범위 0~9. 묻는 칸은 첫 칸 제외(위 버그 고치면 첫 칸도 가능).
  prompt: ko `1부터 하나 건너뛰며 세어요. 빈 동그라미는?` / en `Count by skipping one each time. What goes in the empty circle?` /
  zh `隔一个数一个。空圆圈里是几？` 풀 = 사슬 12종 × 빈칸 3~4 ≈ 40.
- **홀수/짝수 이름 익히기 — (D) `nl_numset`/`parity`**(M5 `pickCard`): 그림에 토큰 n개를 **두 줄 짝**으로 놓고(홀수면 마지막이 짝 없이 남음) "짝이
  다 맞나요? 짝수/홀수?" 두 큰 단추. `{widget:'pickCard', stemParts:[{k:'pairs',n,e}], choices:[{t:짝수},{t:홀수}](순서 rng), answer:번호}`.
  practice n 1~6, main 0~9. 0 은 짝수(빈 그림). 풀 = n 10 × 순서 2 × 토큰 4 ≈ 80.
- **② 조건 ○표 — (D) `nl_numset`/`pick`**: 6개 조건을 **한 문항에 한 조건**으로 쪼개고(위 M1), 두 조건 겹침은 main 에서만(예 `3보다 큰
  홀수`). 교재의 "A보다 크고 B보다 작은 짝수" 3중 조건은 유아에겐 무겁다 → main 최고 난이도로만 둠.
- **소품**: 새 없음(토큰은 기존 16종 중 사과·별·풍선·병아리).
- **인쇄**: `hop` 은 `nlSeqStripHtml` 에 `chain` 이면 동그라미+선. `parity` 는 `nlStemHtml` 두 줄 짝 + 보기. `pick` 은 M1 인쇄.

### p6 보석이 들어 있는 주머니 — 결정 **D**
- **교재**: 4개 주머니에 보석 8개를 나눈 조건 글(같은 수·빈 주머니·한 주머니는 2개)을 읽고 각 주머니 수를 추론(서술 4문항).
- **결정**: 조건 글이 길고 4칸 동시 추론이라 유아에겐 과하다 → **주머니 3개(practice, 합 ≤6)·4개(main, 합 ≤9) + 조건 그림 카드
  2~3장**, 한 문항에 **한 주머니만** 묻고 칩으로 답. 새 위젯 `bagClue`(C):
  `{widget:'bagClue', bags:[{id:'가'|…}], total, clues:[{k:'same',a,b}|{k:'empty',a}|{k:'is',a,n}|{k:'more',a,b}], ask:idx, chips, answer}`.
  화면: 주머니 그림 N개(보석이 보이지 않게 닫힘) + 조건 카드(그림+짧은 말 + 🔊). 아는 주머니는 열려 보석이 보인다.
  생성기는 모든 분배(합 = total)를 열거해 **조건으로 `ask` 가 유일하게 정해지는 것만** 채택(결정 가능성 검증).
- **들어갈 곳**: N-13(수 퍼즐과 추론) `nl13_puzzle`/`bags`, 스레드 NL12 의 레벨 4(가칭). 우선순위는 낮음(마지막에).
- **인쇄**: 주머니를 ○들이 든 상자로 그리고 조건 카드는 문장. 정답지는 `answerLabel` 로 `가 3, 나 3, 다 2, 라 0`.
- **소품(새)**: `pouch`(주머니, 입구 묶인 천 주머니), `gem`(보석 한 알). 열린 주머니·닫힌 주머니는 같은 PNG 에 보석을 얹어 처리.

### p8 수의 개수 — 결정 **B**

### p11 수 채우기 — 결정 **C** (줄형 B + 길 모양 C)
- **교재**: 규칙(±1, ±2) 수열 4칸 빈 칸 4줄 + 달팽이·뱀 모양 길 칸 2개.

  prompt: ko `규칙을 찾아 빈 칸에 올 수는?`. 범위 0~9. 풀 = 시작 10 × 공차 4(±1,±2) × 빈칸 위치 4 ≈ 100 에서 범위 맞는 것 ≈ 60.
- **길 모양 — (C) `nl2_seq`/`path`**(M4).
- **들어갈 곳**: N-02 스레드 NL4(수의 순서) 레벨 4(`rule4`)·5(`path`). **소품** 없음. 인쇄 `nlPathSvg`.

### p12 자물쇠의 비밀번호 — 결정 **D**
- **교재**: 4자리 자물쇠 번호를 힌트 4개(범위·홀짝·아님·묶음 나머지)로 한 자리씩 찾음.

  `nl_numset`/`lock`(M1 `single`). 교재의 "2개씩 묶으면 1개 남는" 힌트는 `odd` 로, "주사위에는 없는" 힌트는 `not`(그 수는 아니에요)로 환산.
  4자리 한꺼번에는 유아에겐 과함 → 4문항을 한 세트로 묶는 연출은 선택안(생성기가 같은 비밀번호에서 한 자리씩 뽑는 `lockSlot` 1~4).
- **들어갈 곳**: N-13 스레드 NL12 레벨 5(`lock`). **소품(새)**: `padlock`(자물쇠 실사 PNG, 열림·잠김 표시는 CSS).
- **인쇄**: 키패드 3×3 + 힌트 문장 + 답칸. 정답지 숫자.

## 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

**새 위젯 (6)**
1. `tilePick` — 타일 4 interaction (multi·count·single·lock 테마). `nl_numset` 용.
2. `cellCode` — 칸 값 합으로 수를 나타내는 격자(read·make·make2·pickMax).
3. `glyphBuild` — 고대 기호 부품 쌓기.
4. `pickCard` — 범용 보기 카드(세 호 공유). `stemParts` 파서 포함.
5. `bagClue` — 주머니 조건 추론(우선순위 낮음).
6. (헬퍼) `NM_ANCIENT.glyph` — 6체계 SVG.

**기존 위젯 확장 (B)**: `matchLine`(`rightType:'ancient'`+`sys`), `seqFill`(`chain` · `layout:'snail'|'snake'` · `blank 0` 버그 수정),
`sortBasket`(바구니 `label` · `num:N` 항목), `framePaint`(`cells` 선택).

**새 생성기/mode**: `nl_numset`(`pick count who lock parity paritySort`), `nl_cellcode`(`read make make2 pickMax`),
`nl_tallybuild` +`ancientMatch ancientRead ancientBuild`, `nl2_seq` +`hop rule4 path`, `nl13_puzzle` +`bags`.
새 스레드 가칭: `NL-홀짝·조건 수`, `NL-도형수`. 기존 NL14·NL4·NL12 에 레벨 추가.

**새 소품(PNG)**: `padlock`(자물쇠), `pouch`(주머니), `gem`(보석) — 3종. 기존 16종·동물 10종은 겹치는 만큼 그대로.
고대 기호는 소품 PNG 가 아니라 **직접 그린 벡터 글리프**.

**새 인쇄 표현**: `nlVisualHtml` 분기 — `tilePick`(타일 줄) · `cellCode`(격자·범례) · `glyphBuild`/`ancientRead`(글리프 카드) ·
`pickCard`(stem + ①②③) · `bagClue`(주머니 상자) · `seqFill chain/path`(`nlPathSvg`) · `matchLine ancient`(글리프 카드).
`nlAnswerLabel` 의 `answerLabel` 패치(공통 규약 3), `NL_PRINT_WORDS` 에 "타일을 모두 눌러요→○표 해요"류 추가,
`problemKey` 필드 추가(공통 규약 4).
