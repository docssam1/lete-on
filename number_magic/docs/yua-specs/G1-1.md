## 0. 공통 전제 (코드를 직접 읽어 확인한 사실)

1. **유닛 ↔ 교재**: `data/courses.js` 과정 0 주석("G1-1~G1-15 = N-01~N-15 1:1")과 `perSessionDrills` 순서가 그렇다. 이 호 = **N-01 수 세기**(`generator:'nl1_count'`, 스레드 NL1 `data/threads.js:2985`).
2. **유닛 하나 = practice 4문항 + lab 4문항, 각각 mode 하나.** N-01 은 practice `mode:'count'`, lab `mode:'make'`. `nl1_count` 의 `count`는 이미 내부 주사위(`roll`)로 장면 종류를 섞는다(nl.js:89~139: 10칸 읽기·숫자 찾기·10칸 칠하기·물건 세기). 새 mode 는 같은 방식으로 **`params.modes`(배열)을 받아 생성기가 `pick(rng, modes)`로 고르게** 하는 것을 제안한다. 4문항에 12활동이 다 못 들어가므로 **교재 전 활동 커버는 스레드 레벨(인쇄·드릴, `courses.js`의 `'NL1@4'` 표기)이 맡고**, 유닛 체험은 대표 mode 만 넣는다.
3. **위젯 판정 계약(중요)**: 유닛 practice/lab 은 `+val===cur.answer`로 판정한다(`main.js:6159`, `:6962`). 배열 answer 는 넘패드 문항만 가능하고 **위젯은 숫자 하나만** 돌려줘야 한다. 그래서 집합·그리기·순서 위젯은 `matchLine`(`widgets.js:1330`)·`dotToDot`(`:1169`)처럼 **내부에서 판정하고 맞을 때 `onAnswer(problem.answer)`, 틀리면 `shake` + `onAnswer(-1)`** 로 한다. `problem.answer` 는 "대표 숫자(개수·조각 수·길이 등)".
4. 위젯의 3지선다 보기는 위젯 안에서 `Math.random()`으로 만든다(`widgets.js:875`, `:957`). 인쇄 정답지와 화면이 어긋날 수 있으므로 **신규 위젯은 생성기가 `choices`를 정해 problem 에 싣고**, 위젯은 있으면 그대로 쓴다(없으면 기존 방식).
5. 인쇄: `exam.js` `nlVisualHtml`(3207)에 widget 별 분기, `nlAnswerLabel`(3244)에 정답 표기, `NL_PRINT_WORDS`(3261~)에 화면 동사(톡톡·콕·골라요)→인쇄 동사 치환. 아래 "인쇄" 항목은 이 세 곳의 변경만 적는다.
6. 소품: `app/object-art.js` `NM_OBJECTS`(16종 + `num:` 숫자) / `animal:` 10종. 새 물건은 같은 토큰 방식(`data/real-art.js`에 실사 PNG 한 줄)으로 연결한다.
7. 눈에 띈 기존 결함(이 호 작업과 겹침): `renderDotToDot`의 힌트가 한국어 고정 문자열("1️⃣ 부터 차례대로!", `widgets.js:1133`)이라 en/zh 에서도 한국어로 나온다 — G1-2 에서 역순 점 잇기를 넣을 때 함께 3언어화해야 한다. `THINGS`(nl.js:21)에는 단위(개/마리)가 없어 동물을 세어도 "개"로 나온다.

## 3. 활동별 상세

### 3-1. 2쪽 숫자 — 같은 수끼리 잇기 (B+C)
- **현재**: `matchLine`(widgets.js:1235)이 있다. 왼쪽은 **숫자만**, 오른쪽은 `rightType` 이 `'dice'`(점)·`'tally'`(탤리) 둘뿐. 호출 생성기는 `nl11_arrange` match(nl.js:492) / `nl_tallybuild` match. 교재의 한자어 수·고유어 수·손가락·10칸 틀이 없다.
- **결정 B+C**: `matchLine` 에 카드 종류를 늘린다. 교재 한 쪽(약 16개)은 앱에서 4개 짝씩 문항으로 쪼갠다.
- **mode `rep`** (`nl1_count`, 스레드 T-REP 1·2):
  ```
  { prompt:{ko,en,zh}, answerType:'number', answer:N, widget:'matchLine',
    left:[n..], leftType:'num'|'native'|'sino',          // 기본 'num'
    right:[n..], rightType:'dice'|'tally'|'frame'|'fingers'|'native'|'sino' }
  ```
  - `N`=짝 수(practice 3, main 4). `left`/`right` 는 같은 N개 수의 서로 다른 셔플(기존과 동일).
  - 카드 그림: `frame` = 10칸 틀에 n 개 칠한 것(CSS, 소품 불필요), `fingers` = 손가락 그림(1~5 한 손, 6~9 는 활짝 편 손 + (n−5)손가락), `native`/`sino` 는 글자 카드.
  - **3언어**: 글자 카드는 위젯이 `S.lang`으로 렌더 — `native`: ko 하나·둘·셋 / en one·two / zh 一·二; `sino`: ko 일·이·삼 / en·zh 는 `native`와 같은 글자로 폴백(생성기는 en·zh 에서 sino 를 안 고르게 `lang` 을 모르므로 **위젯이 폴백**). 한자어 수는 한국어 교재 고유 요구라 en/zh 문구는 "읽는 말"로만 번역한다.
  - practice: 수 1~5, `rightType`∈{dice,frame,fingers}. main: 수 1~9, `rightType`∈{frame,fingers,native,sino}, 드물게 `leftType:'native'`+`rightType:'sino'`(글자끼리).
- **정답 판정**: 기존 `matchLine` 그대로(전부 맞으면 `onAnswer(N)`).
- **인쇄**: `nlMatchHtml`(exam.js:3188)에서 `p.rightType` 에 `frame`→`nlTenframeHtml(n)`, `fingers`→손가락 SVG, `native`/`sino`→글자 span 을 추가하고 꼬리표 ①②…는 그대로. 정답지 `nlAnswerLabel` 변경 없음("3→①").
- **그림**: 손가락 `hand-1`~`hand-5`(PNG 5장, 손바닥을 보이는 오른손, 각 n 손가락 폄) — 6~9 는 앱이 `hand-5`+`hand-(n-5)` 두 장을 나란히 놓는다.
- **치환 문구**: NL_PRINT_WORDS 는 기존 '왼쪽 수 톡 → 오른쪽 점 그림 톡!'을 재사용(prompt 문구를 그대로 쓰면 변경 불필요).

### 3-2. 3쪽 숫자의 개수 (A)
- 이미 있음: `nl1_count` main 의 `digits` 장면(nl.js:121~139) — `num:d` 토큰, 글꼴 5종·기울기·크기가 제각각, 방해 숫자 3종, 목표 2~7개, 위젯 `tapCount`. 교재와 같은 활동.
- 소폭 보완(선택): practice 레벨에도 숫자 장면이 나오게 `roll` 구간을 열고(현재 practice 는 `roll<=3`이 10칸 읽기), 6/9 가 헷갈리지 않도록 기울기를 ±28°로 제한한 지금 값 유지.

### 3-3. 4쪽 세어 보기 (B) · 7쪽①·9쪽 과일 4종
- **현재**: `count`(nl.js:141~165) 는 목표 1종 + **다른 부류** 방해물 1~2종(`pool[1..2]`)을 섞는다. 교재는 **같은 부류 안의 방해**(공 중 축구공·럭비공·야구공, 동물 중 곰·토끼·다람쥐, 별·달·원)와 **단위(개/마리)** 구분을 요구한다.
- **결정 B** — `count` 확장:
  - `FAMILIES` 풀을 신설해 방해물이 같은 부류에서 나오게: 공[⚽,🏀,야구공,럭비공], 동물[`animal:*` 10종 중 곰·토끼·다람쥐·여우·거북이…], 과일[🍎,🍌,🍓,포도,수박], 모양[⭐,달,`shape:circle`].
  - 장면 종류를 주사위 한 칸 더 늘려 `kind:'family'`: 목표 1종 + 같은 부류 2종(main 은 3종까지 → 9쪽 과일 4종 장면을 만들 수 있음, 한 문항은 그중 한 종만 묻는다).
  - `THINGS` 항목에 단위 추가: `unit:{ko:'개'|'마리'|'송이',en:'',zh:'个'|'只'|'朵'}`. problem 에 `unit` 필드를 싣고 ko prompt 의 "몇 개일까요?"를 `${unit}` 로 만든다. 인쇄 답칸은 `nlAnsBox(p.unit||EA)`(exam.js:3216).
- **problem**(추가 필드만): `{…기존 tapCount…, unit:{ko,en,zh}, family:'ball'|'animal'|'fruit'|'shape'}`. 항목 `items` 는 기존 `dress()` 좌표.
- **난이도/범위**: 목표 2~9, 방해 합계 3~8(장면 총 ≤ 16, 기존 상한과 동일).
- **3언어**: ko "곰은 모두 몇 마리일까요? 곰만 세어 보세요" / en "How many bears? Count only the bears" / zh "一共有几只熊？只数熊".
- **인쇄**: 변경 없음(`nlSceneHtml`) — 답칸 단위만 위와 같이.
- **그림(신규 소품)**: `rugby-ball`(럭비공), `baseball`(야구공), `grapes`(포도송이), `watermelon`(수박), `moon`(초승달). 동물은 기존 10종 사용(교재의 돼지는 앱에 없으므로 쓰지 않음 — 토끼·다람쥐로 대체).

### 3-4. 5쪽 네모의 개수 (B)
- **현재**: `frameRead`/`framePaint`(widgets.js:941~1000)는 **고정 10칸(2×5)** 이고 `n` 개가 **앞에서부터** 찬다. `gridPaint` count 는 한 줄 총 4~9칸에서 "정확히 N 개 칠하기"(칸 위치 무관).
- **결정 B** — 두 위젯을 일반화(신규 위젯 아님):
  - problem 에 `rows`,`cols`(기본 2,5), `cells:[i..]`(칠해진 칸 인덱스, 기본 앞 n 개)를 허용. `frameCells(n,em,onTap)`(widgets.js:941)는 10 고정이라 `rows*cols` 와 `cells` 를 받게 바꾸고 CSS 열 수를 `--cols` 로.
  - 물건 없이 **색 채움** 칸을 허용(`emoji:null`).
- **mode `grid`** (`nl1_count`, NL1 레벨 5):
  - `read`: 5×5(main)·3×3~4×4(practice) 격자에 **붙어 있는 모양** n(=3~9)칸 → 개수 고르기. `{widget:'frameRead', rows, cols, cells, n, answer:n, emoji:null}`.
  - `paint`: 빈 격자에 "n칸 칠해요" → `{widget:'framePaint', rows, cols, target:n, answer:n}`. 교재도 자유 작도이므로 **칠한 개수만 확인**(어느 칸이든 정답).
- **칸 모양 생성**: 칠할 칸은 격자 위에서 상하좌우로 이어지는 폴리오미노(임의 성장). 교재식 "붙어 있는 모양"을 위해 연결 보장, 끊어진 조각 금지.
- **인쇄**: `nlFrameObjHtml`(exam.js:3157)이 10칸 고정 → `rows/cols/cells` 반영. read 는 답칸(개), paint 는 빈 격자 + 목표 숫자 + 정답지에 "n칸".
- **치환**: "칸을 톡톡 눌러요" 계열은 기존 `['판을 톡톡 눌러 보세요','판에 그려 보세요']`와 같은 결로 `['칸을 톡톡 눌러요','칸을 칠해요']` 한 줄 추가.

### 3-5. 6쪽 동그라미 나누기 (C+D)
- **현재 없음.**
- **결정 C(+D)**: 신규 위젯 `circleCut`, mode `cut`(T-FIG 3). 교재의 "자유 선 긋기"는 **원 둘레 12개 점(노드)을 두 개 잇는 현**으로 단순화(D). 어느 현이든 **조각 수만 맞으면 정답**이다.
- **problem**:
  ```
  read: { widget:'circleCut', cmode:'read', nodes:12, chords:[[a,b],..], answer:pieces, choices:[..3] }
  draw: { widget:'circleCut', cmode:'draw', nodes:12, target:T, maxChords:4, pre:[[a,b]..]?, answer:T }
  ```
- **조각 수 계산(생성기·위젯 공용 함수)**: 현을 입력 순서대로 처리하며 `R=1`에서 시작해, 새 현마다 `R += 1 + (이전 현들과 원 **안쪽**에서 만나는 서로 다른 교점 개수)`. 끝점이 같은 현은 둘레에서만 만나므로 교점 아님. 같은 현 두 번(중복)은 거부. 교점은 좌표를 소수 6자리로 둥글려 중복 제거(세 현이 한 점에서 만나면 1개로 센다).
- **read 생성**: 현 1~3개(practice 1~2), 조각 수 2~7. 세 현이 한 점에서 만나는 배치는 시각적으로 헷갈리니 생성에서 제외(교점 중복 시 재추첨).
- **draw 위젯 동작**: 원 둘레 점 두 개를 차례로 누르면 곧은 선(현)이 그어진다(첫 점 선택 후 취소는 같은 점 재탭). 이미 그은 현을 누르면 지워진다. 위쪽에 "목표 4조각 / 지금 3조각" 카운터. ✔ 로 제출: 조각 수 = T 이면 `onAnswer(T)`, 아니면 shake + `onAnswer(-1)`.
- **난이도**: practice T=3~5(현 2개로 가능), main T=4~7.
- **3언어**: ko "선을 그어 동그라미를 4조각으로 나눠요" / en "Draw lines to cut the circle into 4 pieces" / zh "画线把圆分成4块".
- **인쇄**: `nlVisualHtml` 에 `circleCut`: read → 현이 그려진 SVG 원 + 답칸(개); draw → 빈 원 + 목표 숫자 상자. 정답지는 read 는 숫자, draw 는 예시로 `조각 T (예: 현 …)`를 한 줄 — 현 한 가지 예시는 생성기가 `sample:[[a,b]..]`로 함께 준다.
- **치환**: "점 두 개를 차례로 눌러 선을 그어요" → 인쇄 "연필로 선을 그어요" 한 줄.

### 3-11. 11쪽 쌓기나무의 개수 (C+D)
- **현재 없음**(`renderCubes`(widgets.js)는 10만들기 큐브로 별개).
- **결정 C(+D)** — 신규 위젯 `blockCount`, mode `blocks`(T-FIG 5). G1-3 10쪽·13쪽①이 같은 위젯을 쓴다(그 호 명세와 공유).
- **problem**:
  ```
  { widget:'blockCount', bmode:'read', heights:[[h,..],..], answer:Σh, choices:[..3], hidden:0|1 }
  ```
  `heights[r][c]` 는 앞(r 큼)·뒤(r 작음) × 좌우 격자의 쌓은 높이(0~3). 격자 최대 3×3, Σ=3~9.
- **렌더**: 등각(아이소메트릭) SVG. 칸을 `(r+c)` 오름차순, 같은 칸은 `z` 오름차순으로 그린다(뒤→앞, 아래→위). 보이는 면은 위·앞(+r)·오른쪽(+c). 쌓기나무는 한 변이 같은 정육면체이며 면별 명암(위 밝게, 왼쪽 중간, 오른쪽 어둡게). 소품은 PNG 한 장(`block-iso.png`, 위·왼·오른쪽 세 면이 보이는 나무 블록)을 위치만 달리해 겹쳐 그리거나, PNG 가 없으면 플랫 3면 SVG 폴백.
- **가려진 블록 처리(교재 "보이지 않는 뒤·아래 블록 추론")**: 칸 `(r,c)`의 `z`층 블록은 **위·앞·오른쪽 면이 전부 가려지면 "완전히 숨음"**: 위가 `H[r][c]>z+1`, 앞이 `r<R-1 && H[r+1][c]>z`, 오른쪽이 `c<C-1 && H[r][c+1]>z`.
  - `hidden:0`(practice·기본 main): 숨은 블록이 하나도 없는 배치만 허용(생성기에서 거름).
  - `hidden:1`(main 후반): 숨은 블록 ≤1개 허용. 어떤 경우에도 **떠 있는 블록은 만들지 않는다**(높이 배열이라 구조상 불가).
  - 배치 제약: 뒤쪽이 앞쪽보다 낮지 않게(`H[r][c] >= H[r+1][c]`) 만들면 윗면이 거의 항상 보여 5~7세에게 적당하다.
- **정답 판정**: 3지선다(`choices`, 생성기가 정함)에서 총 개수를 고른다 → `onAnswer(Σh)`.
- **범위/난이도**: practice 3~5개(앞뒤 1줄·계단형), main 6~9개(3×3). 교재 11쪽 예(4·5·6·7·9개 규모)와 같은 범위.
- **인쇄**: `nlVisualHtml` 에 `blockCount`: 같은 SVG 를 정적 렌더(그림자 3면은 명암 대신 윤곽+빗금 — 흑백 레이저 대비) + 답칸(개). 정답지는 숫자.
- **3언어**: ko "쌓기나무는 모두 몇 개일까요?" / en "How many blocks are there?" / zh "一共有几块积木？".
- **그림(신규)**: 쌓기나무 `block-iso.png`(나무 정육면체, 등각 3면).

### 3-12. 12쪽 길이 (C)

`hand-1`~`hand-5`(손가락 모양), `kite`(연), `rugby-ball`, `baseball`, `grapes`, `watermelon`, `moon`(초승달), `sun`·`rain`·`cloud`(날씨 3종), `block-iso`(쌓기나무). 겹치는 기존 소품(`apple`·`banana`·`strawberry`·`soccer-ball`·`basketball`·`balloon`·`star`·동물 10종)은 재사용. **도형 토큰**(`shape:circle|square|triangle`)은 기하 도형이라 작화 대상이 아니다.

### 4-3. 인쇄 표현(exam.js)
