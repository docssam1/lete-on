# G1-13호 (더하기와 빼기 Ⅱ) → 유아 단계 이식 명세

작성 근거: `docs/g1-inventory/G1-13.md` + PDF 2~13쪽을 직접 렌더링해 확인 + 코드 직접 확인
(`engine/threads/nl.js`, `app/widgets.js` 의 `render()` switch, `app/exam.js` 의 `nlVisualHtml`/`nlAnswerLabel`/`NL_PRINT_WORDS`, `data/threads.js` NL1~NL16).
교재 문제는 그대로 옮기지 않고 **수 범위 9 이내·말 쉽게·칸 수 줄여** 변형했다.

**이 호의 성격**: 교재는 "1~9 덧셈을 제약 조건 퍼즐에 쓰는" 호라서 **현재 앱에 같은 활동이 하나도 없다(A 0건).**
가장 가까운 기존 자산은 `nl13_puzzle`의 `cross` 모드(위+아래=왼+오른, `crossSum` 위젯)뿐이며 교재 6쪽 십자와는 규칙이 다르다
(앱: 위+아래=왼+오른 / 교재: 가로 세 수 합=세로 세 수 합=목표). 대부분 **N-13(nl13_puzzle)** 에 모드를 추가하고,
저울은 **N-12(nl12_scale)**, 연쇄 계산은 **N-08(nl8_machine)** 에 넣는다.

## 0. 먼저 읽을 공통 사실 (코드로 확인한 것)

| 사항 | 확인 내용 |
|---|---|
| 판정 계약 | 위젯은 `onAnswer(값)`을 부르고 호스트가 `+val === problem.answer`(숫자) 또는 배열이면 길이·원소별 `+v === answer[i]` 로 판정(`main.js:5332·4725`). **조건만 만족하면 되는 문항(답이 여러 개)은 위젯이 스스로 조건을 검사하고, 만족하면 `problem.answer`를, 아니면 틀린 값(또는 흔들림만)을 내보낸다** — `dotToDot`이 이미 이렇게 한다. |
| 보기 만들기 | 기존 위젯(`seqFill`·`pyramid`·`crossSum`·`tapCount`)은 보기 3개를 위젯 안에서 `Math.random()`으로 만든다. 새 위젯은 **생성기가 `choices` 배열을 정해서 problem에 싣는다**(화면·인쇄가 같은 값을 보고, rng 규칙 "Math.random 금지"도 지켜짐). |
| 도형 좌표 | `dotToDot`처럼 **생성기가 좌표를 정해서 problem에 싣고 화면(widgets.js)과 인쇄(exam.js)가 같은 좌표를 읽는다.** 겹침 도형·십자·기차 같은 배치는 이 방식을 따른다. |
| 인쇄 | `nlVisualHtml(p)`가 `p.widget`으로 분기. **모르는 위젯이면 빈 문자열이 돌아가 물음 줄만 찍힌다**(그림 없는 학습지가 됨) → 새 위젯마다 `nlXxxHtml()` + 분기 1줄 필수. 정답지는 `nlAnswerLabel(p)`가 사람 말로 바꾼다(배열·여러 답이면 거기에 분기 추가). 화면 문구 → 인쇄 문구는 `NL_PRINT_WORDS` 표(ko/en/zh)로 바꾼다 — **"빈 칸에 올 수를 골라요 / Pick the … / 选出…" 처럼 이미 표에 있는 문장 틀을 쓰면 표 추가가 필요 없다.** |
| 스레드 레벨 | NL12(길 잇기·십자)=3레벨, NL10(저울)=2레벨, NL11(수 기계)=3레벨. 새 레벨은 `id:4`부터 **뒤에 덧붙인다**(`data/courses.js`는 `NL12@2`처럼 레벨 번호로 참조하므로 기존 번호가 밀리면 안 됨). 편성(`C0` 세션 배치)은 이 명세 범위 밖. |
| 수 범위 | 화면에 나오는 모든 수·합은 **9 이내**. 교재 5×5 표·합 10 이상 경로는 줄인다. |

## 2. 활동별 상세 명세

### 2-1. p2 네모 안의 수의 합 — (C) `nl13_puzzle` mode `overlap`
**교재**: 겹쳐진 사각형 2~4개. 큰 네모 하나 안의 수를 모두 더하면 ○ 안의 수. 빈 칸 구하기.
**앱 현황**: 없음. `crossSum`과 이름만 비슷하다(규칙 다름).
**유아용 변형**: 사각형 2개(연습) / 3개(본)을 사슬처럼 겹침. 영역 값은 1~5, 목표 합 ≤9, **빈 칸은 1개**.

**생성 규칙(조건 보장)**
- n=2: 영역 `A`(왼쪽만), `X`(겹침), `B`(오른쪽만). 모든 도형의 합이 T → `A+X = X+B = T`. (`A=B`가 되므로 연습 레벨에서만.)
- n=3: 영역 `a, x, m, y, b` (도형1={a,x}, 도형2={x,m,y}, 도형3={y,b}). `x,y∈1..4`, `m∈1..`, `T=x+m+y ≤ 9`, `a=T−x ≥1`, `b=T−y ≥1`.
- 빈 칸 하나만 `null`. 어느 영역이 비어도 그 영역을 담은 도형 하나로 풀린다(단 한 칸 빈칸이라 항상 성립).

**problem 스키마**
```js
{ prompt:{ko,en,zh}, answer:Number, answerType:'number', widget:'overlapSum',
  shape:'square'|'circle', n:2|3,
  geom:[ {k:'rect',x,y,w,h} | {k:'circle',cx,cy,r} ],      // viewBox 0~100, 생성기가 좌표 결정
  regions:[ {id:'a', v:4|null, at:[x,y]}, ... ],            // at = 숫자 놓일 좌표
  target:Number,                                            // 회색 뱃지(원 또는 네모 안 숫자)
  askId:'x',
  choices:[Number,Number,Number] }                          // 정답 + 이웃 수 2개(범위 1~9)
```
**위젯 `overlapSum`(화면)**: SVG로 도형들을 반투명 테두리로 겹쳐 그리고 영역마다 숫자를 놓는다. 빈 영역은 `?` 칩(깜빡임). 아래 큰 숫자 보기 3개를 탭 — 정답이면 `?` 자리에 숫자가 들어가고 초록, 틀리면 보기 흔들림. 각 도형 안의 영역을 탭하면 그 도형이 **굵은 윤곽으로 강조되고 안의 수의 합이 말풍선으로 뜬다**(스스로 확인하는 장치 — 겹침 판독이 이 활동의 핵심이므로).
**인쇄(`exam.js`)**: `nlOverlapHtml(p)` — 같은 `geom`·`at`을 SVG로, 빈 영역은 빈 네모, 목표 뱃지는 회색 원, 답칸은 영역 안 빈 네모(`nlAnsBox` 아님: 빈칸이 그림 안에 있음). 정답지 숫자 하나.
**판정**: 숫자 하나 일치.
**3언어**: ko "큰 네모 하나 안의 수를 모두 더하면 ⑧이에요. 빈 칸에 올 수를 골라요" / en "Add up the numbers inside one big square — it makes 8. Pick the number for the blank" / zh "一个大方块里的数加起来是8。选出空格里的数". 문구 틀이 `NL_PRINT_WORDS`의 "빈 칸에 올 수를 골라요 / Pick the / 选出"과 맞아 인쇄 변환 추가 불필요. 원 버전은 네모→원 / square→circle / 方块→圆圈.
**소품**: 없음(도형은 벡터).

### 2-2. p3 분동으로 무게 재기 — (D) `nl12_scale` mode `weigh`
**교재**: 1g·2g·4g·8g 중 2~3개로 목표 무게(3~10g)를 만들어 분동 통에 적기.
**앱 현황**: `nl12_scale`은 "더 무거운 쪽 고르기"뿐. 무게 개념 없음(개수 비교).
**유아용 변형**: 분동 3종만, 목표는 7g까지. 적어 넣는 대신 **분동을 접시에 올려 담기**.
- 연습: 분동 `[1,2,3]`, 목표 2~5 → **여러 답 허용**(3g = 3 하나 또는 1+2).
- 본: 분동 `[1,2,4]`, 목표 3~7 → 답이 하나(2의 거듭제곱 분해). 교재가 노린 개념이 여기.
- 한 번에 최대 3개.

**problem 스키마**
```js
{ prompt, answer:Number /*=target*/, answerType:'number', widget:'weightPick',
  weights:[1,2,4], target:6, maxPick:3,
  solutions:[[2,4]] }          // 정답지 표시용(연습은 여러 개)
```
**위젯 `weightPick`**: 아래에 분동 3개(밑이 평평한 금속 원통, 윗면에 `1g` 글자), 위에 접시 하나. 분동 탭 → 접시에 올라가며 합계 숫자가 접시 아래에 커짐. 다시 탭하면 내려감. 목표 무게는 상단 큰 뱃지 `6g`. **합이 목표와 같으면 "딩동"+초록 → `onAnswer(target)`.** 합이 목표를 넘으면 접시가 붉게 흔들리고 합계가 흔들림(분동 하나를 빼 보라는 신호). 별도 확인 버튼은 두지 않는다(합이 같아지는 순간 완성). 3개를 올려도 안 맞으면 전부 내려 보내고 한 번 흔든다. 두 번 연속 틀리면 호스트에는 `onAnswer(-1)` 전송.
**인쇄**: `nlWeightsHtml(p)` — 분동 그림 3개를 가로로, 목표 뱃지, 아래 "필요한 분동에 ○표". 정답지는 `1g+4g`. (`nlAnswerLabel`에 `widget==='weightPick'` 분기: 연습은 첫 번째 해만.)
**판정**: 선택 합 == target(조건 검사). 순서 무관.
**교재 13쪽 ② "1·2·4g로 잴 수 있는 무게 모두"** 는 이 모드를 1~7 모두 한 번씩 돌리는 것으로 대체(별도 "모두 고르기" UI는 만들지 않음 — 답이 항상 전부라 변별이 없다).
**3언어**: "분동"=ko `분동`, en `weights`, zh `砝码`. ko "분동을 올려 6g을 만들어요" / en "Put weights on the pan to make 6 g" / zh "把砝码放到盘里，凑成6克".
**소품(신규)**: 분동 — 금속 원통 + 손잡이, 1g·2g·4g 3개(같은 모양·크기만 다르게). 실사 PNG 필요.

### 2-3. p4 합이 가장 작게 — (D) `nl13_puzzle` mode `minpath` variant `ru`
**교재**: 3×3·4×4 숫자 원판. 왼쪽 아래→오른쪽 위, 오른쪽/위로만 이동, 지나는 수 합이 최소.
**앱 현황**: `dotToDot`(순서대로 점 잇기)만 있음. 경로 선택·합 비교 없음.
**유아용 변형**
- 연습: **2×2 판**, 길이 단 두 가지(가운데 칸을 어느 쪽으로 지나느냐). 칸 값 1~4. 두 길의 합을 직접 비교하면 되므로 "작은 길 고르기"의 첫걸음.
- 본: **2×3 또는 3×3**(길 3~6가지), 칸 값 1~3, **최소 합 ≤9**를 만족하도록 생성(5칸 경로, 평균 1.8 이하).
- 생성 조건: 최소 합 경로가 존재하고 ≤9 / 최소 합 경로가 1개(동점이면 어느 길이나 허용하지만 연습엔 유일해를 우선) / **본 레벨은 "눈에 띄는 작은 수만 쫓아가는 탐욕 경로"가 최소가 아닌 판**을 절반 이상.

**problem 스키마**
```js
{ prompt, answer:Number /*=최소 합*/, answerType:'number', widget:'pathSum',
  rows:3, cols:3, cells:[[2,1,3],[1,2,1],[3,1,1]],   // 위 행부터, 행 우선
  start:[2,0], goal:[0,2],                           // [행,열]
  moves:'ru',                                        // 'ru'=오른쪽·위 / 'dr'=오른쪽·아래
  minPath:[[2,0],[2,1],...] }                        // 정답지용 한 예
```
**위젯 `pathSum`**: 격자(동그라미 칸). 시작 칸에 화살표 표시 + 깜빡임. 탭하면 그 칸이 선택되고 **다음에 갈 수 있는 칸(오른쪽·위)만 활성**. 위에 "지금까지 합 5" 누적 숫자. 도착 칸을 찍으면: 합이 최소면 초록+`onAnswer(min)`, 아니면 "더 작은 길이 있어요" 흔들림 + 경로 지우고 다시(호스트에는 보내지 않음, 2회 오답 시 `onAnswer(합)`). 마지막 칸 탭 직전 되돌리기 가능(선택 칸 다시 탭).
**인쇄**: `nlPathSumHtml(p)` — 격자 + 시작 화살표(교재 모양 그대로 ➚ 표기) + "합: ▢". 아이가 선을 긋고 합을 적는다. 정답지는 `최소 합 6 (2→1→1→1→1)`.
**판정**: 경로가 규칙대로이고 합 == 최소 합(조건 검사). 같은 최소 합의 다른 길도 인정.
**3언어**: ko "출발에서 도착까지 지나는 수를 더해요. 합이 가장 작은 길을 찾아요" / en "Add the numbers on your way from start to finish. Find the smallest total" / zh "从起点走到终点，把经过的数加起来。找出和最小的路". `NL_PRINT_WORDS` 추가: ko `['길을 눌러 이어요','길을 선으로 그어요']`, en `['Tap the cells','Draw a line through the cells']`, zh `['点一点格子','用线连一连格子']`.
**소품**: 없음.

### 2-4. p10 숫자의 합 — (B) p4의 `minpath` 에 variant `dr`
**교재**: 3×3, 위 양 끝에서 시작해 아래 반대쪽에 도착, 합 최소. 4쪽의 변형.
**처리**: 같은 위젯 `pathSum`에서 `moves:'dr'`(오른쪽·아래), `start:[0,0]`, `goal:[rows-1,cols-1]`. 시작 칸을 좌우로 고르는 교재 형식은 **단순화해 시작을 왼쪽 위 하나로 고정**(어디서 시작할지 고르는 일은 5~7세에게 변수가 하나 더). 같은 NL12 레벨 안에서 `variant`만 바꾼 별도 레벨로(연속 풀이 중 방향이 바뀌는 혼란 방지: 한 레벨에 한 방향).
인쇄·판정·3언어는 p4와 동일. 시작 화살표만 왼쪽 위로 이동.

### 2-5. p5 가로·세로의 합 같게 — (D) `nl13_puzzle` mode `gridsum`
**교재**: 5×5 표, 모든 가로줄·세로줄의 합이 같도록(5 또는 8) 빈 칸 채우기. 첫 문항은 줄별 힌트 제공.
**유아용 변형**: **3×3**, 합 T=4 또는 5, 칸 값 0~4, 빈 칸 1~2개(연습) / 3~4개(본). 줄별 힌트 표는 뺀다.

**생성(해가 유일하게 보장)**: T개의 3×3 순열행렬을 합해 전 행·열 합이 T인 표를 만든다. 빈 칸 후보를 고르고 **"행 또는 열에 빈 칸이 정확히 하나인 줄을 하나씩 풀어 나가면 전부 풀리는" 판만 채택**(연쇄 추론 가능). 칸마다 해가 하나라 배열 비교 판정이 맞다.
**problem 스키마**
```js
{ prompt, answer:[3,1], answerType:'array', widget:'gridSum',
  n:3, T:4, grid:[[2,null,1],[1,1,2],[null,2,1]],   // null=빈 칸
  blanks:[[0,1],[2,0]] }                              // 정답 배열의 순서
```
**위젯 `gridSum`**: 격자 + 각 행 오른쪽·각 열 아래에 **합 뱃지**(현재 합 / T, 같으면 초록·모자라면 파랑·넘치면 빨강). 빈 칸을 탭 → 아래 숫자 칩(0~T)에서 고름. **합 뱃지가 실시간으로 바뀌므로 아이가 스스로 검증**. 모든 칸이 차면 "다 됐어요" 버튼이 켜져 `onAnswer([...])`.
**인쇄**: `nlGridSumHtml(p)` — 격자 + "가로줄·세로줄의 합이 모두 T" 안내. 빈 칸은 빈 네모. 정답지: `3, 1`(칸 순서). **`nlAnswerLabel`에 `gridSum` 분기: `p.answer.join(', ')`**(배열 답이 NL 인쇄에서 처리되는 경로를 확인하지 못했으므로 명시적 분기 필요).
**판정**: 배열 비교(해 유일).
**3언어**: ko "가로줄과 세로줄의 합이 모두 4가 되도록 빈 칸을 채워요" / en "Fill the blanks so every row and every column adds up to 4" / zh "填空，让每一行、每一列的和都是4".
**소품**: 없음.

### 2-6. p11 가로·세로의 합 같게 — (B) p5의 `gridsum` 레벨 확장
**교재**: 5×5, 합 6·7·9·9, 빈 칸 다수.
**처리**: 같은 모드·위젯에서 **`n:4`, T=5~7, 빈 칸 4~5개** 레벨 추가(칸 값은 0~4 유지). 5×5·T=9는 화면 폭·수 범위상 제외. 생성기는 `n`·`T`·`blankCount`를 params로 받는다.
스레드: NL12에 `{id:6,label:{ko:'가로·세로 합 같게(4×4)'},params:{mode:'gridsum',level:'main',n:4}}`.

### 2-7. p6 합이 같게 — (D) `nl13_puzzle` mode `crossplace`
**교재**: 십자(네모 5칸)에 1~5를 한 번씩, 가로 세 수 합 = 세로 세 수 합 = 목표(8, 9). 삼각형(원 6개)에 1~6, 한 변 세 수 합 = 목표.
**유아용 변형**: **십자만.** 삼각형(변 위 원 6개, 1~6 배치)은 시행착오가 커서 뺀다(E에 가까운 D — 대체 없음).
**수학 사실**: 1~5를 한 번씩 쓰는 십자에서 정수 합이 맞는 판은 **가운데 1(합 8: 2+5, 3+4)** 과 **가운데 3(합 9: 1+5, 2+4)** 뿐이다(가운데 2·4는 짝이 안 맞고, 5는 합 10이 되어 범위 밖). 그래서 변형은 "빈 칸 수"로 만든다.
- 연습: 가운데 + 팔 2개가 주어지고 나머지 2칸 채우기.
- 본: 가운데만 주어지고 팔 4칸 모두 채우기.
- **서로 다른 문항 수가 적다**(대략 2센터 × 배치 8 = 16 이내). 학습지 한 회차에 12 이상 나오면 중복이 생기므로 **스레드 편성량을 12 이하로 제한**하고 `data/courses.js`의 편성 상한 표(`'NL12@1':12` 같은 줄)에 추가할 것.
**problem 스키마**
```js
{ prompt, answer:Number /*=T*/, answerType:'number', widget:'crossPlace',
  T:8, nums:[1,2,3,4,5],
  cells:{ c:1, u:null, d:null, l:2, r:null },   // 주어진 칸(값) / null=빈 칸
  solutions:[ {u:3,d:4,l:2,r:5}, ... ] }        // 정답지용
```
**위젯 `crossPlace`**: 십자 5칸 + 아래 숫자 카드 1~5(주어진 칸의 수는 이미 쓴 카드로 흐리게). 빈 칸 탭 → 카드 탭으로 넣기(쓴 카드는 흐려짐, 다시 탭하면 회수). 가로 합·세로 합이 십자 옆에 `=8` 뱃지로 실시간 표시(맞으면 초록). 5칸이 다 차고 두 합이 T이면 `onAnswer(T)`.
**인쇄**: `nlCrossPlaceHtml(p)` — 십자 모양 빈 네모 5칸(주어진 칸 숫자) + 카드 목록 + 합 뱃지. 정답지는 한 예(`위 3 아래 4 …`).
**판정**: 조건(가로합=세로합=T, 1~5 한 번씩) — 해가 여러 개(같은 쌍의 위치 바꿈).
**3언어**: ko "1부터 5까지를 한 번씩 넣어서, 가로 세 수와 세로 세 수의 합이 모두 8이 되게 해요" / en "Use 1 to 5 once each so the row of three and the column of three both add to 8" / zh "1到5各用一次，让横着三个数和竖着三个数的和都是8".
**소품**: 없음.

### 2-8. p8 원 안의 수의 합 — (B) `overlap` 의 shape:`circle`
**교재**: 겹친 원(벤 다이어그램)의 수 합이 네모 안 수와 같음. 세 원.
**처리**: p2와 같은 `overlapSum`에서 `shape:'circle'`, `geom`을 `{k:'circle',cx,cy,r}`로, 목표 뱃지를 **네모**로(교재의 반전을 살림). 세 원이 가운데에서 모두 겹치는 판(교재 8쪽 4번)은 영역이 7개라 유아에겐 과함 → **원 2개·3개 사슬형까지만**. 문구만 "큰 네모→원".

### 2-9. p9 무게 재기 — (D) `nl12_scale` mode `balance`
**교재**: 1g·3g·9g 분동으로 양팔저울에 올려 목표 무게(○, 2~8g)를 재도록 분동에 무게를 적는다. 분동을 반대쪽 접시에 올려 "빼는" 효과가 핵심.
**앱 현황**: `balanceScale`은 개수 비교 후 접시 탭만.
**유아용 변형**: 저울은 **항상 평형**, 한 접시에 물체(회색 뱃지, 무게 W)와 분동이 놓여 있고 **분동 하나의 무게가 빈 칸**. 분동은 1~5g의 평범한 정수(1·3·9 같은 3의 거듭제곱 체계는 쓰지 않음). 연습은 "물체와 반대쪽 접시에 분동(빈 칸)과 알려진 분동", 본은 "물체와 같은 접시에 분동이 있는 경우"(교재의 뺄셈 효과)까지.
- 연습: 좌 `[물체 W]` / 우 `[분동 w1, 분동 ?]` → `? = W−w1`.
- 본: 좌 `[물체 W, 분동 ?]` / 우 `[분동 w2]` → `? = w2−W` (w2>W).
- W 2~8, 모든 분동 1~5, 접시 총합 ≤9.

**problem 스키마**
```js
{ prompt, answer:Number, answerType:'number', widget:'balanceEq',
  objW:5, objSide:0,                       // 0=왼쪽 접시에 물체
  fixed:[ {side:1, w:2} ],                 // 알려진 분동
  blank:{ side:1 },                        // 빈 칸 분동이 놓인 접시
  choices:[1,2,3] }
```
**위젯 `balanceEq`**: 빔은 수평(**기울이면 답이 보임**). 접시마다 물체·분동을 놓고, 빈 분동은 `?`. 보기 3개 탭. 정답이면 `?` 가 숫자로 바뀜. 교재의 "분동은 한 번씩만"은 단순화해 따지지 않음.
**인쇄**: `nlBalanceEqHtml(p)` — `nlScaleHtml`을 확장(접시 위에 분동 직사각형 + 물체 회색 원). 정답지 숫자 하나.
**판정**: 숫자 일치.
**3언어**: "저울이 평평해요! 빈 분동은 몇 g일까요?" / "The scale is level! How many g is the blank weight?" / "天平是平的！空白的砝码是几克？".
**소품**: 분동(위 2-2와 같음, 크기 5종 필요: 1~5g) + 양팔저울(평평한 상태) 실사 PNG.

### 2-10. p12 두 수의 합 같게 — (D) `nl13_puzzle` mode `pairs`
**교재**: 숫자 카드 6장을 2장씩 묶어 세 쌍의 합이 모두 같도록(식 쓰기).
**유아용 변형**: 카드 4장 → 2쌍(연습) / 6장 → 3쌍(본). 카드는 0~9 서로 다른 수, **합 T ≤9**.
- k=2: T 5~9, 두 쌍 `(a,T−a),(b,T−b)` (a≠b, 모든 수 서로 다름).
- k=3: T 5~9에서 세 쌍을 고른다(T=5이면 카드 0~5 전부). **디코이 없이 6장이 정확히 3쌍으로 나뉘는 판**을 쓴다.
**problem 스키마**
```js
{ prompt, answer:Number /*=T*/, answerType:'number', widget:'pairUp',
  cards:[1,6,2,5,3,4], k:3, T:7 }
```
**위젯 `pairUp`**: 카드 6장이 가로로 놓임. 카드 둘을 탭하면 그 둘이 같은 색 테두리로 **묶이고 합이 작은 풍선에 뜬다**. 모두 묶이면 합 풍선이 전부 같은지 확인 — 같으면 `onAnswer(T)`, 다르면 묶음 전부 풀리고 흔들림. 이미 묶인 카드를 탭하면 그 묶음만 풀림.
**인쇄**: `nlPairUpHtml(p)` — 카드 그림 줄 + 식 칸 `▢+▢=▢` × k. 정답지 `1+6, 2+5, 3+4 (합 7)`. 교재 예시 1줄은 첫 줄에 채워 둔다.
**판정**: 조건(모든 쌍의 합이 같음, 카드 모두 사용). 쌍 순서·카드 순서 무관.
**3언어**: ko "카드를 두 장씩 묶어요. 묶은 합이 모두 같아지게!" / en "Pair up the cards two by two so every pair adds to the same number" / zh "把卡片两张两张配对，让每一对的和都相同".
**소품**: 숫자 카드(실사 인쇄 카드 한 장 — 모양만 있고 숫자는 앱이 얹음).

### 2-11. p7 확인학습 — (C) 앞 유형의 재조합 + 연쇄 계산(`chain`)
교재 6문항을 **새로 만들 모드로 다시 대응**한다. 확인학습은 별도 모드를 만들지 않고 `boost`/세션이 앞 레벨을 섞어 부르면 된다.
| 교재 | 대응 |
|---|---|
| ① 네모 합 | p2 `overlap` |
| ② 1g·2g·3g 분동으로 잴 수 있는 무게에 ○ | p3 `weigh`(연습 레벨 `[1,2,3]`, 여러 해) |
| ③ +2, +1, −5 … 연쇄 계산(물음표 모양 원) | **신규 `nl8_machine` mode `chain`** (아래) |
| ④ 별 모양 원 1~6 합 7 | 제외(p6 삼각형과 같은 이유) → 대체: `crossplace` T=8 |
| ⑤ 4×4 표 합 7 | p11 `gridsum` n:4 |
| ⑥ 지나는 수 합 최소 | p4/p10 `minpath` |

**연쇄 계산 `chain` (N-08 · NL11 레벨 6, 같은 위젯의 라벨 변형)**: 시작 수에서 화살표 위에 적힌 **±k를 차례로 적용**해 빈 원을 채운다. 위젯 `arrowChain`을 쓰며 **정의는 `G1-14.md`의 p8 절에 있다**(두 호가 공유). 이 호에서의 설정: `layout:'snake'`(교재의 물음표 모양 대신 S자), 화살표마다 숫자 라벨(`arrows:[{d:+2,style:'plain'}, ...]`, `legend:null`), 시작 1개 주어지고 **원 3~4개 중 하나를 질문**, 중간 값은 항상 **0~9 사이**(음수·10 이상 없음).

### 2-12. p13 확인학습 — (D) 재조합 + `ring`(P3)
| 교재 | 대응 |
|---|---|
| ① 세 원 합 8 | p8 `overlap` circle |
| ② 1·2·4g로 잴 수 있는 무게 모두 | p3 `weigh` 전 목표 1~7 (§2-2 설명) |
| ③ 사각 배치(꼭짓점 2·3·4·5, 변 합 5·6·8·9) | **신규 `nl13_puzzle` mode `ring`** (아래) — P3 |
| ④ 경로 | p4/p10 |
| ⑤ 4×4 표 합 9 | p11 (T≤7로 제한 → 9는 `n:3,T=4~5`로 대체) |
| ⑥ 십자 합 9 | p6 `crossplace` T=9(가운데 3) |

**`ring`(P3, 네 꼭짓점 합)**: 네모의 네 꼭짓점 원에 수, 네 변 위에 인접 두 꼭짓점의 합이 적혀 있고 **꼭짓점 1~2개가 비어 있다**. 꼭짓점 값 1~5 서로 다름.
```js
{ prompt, answer:Number|Array, widget:'ringSum',
  corners:[2,null,4,5], sides:[5,6,8,9]   // sides[i] = corners[i] + corners[i+1](순환)
}
```
빈 꼭짓점 1개(연습): 변 합 하나와 이웃 꼭짓점으로 결정. 빈 꼭짓점 2개(본): 숫자 카드를 놓아 모든 변 합을 맞춤(조건 검사). 위젯은 `crossPlace`와 같은 "카드 → 칸" 코드를 재사용. **우선순위가 낮다** — 교재 확인학습의 한 문항일 뿐이고, 같은 사고(합으로 값 거꾸로 구하기)는 p2·p5가 이미 충분히 훈련한다.

## 4. 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

**새 위젯 (8, 모두 problem이 `choices`/좌표를 싣고, 판정은 숫자·배열·조건)**
| 위젯 | 모드 | 핵심 상호작용 |
|---|---|---|
| `overlapSum` | `overlap` | 겹친 도형 영역 판독 + 보기 탭, 영역 탭 시 도형별 합 말풍선 |
| `weightPick` | `weigh` | 분동 탭→접시에 올려 합 맞추기 |
| `pathSum` | `minpath` | 인접 칸 탭으로 경로 잇기 + 누적 합 + 최소 합 검증 |
| `gridSum` | `gridsum` | 칸 채우기 + 행·열 합 뱃지 실시간 |
| `crossPlace` | `crossplace` | 카드를 십자 칸에 놓기 + 두 합 실시간 |
| `pairUp` | `pairs` | 카드 둘씩 묶고 합 풍선 비교 |
| `balanceEq` | `balance` | 평형 저울의 빈 분동 무게 고르기 |
| `arrowChain` | `chain` (nl8) | 화살표 사슬 계산(정의 → G1-14.md p8) |
| `ringSum`(P3) | `ring` | 네 꼭짓점 카드 배치 |

**기존 위젯 재사용**: `seqFill`·`pyramid`·`tapCount`·`numberBond` 등은 이 호에서 쓰지 않는다.
