# G1-15호 (더하기와 빼기 Ⅱ — 문장제·어떤 수) → 유아 단계 이식 명세

작성 근거: `docs/g1-inventory/G1-15.md` + PDF 2~13쪽 직접 렌더링 확인 + 코드 직접 확인.
교재 문제는 그대로 옮기지 않고 **수 범위 9 이내·한 문장 짧게·그림으로 상황을 보이게** 변형했다.

**이 호의 성격**: 글(문장제)이 중심이라 **읽기 부담**이 가장 큰 호다. 앱의 기존 문장제 자산은 `nl15_logic` story(더 받음/먹음 → `storyCard` numpad)와
`nl5_story`(줄서기·계단 → `storyCard`)이고, 둘 다 **🔊 다시 듣기 버튼**(`storyCard`의 replay, `NM_SAY`)과 이모지 장면을 갖는다.
유아용 이식의 원칙은 ① 문장은 음성으로도 들려주고 ② 수량은 반드시 **그림으로 보여** 주고 ③ 쓰는 답은 **숫자 하나(또는 두 개)** 로 줄이며 ④ 열린 서술형은 선택식으로 바꾸는 것이다.

## 0. 공통 사실 (G1-13.md §0과 같다 — 요점만)
- 판정: 위젯이 `onAnswer(값)`, 호스트가 `+val === answer`(배열이면 원소별) — `main.js:5332·4725`.
- 새 위젯은 생성기가 `choices`·좌표를 problem에 싣는다(위젯 `Math.random()` 지양).
- 인쇄: `nlVisualHtml` 분기 + `nlXxxHtml` + `nlAnswerLabel` + `NL_PRINT_WORDS`. 모르는 위젯은 그림 없이 물음 줄만 나온다.
- `storyCard`(`widgets.js:1572`): `interaction:'tap'|'numpad'`, `layout:'row'|'stairs'`. `numpad`는 2자리 숫자패드 + 🔊 버튼. 계단은 `total`·`mark` — **`mark`가 어느 칸과도 일치하지 않으면(`-1`) 마커 없이 계단만 그려진다**(화면·인쇄 `nlStairsHtml` 모두 `i===mark` 비교라 추가 수정 불필요).
- `sortBasket`(`widgets.js:1810`)은 **바구니 2개 고정**(`basketA`/`basketB`, `item.type 'A'|'B'`). 3종 분류는 확장이 필요.
- `multiPadState(screen, answerArr, shape)`(`widgets.js`)가 **여러 칸 답 + 숫자패드** 부품으로 이미 있다 — 새 위젯이 두 수를 답으로 받아야 할 때 재사용.
- 스레드 레벨: NL9(줄서기·계단)·NL13(이야기 셈·분류)·NL15(분류하고 세기) 모두 3레벨. 새 레벨은 `id:4`~ 뒤에 덧붙인다.

## 2. 활동별 상세 명세

### 2-1. p2 숫자 이야기 — (C) `nl15_logic` mode `fill`, 위젯 `storyFill`
**교재**: 이야기 글의 빈 칸 3~5개에, 주머니 속 수 카드 중 알맞은 수를 찾아 넣기(점수·인원·나이).
**앱 현황**: `nl15_logic` story는 "시작 수·변화 수 → 답 하나"뿐. 글 속 **여러 빈 칸을 주머니 수로 채우는** 형식 없음.
**유아용 변형**: 빈 칸 3개(연습) / 4개(본), **주머니 수 카드도 그 개수**(교재는 카드가 빈 칸 수와 같거나 많음). 모든 수 ≤9.

**이야기 템플릿(생성기가 고름)**
| id | 칸 | 문장(ko) 틀 | 카드 | 풀이의 근거 |
|---|---|---|---|---|
| `score` | 3 | "🐰팀이 이겼어요. 이긴 팀은 {0}점, 진 팀은 {1}점이에요. 모두 합쳐 {2}점이에요." | `{a, b, a+b}`(a>b) | 합이 가장 큰 수, 이긴 쪽이 큰 수 |
| `group` | 4 | "모두 {3}명이에요. 남학생은 {0}명, 여학생은 {1}명이고, 남학생이 {2}명 더 많아요." | `{a, b, a−b, a+b}` | 합=가장 큰 수, 차 관계 |
- **카드 배정이 하나로만 결정되도록 생성**: 생성기가 카드 순열을 전수 검사해 조건(합·크기 비교)을 만족하는 배정이 **정확히 하나**인 `(a,b)`만 채택(예: group에서 a−b 가 b와 같으면 모호하므로 제외).
- 인물은 동물 토큰(`animal:rabbit` 등)으로 "토끼 팀 vs 거북이 팀", "토끼 반 친구들" 식(교재의 철수·미현 같은 이름은 쓰지 않음).

**problem 스키마**
```js
{ prompt:{ko,en,zh}, answer:[5,3,8], answerType:'array', widget:'storyFill',
  story:{ ko:'🐰팀이 이겼어요. 이긴 팀은 {0}점, 진 팀은 {1}점이에요. 모두 합쳐 {2}점이에요.', en:'…', zh:'…' },
  slots:3, chips:[3,8,5],                     // 주머니 안 카드(섞음)
  scene:{ emoji:'⚽' } }                      // 장면 소품(선택)
```
**위젯 `storyFill`**: 위에 짧은 이야기 문장(빈 칸은 점선 네모 `{n}`), 아래에 **주머니 그림 + 카드 칩**. 카드 칩 탭 → 다음 빈 칸에 들어가고 칩은 흐려짐. 빈 칸을 탭하면 그 카드가 주머니로 돌아감. 모든 칸이 차면 "다 됐어요" 활성화 → `onAnswer([...])`. 틀리면 칸 전체가 흔들리고 모두 주머니로(한 번만 — 두 번째는 정답 하나만 보여 줌). 🔊 버튼으로 **빈 칸마다 "빈칸" 소리 없이 문장 전체를 읽어 줌**(칸은 "…" 정지로).
**인쇄**: `nlStoryFillHtml(p)` — 이야기 글(빈 칸은 네모) + 오른쪽 주머니 그림에 카드 숫자 흩뿌림(교재 모양을 따르되 그림은 신규 소품). 정답지 `5, 3, 8`.
**판정**: 배열 비교(생성기가 해 유일을 보장).
**3언어**: ko "이야기에 알맞은 수를 주머니에서 찾아 빈 칸에 넣어요" / en "Find the right number in the pouch for each blank in the story" / zh "从口袋里找出合适的数，填进故事的空格". `{n}` 칸 표기는 언어별 문장 틀에 그대로.
**소품(신규)**: **주머니**(실사 복주머니·작은 천 주머니 PNG 한 장). 축구공은 기존(`⚽`) 사용.

### 2-2. p3 어떤 수 구하기 1 — (D) `nl15_logic` mode `unknown` + mode `eqpick`
**교재**: 7행 표(문장 | □를 쓴 식 | 어떤 수). 문장→식, 식→문장(쓰기), 어떤 수 구하기.
**유아용 변형**: 쓰기를 줄이고 **그림으로 "숨은 수"를 보여 준다.** 상자 안에 몇 개인지 모르는 물건 + 밖에 보이는 물건 → 합계/남은 개수가 주어지면 상자 안의 개수가 "어떤 수".

**(a) `unknown` — 숨은 수 구하기 (위젯 `mysteryBox`)**
| op | 이야기 | 식 | 답 |
|---|---|---|---|
| `add` | "상자에 사과가 몇 개 있어요. 밖에 3개 더 놓았더니 모두 6개" | `□ + 3 = 6` | 3 |
| `subL` | "사과 6개가 있었어요. 몇 개를 먹었더니 4개가 남았어요" | `6 − □ = 4` | 2 |
| `subR` | "상자의 사과를 3개 먹었더니 6개가 남았어요" | `□ − 3 = 6` | 9 |
| `expr`(P3) | 오른쪽이 식인 경우 `□ − 2 = 4 + 3` | | 9 |
- 모든 수·답 ≤9. 레벨 1은 `add`/`subL`, 레벨 2는 `subR` 포함, 레벨 3은 `expr` 포함.
```js
{ prompt, answer:Number, answerType:'number', widget:'mysteryBox',
  op:'add', emoji:'🍎', loose:3, total:6,        // add: 밖 loose, 합 total
  eq:{ ko:'□ + 3 = 6', ... } | null,             // 레벨 2+ 에서 식도 화면에 보여 줌
  choices:[2,3,4] }                              // 정답 ± 이웃
```
**위젯 `mysteryBox`**: 왼쪽에 **물음표가 붙은 상자**(안이 보이지 않음), 오른쪽에 밖의 물건(`loose`개), 가운데 `+`·`=`, 맨 오른쪽에 합계(또는 남은 개수). 보기 3개 탭 → 정답이면 상자 뚜껑이 열리며 그 개수만큼 물건이 쏟아져 나와 합을 보여 줌. `eq`가 있으면 아래에 `□ + 3 = 6` 식도 함께 표시(문장→식 번역을 눈에 익히게).
**인쇄**: `nlMysteryBoxHtml(p)` — "[ ? ] + ●●● = 6개" 그림 + 식(레벨 2+) + 답칸 `nlAnsBox`. 정답지 숫자.
**3언어**: ko "상자 안에 몇 개 있을까요? 식을 보고 알아봐요" / en "How many are in the box? Use the picture to find out" / zh "盒子里有几个？看图想一想".

**(b) `eqpick` — 문장↔식 고르기 (위젯 `eqChoice`)**: 교재의 "문장을 식으로 쓰기 / 식을 문장으로 쓰기"를 **보기 3개 중 고르기**로. 문장 하나를 주고 식 3개 중 맞는 것을, 또는 식 하나를 주고 문장 3개 중 맞는 것을 고른다. 오답은 **연산 기호를 바꾸거나 □ 위치를 바꾼 것**(예: 맞는 `□+3=6`, 오답 `6−□=3`·`□−3=6`).
```js
{ prompt, answer:0|1|2 /*정답 보기 번호*/, answerType:'number', widget:'eqChoice',
  stem:{ kind:'sentence'|'eq', ko:'…', en:'…', zh:'…' },
  choices:[ {kind:'eq', txt:'□ + 3 = 6'}, {kind:'eq', txt:'6 − □ = 3'}, ... ],   // 문장 보기일 땐 {kind:'sentence', ko,en,zh}
  hint:{ emoji:'🍎', items:… } | null }          // 그림 힌트(선택)
```
**위젯 `eqChoice`**: 위에 줄글(또는 식), 아래에 보기 카드 3장(카드 하나를 탭하면 즉시 판정, `balanceScale`·`storyCard tap` 방식 — 정답은 초록, 오답은 흔들림). 보기 순서는 생성기가 `answer`를 3A/3B식으로 분산.
**인쇄**: `nlEqChoiceHtml(p)` — 보기 ①②③ 카드 + "○표". `nlAnswerLabel`: `②번`(0/1/2 대신 말로).
**판정**: 보기 번호 일치.
**이 모드의 재사용**: p9(문장제 만들기 식 쓰기), p8 일부 보기에도 이 위젯.
**3언어**: ko "이야기에 맞는 식을 골라요" / en "Pick the number sentence that matches the story" / zh "选出和故事相符的算式". `NL_PRINT_WORDS` 추가: ko `['카드를 콕! 눌러요','에 ○표 하세요']`, en `['Tap the card','Circle the card']`, zh `['点一点卡片','圈出卡片']`.

### 2-3. p4 어떤 수 구하기 2(잘못 계산) — (D) `nl15_logic` mode `wrong` (P3)
**교재**: "어떤 수에서 3을 빼야 하는데 잘못하여 더했더니 8. 바르게 계산하면?" — 두 단계(잘못→어떤 수→바른 값).
**유아용 변형**: 이야기 한 줄 + **두 번 고르기**. 수 ≤9, 어떤 수 ≥ 뺄 수.
```js
{ prompt, answer:[5,2], answerType:'array', widget:'mysteryBox',
  op:'wrong', intended:'sub', mistaken:'add', k:3, mistakenResult:8,   // 뺄셈을 덧셈으로 잘못함
  phases:[ {ask:'x',choices:[4,5,6]}, {ask:'final',choices:[1,2,3]} ] }
```
**위젯 `mysteryBox` 2단계**: 1단계 "잘못 계산한 식 `□ + 3 = 8`에서 □는?" 보기 3개 → 정답이면 상자가 열리며 `5`가 드러남. 2단계 "바르게는 `5 − 3 =`?" 보기 3개 → 모두 맞으면 `onAnswer([5,2])`. 1단계에서 틀리면 2단계 진입 불가.
**인쇄**: 두 줄 `[ ? ]` 식 + 답칸 2개. 정답지 `5, 2`.
**판정**: 배열 비교. **우선순위 P3** — 교재에서도 "상" 난이도 두 단계 추론이고, 5~7세 상위 후반 이후에 둘 것(NL13 새 레벨의 마지막).
**p11**은 p3·p4와 같은 유형의 정리판이므로 레벨만 추가(B).

### 2-4. p11 어떤 수 구하기(정리판) — (B)
**교재**: 문장→□ 식→어떤 수(3행), 잘못 계산한 문장(3행). p3·p4의 정리.
**처리**: `unknown`(레벨 1~3)과 `wrong`(레벨 4)을 한 곳에 둔 유닛 정리 세션(`NL13`에 새 레벨)에서 재사용. 신규 모드·위젯 없음.

### 2-5. p5 나이 알아보기 — (D) `nl15_logic` mode `compare` (기존 `storyCard` 재사용)
**교재**: 가족 나이 관계 글 6문항(가족 수·가장 어린 사람·각자 나이·나이 차 등), 서술형.
**유아용 변형**: 인물을 **동물 친구 2~3마리**로, 관계는 "…보다 N살 많아요/적어요" 한 단계씩만. 질문 유형을 3가지로 나눔.
| 질문 | 입력 | 위젯 |
|---|---|---|
| "곰은 몇 살?" (기준 나이 + 차) | 숫자 | `storyCard` `interaction:'numpad'` (`chars`에 동물 줄을 그려 줌) |
| "가장 어린 친구는?" (나이 비교, 3마리) | 동물 탭 | `storyCard` `interaction:'tap'` (`targetIndex`) |
| "토끼는 곰보다 몇 살 많아요?" (차) | 숫자 | `storyCard` numpad |
- 나이 3~9, 차 1~4, 결과 ≤9. 한 문제 안 정보는 **2~3개**로 제한(교재는 4~5개 조합).
- 한 문장에 관계를 하나만, 문장은 3줄 이내.
```js
{ prompt, answer:Number, answerType:'number', widget:'storyCard',
  interaction:'numpad', layout:'row', total:2,
  chars:['animal:rabbit','animal:bear'],
  facts:[ {who:0,age:4}, {who:1,rel:'older',by:2,of:0} ] }      // 화면 문장은 prompt 에 이미 풀어 씀; facts 는 검산용
```
**위젯 확장 한 줄**: `storyCard`의 `chars` 줄 아래에 **각 동물 이름표/나이 칸**을 그리는 선택 필드(`labels:[…]`)가 있으면 좋다(없어도 동작).
**인쇄**: 기존 `nlVisualHtml` `storyCard` 분기가 `chars`를 그려 주므로 **추가 구현 없음**(답칸만 `nlAnsBox`). 나이 그림은 숫자가 아니라 텍스트로.
**판정**: 숫자 또는 탭 인덱스 일치.
**3언어**: ko "곰은 토끼보다 2살 많아요. 토끼는 4살이에요. 곰은 몇 살일까요?" / en "The bear is 2 years older than the rabbit. The rabbit is 4. How old is the bear?" / zh "小熊比小兔大2岁。小兔4岁。小熊几岁？".
**소품**: 기존 동물 10종(토끼·곰 등)으로 충분 — 신규 없음.

### 2-6. p6 문제 해결력(계단 가위바위보) — (D) `nl5_story` mode `game`
**교재**: 이기면 2칸 올라가고 지지면 1칸 내려감. 출발부터 4번 이겼고 지금 5번 계단 — 몇 번 졌나? 올라간 칸·내려온 칸 등.
**앱 현황**: `nl5_story` stairs는 "마커가 어느 계단인지 세기"뿐. 규칙을 따라 위치를 계산하는 활동 없음.
**유아용 변형**: 계단 최대 9칸, 이기면 +2·지면 −1 **한 가지 규칙**.
- 레벨 1: **이긴 횟수만**(0번 졌음). `w=1~4`, 위치 `2w ≤9`. 질문: "지금 몇 번째 계단?" 답 `2w`.
- 레벨 2: 이긴 횟수 `w`와 진 횟수 `l`을 주고 위치 묻기. 위치 `2w−l`, **1~9**.
- 레벨 3(P3): 위치(마커 표시)와 이긴 횟수 `w`를 주고 **진 횟수** 묻기: `l = 2w − 위치`.
```js
{ prompt, answer:Number, answerType:'number', widget:'storyCard',
  interaction:'numpad', layout:'stairs', total:9, mark:-1|k-1, emoji:'animal:rabbit',
  game:{ up:2, down:1, wins:3, losses:1, ask:'pos'|'losses' } }
```
- `mark:-1` 이면 마커 없는 계단만 그려진다(코드 확인: 화면·인쇄 모두 `i===mark` 비교). 시작 위치는 땅(계단 왼쪽 앞)이므로 출발 표시는 **그림 위에 "출발" 글자**(교재도 같음) — `storyCard` stairs에 `startLabel` 선택 필드가 있으면 좋다.
- **가위바위보 장면 그림**은 문장 위에 작은 이모지 줄(✌️✋ 대신 이기면 ⬆2, 지면 ⬇1 아이콘 두 개)로 규칙을 보여 준다(실제 가위바위보 사진은 쓰지 않음 — 손 모양 실사는 오히려 규칙 판독에 방해).
**인쇄**: `nlStairsHtml`이 그대로 계단을 그리고 규칙 줄이 `p.prompt` 에 들어간다. 위치 묻는 문항은 `nlAnsBox(lk('째 계단',…))`가 이미 있음. 진 횟수 묻기는 단위가 "번"이므로 `nlAnsBox` 단위를 `p.game.ask==='losses' ? lk('번','times','次') : …`로 분기.
**판정**: 숫자.
**3언어**: ko "이기면 2칸 올라가고, 지면 1칸 내려가요. 3번 이기고 1번 졌어요. 지금 몇 번째 계단일까요?" / en "Win: go up 2. Lose: go down 1. You won 3 times and lost once. Which step now?" / zh "赢了上2级，输了下1级。赢了3次，输了1次。现在在第几级？".
**소품**: 계단(기존 벡터) + 동물(기존). 신규 없음. **스레드**: NL9에 `{id:4,label:{ko:'계단 오르내리기(이긴 횟수만)'}}`,`{id:5,label:{ko:'계단 오르내리기(이기고 지기)'}}`,`{id:6,label:{ko:'계단 오르내리기(진 횟수 찾기)'}}`.

### 2-7. p8 틀린 부분 찾기 — (D) `nl15_logic` mode `wrongSentence`, 위젯 `tapWrong`
**교재**: 문장 속 수 관계가 틀린 부분을 찾아 바르게 고쳐 쓰기(7문장).
**유아용 변형**: **고쳐 쓰기를 "틀린 수를 눌러 → 맞는 수를 고르기"** 로 바꾼다. 문장은 **그림 한 장과 함께** 주어져, 그림이 진실을 말해 준다(글만 있으면 합계가 틀린 건지 개별 수가 틀린 건지 모호).
- 예: 그림에 🍎 3개·🍐 5개. 문장 "사과 3개와 배 5개, 모두 **7**개예요." → 틀린 수 = 7 → 정답 8.
- 오류 유형: `sumWrong`(합계가 틀림), `diffWrong`("민수가 4개 더 많아요" 실제 차는 3 등), `partWrong`(부분 수가 그림과 다름). 한 문장에 틀린 곳은 **정확히 하나**.
```js
{ prompt, answer:Number /*=맞는 수*/, answerType:'number', widget:'tapWrong',
  scene:{ items:[ {e:'🍎',n:3}, {e:'🍐',n:5} ] },              // 그림이 진실
  tokens:[ {t:'사과 '},{n:3},{t:'개와 배 '},{n:5},{t:'개, 모두 '},{n:7,wrong:true},{t:'개예요.'} ],
  wrongIdx:5, choices:[6,8,9] }
```
**위젯 `tapWrong`**: 위에 장면 그림(각 종류가 줄로), 아래에 문장 토큰. **수 토큰은 탭 가능**(점선 밑줄). **1단계**: 틀린 수 토큰을 탭 — 맞으면 그 수가 붉게 표시되고 "고쳐요"가 뜬다, 아니면 흔들림(2번 틀리면 정답 토큰이 깜빡임). **2단계**: 보기 3개 중 맞는 수를 탭 → 정답이면 문장의 수가 고쳐져 초록. `onAnswer(맞는 수)`.
**인쇄**: `nlTapWrongHtml(p)` — 장면 + 문장(수에 밑줄) + "틀린 수에 ○표 하고 바르게 고쳐 써요" + 답칸 하나. 정답지 `7 → 8`.
**판정**: 맞는 수 숫자 일치(탭 단계는 위젯 내부 검증).
**3언어**: ko "그림과 다른 곳을 찾아요! 틀린 수를 누르고 바르게 고쳐요" / en "Find what doesn't match the picture! Tap the wrong number and fix it" / zh "找出和图不一样的地方！点一下错的数，再改正". `NL_PRINT_WORDS`: ko `['틀린 수를 누르고','틀린 수에 ○표 하고']`, en `['Tap the wrong number and','Circle the wrong number and']`, zh `['点一下错的数','圈出错的数']`.
**소품**: 기존 `NM_OBJECTS`(사과·바나나·딸기·쿠키…) — 신규 없음.

### 2-8. p9 문장제 만들기 — (D) 식 고르기 + 창작은 E
**교재**: 문제에 맞는 식 쓰기, **식에 맞는 문제 만들기**(열린 창작).
**처리**
- **식 쓰기 → `eqpick`**(p3의 `eqChoice`): 문제 문장을 주고 식 3개 중 고르기. 식은 `3 + □ + □ = …`식 빈칸 쓰기 대신 **완성된 식**(`3 + 2 + 2 = 7` 같은 것)을 고르게 함.
- **식에 맞는 문제 만들기 = (E) 앱 입력으로 채점 불가.** 대체: ① 앱에서는 **식 → 문장 고르기**(`eqChoice` `stem.kind:'eq'`, 보기가 문장 3개) 로 "식과 이야기의 연결"만 확인. ② **인쇄 학습지에는 '내 문제 만들기' 빈 줄 + `선생님 확인 ☐`** 를 둔다(채점 안 함, 정답지엔 "열린 답"). 이를 위해 문항 객체에 `openEnded:true` 플래그를 두고 **앱 스레드에서는 생성하지 않고 인쇄 전용 생성기에서만** 만든다.
- 수 ≤9, 식 항 2~3개.
**problem 스키마(인쇄 전용 열린 문항)**: `{ prompt, answer:null, answerType:'open', widget:null, tex:'2 + 3 + 4 = 9', openEnded:true }` — `widget`이 없으므로 `nlVisualHtml`이 빈 문자열을 돌려주고 `tex` 식과 빈 줄만 찍힌다(기존 인쇄 규칙과 맞음).
**3언어**: ko "식에 어울리는 이야기를 골라요" / en "Pick the story that fits the equation" / zh "选出和算式相配的故事".

### 2-9. p10 문제 해결력(8×4 숫자판) — (D) `nl10_data` mode `digits`, 위젯 `digitBoard`
**교재**: 8×4 숫자판(0~9)에서 좋아하는 숫자별 인원을 표로 세고, 최다·최소·차·합을 구한다(5문항).
**앱 현황**: `nl1_count` main에 **숫자 흩어놓고 지정 숫자만 세기**(`digits`, `tapCount` + `'num:7'` 토큰)가 이미 있다 — "한 숫자 개수 세기"는 **(A) 이미 있음**. 없는 것은 **여러 숫자를 표로 집계하고 비교**하는 부분.
**유아용 변형**: **4×5 판(20칸), 숫자 3종(연습) / 4종(본)**, 종류별 개수 1~7(합 20).
- 질문 유형: `most`(가장 많이 나온 숫자는? — **숫자 칩 고르기**), `least`(가장 적게), `diff`(가장 많은 수와 가장 적은 수의 차 — 숫자 칩), `count`(숫자 k는 몇 번? — 기존 `tapCount`로 충분하니 쓰지 않음).
- 동점은 만들지 않는다(`most`·`least`가 유일).
```js
{ prompt, answer:Number, answerType:'number', widget:'digitBoard',
  grid:[[1,3,2,1,3],[2,1,1,3,2],…], kinds:[1,2,3],            // 판 4×5
  ask:'most'|'least'|'diff', choices:[1,2,3] }
```
**위젯 `digitBoard`**: 판의 숫자 칸을 탭하면 그 칸이 흐려지고 **위쪽 집계표의 해당 숫자 칸이 1 올라간다**(한 칸씩 탤리). 다 세면 질문 칩(보기 3개)이 나타난다. 집계표가 곧 "표 채우기" 활동 — 교재 1번(표 완성)을 **자동 집계 + 아이가 한 칸씩 누르며 센다**로 바꾼 것.
**인쇄**: `nlDigitBoardHtml(p)` — 판 + 빈 집계표 `숫자 | 1 | 2 | 3 / 사람 수 | ▢ ▢ ▢` + 답칸. 정답지에 집계값도 함께(`1:6 2:7 3:7 → …`).
**판정**: 숫자 하나.
**3언어**: ko "숫자판에서 가장 많이 나온 숫자는 무엇일까요? 눌러서 세어 봐요" / en "Which number shows up the most on the board? Tap to count" / zh "数字板上出现最多的是哪个数？点一点数一数".
**소품**: 없음.

### 2-10. p12 과녁 맞히기 — (D) `nl15_logic` mode `dart`, 위젯 `dartTarget`
**교재**: 3점·2점·1점 세 원 과녁. 화살 4발, 결과에서 과녁 점수 합·㉠·㉡·㉠+㉡ 값(5문항).
**유아용 변형(대폭 단순화)**: 과녁 한 장 위에 **화살이 박힌 위치를 보이고** 점수를 더한다.
- 레벨 1: 화살 2~3발이 박혀 있고 **합 구하기**(≤9, 예: 3+2+1).
- 레벨 2: 화살 3발 중 **한 발이 구름(☁)에 가려져 있고 전체 합이 주어짐** → 가려진 화살의 점수 구하기(≤3, 보기 3개).
- 레벨 3(P3): 던진 횟수와 합이 주어지고 "3점을 몇 번 맞혔나" — 교재의 ㉠㉡ 추론. **P3, 지나치게 추상적이라 뒤로 미룸.**
```js
{ prompt, answer:Number, answerType:'number', widget:'dartTarget',
  rings:[3,2,1],                                     // 바깥 1점 → 안쪽 3점
  hits:[ {ring:3,ang:40,r:0.15}, {ring:2,ang:200,r:0.5}, {ring:1,ang:120,r:0.85} ],  // ring=null → 가려진 화살
  ask:'sum'|'missing', total:7, choices:[1,2,3] }
```
**위젯 `dartTarget`**: 과녁 SVG(바깥 → 안쪽 3겹, 각 띠에 점수 숫자), 화살이 박힌 곳에 **핀(화살 머리)**. `ask:'sum'`이면 합 보기 3개, `'missing'`이면 가려진 화살 자리를 탭할 수 있는 3개 띠 중 고르기(점수 보기를 띠에서 직접 탭 — 과녁 자체가 보기). 정답이면 핀이 반짝이고 합 식 `3 + 2 + 1 = 6`이 아래에 나타남.
**인쇄**: `nlDartHtml(p)` — 과녁 SVG(핀 포함) + 답칸. 정답지 숫자(합 식 보조).
**판정**: 숫자(또는 띠 점수).
**3언어**: ko "화살이 박힌 곳의 점수를 모두 더해요" / en "Add up the points where the arrows landed" / zh "把箭射中的分数加起来".
**소품(신규)**: **과녁**(3겹 동심원 양궁/다트 과녁 — 숫자 글자 없는 실사 PNG, 앱이 점수 얹음) + **화살 핀**(작은 화살 한 개, 방향 하나). 

### 2-11. p7 확인학습 — (B) 신규 없음
| 교재 | 대응 |
|---|---|
| ① 구슬 합(재민 2개, 형은 4개 더 많음 → 모두?) | `compare`(`storyCard` numpad, 답=합) — 이야기에 "모두 몇 개?"를 묻는 변형 |
| ② 색종이 7장 나누는 방법(다슬이가 더 많게, 한 장 이상) | G1-14 `splitAll` `cmp:'more'` (n=7 → 3가지) |
| ③ 3+어떤 수=8 | p3 `unknown` `add`(`□ + 3 = 8` → 5) |
| ④ 3계단씩 3번 오르고 4계단씩 내려옴 | p6 `game` 변형 — **규칙 대신 단계별 화살표**(+3,+3,+3,−4)로 `arrowChain`(G1-14) 재사용도 가능 |
| ⑤ 연필+지우개 합 9, 지우개가 3 더 많음(각각 몇 개?) | **`sumdiff`**(아래) |
| ⑥ ◇=♡4개 카드 교환 | **`exchange`**(아래, P3) |

**`sumdiff` (이야기형 합·차 → 두 수)**: "연필과 지우개가 모두 9개예요. 지우개가 연필보다 3개 더 많아요. 각각 몇 개일까요?" → `[연필 3, 지우개 6]`. G1-14 p11 `shapeEq`의 합·차 구조와 같은 수학이므로 **`shapeEq` 위젯을 재사용**하되 기호 자리에 물건 그림(연필 대신 `NM_OBJECTS`의 쿠키·딸기 등)을 쓰는 것이 가장 가볍다. 문장형으로 읽고 답하려면 `storySolve`(아래)를 쓴다.
**`storySolve`(신규, 선택)**: `storyCard`의 numpad 변형으로 **빈 칸이 둘 이상**(`blanks:[{label},{label}]`)이고 내부에 이미 있는 `multiPadState`를 쓴다. `compare`의 "각각 몇 개" 질문과 p2 `fill`의 대안(숫자패드 입력)에도 쓸 수 있다. P3.
```js
{ prompt, answer:[3,6], answerType:'array', widget:'storySolve', blanks:[{label:'연필'},{label:'지우개'}],
  chars:['🍪','🍓'], story:{…} }
```

**`exchange`(P3, 카드 교환 게임)**: 규칙 상자 "⭐ 1개 = 🍬 3개". 두 친구의 카드가 각각 `⭐ ×a` / `⭐ ×b + 🍬 ×c`로 놓여 있고 "누가 사탕으로 몇 개 더 가졌나"를 묻는다(`|3a − (3b + c)|`, 모든 수 ≤9).
```js
{ prompt, answer:Number, widget:'exchangeBoard', rule:{ from:'⭐', to:'🍬', n:3 },
  rows:[ {who:'animal:rabbit',cards:[['⭐',2]]}, {who:'animal:turtle',cards:[['⭐',1],['🍬',2]]} ], choices:[1,2,3] }
```
교환 비율 개념 때문에 **P3**, 다른 활동에 비해 가치가 낮다. 소품은 기존 별·사탕 토큰으로 충분.

### 2-12. p13 확인학습 — (B)
| 교재 | 대응 |
|---|---|
| ① 초콜릿 9개, 가족이 2개씩 먹었더니 1개 남음 → 가족 수 | **`groupRing`(P3, 보류 권고)** — "8개를 2개씩 묶으면 몇 묶음?" 형태로, 아이가 8개 줄에서 2개씩 동그라미를 쳐서 묶음 수를 센다. 덧셈·뺄셈 호에 **나눗셈 선행**이라 유아용에서는 **제외해도 무방**. 구현한다면 `tapMake`처럼 물건 줄에 탭으로 묶음 표시 후 개수 보기 선택. |
| ② 과일 흩어진 그림에서 가장 많은 것과 가장 적은 것의 개수 차 | **`nl10_data` mode `sort3` (3종 분류)** — `sortBasket`을 **바구니 3개**로 확장. 칩을 종류별 바구니로 옮겨 세고, `ask:'diff'|'most'|'least'`. 과일은 `NM_OBJECTS`의 사과·바나나·딸기. 종류별 개수 2~6, 총 ≤12, 동점 없음. |
| ③ 4를 더해야 하는데 잘못 빼 1이 됨 → 바른 값 | p4 `wrong` |
| ④ 파랑 5·빨강 5 구슬에서 6개 꺼내는 방법 | G1-14 `splitAll` `ordered:true,caps:[5,5],minPart:0` (5가지) |
| ⑤ 배구공 1개, 야구공은 2개 더 많고, 축구공은 야구공보다 4개 더 많음 → 각각? | `compare` **두 단계** — 구기 종류를 **농구공·축구공 + 기존 토큰 하나**로(교재의 야구공·배구공 소품은 만들지 않고 `NM_OBJECTS`의 축구공·농구공·공 종류로 대체), 값 ≤9: 1, 1+2=3, 3+4=7. 답은 둘 이상이므로 `storySolve`. |
| ⑥ 색종이 분배(3+4+1=8장, 동생이 2장 더 많이) | `sumdiff` (8 = 3 + 5) |

**`sort3` 상세**: `sortBasket` 확장 — `kinds:[{emoji,type:'A'},{emoji,type:'B'},{emoji,type:'C'}]`, 바구니 3개 레이아웃(좁은 화면은 가로 스크롤 금지 → 칩 크기를 줄여 3열). `askMode:'diff'`(가장 많은−가장 적은) 또는 `'most'`(가장 많은 바구니 탭). 인쇄는 `nlBasketsHtml`을 3개 바구니로 확장.
```js
{ prompt, answer:Number, widget:'sortBasket', askMode:'diff'|'most'|'least',
  items:[{e,type:'A'|'B'|'C'}…], baskets:[{emoji},{emoji},{emoji}] }
```
(`basketA/basketB` 기존 필드와 호환: 3종일 때만 `baskets` 배열을 우선.)

## 3. 스레드·편성 제안 (참고)
| 스레드 | 새 레벨 | 모드 |
|---|---|---|
| NL13 (이야기 셈과 분류, N-15) | 4 이야기에 수 채우기 · 5 숨은 수 상자(더하기) · 6 숨은 수 상자(빼기) · 7 문장↔식 고르기 · 8 나이·몇 개 더 많은지 · 9 틀린 수 고치기 · 10 과녁 · 11 잘못 계산한 수(P3) · 12 합·차 이야기(P3) | `fill` `unknown` `eqpick` `compare` `wrongSentence` `dart` `wrong` `sumdiff` |
| NL9 (줄서기와 계단, N-05) | 4 계단 오르내리기(이긴 횟수만) · 5 이기고 지기 · 6 진 횟수 찾기(P3) | `game` |
| NL15 (분류하고 세기, N-10) | 4 숫자판 집계(가장 많은 수) · 5 숫자판 집계(차) · 6 세 가지 분류 | `digits` `sort3` |

N-15 유닛 정의의 `practice`/`lab`은 현재 `story`/`sort` 두 모드. **어떤 신규 모드를 유닛 lab으로 올릴지**는 별도 결정(이 명세는 스레드 레벨까지).
**문장제 읽기 부담 대응**: 모든 신규 문장제 위젯에 **🔊 버튼**(이미 `storyCard`가 `NM_SAY`로 제공)을 넣고, 문장은 한 번에 **2~3줄**(약 40자) 이내로 쓴다. 인쇄 학습지는 소리가 없으므로 문장 위에 **그림 한 줄**을 반드시 둔다(`scene`/`chars`).

## 4. 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

**새 위젯 (7 + 선택 2)**
| 위젯 | 모드 | 핵심 |
|---|---|---|
| `storyFill` | `fill` | 이야기 빈 칸에 주머니 카드 채우기(조건 검사) |
| `mysteryBox` | `unknown`, `wrong` | 상자 속 숨은 수 + 보기, 2단계 변형 |
| `eqChoice` | `eqpick` | 문장↔식 보기 3장 탭(p3·p9 공용) |
| `tapWrong` | `wrongSentence` | 장면+문장, 틀린 수 탭 → 맞는 수 고르기 |
| `digitBoard` | `digits` | 숫자판 탭 집계 → 질문 칩 |
| `dartTarget` | `dart` | 과녁 SVG 점수 합·가려진 화살 |
| `exchangeBoard`(P3) | `exchange` | 교환 비율 카드 줄 |
| `storySolve`(선택, P3) | `compare`·`sumdiff` 다중 답 | `multiPadState` 재사용 숫자패드 |
| `groupRing`(P3, 보류 권고) | — | 물건 줄 묶음 표시 |

**기존 위젯 수정**: `sortBasket`(바구니 3개·`askMode:'diff'|'most'|'least'`) · `storyCard`(`labels`, 계단 `startLabel` — 선택). **재사용**: `storyCard`(나이·계단), `shapeEq`(G1-14, 합·차).

**새 소품(실사 PNG)**: **주머니**(복주머니/천 주머니) · **과녁**(3겹, 글자 없음) · **화살 핀**. 상자(`mysteryBox`)는 **상자 뚜껑 열림 애니메이션**이 필요해 벡터(SVG)로 만들고 실사 PNG는 선택(원하면 "골판지 상자 닫힌 것 / 열린 것" 두 장). 기존 `NM_OBJECTS` 16종·동물 10종은 이 호의 거의 모든 장면에 재사용(사과·바나나·딸기·쿠키·축구공·농구공·별·사탕, 토끼·곰·거북이 …). **야구공·배구공·연필·지우개·초콜릿은 만들지 않고 기존 물건으로 대체**.

**새 인쇄 표현(`exam.js`)**: `nlStoryFillHtml` · `nlMysteryBoxHtml` · `nlEqChoiceHtml` · `nlTapWrongHtml` · `nlDigitBoardHtml` · `nlDartHtml`(+ `nlExchangeHtml`) 6~7개와 `nlVisualHtml` 분기, **`nlBasketsHtml` 3바구니 확장**, `nlStairsHtml` 단위 분기(진 횟수), `nlAnswerLabel`에 `eqChoice`(보기 번호→"②")·`storyFill`(배열)·`mysteryBox`(배열)·`tapWrong`("7 → 8") 분기, `NL_PRINT_WORDS`에 "카드를 콕! 눌러요"·"틀린 수를 누르고" 계열 ko/en/zh 각 2줄, **열린 문항**(`openEnded`)은 `widget` 없이 식 + 교사 확인 빈 줄.

**위험·확인 필요**
1. **배열 답 인쇄**(`storyFill`·`mysteryBox` 2단계·`storySolve`): NL 인쇄 경로에서 배열 답이 어떻게 찍히는지 확인하지 못했다(`exam.js:5328` 근처에 `Array.isArray(p.answer)` 가드). `nlAnswerLabel` 분기로 문자열을 명시해 돌려줄 것.
2. **`storyFill` 해 유일성**은 생성기가 카드 순열 전수 검사로 보장해야 한다(보장 안 되면 조건 판정으로 바꿔야 함).
3. **열린 문항(`openEnded`)** 은 현재 인쇄 파이프라인이 `p.answer` 숫자를 전제로 하는 곳(`5328` 가드 등)이 있어 `answer:null`이 안전한지 확인이 필요하다 — 가장 안전한 방법은 앱 스레드·정답지 생성에서 완전히 분리된 **인쇄 전용 보조 블록**으로 두는 것.
4. `groupRing`(p13 ①)은 나눗셈 선행이라 덧뺄셈 호의 유아 이식에서는 **의도적으로 보류**를 권한다.
5. 문장제는 읽기 능력 편차가 크므로 **🔊 필수** + 그림 우선. 영·중 문장도 같은 장면에서 같은 수·같은 구조가 되도록 번역 틀을 템플릿에 함께 둔다(`story:{ko,en,zh}`).
