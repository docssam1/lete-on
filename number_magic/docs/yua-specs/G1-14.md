# G1-14호 (더하기와 빼기 Ⅱ — 규칙·약속·모양수) → 유아 단계 이식 명세

작성 근거: `docs/g1-inventory/G1-14.md` + PDF 2~13쪽 직접 렌더링 확인(12쪽 막대 표기는 확대해서 모양 확인) + 코드 직접 확인.
교재 문제는 그대로 옮기지 않고 **수 범위 9 이내·말 쉽게**로 변형했다.

**이 호의 성격**: "규칙 찾기 호"다. 앱에서 가장 가까운 것은 `nl8_machine`(수 기계: 입력→규칙→출력, N-08), `nl2_seq`(수열 빈칸, N-02),
`nl14_pattern` arrow(±1 수열 빈칸, N-14), `nl9_chain` pyramid(이웃 합 피라미드, N-09), `nl4_bond`(가르기, N-06).
기존 것이 교재의 **쉬운 끝**을 이미 덮고, 교재의 나머지는 **같은 위젯의 확장 또는 신규 위젯**이다.

## 0. 공통 사실 (G1-13.md §0과 같다 — 요점만)
- 판정: 위젯이 `onAnswer(값)`, 호스트가 `+val === answer`(배열이면 원소별) — `main.js:5332·4725`. 조건 판정 위젯은 만족 시 `problem.answer`를 내보냄.
- 새 위젯은 **생성기가 `choices`·좌표를 problem에 싣는다**(위젯 내 `Math.random()` 지양).
- 인쇄는 `nlVisualHtml` 분기 + `nlXxxHtml` + `nlAnswerLabel` + `NL_PRINT_WORDS` 필요. 모르는 위젯은 그림 없이 물음 줄만 나온다.
- 스레드 레벨은 뒤(`id:4~`)에 덧붙임(편성이 `NL16@2`식 번호 참조).
- 현재 레벨 수: NL2·NL4·NL5·NL9·NL11·NL14·NL16 모두 3.
- **`seqFill` 주의(코드 확인)**: `const blank=problem.blank||1;` — 빈 칸 index가 **0이면 1로 바뀐다.** 생성기가 `R(rng,1,len-2)`처럼 0을 피하고 있어 지금은 안 드러났다. 이 호에서 빈 칸이 둘 이상이거나 첫 칸을 비울 수 있게 하려면 `problem.blank??1`로 고칠 것.

## 2. 활동별 상세 명세

### 2-1. p2 규칙 찾기(표) — (C) `nl14_pattern` mode `table`
**교재**: 3열 표(셋째 열 = 앞 두 열의 합 또는 차), 4열 표(넷째 열 = 앞 세 열 관계). 빈 칸 채우기.
**앱 현황**: `nl8_machine` guess가 "예시 둘 보고 규칙 추리"이지만 입력 하나·출력 하나 구조(+n/−n)뿐. 두 입력 표 없음.
**규칙(유아용)**
| 레벨 | 열 | 규칙 | 값 범위 |
|---|---|---|---|
| 1 | 3 | 셋째 = 첫째 + 둘째 | 첫째·둘째 1~5, 셋째 ≤9 |
| 2 | 3 | 셋째 = 첫째 − 둘째 (첫째 > 둘째) | 첫째 ≤9 |
| 3 | 4 | 넷째 = 첫째 + 둘째 + 셋째 | 각 1~3, 넷째 ≤9 |
- 표는 **예시 3줄(완성) + 묻는 1줄(빈 칸 하나, 마지막 열)**. 교재는 줄 수가 4~5지만 아이가 규칙 추정에 필요한 예시는 3줄이면 충분.
- **규칙이 하나로만 설명되는지 검사**: 예시 3줄이 `+`와 `−`(또는 다른 후보)를 동시에 만족하지 않게 생성(예: `2,2,4`는 합과 `2×2` 둘 다 가능 → 곱은 후보에 없으므로 무관, `+`/`−`만 구분).
- 레벨 1~2에서는 프롬프트에 "셋째 칸은 앞의 두 칸과 관계가 있어요"를 적고(교재와 같이), 레벨 3은 적지 않는다.

**problem 스키마**
```js
{ prompt, answer:Number, answerType:'number', widget:'ruleTable',
  cols:3, rows:[[3,2,5],[4,4,8],[5,1,6],[2,7,null]],   // 마지막 줄의 null 이 질문
  askRow:3, askCol:2, rule:'a+b',                      // rule 은 정답지·디버그용(화면에 안 보임)
  choices:[7,8,9] }
```
**위젯 `ruleTable`**: 표(칸이 큼직한 격자). 빈 칸은 `?`. 아래 숫자 보기 3개(≤9) 탭. 정답이면 `?`가 숫자로 바뀌고 해당 줄의 세 칸에 연결선 애니메이션(앞 두 칸→셋째 칸)으로 규칙을 보여 준다.
**인쇄**: `nlRuleTableHtml(p)` — 격자 표 + 빈 칸 네모. 정답지 숫자 하나.
**판정**: 숫자 일치.
**3언어**: ko "표의 규칙을 찾아 빈 칸에 올 수를 골라요" / en "Find the rule in the table. Pick the number for the blank" / zh "找出表里的规律，选出空格里的数"(기존 `NL_PRINT_WORDS` 틀 사용 → 추가 불필요).
**소품**: 없음.

### 2-2. p3 숫자 기차 — (C) `nl14_pattern` mode `train`
**교재**: 기차 칸 5개(숫자)와 칸 사이 위의 원(숫자). 규칙을 찾아 빈 네모·원 채우기. 교재 확인 결과 **원 = 오른쪽 칸 − 왼쪽 칸**(1,2,3,4 → 원 1,1,1 / 1,2,□,7,11 → 원 1,□,3,4 로 검산됨).
**유아용 변형**: 칸 4~5개, **칸 값 0~9**(교재의 11은 범위 밖이라 쓰지 않음), 빈 칸은 **칸 또는 원 하나**.
- 레벨 1: 차가 일정(1,1,1 / 2,2,2) — 규칙이 보이기 쉬움. 프롬프트에 규칙 설명("동그라미는 이웃한 두 칸의 차예요").
- 레벨 2: 차가 줄마다 다름(1,2,3 등), 규칙 설명 생략(교재처럼 찾아내기). 단, **완성된 원이 최소 2개** 보이게 해서 규칙 추정 가능.
**problem 스키마**
```js
{ prompt, answer:Number, answerType:'number', widget:'numberTrain',
  cars:[1,2,null,7], links:[1,null,3],          // links[i] = cars[i+1]-cars[i]
  askKind:'car'|'link', askIndex:2, choices:[3,4,5],
  showRule:true|false }
```
**위젯 `numberTrain`**: SVG 기관차 + 객차 4~5량, 각 칸 위로 선이 올라가 **두 이웃 칸을 잇는 동그라미**. 빈 곳은 `?`. 보기 3개 탭. 정답이면 `?`에 숫자가 들어가고, 이어서 동그라미→두 칸 연결선을 한 번 깜빡여 규칙을 보여 준다.
**인쇄**: `nlTrainHtml(p)` — 같은 SVG(칸 번호는 박스, 빈 칸은 빈 박스). 정답지 숫자 하나.
**판정**: 숫자 일치.
**3언어**: ko "기차 칸의 수와 위의 동그라미는 규칙이 있어요. 빈 곳에 올 수를 골라요" / en "The train cars and the circles above follow a rule. Pick the missing number" / zh "火车车厢上的数和上面的圆圈有规律。选出缺的数".
**소품**: **기차**(기관차 + 객차) — 장난감 기차 실사 PNG 또는 벡터 SVG(교재의 선화풍을 따라 그리지 않고 단순 도형으로). 기존 NM_OBJECTS에 없음 → 신규.

### 2-3. p4 약속(◆, ＊ 규칙 찾기) — (D) `nl8_machine` mode `promise`, hidden 레벨
**교재**: 기호 ◆의 규칙을 예시(2◆1=2, 3◆2=2, 4◆2=4 …)에서 찾아(= (앞−뒤)+(앞−뒤)) 새 식을 계산. ＊도 같은 방식.
**앱 현황**: `nl8_machine` guess(`+n/−n` 하나 숨김)가 가장 가깝지만 **입력이 둘인 연산은 없다.**
**유아용 변형**: 연산 기호 하나를 두고 **규칙 후보를 3종으로 제한**, 예시 3줄을 보여 준 뒤 새 식의 값을 묻는다.
| 규칙 id | 식(앞 수 a, 뒤 수 b) | 조건 |
|---|---|---|
| `add1` | a + b + 1 | 결과 ≤9 |
| `dbl` | (a − b) + (a − b) = 두 번 더한 차 | a>b, 결과 ≤9 |
| `back2` | a − b − b | a ≥ 2b |
- **예시 3줄이 후보 규칙 중 하나에만 맞도록**(다른 후보와 값이 겹치지 않게) 생성 — 추리가 유일해야 한다. 생성기에서 후보 3개를 모두 계산해 값이 서로 다른 `(a,b)`만 예시·질문으로 채택.
- 기호는 ◆·◎·＊ 중 하나를 매번 바꿔 쓰되 **원본 도형 글리프**(교재 그림을 따라 그리지 않은 단순 도형).
- 레벨 3(P3): 중간 칸 묻기 `5◆□=4` → `askPos:'b'`.
**problem 스키마**
```js
{ prompt, answer:Number, answerType:'number', widget:'promiseBox',
  sym:'◆', examples:[[2,1,2],[3,2,2],[4,2,4]],     // [앞,뒤,결과]
  target:[5,3], ruleShown:null,                    // null=숨김(추리), 'a+b+1'=공개(p10 레벨)
  askPos:'result'|'b', rule:'dbl', choices:[3,4,5] }
```
**위젯 `promiseBox`**: 위에 "약속" 상자(규칙 숨김이면 `?`), 예시 줄 3개를 세로로 나열, 마지막 줄이 묻는 줄(`5 ◆ 3 = ?`). 보기 3개(숫자 칩) 탭. 오답이면 예시 줄 중 하나가 깜빡이며 "이 줄을 다시 봐요" 힌트(최대 1회).
**인쇄**: `nlPromiseHtml(p)` — 약속 상자 + 예시 + 묻는 식(답은 빈 네모). 규칙 공개 레벨이면 규칙 문장을 상자에 인쇄. 정답지는 숫자 + 규칙 한 줄("규칙: 앞−뒤를 두 번 더하기").
**판정**: 숫자 일치.
**3언어**: ko "◆는 비밀 규칙이에요. 예시를 보고 규칙을 찾아서 마지막 식을 계산해요" / en "◆ has a secret rule. Look at the examples to find it, then solve the last one" / zh "◆有个秘密规则。看例子找出规则，再算最后一题". "약속"은 ko `약속`, en `secret rule`, zh `约定`(기존 `nl8_machine`의 'secret rule' 표기와 맞춤).
**소품**: 없음.

### 2-4. p10 약속(규칙이 보임) — (B) p4의 `promise` 에 `ruleShown` 레벨
**교재**: ◎ 가◎나 = 가+나+1, ＊ 가＊나 = 가−나−나. 규칙이 문장으로 주어지고 계산만.
**처리**: 같은 모드·위젯, `ruleShown:'a+b+1'`(상자에 식 표시), `examples:[]`(예시 없음). 프롬프트는 "앞 수와 뒤 수를 이 규칙대로 계산해요". 숫자 칩 3개 선택(또는 숫자패드). 규칙 id는 위 3종 + `a+b−1`·`a−b` 2종을 추가해 이 레벨에서만 쓴다.
스레드: NL11에 `{id:4,label:{ko:'두 수 약속(규칙 보임)'},params:{mode:'promise',level:'practice',shown:true}}`, `{id:5,label:{ko:'두 수 약속(규칙 찾기)'},params:{mode:'promise',level:'main'}}`. (레벨 순서: 규칙 보임이 먼저.)

### 2-5. p5 모양수 — (C) `nl14_pattern` mode `shapenum`
**교재**: 같은 모양=같은 수, 다른 모양=다른 수. 삼각형·원 식 3개씩. 빈 네모(보통 마지막)를 구함.
**유아용 변형**: 모양 대신 **같은 그림 = 같은 수**(사과·바나나 같은 기존 NM_OBJECTS 물건)로 시작하고, 레벨이 오르면 도형(▲●■★)으로. 식은 2~3줄, 값 1~9, **다른 기호는 다른 값**.
- 레벨 1(물건): `🍎 = 3`, `🍎 + 🍌 = 7`, `🍌 = ?` (한 칸 대입).
- 레벨 2(도형): `▲ + 5 = 8` 대신 `▲ + ● = 7`, `● = 3`, `▲ = ?` 등 대입 한 번 이상.
- 모든 식의 결과·값 ≤9, **풀이가 한 줄씩 대입으로 유일하게 풀리는 판**만.
**problem 스키마**
```js
{ prompt, answer:Number|Array, answerType:'number'|'array', widget:'shapeEq',
  syms:{ X:'🍎', Y:'🍌' },            // NM_OBJECTS 토큰 또는 도형 글리프('▲','●','■','★')
  eqs:[ {l:['X','+','Y'], r:7}, {l:['X'], r:3} ],   // l 의 원소: 기호 key | 수 | '+' | '-' ; r: 수 | 기호 key
  ask:['Y'],                           // 구할 기호 목록(1개 또는 2개)
  choices:[[3,4,5]] }                  // 묻는 기호마다 보기 3개(배열의 배열)
```
**위젯 `shapeEq`**: 식을 세로로 나열. 기호는 그림(또는 도형)으로, 구할 기호 자리는 `?`. 보기 3개 탭(구할 기호가 둘이면 차례로). 오답이면 해당 식이 깜빡임.
**인쇄**: `nlShapeEqHtml(p)` — 식 줄 + 구할 기호의 빈 네모. 기호는 `nlObjHtml`로(물건) 또는 SVG 도형. 정답지 숫자(들).
**판정**: 숫자(또는 배열) 일치. 해가 유일하므로 단순 비교.
**3언어**: ko "같은 그림은 같은 수예요. 빈 칸에 알맞은 수를 골라요" / en "Same picture, same number. Pick the number for the blank" / zh "相同的图案代表相同的数。选出空格里的数".
**소품**: 기존 `NM_OBJECTS`(사과·바나나·딸기·쿠키·별…)로 충분. 신규 없음. 도형은 벡터.

### 2-6. p11 수 넣기 — (B) `shapenum` 의 합·차 레벨
**교재**: `○ + □ = 합`, `○ − □ = 차` 두 식으로 ○, □ 두 수를 동시에 구함. 8세트(합·차: 5/1, 8/4, 9/7 …).
**처리**: 같은 위젯, `ask:['X','Y']`, `eqs:[{l:['X','+','Y'],r:5},{l:['X','-','Y'],r:1}]`. 정답 `[3,2]`(배열). 합 ≤9·차 ≥1, **합과 차의 홀짝이 같아야** 정수해(둘이 같은 홀짝) → 생성기가 `(합+차)/2`가 정수가 되는 조합만 채택. 레벨: 합 5~9. 구하는 두 값이 서로 달라야 함(다른 기호=다른 수).
스레드: NL16에 `{id:4,label:{ko:'모양수(두 수 구하기)'},params:{mode:'shapenum',level:'main',pair:true}}`.
**배열 답 인쇄 확인 필요**(G1-13.md §4 위험 1과 동일): `nlAnswerLabel`에 `shapeEq`가 배열이면 `"3, 2"`로 돌려주는 분기 추가.

### 2-7. p6 가르기(모든 방법·가짓수) — (C) `nl4_bond` mode `splitAll`
**교재**: 수(5·7·8·9)를 두 수로 가르는 방법을 모두 쓰고 **가짓수**를 센다(예시: 6→1·5, 2·4, 3·3, 순서는 무시).
**앱 현황**: `nl4_bond` split/join은 "한 부분을 알면 나머지"(넘버본드 1회). 모든 방법을 찾는 활동 없음.
**유아용 변형**: 수 4~9, 한 부분 1 이상(0 제외), **순서 무시**(예시 한 줄을 화면에 보여 주어 규칙을 알려 줌 — 교재도 예시로 판단).
- 가짓수 `k = ⌊n/2⌋`: 4→2, 5→2, 6→3, 7→3, 8→4, 9→4.
- 연습: n 4~6, 본: n 7~9.

**problem 스키마**
```js
{ prompt, answer:Number /*=k*/, answerType:'number', widget:'splitList',
  whole:7, example:[1,6], ordered:false, minPart:1, maxPart:null, k:3 }
```
**위젯 `splitList`**: 위에 큰 수 원 `7`, 가운데에 **"찾은 방법" 목록**(처음엔 예시 한 줄만 `7 → 1·6`). 아래 숫자 칩 `1..n-1`. 칩 탭 → 왼쪽 부분이 되고 오른쪽은 자동 `n−왼쪽`으로 채워져 새 줄이 생긴다. **이미 있는 방법과 순서만 다른 것**(예: 6·1)을 고르면 "같은 방법이에요!" 흔들림. "다 찾았어요" 버튼: 찾은 개수 == k 이면 `onAnswer(k)`(초록), 아니면 "더 있어요" 흔들림(힌트로 찾은 개수 표시). 2회 연속 조기 제출은 `onAnswer(-1)`.
**인쇄**: `nlSplitListHtml(p)` — 큰 수 + 예시 줄 + 빈 줄 몇 개(칸 수는 k+1) + "모두 □가지". 정답지 `1·6, 2·5, 3·4 → 3가지`.
**판정**: 모두 찾기(집합 검사) + `onAnswer(k)`.
**변형 모드(P3, 같은 위젯 파라미터)**: 교재 7쪽 "색종이 7장을 두 사람이 나눠(한 장 이상, 다슬이가 더 많게)" → `cmp:'more'`(찾는 쌍을 `a>b`로 제한, 7→(6,1),(5,2),(4,3) 3가지). 교재 G1-15 13쪽 "파랑 5·빨강 5 구슬에서 6개 꺼내기" → `ordered:true, caps:[5,5], minPart:0`(색이 달라 순서가 구별됨, 5가지). 둘 다 파라미터만 다르다.
**3언어**: ko "6을 두 수로 가르는 방법을 모두 찾아요. 순서가 달라도 같은 방법이에요" / en "Find every way to split 6 into two numbers. The same two numbers in a different order count once" / zh "找出把6分成两个数的所有方法。两个数一样只是顺序不同算同一种". 인쇄 변환: ko `['칩을 눌러 방법을 만들어요','빈 줄에 방법을 써요']`, en `['Tap a chip to make a way','Write each way on a line']`, zh `['点一点数字做出一种分法','把每种分法写在横线上']`.
**소품**: 없음(칩·원은 UI).

### 2-9. p8 화살표 규칙 — (C) `nl8_machine` mode `chain`, 위젯 `arrowChain`
**교재**: 실선 화살표 = "3 큰 수", 점선 화살표 = "2 작은 수". 원들을 화살표로 이은 사슬에서 규칙대로 빈 원을 채우거나(앞 두 문항), **규칙의 수 자체를 거꾸로 찾는**다(뒤 두 문항).
**앱 현황**: `nl14_pattern` arrow는 이름만 화살표이고 사실은 ±1 수열 빈칸(`seqFill`). 화살표 종류별 규칙·사슬 구조 없음.

**유아용 변형**: 화살표는 **실선=큰 수(+a), 점선=작은 수(−b)** 2종만. 모든 원 값은 **0~9** 안에서 움직이게 생성(범위 밖이면 재생성).
- 레벨 1: 규칙 보임, 직선 사슬 5원 중 시작 하나, **빈 원 1개** 질문.
- 레벨 2: 규칙 보임, 빈 원 2~3개를 **차례로** 채움(배열 답).
- 레벨 3(P3): **규칙 찾기** — 사슬이 모두 주어지고(교재 8쪽 뒤 두 문항), 실선·점선 규칙(`+a`, `−b`)을 숫자로 구한다. 한 규칙이 사슬에서 **두 번 이상 확인**되도록 화살표 ≥4개.

**problem 스키마(G1-13 p7③ 연쇄 계산과 공용)**
```js
{ prompt, answer:Number|Array, answerType:'number'|'array', widget:'arrowChain',
  layout:'line'|'zigzag'|'snake'|'loop',
  nodes:[7,null,null,null,null],                    // null=빈 원
  arrows:[ {d:-2,style:'dash'}, {d:-2,style:'dash'}, {d:+3,style:'solid'}, {d:+3,style:'solid'} ],
  legend:[ {style:'solid',txt:{ko:'3 큰 수',en:'3 more',zh:'多3'}}, {style:'dash',txt:{ko:'2 작은 수',...}} ] | null,
  hideDelta:false,                                  // true 면 화살표 위 ± 숫자 안 보임(규칙을 legend 로만 알려줌)
  asks:[1,2,3],                                     // 채울 원 인덱스(차례대로)
  askRule:false,                                    // true 면 answer=[a,b] (실선 +a, 점선 −b)
  choices:[[5,6,7],[3,4,5],...] }
```
**위젯 `arrowChain`**: 원을 레이아웃대로 배치하고 화살표를 SVG(실선·점선, 위에 라벨 선택)로. 빈 원은 `?`, **지금 채울 원만 깜빡임**. 보기 3개(원마다 `choices[i]`) 탭 → 정답이면 그 원이 채워지고 다음 원으로. 모두 채우면 배열이면 `onAnswer([...])`. `askRule:true` 이면 규칙 상자(`legend`)의 빈 칸 두 개를 차례로 숫자패드(0~9 칩)로 채운다.
**G1-13 p7③ 용 설정**: `legend:null`, `arrows[i].style:'plain'`, 화살표 위에 숫자 라벨(`+2`, `+1`, `−5` …)이 항상 보임, 시작 원 1개 + 질문 1~2개.
**loop 레이아웃(P3)**: 교재 13쪽 ②의 원형 순환. 5원이 고리를 이루고 마지막 화살표가 처음으로 돌아온다. 한 바퀴 합이 0이어야 하므로 규칙은 `(+2, −3)`·`(+3, −2)` 중 하나이고 `실선 3개 + 점선 2개`(또는 반대)로 5개 화살표를 구성 — 생성기가 고리 일관성을 검증한다.
**인쇄**: `nlArrowChainHtml(p)` — 원(빈 원은 빈 원)과 화살표(`stroke-dasharray`로 점선) + 규칙 상자. 정답지 `4, 6, 9`(배열) 또는 `+3, −2`(규칙 찾기). **`nlAnswerLabel` 에 `arrowChain` 분기 필요.**
**판정**: 배열 비교(값이 규칙대로 결정되므로 유일). 규칙 찾기는 `[a,b]` 순서 고정.
**3언어**: ko "화살표 규칙대로 빈 원을 채워요. 실선은 3 큰 수, 점선은 2 작은 수" / en "Follow the arrow rule to fill the blank circles. Solid = 3 more, dashed = 2 less" / zh "按箭头规则填空圆。实线是多3，虚线是少2". 규칙 찾기: ko "실선과 점선은 각각 몇 큰 수·작은 수일까요?" 
**소품**: 없음.
스레드: NL11 수 기계에 `{id:6,label:{ko:'화살표 사슬'},params:{mode:'chain',level:'practice'}}`, `{id:7,label:{ko:'화살표 규칙 찾기'},params:{mode:'chain',level:'main',askRule:true}}` (id 4·5는 위 약속 모드).

### 2-10. p9 수열 — (B) `nl2_seq` mode `gap` 확장 + `seqFill` 수정
**교재**: ±1·+2 홀짝·−2·점점 커지는 증가폭(1,2,4,□,11,16,22: +1,+2,+3,+4,+5,+6) 등 7줄.
**앱 현황**: `nl2_seq` gap = `up`(+1), `down`(−1), `skip2`(+2) 3종, 빈 칸 **1개**, `seqFill` 위젯. 교재 7줄 중 +1·−1·+2는 **이미 있음(A)**, 나머지가 신규.
**추가할 종류**
| kind | 예 | 범위 |
|---|---|---|
| `down2` | 9,7,5,3,1 | 시작 ≤9 |
| `even` / `odd` | 0,2,4,6,8 / 1,3,5,7,9 | 0~9 |
| `grow` | 0,1,3,6 / 1,2,4,7 / 2,3,5,8 (더하는 수가 1씩 커짐) | 길이 4, 마지막 ≤9 |
| `multiBlank` | 위 어느 종류든 빈 칸 2개(차례로 채움) | 배열 답 |
- **교재의 22·16 같은 두 자리 수는 범위 밖**이라 `grow`는 길이 4(값 ≤9)로 줄인다.
- `up`/`down`/`skip2`의 범위가 현재 1~20이다(유아 9 이내 지침과 다름 — 기존 동작이므로 건드리지 않고, 새 종류만 ≤9).
**problem 스키마(확장)**
```js
{ prompt, answer:Number|Array, widget:'seqFill',
  seq:[1,2,4,7], blank:3,            // 기존 호환(단일)
  blanks:[2,3],                      // 신규: 둘 이상(있으면 blank 무시), answer 는 배열
  kind:'grow', step:null }
```
**`seqFill` 수정 사항(코드 확인한 것)**: ① 빈 칸 index 0 처리(`||1` → `??1`). ② `blanks` 지원: 빈 칸마다 순서대로 보기 3개를 만들고 차례로 채움(배열 답). ③ 보기 만들기가 `step=seq[1]-seq[0]` 한 값으로 이웃 수를 만드는데 `grow`는 간격이 일정하지 않으므로 **`answer±1`, `answer±2`를 후보로** 하고 `step` 후보는 일정 간격 종류에서만.
**인쇄**: `nlSeqStripHtml`이 `blank`(단일)만 처리 → **`blanks` 배열 지원**(여러 빈 칸을 빈 칸 네모로). 정답지 배열.
**스레드**: NL4에 `{id:4,label:{ko:'수열 빈칸(2씩 거꾸로·짝수·홀수)'},params:{mode:'gap',level:'main',kinds:['down2','even','odd']}}`, `{id:5,label:{ko:'수열 빈칸(점점 커지는 수)'},params:{mode:'gap',level:'main',kinds:['grow']}}`, `{id:6,label:{ko:'수열 빈칸 2개'},params:{mode:'gap',level:'main',blanks:2}}`.
**3언어**: grow ko "더하는 수가 1씩 커져요! 빈 칸에 올 수를 골라요" / en "The number you add grows by 1 each time! Pick the number for the blank" / zh "每次加的数多1！选出空格里的数". 짝/홀: "짝수만 / 홀수만 이어 세요".

### 2-11. p12 새로운 수의 표기(막대) — (D) `nl_tallybuild` mode `rod` (P3)
**교재 확인(PDF 12쪽 확대)**: 1~9를 새 기호로 표기 — **1~5 = 네모 안에 (n−1)개 막대, 6~9 = 네모 안에 (n−6)개 막대 + 네모 양옆에 짧은 가로선**. 이 기호로 덧셈·뺄셈 식을 계산해 **같은 기호로 써 넣기**(12식).
**앱 현황**: N-04 탤리(`tallyBuild`·`matchLine` tally)가 "막대로 수 만들기·읽기"를 이미 한다. 그러나 **새 기호 체계 학습**은 없다.
**유아용 변형(대폭 축소)**: **직접 그리는 입력은 뺀다**(교재도 선을 긋는 활동, 앱에선 입력 방식이 새로 필요). 대신 **읽기·고르기 두 가지**만:
- 레벨 1: 기호 하나를 보고 **일반 숫자로 읽기**(보기 3개).
- 레벨 2: 기호 + 기호 = ? 를 풀고 **결과 기호를 보기 3개 중에서 고르기**(≤9). 예: `[2]+[3] = ?` → 5의 기호 고르기.
- 기호 체계는 교재를 그대로 베끼지 않고 **우리 도형으로 새로 그린다**: 예) 1~5는 칸 속 점·막대 n−1개 대신 **막대 n개**(1은 막대 1개), 6~9는 위에 가로 막대(=5) + 나머지 막대. (교재와 다른 체계여도 학습 목표인 "기호를 읽고 쓰는 새 약속"이 같다 — "교재 문제는 조금 변형해서"에 맞는 선택.) 글리프 규칙표를 `problem.legend`로 화면 위에 항상 보여 준다.
**problem 스키마**
```js
{ prompt, answer:Number, answerType:'number', widget:'rodNumeral',
  expr:{ a:2, op:'+', b:3 } | { glyph:5 },       // 둘 중 하나
  choices:[4,5,6] }                              // 숫자값; 위젯이 글리프로 그림(레벨 2) 또는 숫자로(레벨 1)
```
**위젯 `rodNumeral`**: 상단에 1~9 글리프 표(항상 표시), 식을 글리프로 그림, 보기 3개를 레벨에 따라 숫자 또는 글리프로 탭.
**인쇄**: `nlRodNumeralHtml(p)` — 같은 SVG 글리프(소스 `rodGlyph(n)` 함수를 `widgets.js`와 `exam.js`가 공용 사용 — 현재 두 파일이 별 파일이라 `nl.js`의 `NM_RNG` 옆에 `NM_GLYPH` 전역을 두거나 problem에 글리프 SVG 경로를 싣는다).
**판정**: 숫자 일치.
**우선순위 P3** — 5~7세의 학습 목표(1~9 덧뺄셈, 규칙)에 직접 기여하는 정도가 낮고, 기호 체계 하나를 새로 학습해야 하는 부담이 크다. 이 호에서 가장 먼저 미뤄도 되는 항목.

|---|---|---|
| `ruleTable` | `table` | 표에서 규칙 찾아 빈 칸 고르기, 정답 후 연결선 애니메이션 |

| `arrowChain` | `chain` | 실선/점선 화살표 사슬(직선·지그재그·고리), 규칙 찾기 포함(G1-13 p7③과 공용) |

**기존 위젯 수정**: `seqFill`(빈 칸 다중·index 0·보기 후보) · `pyramid`는 그대로(생성기만 `pascal` 추가) · `nl2_seq` 생성기에 새 kind 4종.

**새 소품(실사 PNG)**: **기차**(기관차 1 + 객차 1 — 연결해 4~5량으로 반복해서 씀) 하나뿐. 모양수는 기존 `NM_OBJECTS`(사과·바나나·딸기·쿠키·별·풍선…)를 그대로 쓴다. 막대 기호·도형은 벡터.

**새 인쇄 표현(`exam.js`)**: `nlRuleTableHtml` · `nlTrainHtml` · `nlPromiseHtml` · `nlShapeEqHtml` · `nlSplitListHtml` · `nlArrowChainHtml` · `nlRodNumeralHtml`(P3) 7개와 `nlVisualHtml` 분기, **`nlSeqStripHtml`의 `blanks` 배열 지원**, `nlAnswerLabel`에 배열 답 분기(`arrowChain`·`shapeEq` 2개·`seqFill` 다중), `NL_PRINT_WORDS`에 `splitAll` 문구 2~3줄.

**위험·확인 필요**
1. 배열 답이 NL 인쇄에서 어떻게 처리되는지 확인되지 않음(G1-13.md §4 위험 1) — `nlAnswerLabel` 분기로 명시 처리할 것.
2. `promise`의 규칙 3종·예시 3줄은 **추리 유일성을 생성기에서 검증**해야 한다(후보 규칙 모두 계산 후 값이 서로 다른 `(a,b)`만 채택).
3. `rod`는 교재 기호를 그대로 쓰지 않고 새로 그리는 것을 전제로 했다(변형 지침). 교재 그대로가 필요하면 §2-11 첫 줄의 모양을 그대로 구현하면 된다.
4. `shapenum`에서 "다른 기호 = 다른 수" 조건을 생성기가 지켜야 하며(교재 규칙), 풀이가 **대입 한 번**으로 유일하게 내려오는 판만 쓴다.
