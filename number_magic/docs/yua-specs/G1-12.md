# G1-12호 명세 — 세 수·네 수 가르기·모으기 (표지 제목은 11호와 같은 "더하기와 빼기 II")

교재 12개 활동(2~13쪽). 표지는 11호와 같지만 내용은 다르다: **한 수를 세 수·네 수로 가르고 모으기**가 중심이고, 같은 수 모으기(배수 입구), 숫자 격자 묶기, 양팔저울 식(+/− 추론)으로 이어진다. 교재 PDF 쪽을 직접 보고 확인했다(2·3·4·5·6·7·9·10·12·13쪽).
교재 문장·수는 그대로 옮기지 않고 바꾼다. **수 범위 9 이내**. 이 호는 앱 N-12 "무당벌레 가르기와 저울"(`nl4_ladybug` + `nl12_scale`)과 구조가 가장 잘 맞는 호다.

공통 전제(채점 방식, `problemKey` 화이트리스트, `nlVisualHtml`/`nlAnswerLabel`/`nlPrintAsk` 분기, 음성)는 `G1-10.md` 0절과 같다.

## 0. 코드로 확인한 이 호 관련 사실

- `numberBond`(`widgets.js` 1010행)는 **두 부분**만 안다: 위 원(전체) + 아래 두 원, `dir:'join'|'split'`, 이모지를 탭해 채운 개수를 `onAnswer(fill)`. 세 수·네 수 불가. 기존 생성기 `nl4_bond`(전체 3~9에 한 부분 0~전체 제시, `join`: 두 부분 a,b 0~9) · `nl4_ladybug`(점 ≤9, 한쪽 날개 제시)는 **전부 두 부분**이다.
- 기존 `balanceScale`(1663행)은 **접시 위 물건 개수**로 무거운 쪽을 탭한다(`nl12_scale`: 좌우 1~9개, 서로 다름). 식 계산 저울은 없다.
- 기존 `crossSum`(`nl13_puzzle cross`: 위+아래 = 왼쪽+오른쪽, 빈칸 하나)이 "합이 같다"는 등호 맛은 이미 준다.
- 판정 방식: 호스트는 `+val===answer`/배열 일치만 안다. 열린 가르기는 **위젯이 합 규칙으로 직접 판정하고 합(또는 개수)을 답으로 올리는 방식**을 쓴다(G1-10.md 0절). 이 호에서는 "정답 = 목표 전체 수 w" 로 두고 위젯이 `onAnswer(자식 합)`을 부르면 호스트 비교(`sum===w`)가 그대로 규칙 판정이 된다 — **가장 단순하고 `check-answerable.js`도 통과**한다(숫자 w를 입력하면 통과).
- N-12는 `practice`=`nl4_ladybug`, `lab`=`nl12_scale`. 과정 C0 12주차 드릴은 `['NL3@2','NL10@2']`(`courses.js`). NL3·NL10의 기존 레벨은 그대로 둔다.

## 2. 활동별 상세

### 2·3·4·5·8·9·10쪽 — 공통 틀: 여러 수로 가르고 모으기 (결정 C, 위젯 `partsFill`)

일곱 쪽이 **같은 구조**(전체 수 w와 N칸. 칸 수의 합 = w)이고 그림 틀만 다르다 — 위젯 하나에 그림 종류를 `art` 인자로 둔다.

| 쪽 | `art` | 칸 수 | 방향 | 전체 w | 교재 특징 |
|---|---|---|---|---|---|
| 2 | `ladybug` | 3 | split | 9(레벨2), 5~8(레벨1) | 한 마리 예시 + 서로 다른 방법으로 |
| 3·8 | `plane` | 3 | split | 4~7 | 비행기에 w, 낙하산 3개에 수 |
| 4 | `gather` | 3 | join | 7·8 | 세 칸 → 아래 목표 |
| 5 | `balloons` | 4 | join | 4~7 | 풍선 4개 → 별 |
| 9 | `balloons` | 2 또는 3 | join | 2·4·6·8 / 3·6·9 | **같은 수**로 |
| 10 | `triangle` / `diamond` | 3 / 4 | join | 4~9 | 가운데 색칠 칸이 합 |

- **앱 현황**: 두 부분만 가능(`numberBond`). 세·네 부분 없음 → 신규.
- **mode**: `NM_TGEN['nlg12_parts']`, params `{level, parts:3|4|2, dir:'split'|'join', art, equal?, distinct?, given?}`.
- **problem 스키마**
  ```js
  { prompt:{ko:'9를 세 수로 갈라 봐요. 빈 동그라미에 수를 써요',…},
    widget:'partsFill',
    art:'ladybug',                // 'ladybug'|'plane'|'gather'|'balloons'|'triangle'|'diamond'
    dir:'split',                  // 전체가 위(분할 그림) / 'join': 전체가 아래(별·결과)
    whole:9, parts:3,
    given:{ "0":1 },              // 미리 채워진 칸(예시, 잠김). 칸 번호→값. 없으면 {}
    equal:false,                  // true: 모든 칸이 같아야 함(9쪽)
    distinct:1,                   // K>1: 서로 다른 방법 K개(7·13쪽 "여러 가지")
    min:1,                        // 각 칸 최솟값(기본 1; 0은 쓰지 않음)
    answer:9, answerType:'number' // distinct=1이면 whole, distinct>1이면 K
  }
  ```
- **위젯 `partsFill`(신규) 화면 동작**
  - 그림(`art`)이 틀이고 칸마다 빈 상자. 칸을 탭 = 포커스(기본은 첫 빈 칸). 하단 한 자리 numpad(`buildNumpad`/`numpadState(screen,1)`). 입력하면 칸에 들어가고 다음 빈 칸으로 자동 이동.
  - 칸이 모두 차면 ✔ 활성. ✔ → 각 칸이 `min` 이상인지 확인 후 **자식 합**을 `onAnswer(sum)`으로 올림(거부 시 `shake`만 하고 올리지 않음). 호스트 비교 `sum===whole`이 규칙 판정이다.
  - `equal:true`면 한 칸에 입력하면 나머지 칸이 같은 값으로 따라 채워진다(교재 9쪽: "같은 수 모으기"의 핵심은 한 번 정하면 전부 같다는 것) → 합이 `whole`이면 통과, 아니면 `onAnswer(sum)`이 `whole`과 달라 오답.
  - `distinct:K>1`: ✔ 후 맞으면 칸을 비우고 "방법 1/K ⭐" 진행 표시. 이미 쓴 분해(정렬한 배열)와 같으면 "다른 방법으로!" 토스트. K개를 모으면 `onAnswer(K)`.
  - 오답이면 틀린 합을 올려 호스트가 틀림 처리(`nlg` 기존 위젯과 같은 `shake`+효과음).
- **판정**: 합 규칙 + (`min`, `equal`, `distinct`는 위젯이 보증). 정답 하나(`whole` 또는 `K`)로 정규화돼 `check-answerable`·학습지 정답지가 모두 숫자 하나로 끝난다.
- **난이도/수 범위**: 
  - 레벨1: parts 3, w 4~6, `given` 칸 1개 제시(나머지 둘만 채움), `art` ladybug/plane.
  - 레벨2: parts 3, w 5~9, given 없음.
  - 레벨3: parts 4(풍선·마름모), w 4~9.
  - 같은 수(`equal`) parts 2: w∈{2,4,6,8}, parts 3: w∈{3,6,9}.
  - 삼각형/마름모: w 4~9, 첫 도형은 예시(`given` 전부 + 한 칸 비움).
- **유일 가능성/중복 방지**: `distinct:K`는 w와 parts에서 **서로 다른 분해 수**가 K 이상이어야 한다(예: w=5, parts=3 → {1,1,3},{1,2,2}만 2개 → K≤2). 생성기가 분해 수(`partitions(w, parts, min)`)를 세어 K를 정한다. 교재 7쪽 "합 5가 되는 경우 모두 찾기"는 `distinct = partitions 전부 개수`.
- **인쇄**: `nlVisualHtml`에 `partsFill` 분기 — 그림 틀(SVG 박스 모양, 아래 소품 참조) + 빈 상자 + 전체 수. 예시(`given`)는 값이 찍혀 나간다. `distinct`이면 같은 틀을 K개(교재처럼 6마리/6칸) 인쇄. 정답지는 숫자 하나(`whole`/`K`)이고 `nlAnswerLabel`에서 "여러 가지 정답 가능"을 덧붙임.
- **3언어 요령**: "9를 세 수로 갈라요 / Split 9 into three numbers / 把9分成三个数". 같은 수: "같은 수 두 개로 모아요".
- **교재 오타 주의**: 2쪽 첫 마리 예시가 `1·4·7`로 보이는데 합이 12다(합 9가 아님). 전사 오류 또는 교재 오타로 보이므로 **앱 예시는 합이 맞는 값(예 1·3·5)으로 새로 만든다.**
- **소품(작화/UI)**: 
  - `ladybug` 틀: 등껍질 위에 칸 3개(날개 점) — 기존 `🐞` 소품 토큰(있음)을 배경으로 쓰거나 **UI용 SVG 새로(무당벌레 등판)**. 
  - `plane`+`parachute`: 비행기(수 표시) 아래 낙하산 3개 → **신규 UI SVG** 또는 실사 PNG 2개(`plane`, `parachute`).
  - `gather`(세 칸 → 깔때기 화살표 → 결과), `balloons`(풍선 줄이 별로 모임; 풍선 `🎈` 기존 토큰 재사용), `triangle`/`diamond`(가운데 색칠 칸이 합): UI 도형(CSS/SVG).
- **키 필드**: `art`, `whole`, `parts`, `dir`, `given`, `equal`, `distinct`.

### 6·11쪽 수 묶기 — 결정 C

- **교재**: 4×4 숫자 격자에서 **서로 인접한** 세 수(11쪽은 세·네 수)의 합이 목표(7·8·9)가 되도록 타원으로 묶는다. 떨어진 수는 못 묶는다. 6쪽 예시 격자에 가로·세로·**대각선** 묶음이 모두 있다.
- **앱 현황**: 없음.
- **mode**: `nlg12_gridgroup`. 레벨1: 4×4, 묶음 크기 3, 목표 7·8·9, 찾아야 할 묶음 K=2. 레벨2: 5×5(확인학습용), 크기 3 또는 4, K=3.
- **problem 스키마**
  ```js
  { prompt:{ko:'이웃한 세 수의 합이 7이 되게 묶어요',…},
    widget:'gridGroup',
    grid:[[0,1,4,2],[4,6,5,0],[3,1,3,7],[4,5,2,5]],   // n×n, 값 0~9
    size:3, target:7, need:2,                          // 한 묶음의 칸 수 / 목표 합 / 찾아야 할 묶음 수
    answer:2, answerType:'number' }                    // = need
  ```
- **생성기**: 값은 0~5 위주로 무작위 격자를 만든 뒤 **풀이기**(연결 성분 열거: 8방향 인접으로 이어진 크기 `size` 부분집합, 서로 겹치지 않는 `need`개)가 해를 하나 이상 찾을 때만 채택. 해가 너무 많아 아무 데나 찍어도 맞는 격자(예: 목표 합을 만드는 묶음이 전체의 30% 초과)는 재추첨.
- **위젯 `gridGroup`(신규) 화면 동작**: 격자 칸을 탭해 선택(연속 탭, 새 칸은 이미 고른 칸 중 하나와 8방향 인접이어야 함 — 아니면 `shake`). 고른 칸 합이 실시간으로 위에 표시(작은 배지). 고른 칸이 `size`가 되면 규칙 판정: 합이 `target`이면 색이 채워진 타원(영역 색)으로 잠기고 "묶음 1/K ⭐", 아니면 선택만 풀림. 이미 잠긴 칸은 다른 묶음에 못 쓴다(교재 타원은 겹치지 않음). K개를 묶으면 `onAnswer(K)`. 되돌리기 버튼(마지막 묶음 해제).
- **판정**: 위젯이 규칙으로 판정, 호스트는 K와 비교(열린 답 허용).
- **인쇄**: `nlVisualHtml` 분기 `gridGroup` — 격자(굵은 선) + "○로 묶어요" + 답칸 없음(칠판에 그리기). 정답지: 생성기가 찾은 묶음 좌표를 `p.solutionGroups`로 가지고 있다가 "예시 묶음: (1행 2~4열), …" 같이 적고 "여러 정답 가능". (좌표 표기는 한 줄 이내로.)
- **수 범위/제약**: 모든 값 0~9, 목표 합 ≤ 9. 0이 섞이면 묶음 해가 늘어 쉬워지므로 레벨1은 0을 1~2개만.
- **키 필드**: `grid`, `size`, `target`, `need`.

### 12쪽 양팔저울 — 결정 C

- **교재**: 양쪽 접시에 `4 □ 3` / `9 □ 2`처럼 식이 있고 □에 +/−를 넣어 **양쪽 결과가 같게**(수평). 교재 3문항 확인: `4?3 = 9?2`(→ 4+3=9−2=7), `4?2 = 7?5`(→ 4−2=7−5=2), `7?2 = 5?4`(→ 7+2=5+4=9). 세 문항 모두 연산자 조합이 **유일**하다(교재는 유일성을 보증하지 않으니 앱이 확인해야 한다).
- **앱 현황**: `balanceScale`은 물건 개수를 세어 무거운 쪽을 탭할 뿐 식은 없다. 등호 개념을 식으로 다루는 것은 이 활동이 처음.
- **mode**: `nlg12_eqscale`. 레벨1: 한 쪽 접시만 □(다른 쪽은 식과 값이 보이거나 값만), 레벨2: 두 쪽 모두 □.
- **problem 스키마**
  ```js
  { prompt:{ko:'양쪽 식의 결과가 같아지게 ＋ 또는 －를 골라요',…},
    widget:'eqScale',
    pans:[ {a:4, b:3, op:null}, {a:9, b:2, op:null} ],   // op:null = 빈칸
    answer:[1,0], answerType:'numbers' }                 // 빈칸 순서, 1=＋ 0=－ (빈칸 하나면 숫자 하나)
  ```
- **생성기 규칙(필수)**: 모든 연산자 조합을 열거해 **양쪽 값이 같아지는 조합이 정확히 1개**일 때만 채택(예 `4? 3`, `9? 2`: 4+3=7, 9−2=7 ✓ 유일). 음수 없음(`−`는 a≥b). 모든 수·값 ≤ 9. 값이 같은 서로 다른 조합이 둘이면 재추첨.
- **위젯 `eqScale`(신규) 화면 동작**: 저울 그림(`balanceScale`의 기둥·빔 CSS 재사용) 위 접시마다 식 카드. □는 큰 토글 버튼(탭 = 비어 있음 → ＋ → －). 모든 □가 정해지면 ✔; 맞으면 빔이 수평으로 움직이는 애니메이션, 아니면 기울어짐(양쪽 값 차이에 따라 `balanceScale`과 같은 `angle` 계산). `onAnswer([…])`.
- **인쇄**: `nlVisualHtml` 분기 `eqScale` — 저울 SVG(기존 `nlScaleHtml` 틀 재사용) + 접시 식 `4 ○ 3`, ○ 칸에 쓰게. `nlAnswerLabel`: `＋ －` 기호열(`4＋3 = 9－2`).
- **판정**: 배열 일치(유일해 보장).
- **소품**: 새 그림 없음(저울 UI 재사용).
- **키 필드**: `pans`.

## 3. 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

### 새 위젯 (`render()` switch)
| 이름 | 용도 | 답 |
|---|---|---|
| `partsFill` | 여러 칸에 수를 써서 합이 w가 되게(가르기·모으기·같은 수·여러 방법) — 그림 틀은 `art` 인자 | `whole` 또는 K |
| `gridGroup` | 숫자 격자에서 인접 칸 묶음 만들기 | K |
| `eqScale` | 식 저울의 ＋/－ 고르기 | 1/0 배열 |
| (재사용) `numPick` | 합이 맞는 세 수 고르기(`sumpick`) — G1-11 | 정렬 배열 |
| (재사용) `storyCard layout:'groups'` | 묶음 세기 — G1-10 | 숫자 |

### 새 소품 / UI 그림
- 실사 PNG(선택): `plane`(비행기), `parachute`(낙하산). 무당벌레 등판은 기존 `🐞` 토큰 + UI 원.
- UI 도형(SVG/CSS): 세 칸 모으기 틀(`gather`), 풍선 묶음(풍선 `🎈` 기존 토큰 재사용), 삼각형·마름모(가운데 색칠 칸), 나무 가지 틀(`tree`).
- 필수 새 PNG는 **없음**(비행기·낙하산은 UI SVG로 대체 가능). 실사로 가려면 `plane.png`, `parachute.png` 2개.

### 새 인쇄 표현 (`exam.js`)
- `nlVisualHtml`: `partsFill`(art별 SVG 틀: ladybug·plane·gather·balloons·triangle·diamond·tree), `gridGroup`(격자), `eqScale`(저울+식).
- `nlAnswerLabel`: `partsFill`/`gridGroup`에 "여러 정답 가능" 문구, `eqScale`에 식 기호열.
- `NL_PRINT_WORDS`: "써요/골라요" 인쇄 동사 정리, "탭" 표현 제거.
- `problemKey` 화이트리스트: `art`,`whole`,`parts`,`given`,`equal`,`distinct`,`grid`,`size`,`need`,`pans`(+ `target`,`dir`는 G1-11과 공유).
- 새 문구 오디오 재생성(`generate-nm-audio.js`).

### 교재와 일부러 달라지는 점
- 열린 가르기(정답 여럿)는 **합 규칙으로 판정**하고 학습지 정답지에는 "여러 정답 가능" 한 줄 + 예시 1개.
- 2쪽 예시 1·4·7(합 12)은 교재 오류로 보고 합이 맞는 새 예시로.
- 같은 수 모으기(9쪽)는 곱셈 기호 없이 "같은 수를 여러 번 모으기"로만.
- 5×5 격자(확인학습)는 레벨2로 분리(화면 크기 고려).
