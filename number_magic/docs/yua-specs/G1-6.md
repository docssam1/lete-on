# G1-6호 (더하기와 빼기 I) → 앱 유아 단계 이관 명세

대응 유닛: **N-06 모으기와 가르기**(1:1). 활동 목록 원본: `docs/g1-inventory/G1-6.md`. PDF 쪽을 직접 보고 확인했다.
이 호는 세 호 중 앱의 유아 유닛과 **가장 직접 겹친다**(가르기·모으기·덧셈 첫 도입·뺄셈 = 남기기). 그래도 교재의 핵심은
**열린 활동**(정답이 여러 개: 6을 서로 다르게 가르기)과 **그리기·칠하기**인데, 앱 `numberBond` 는 '한 칸 채우기'뿐이라 대부분 새 위젯이 필요하다.

## 공통 규약 (G1-4/5/6 세 파일이 같은 문구)

1. **답 계약(코드 확인)**: 위젯은 `onAnswer(숫자 하나)` 만 부르고 채점은 `+val === problem.answer`
   (main.js 3149·4724·5331·6156). 정답이 여러 개인 열린 활동은 **위젯이 스스로 검증**해서 맞으면 `problem.answer`,
   아니면 `-1` 을 보낸다(+`shake`). 배열 입력이 필요해도 숫자 하나로 접는다.
2. **보기 고르기**: 숫자 칩은 `problem.chips`(숫자 배열, 생성기가 `rng` 로 섞어 실음, 답은 그 숫자 값). 글/그림 보기는
   `problem.choices`(배열) + **답 = 1부터 세는 보기 번호**(인쇄 ①②③와 같음). 기존 위젯 다수가 위젯 안에서 `Math.random`
   으로 보기를 만드는데(widgets.js 875·957·1099…) 새 위젯은 따르지 말 것 — 인쇄·재현이 안 된다.
3. **인쇄(exam.js)**: nl 문항은 `nlVisualHtml(p)` 의 widget 별 분기가 그림을 만든다. 모르는 widget 은 **빈 문자열**이 되어
   그림이 통째로 빠진다 → 새 widget 마다 분기 필수. 정답지는 `nlAnswerLabel(p)` 가 말로 바꿔 적는다. **한 줄 패치 권장**:
   `nlAnswerLabel` 맨 앞에 `if(p.answerLabel) return pickL(p.answerLabel)`(문자열 또는 `{ko,en,zh}`) — 열린 활동·글 답을
   생성기가 직접 적게 한다. 화면 말투(톡톡·콕)는 `NL_PRINT_WORDS` 에 새 문구를 추가해 인쇄용으로 바꾼다.
4. **중복 키**: `problemKey()`(exam.js 4899)는 열거된 필드만 본다. 새 필드(`skin preset parts distinct hide trees keep
   groups sign leftLabels sumTo kind` 등)를 목록에 추가하지 않으면 **서로 다른 문항이 같은 키로 합쳐져** 풀이 줄어든다.
   `choices` 는 이미 키에 있어 보기 순서만 다른 같은 문제가 다른 문항으로 센다 — 풀 크기는 '질문의 개수'로만 셀 것
   (권장: `choices` 를 키에서 빼고 `uq` 문자열 하나를 넣는 패치).
5. **풀 크기**: 한 레벨에서 서로 다른 key 24개 이상(20+예시1+따라풀기3, `docs/unique-shortfall-2026-09-25.json` 기준).
   **열린 그리기 활동은 변형이 본질적으로 적다** — 그래서 토큰(16종)·접시 같은 겉모습을 key 에 넣어 풀을 늘린다(아래 각 항목).
6. **수 범위**: `practice` ≤5, `main` ≤9. 문장은 짧게, 화면 문구는 `NM_SAY` 로 읽힌다(기호 금지: "더하기"·"빼기"·"같아요").
   식(`3+2=5`)은 기호라 화면·인쇄에 그대로 쓴다. 3언어 한 벌 `{ko,en,zh}`.
7. **새 스레드 번호**: `NL-?` 는 가칭. 다른 호 명세와 겹치지 않게 통합 때 부여. 과정 C0 의 N-06 주(`perSessionDrills`)에 넣는다.
8. **검증**: 새 위젯·mode 는 `node scripts/check-answerable.js <스레드>` 와 인쇄 미리보기로 확인.

## 이 호의 새 모듈 (활동별 명세에서 참조)

### M1. `splitDraw` — 서로 다르게 가르기 (열린 활동, 새 위젯)
교재 2·3·4·8·9쪽은 모두 **한 수를 두 부분으로 서로 다르게 나누어 그리기/칠하기**다. 하나의 위젯으로 다섯 겉모습을 낸다.
- 스키마
  ```
  { widget:'splitDraw', answerType:'number', skin:'cake'|'plate'|'paint'|'circle'|'bar',
    total:T, rows:R, preset:[{a,b}…] (이미 완성돼 잠긴 예시 줄),
    parts:2|3 (circle 의 동그라미 수), distinct:'ordered'|'unordered',
    e:토큰, colors:['A색','B색'] (paint), prompt:{ko,en,zh}, answer:T }
  ```
- 줄(행)마다 `a+b === T`(둘 다 ≥1)이고, 줄끼리 **서로 달라야** 한다. 모든 줄이 맞으면 `onAnswer(T)`, 아니면 `-1`+shake+힌트
  ("합이 6이 아니에요" / "다른 방법도 찾아봐요!"). 남은 줄 수를 `n개 더!` 로 보여 줌.
- **교재의 '서로 다르게' 규칙을 실제로 세어 확인했다**(그래서 distinct 가 갈린다):
  - 케이크(2쪽)·동그라미(8쪽)·막대(4쪽)는 **순서가 없다**(`unordered`): 6 의 가르기는 (1,5)(2,4)(3,3) 3개 → 예시 (4,2) 빼고 **남은 2줄**;
    동그라미 4→2개·5→2개·6→3개 = ⌊T/2⌋개; 막대 7→(1,6)(2,5)(3,4) 예시 포함 3줄, 막대 5→2줄. 교재 줄 수와 정확히 일치.
  - 꽃(3쪽)·칩(9쪽)은 **색 순서가 있다**(`ordered`): 9 → (1,8)…(8,1) 8줄(예시 포함), 8 → 7줄. 교재 줄 수와 일치.
  → 유아용은 줄 수 `rows` 를 줄여(2~4줄, 아이가 정하는 다른 방법) 낸다. `rows` 를 가능한 가르기 수 전체로 두는 '완성' 변형은 main 상위.
- skin 별 동작
  - `cake`/`plate`: 두 접시(케이크)가 한 줄. **접시를 누르면 토큰(양초/물건)이 하나 놓이고 토큰을 누르면 지워짐**(최대 9). `plate` 는 기존 토큰 16종을
    아무거나 쓸 수 있는 접시판 — 케이크·양초는 새 소품이지만 plate 는 기존 토큰으로 이미 풀이 충분하다.
  - `paint`: 줄마다 토큰 T개가 회색으로 놓임. 위쪽 **색 두 개 팔레트**(🔴🔵)를 고르고 토큰을 눌러 칠함(다시 누르면 회색). 모두 칠해야 한 줄 완성.
  - `circle`: 가운데 선이 그어진 동그라미 `parts` 개(2 또는 3). 반쪽을 누르면 점(⚫)이 놓임. 동그라미마다 합 T.
  - `bar`: T칸 막대 `rows` 개. 칸 k 를 누르면 **앞 k칸이 A색, 나머지가 B색**(앞쪽부터 칠하는 접두 방식, 교재의 "두 막대로 나누기"). 맞으면 옆에
    가르기 모형(숫자)이 떠올라 확인시킴. 숫자를 **쓰는** 단계는 `bondNum`(M2) 이 따로 맡는다.
- 범위: practice T 3~5 / main T 4~9, `rows` practice 1~2, main 2~4.
- 인쇄: 접시·칸·동그라미를 빈 모양으로 그리고 "서로 다르게 ○를 그려요/칠해요". 정답이 열려 있으므로 `answerLabel` 로
  **가능한 가르기 목록**(`1+5, 2+4, 3+3`)과 "합이 6이면 정답"을 적는다. 교재 예시 줄은 `preset` 으로 미리 그려 인쇄.
- 풀: `plate` T 3~9(7) × 예시 선택 × `rows` 1~3 × 토큰 16종 → 수백; `cake` T 4~9 × 예시 × rows ≈ 40; `circle`/`bar` ≈ 15 씩(→ 레벨을
  섞거나 토큰·색 변형으로 확보).
- 3언어 문구 예: ko `양초를 모두 6개가 되게 그려요. 서로 다른 방법으로!` / en `Draw candles so there are 6 in all. Find different ways!` / zh `把蜡烛画成一共6根，试试不同的分法！`

### M2. `bondNum` — 숫자 가르기 모형 (`numberBond` 의 숫자판)
기존 `numberBond` 는 이모지를 **채우는** 모양(점 그림 단계)이다. 교재 4·7·10·13쪽은 그림 없이 **숫자만 든 모형**(위 전체, 아래 두 부분)의 빈 칸을 채운다 —
점 그림 → 숫자 기호로 가는 다음 단계.
- 스키마
  ```
  { widget:'bondNum', answerType:'number', interaction:'fill'|'max',
    whole, a, b, hide:'whole'|'a'|'b', bar?:{T,k} (막대 그림을 옆에 보여 줌),
    chips:[3 숫자], trees?:[{whole,a,b,hide}×4] (max), answer }
  ```
- `fill`: 숫자 원 3개 중 하나가 `?`, 칩 3개를 눌러 즉시 판정(맞으면 칸에 들어가고 `.on`). `bar` 가 있으면 칠해진 막대(앞 k칸 색)를 곁에 그려 "그림 → 숫자" 연결.
  practice ≤5, main ≤9(0 포함). `hide` 세 위치 모두.
- `max`(p10 '큰 수 찾기'): 작은 모형 4개를 한 화면에 보여 주고 **빈칸에 들어갈 수가 가장 큰 모형을 누름**. 답 = 1부터 센 번호. 네 모형의 빈칸 수는 서로 달라야 함.
- 인쇄: `bondSvg`(split, 오른쪽 빈칸)·`bondSvgTop`(join, 위 빈칸)는 있으나 **왼쪽 빈칸**이 없다 → `nlBondNumHtml(whole,a,b,hide)` 로 세 위치를 모두 그린다.
  `max` 는 네 모형에 ①~④ 표시 + ○표. 정답지: 숫자 / 번호.
- 풀: `fill` (전체 0~9 × a 0~전체 × hide 3) 165, practice(≤5) 63. `max` 는 네 값 조합 수천.
- 3언어: ko `빈 동그라미에 들어갈 수는?` / en `What number goes in the empty circle?` / zh `空圆圈里填几？`

### M3. `crossLeave` — 남기기(뺄셈의 첫 모습, 새 위젯)
교재 6·12쪽은 뺄셈을 '몇 개를 없애야 ✹ 안의 수만큼 남는가'로 연다.
- 스키마 `{widget:'crossLeave', answerType:'number', skin:'balloon'|'cookie'|'bar', total:T, keep:R, e:토큰, eq:boolean, answer:T−R}`
- 화면: 토큰 T개(풍선은 묶음, 쿠키는 접시 위, `bar` 는 칸 줄) + 한쪽에 **별 배지 `R`**(남길 수). 토큰을 누르면 `×`(풍선은 날아감, 쿠키는 사라짐)·다시 누르면 되돌림.
  아래에 `남은 n / 없앤 c` 두 수. ✔ 로 제출 → `onAnswer(없앤 c)`. `c === T−R` 일 때만 정답(남은 수가 R 이 아니면 틀림). R 이 0 이면 전부 없애는 문항.
  `eq:true`(bar skin) 이면 식 `T − □ = R` 를 위에 보여 줌.
- 범위: T 2~9, R 0~T−1. practice T ≤5. 교재 6쪽(풍선, 남길 수 3·2·0·5·6·2)·12쪽(밤, 2·1·3·3·2·4)과 같은 형식, **밤은 새 소품 없이 기존 `🍪` 쿠키로 대체**(선택: 밤 PNG).
- 인쇄: 토큰을 그리고 `남길 수 ✹R`, 답칸 `없앤 것 ( )개` + "없앨 것에 ×표". 정답지 숫자.
- 풀: 44(T 2~9 × R) × skin 2 = 88, practice 28.
- 3언어: ko `풍선이 7개 있어요. 3개만 남으려면 몇 개를 날려 보내야 할까요? 날릴 풍선을 눌러요` / en `There are 7 balloons. To leave only 3, how many must fly away? Tap the ones to send away.` / zh `有7个气球。只留下3个，要飞走几个？点一点要飞走的气球。`

### M4. 기존 위젯 확장 (B) — `matchLine`·`selectPairs`·`pickCard`
- `matchLine` 에 규칙·표시를 더한다: ① `matchRule:'sum', sumTo:n` — `left+right === sumTo` 를 짝으로 인정(교재 7쪽 4번) ② `rightType:'num'|'objs'`
  — 오른쪽 카드를 큰 숫자 / 토큰 묶음(`rightEm`)으로 ③ `leftLabels:['9−4',…]` — 왼쪽 카드에 식을 보이고 값(`left`)으로 판정(13쪽 6번).
  기존 판정 `left[selL]===num` 은 `matchRule` 이 없을 때 그대로. 생성기는 **짝이 유일하게 정해지게**(합 규칙은 한쪽 값이 서로 다름) 만든다.
- `selectPairs`(기존, A-계열이 쓰는 두 칩 합 맞추기)에 `pairsOnly:true` 를 더해 **짝을 찾으면 합 단계 없이 즉시 `onAnswer(answer)`**(13쪽 2번).
  ⚠ 이 위젯의 문구가 한국어 고정(`problem.prompt.ko`·"짝을 모두 찾았어요")이라 3언어로 바꿀 때 `NM_L` 을 쓰게 고쳐야 한다.
- `pickCard`(G1-4·5 와 공유): `stemParts:[{k:'groups',list:[{e,n}…],sign:'+'}|{k:'eq',t}]`, `choices`(식 문자열), 답 = 보기 번호. 즉시 판정.

`NL-남기기·덧셈식`(leave·addEq·sameSum·exprMatch·objMatch).

  `rows:1`). 케이크가 없는 레벨은 `plate` skin(기존 토큰). 정답: 두 접시의 합이 T, 예시·다른 줄과 다름.

- **소품(새)**: `cake`(접시 위 케이크), `candle`(양초 한 자루, 불꽃 포함), `plate`(접시, 위에서 본 모습). **인쇄**: M1.

### p3 꽃 9송이 가르기 — 결정 **B**

### p5 동물의 마리수 — 결정 **C**
- **교재**: 두 칸의 동물 그림(원숭이 3·새 2…)을 보고 합한 마리 수를 덧셈식으로 씀(예시 `3 + 2 = 5`, 6문항).
- **앱 현황**: 덧셈식(기호 `+ =`)이 없다. `nl4_bond`/`join` 은 점 채우기, `nl15_logic`/`story` 는 글 문장제 + 숫자패드.
- **결정**: `nl_addsub`/`addEq` — 장면에 **서로 다른 동물(또는 토큰) 두 무리**가 `+` 로 이어져 있고:
  - practice(≤5): **식 고르기** `pickCard` — stem `{k:'groups',list:[{e:rabbit,n:3},{e:duck,n:2}],sign:'+'}`, 보기 3개
    `3 + 2 = 5`·`3 + 2 = 6`·`3 + 3 = 6`(맞는 식 + 합만 틀린 식 + 수 하나 바뀐 식), 답 = 번호. 보기 순서는 rng.
  - main(≤9): **합 쓰기** — 기존 `storyCard`(numpad)에 `eqLine:'3 + 2 = ?'` 를 보여 주는 (B) 확장. 식 전체 쓰기는 칸 3개 입력이라 유아에겐 과함 → 합만.
- 동물은 기존 10종 + 나비·병아리 등 토큰(교재의 원숭이·소·달팽이 같은 **새 동물은 만들지 않는다**). 합 ≤9, 무리당 1~6.
- **들어갈 곳**: `NL-남기기·덧셈식` 레벨 1(`addEq` 고르기 practice), 2(고르기 main), 3(합 쓰기).
- 인쇄: 그림 + 보기 ①②③ + `답 ( )번` / 식 줄 + 답칸. 정답지 `3 + 2 = 5`.
- 풀: 무리 (a,b) 1~6 합 ≤9 ≈ 30 × 동물 쌍 5 = 150.
- 3언어: ko `두 무리를 합하면 모두 몇 마리일까요? 맞는 식을 골라요` / en `How many animals in all? Pick the right equation` / zh `两群合起来一共几只？选出正确的算式`

### p7 확인학습(첫째) — 결정 **B** (모두 M1~M5 재사용)
| 문항 | 교재 내용 | 앱 대응 |
|---|---|---|
| 1 | 가르기·모으기 빈칸 (2,3 → □ / 3,6 → □) | `bondNum` fill (`hide` 3위치) |
| 2 | 숨은 구슬 수 (총 6, 보이는 수에서) | **A** 이미 있음: `nl4_bond`/`split`(이모지 `⚫`)·`nl4_ladybug` 와 같은 수학. 선택: 주먹 그림 skin(새 소품 `hand`) — 불필요 |

## 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

**새 위젯 (4)**: `splitDraw`(5 skin) · `bondNum`(fill·max) · `crossLeave`(3 skin) · `gridSum`. 공유 위젯 `pickCard`(G1-4·5 와 공통).

**기존 위젯 확장 (B)**: `matchLine`(`matchRule:'sum'` · `rightType:'num'|'objs'` · `leftLabels`), `selectPairs`(`pairsOnly` + 3언어 문구),
`storyCard`(numpad 위에 `eqLine`). `numberBond`(점 그림판)는 그대로 둔다.

**새 생성기/mode**: `nl_addsub` — `split bondNum bondMax leave addEq sameSum pairPick pairSum exprMatch objMatch`, `nl9_chain` +`grid`.
새 스레드 가칭: `NL-가르기그리기`, `NL-가르기모형`, `NL-남기기·덧셈식`; `NL5` 에 레벨 추가. 과정 C0 의 N-06 주 `perSessionDrills` 에 반영.

**새 소품(PNG)**: `cake`(접시 위 케이크), `candle`(양초), `plate`(접시) — 3종, 선택 `chestnut`(밤), `hand`(주먹). 풍선·쿠키·꽃·바둑돌·토끼 등 나머지는 기존 16종·동물 10종 재사용.

**새 인쇄 표현** `nlVisualHtml` 분기: `splitDraw`(빈 접시·칸·동그라미·막대, 예시 줄 `preset` 미리 그림) · `bondNum`(`nlBondNumHtml`, 왼쪽 빈칸 포함, `max` 4개 모형) ·
`crossLeave`(토큰 + ✹ 배지 + 답칸) · `gridSum`(2×2 + 합 칸) · `pickCard`(식 보기) · `matchLine`(`rightType:'num'|'objs'`, 식 라벨).
`nlAnswerLabel` 의 `answerLabel` 패치(열린 답 목록), `NL_PRINT_WORDS` 추가("접시를 눌러 → 접시에 그려", "토큰을 눌러 → ×표"), `problemKey` 필드 추가.
