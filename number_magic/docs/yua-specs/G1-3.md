교재 활동표: `docs/g1-inventory/G1-3.md` (12활동, PDF 2~13쪽). 읽기 전용 분석, 코드 미수정. PDF 이미지로 직접 확인한 쪽: 3·5·6·8·9·10·12·13(= 확인학습 2회 포함). 교재 문장은 옮기지 않고 변형·요약. 수 범위는 0~9(교재가 5쪽 □ 문제에서 0 을 보기에 넣는다) · 칸은 10까지.

## 0. 공통 전제 (코드를 직접 읽어 확인한 사실)

1. **유닛 ↔ 교재**: `data/courses.js` 과정 0 의 1:1 편성. 이 호 = **N-03 몇째와 크기 비교**(`generator:'nl3_ordinal'`, 스레드 NL8 `data/threads.js:3064`). 유닛은 practice `mode:'position'` 4문항 + lab `mode:'paint'` 4문항.
2. **유닛 이름은 "크기 비교"인데 생성기에 크기 비교가 전혀 없다**(`nl3_ordinal`은 `position`·`paint` 둘뿐, nl.js:518~565). 이 호의 5·6·7·10·11·12·13쪽이 그 빈자리다. 비교 계열도 같은 생성기 `nl3_ordinal`의 새 mode 로 넣는다(유닛 `generator` 키 불변).
3. **mode 가 하나뿐인 유닛 구조** → 신규 mode 는 `params.modes`(배열)로 받아 `pick(rng,modes)`. 전 활동 커버는 스레드 레벨(`'NL8@k'`)이 맡는다(G1-1 명세 §0-2).
4. **위젯 판정 계약**: 유닛 practice/lab 은 `+val===cur.answer`(`main.js:6159`, `:6962`) → 위젯은 **숫자 하나**만 돌려준다(배열 answer 는 넘패드 전용). 집합·그리기·순서 위젯은 `matchLine`(`widgets.js:1330`)/`dotToDot`(`:1169`)처럼 **내부에서 판정, 맞으면 `onAnswer(problem.answer)`, 틀리면 shake + `onAnswer(-1)`**. 이진 선택(>/<)은 `answer`에 **1(왼쪽이 큼 `>`) / 2(왼쪽이 작음 `<`)** 코드를 쓴다.
5. 위젯의 3지선다 보기는 위젯이 `Math.random`으로 만든다(`widgets.js:875`, `:957`). 신규 위젯은 **생성기가 `choices`를 정해 problem 에 싣는다**(결정성·인쇄 정답지 일치).
6. 인쇄는 `exam.js` `nlVisualHtml`(3207)/`nlAnswerLabel`(3244)/`NL_PRINT_WORDS`(3261~). 서수 표기 상수: `ORDINAL`(nl.js:243, 첫째~아홉째)과 `exam.js nlAnswerLabel` 안의 `ORD_KO` — 이 호에서는 **개수 낱말(하나·둘…)** 도 필요하니 `NATIVE`(nl.js:90, `nl1_count` 지역 상수)를 파일 상단 공용 상수로 올려야 한다.
7. 기존 서수 위젯: `gridPaint` 'single'(왼/오른쪽에서 n째 한 칸 짚기, `widgets.js:1404`)과 'count'(총 N칸 아무데나 칠하기, `:1419`). 교재의 **개수 vs 순서 대비**(같은 말 "다섯"/"다섯째"를 한 줄은 여러 칸, 한 줄은 한 칸)와 **오른쪽 시작**은 없다.
8. **화살표 약속(6·12쪽)**을 PDF 6쪽 이미지로 확인했다: `4 ──▶ 3`은 "4는 3보다 큽니다", `7 ◀── 9`는 "7은 9보다 작습니다". 즉 **꼬리가 큰 수, 머리(뾰족한 쪽)가 작은 수** — 큰 수에서 작은 수 쪽으로 화살표가 간다. (활동표의 "→ 큰 수 쪽에서 가리킴" 표현은 모호하니 이 규약을 따를 것.)

## 3. 새 mode·위젯 상세

### 3-1. 2·8·7쪽③ 개수 vs 순서 색칠 — `gridPaint` `gridMode:'ord'` (C)
- **현재**: 'single'(몇째 한 칸 짚기)·'count'(N칸 아무 칸) 둘뿐(§0-7).
- **mode `ord`** (`nl3_ordinal`, NL8 레벨 4):
  ```
  { widget:'gridPaint', gridMode:'ord', answerType:'number', total:10,
    rows:[{kind:'cardinal'|'ordinal', n, from:'left'|'right'}..],   // 1줄(practice) 또는 2줄(main)
    answer:n }
  ```
  - 한 문항 안에 **같은 수의 개수 줄과 순서 줄**을 한 쌍으로(main, 교재 2쪽의 핵심 대비): `rows:[{ordinal,5},{cardinal,5}]` 순서는 섞는다. practice 는 한 줄.
  - 칸은 원 10개 한 줄(교재 원 10개), 시작 쪽에 작은 깃발/화살표 표시(`from`).
  - **판정**(위젯 내부): `cardinal` → 시작 쪽에서 **연속한 n 칸**(예: 오른쪽에서 넷 = 오른쪽 끝 4칸)만 칠해져 있어야 함. `ordinal` → **시작 쪽에서 n 번째 한 칸만**. 두 줄이 모두 맞아야 `onAnswer(n)`; 틀리면 shake + `onAnswer(-1)`, 칸은 지워지지 않고 아이가 고친다(✔ 로 제출). (`'count'`처럼 위치 무관 판정이면 개수·순서 대비가 사라지므로 위치까지 본다.)
  - 칸 수는 10 이지만 n 은 1~9 · 기수는 2~9(1 은 순서와 같아져 대비가 안 되므로 제외).
- **낱말 만들기**(prompt): 
  - ko 기수 `NATIVE[n]`(하나·둘·셋·넷·다섯·여섯·일곱·여덟·아홉) / 서수 `ORD_KO[n]`(첫째~아홉째). "왼쪽에서 일곱을 칠해요", "왼쪽에서 일곱째를 칠해요". 교재의 핵심 오답이 "다섯"↔"다섯째" 혼동이므로 낱말을 **큰 글씨로**.
  - en: "Color seven from the left" / "Color the seventh one from the left". zh: "从左边涂七个" / "涂从左边数第七个"。
- **인쇄**: `nlVisualHtml`: `gridPaint`+`ord` → 원 10개 줄 N 줄(`nlBoardHtml(10,10)`, 시작 쪽 표시 + 낱말 라벨), 정답지는 `칠할 칸: 5 / 5째`. `nlAnswerLabel`: `rows` 를 `개수 5(왼쪽부터) · 순서 5째` 로.
- **치환**: "칸을 눌러 칠해요" → "칸을 칠해요".

### 3-2. 3·9쪽 양쪽 순서수 → 모두 몇 개 — 신규 위젯 `ordRow` (C / 9쪽 C+D)
- **현재 없음**(`gridPaint` single 은 한 방향·고정 총 칸).
- **결정 C** — 신규 위젯 `ordRow`, mode `both`(NL8 레벨 6). 한 위젯이 4개 하위 모드를 갖는다: `build`(이 절)·`flip`·`find`·`word`(3-3). 공통 필드: `axis:'row'|'col'|'queue'`, `labels:[시작쪽,끝쪽]`(row: 왼쪽·오른쪽 / col: 위·아래 / queue: 앞·뒤).
- **`build`** (3쪽·9쪽):
  ```
  { widget:'ordRow', ordMode:'build', axis:'row'|'col'|'queue',
    a:n(시작쪽에서 a째), b:m(끝쪽에서 b째), total:a+b-1, answer:total, choices:[..3] }
  ```
  - 시작: **a 칸**만 있고 마지막 칸(= a째)이 칠해져 있다. 끝쪽 가장자리에 `+`/`−` 버튼으로 칸을 늘리고 줄인다. 위에 "끝쪽에서 b째가 되게 칸을 더해요" — 라벨 번호는 **보이지 않는다**(보이면 세지 않아도 답).
  - ✔ 로 모양 확인: 칠한 칸 뒤쪽(끝쪽) 칸 수가 `b-1` 이면 통과, 아니면 shake. 통과하면 아래에 3지선다("모두 몇 칸?")가 열리고, 고르면 `onAnswer(chip)`(정답 `a+b-1`).
  - 교재 3쪽의 예시 흐름(왼 5째·오른 4째 → 8칸)을 discover 의 시연으로 쓴다.
  - 범위: a,b 1~6, 합 `a+b-1` ≤ 9(칸은 최대 9 → 칸 수가 10 을 넘지 않게). practice a,b ≤ 4.
- **9쪽 변형(D)**: 교재 9쪽은 첫 문항 외에는 칸 그림 없이 학생이 직접 그려야 한다. 앱은 **칸 수를 고정**하지 않고 같은 `build` 흐름(칸 늘리기)을 쓰되, `axis:'col'`(위/아래) 또는 `'queue'`(앞/뒤)로 바꾼다. 세로는 칸이 위→아래, 앞/뒤는 가로 줄에 앞 표시(◀ 앞 / 뒤 ▶). 낱말 라벨은 언어별: ko 위/아래·앞/뒤, en top/bottom·front/back, zh 上/下·前/后.
- **인쇄**: 칸 그림 없이 "a째 / b째" 말풍선 + 답칸(개) — 교재 9쪽과 같은 "직접 그려서 풀기". 정답지는 `a+b-1`. 인쇄에서 `nlVisualHtml` 은 `ordRow build` 에 대해 `nlStage`(빈 칸 영역 점선 판) + 말풍선 2줄 + `nlAnsBox`.

### 3-3. `ordRow` 나머지 하위 모드 — `flip`·`find`·`word` (C)
- **`flip`**: 칸 `total` 개 중 한 칸이 칠해져 있고 "왼쪽에서 a째예요. 오른쪽에서는 몇째?"(`b=total-a+1`)를 3지선다로. `{ordMode:'flip', total, a, from:'left', answer:b, choices}`. NL8 레벨 5. `total` 5~9.
- **`find`**(7쪽⑤·13쪽③): 숫자 카드 한 줄(중복 없는 수 7장, 예 2 5 6 8 7 1 4) + 기준 문장 "6은 왼쪽에서 셋째예요. 그럼 7은?" → 몇째인지 3지선다. `{ordMode:'find', cards:[..], ref:{v,pos}, ask:v2, answer:pos2, choices}`. 기준 카드는 위쪽에 강조(`ref`). 카드 수 5~7. `ask` 는 `ref` 와 다른 카드.
- **`word`**(13쪽②): 10칸 줄 하나가 칠해져 있고(연속 n 칸 = 개수, 한 칸 = 순서), 아래에서 알맞은 **낱말**을 고른다. 교재의 "낱말 쓰기"는 입력 불가(E)라 **고르기로 변환**. `{ordMode:'word', total:7, n, kind:'cardinal'|'ordinal', from, choices:[3개 코드], answer:code}` — 코드 `n*10+(ordinal?1:0)`(기수=0, 서수=1)로 낱말을 숫자 하나로 인코딩한다. 보기 3개는 `[정답, 같은 n 의 반대 종류, 다른 n 의 같은 종류]`. 보기는 위젯이 `S.lang`으로 렌더("넷"/"넷째", en "four"/"fourth", zh "四个"/"第四个").
- **인쇄**: 칸 줄(`nlOrderStripHtml`을 재사용해 칠한 칸 표시 추가) + 보기 ①②③ ○표(`nlAnswerLabel`에 `ordRow` → `① 넷째`). `find` 는 `nlStage(카드 줄)` + 답칸(째).

### 3-4. 4쪽·7쪽①·13쪽④ 순서대로 쓰기 — 신규 위젯 `orderTiles` (C)
- G1-2 명세와 **공용 위젯**(`otype` 로 구분).
- **mode `order`** (`nl3_ordinal`, T-CMP 3):
  ```
  { widget:'orderTiles', answerType:'number', otype:'asc'|'desc', answer:N, tiles:[..N개 중복 없는 수 1~9, 섞음] }
  ```
  화면: 숫자 카드(교재 5장 카드 모양)가 흩어져 있고 아래에 순서 칸 N 개. **작은 수부터(asc)/큰 수부터(desc)** 누르는 순서대로 칸에 들어간다. 맞는 카드만 칸에 들어가고 틀리면 shake, 칸은 변하지 않는다. 다 채우면 `onAnswer(N)`.
  - practice N=4(asc), main N=5~6(asc·desc 반반). 교재 5쪽 수 6개·카드 5장 규모와 같다.
- **3언어**: ko "작은 수부터 차례로 눌러요" / en "Tap from the smallest to the biggest" / zh "从小到大依次点".
- **인쇄**: 숫자 카드 줄 + 빈 칸 N 개 점선. 정답지 `1, 4, 5, 6, 7`. `nlAnswerLabel`: `orderTiles` → 정렬된 열.

### 3-5. 5쪽②·7쪽⑥ 크기 비교 부등호 — 신규 위젯 `cmpSign` (C)
- **현재 없음.**
- **mode `cmp`** (T-CMP 1):
  ```
  { widget:'cmpSign', answerType:'number', left:a, right:b, ask:'sign'|'word', answer:1|2 }
  ```
  `a≠b`, 0~9. 화면: 큰 숫자 두 개 사이에 점선 원 `○`, 아래 큰 버튼 `>` `<`. 누르면 원에 기호가 들어가고 `onAnswer(1|2)`: `>`면 1, `<`면 2(왼쪽이 큰 경우 정답 1). `ask:'word'`(7쪽⑥): 기호를 정한 뒤 "6은 8보다 (큽니다/작습니다)"의 낱말 두 개를 추가로 고른다(두 선택이 모두 맞아야 `onAnswer(code)`, 틀린 쪽은 shake).
  - 개념은 N-03 discover 에서 약속 박스(교재 5쪽 위)로 설명: 7>6, 7<8, 5>3, 6<8, 각각 "…보다 큽니다/작습니다".
  - practice: 차 ≥3, 0 제외, 6문항 중 `>`/`<` 균형. main: 차 1~2 포함, 0 포함.
- **3언어**: ko "7과 9 중 어느 쪽이 더 클까? 알맞은 기호를 눌러요" / en "Which sign fits? 7 ○ 9" / zh "7 ○ 9，选出合适的符号". 낱말: ko 큽니다/작습니다, en bigger/smaller, zh 大于/小于.
- **인쇄**: `a ○ b` 큰 글씨 + (ask:'word' 이면) 아래 문장 "…보다 (큽니다, 작습니다)". 정답지 `>`/`<`. `nlAnswerLabel`: `cmpSign` → `p.answer===1?'>':'<'`.
- **치환**: "알맞은 기호를 눌러요" → "○ 안에 >, <를 써요".

### 3-6. 5쪽③·7쪽②·11쪽·13쪽⑥ 수 고르기 — 신규 위젯 `numPick` (G1-2 와 공용) (C)
- 위젯 스키마는 G1-2 명세 3-3 과 같다(`tiles`, `marks:[{sym,set}]`, `scene?`, 내부 판정, `onAnswer(K)`/`-1`).
- **mode `range`**(5쪽③·13쪽⑥, T-CMP 2): 타일 0~9(교재처럼 0 포함) 10개. 식 `expr:{form:'□>k'|'k<□'|'□<k'|'k>□', k}`, 정답 집합 = 조건을 만족하는 수. `marks:[{sym:'○', set}]`. 정답 집합 크기 1~7(예 `□>2` → 3~9 7개, 교재와 같다). practice 는 집합 크기 ≤4. `ask:'count'`(13쪽⑥)는 표시를 마친 뒤 "몇 개?"를 3지선다로 한 번 더 묻는다(두 단계; `choices` 를 problem 에 싣고 마지막에 `onAnswer(count)`).
- **7쪽② mode**: 사탕 `scene:{emoji:'🍬', n:6}`(그림 6개) 아래 후보 `4 5 6 7 8` → 하나 더 많은 수 ○(7), 하나 더 적은 수 △(5). `marks:[{sym:'○',set:[idx(7)]},{sym:'△',set:[idx(5)]}]`.
- **mode `minmax`**(11쪽, T-CMP 5): ① 한 줄 5~6개(중복 없는 수) → "가장 큰 수 ○ · 가장 작은 수 △". ② 카드 7장(교재 5 7 8 3 2 6 1) → 질문 4종 중 하나: 가장 큰 수 / 가장 작은 수 / **5보다 큰 수 모두** / **5보다 작은 수 모두**(후자 둘은 집합 표시).
- **인쇄**: 타일 줄(숫자 칸, 교재식 괄호 `( 0, 1, …, 9 )`) + 조건식, 정답지는 표시할 수 `○ 7·8·9`. `nlAnswerLabel`: `numPick` → 표시별 수 열.

### 3-7. 6·12쪽 화살표 상자 — 신규 위젯 `arrowTri` (C)
- **현재 없음.** 약속(§0-8): **화살표는 큰 수에서 작은 수 쪽으로**(꼬리=큰 수, 머리=작은 수).
- **mode `arrowTri`** (T-CMP 4):
  ```
  draw: { widget:'arrowTri', amode:'draw', vals:[v0,v1,v2], answer:max }
  fill: { widget:'arrowTri', amode:'fill', arrows:[[from,to]×3], bank:[3수], pre:{vi:n}?, answer:max }
  ```
  - 삼각형 꼭짓점 3개(위·왼아래·오른아래)와 변 3개. `vals` 는 서로 다른 수 1~9.
  - **draw**(교재 위 문제): 꼭짓점에 수 3개가 적혀 있고 변 3개에 화살표를 그어야 한다. 변을 누를 때마다 `없음 → 한쪽 방향 → 반대 방향 → 없음` 순으로 돈다. ✔ 로 제출: 세 변 모두 **큰 수 → 작은 수** 방향이면 `onAnswer(max(vals))`, 아니면 shake + `onAnswer(-1)`.
  - **fill**(교재 아래 문제): 화살표 3개가 이미 그려져 있고 꼭짓점 3개가 비어 있다. 수 3개(`bank`)를 꼭짓점에 놓는다(수를 누르고 꼭짓점을 누른다; 놓인 수를 누르면 빼기). ✔ 로 제출: 모든 화살표가 "큰 수 → 작은 수"를 만족하면 `onAnswer(max)`, 아니면 shake. 화살표 세 개는 항상 **순환이 없게**(한 꼭짓점이 두 변의 꼬리, 한 꼭짓점이 두 변의 머리) 만들어 해가 유일하게 한다. practice 는 꼭짓점 하나를 `pre` 로 미리 채운다.
  - 범위: 수 1~9, practice 3수 모두 차 ≥2.
- **3언어**: ko "큰 수에서 작은 수 쪽으로 화살표를 그려요" / en "Draw each arrow from the bigger number to the smaller" / zh "箭头从大数指向小数".
- **인쇄**: `nlVisualHtml` 에 삼각형 SVG(draw: 변에 빈 화살표 자리, fill: 화살표 + 빈 원 + 수 상자). 정답지는 `3>2·7>3·7>2` 식.
- **치환**: "변을 눌러 화살표를 그려요" → "화살표를 그려요", "수를 눌러 놓아요" → "수를 써요".

### 3-8. 7쪽④ 묶고 남은 수 (B)
- **현재**: `tapCount` 는 "탭한 것만 센다". **확장 `ask:'rest'`**: `items` 가로 한 줄(`x,y` 없이) T 개, 앞의 k 개는 **묶음 표시**(`ring:true`, 둥근 윤곽선, 탭 불가) → 묶지 않은 별을 세어 답한다. `{widget:'tapCount', ask:'rest', items:[…{e,ring?,t}…], ring:k, answer:T-k, emoji:'⭐'}`. 보기 3개는 기존 자동(`answer±1,2`, `:873`) — 정답 `T-k` 가 1 이상이어야 하므로 `k ≤ T-1`. 교재의 별 7~8개, 왼쪽 수 4 처럼 `T 6~9, k 2~5`.
- **3언어**: ko "왼쪽 4개를 묶었어요. 남은 별은 몇 개?" / en "4 on the left are grouped. How many stars are left?" / zh "左边4个圈起来了，还剩几颗星？".
- **인쇄**: `nlGlyphRows` 한 줄 + 앞 k 개를 묶는 괄호(`nm-nl-ring` 윤곽선 CSS 신규) + 답칸(개). 이것은 뺄셈 개념의 첫 맛보기이므로 N-06 가르기와 겹치는 점은 문제 없음(같은 수 구조).

### 3-9. 10쪽·13쪽① 쌓기나무 개수 비교 (C+D)
- G1-1 명세 3-11 의 `blockCount` 와 **같은 위젯**, `bmode:'cmp'`(T-CMP 6).
  ```
  { widget:'blockCount', bmode:'cmp', heightsA:[[..]], heightsB:[[..]], answer:1|2, withCounts?:true }
  ```
  - 두 그림의 총 개수가 **달라야** 하고(`ΣA ≠ ΣB`), 합 5~9. 교재 10쪽 첫 예시(9 > 7)처럼. 가려진 블록 규칙·생성 제약은 G1-1 명세와 동일(`hidden:0` 기본, main 후반 `hidden:1`).
  - **단순화(D)**: 교재는 두 그림의 개수를 각각 □에 쓰고 ○에 부등호를 쓴다. 기본은 **부등호만**(`>`/`<` 두 버튼, 코드 1/2); `withCounts:true` 일 때 먼저 각 그림 아래에서 개수 3지선다 두 번(작은 칩)을 거친 뒤 부등호를 고르게 한다(스레드 레벨 6 상위 단계, 유닛에는 쓰지 않음).
  - `onAnswer`: `>`=1, `<`=2 (왼쪽 그림이 더 많으면 1).
- **인쇄**: 두 쌓기나무 SVG 사이에 `□ ○ □` 틀 — 교재와 같은 모양. 정답지 `9 > 7`(생성기가 `sumA`,`sumB`를 싣는다).
- **그림**: `block-iso`(쌓기나무, G1-1 과 공용 소품).

### 3-10. 13쪽⑤ 하나 더 많게 놓기 (B)
