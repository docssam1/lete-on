# G1-10호 명세 — 더하기와 빼기 I (이야기·자료 정리)

교재 12개 활동(2~13쪽, 두 바퀴: 숫자 이야기 → 생활 속의 수학 → 틀린 부분 찾기 → 문장제 만들기 → 조사/분류 → 확인학습)을
유아 단계(과정 C0, N-10, 스레드 NL)로 옮기는 설계도. 교재 PDF 쪽을 직접 보고 확인했다(조사하기 6쪽·분류하기 12쪽·확인학습 7쪽·문장제 만들기 11쪽 등).
교재 문장은 그대로 옮기지 않고 사람·소재·수를 바꾼다. **수 범위는 9 이내**, 글은 짧게(음성 낭독 전제).

## 0. 코드로 확인한 전제 (이 호 명세 전체가 기대는 사실)

- 유닛은 `practice` 1개 생성기(+params) · `lab` 1개 생성기(+params)만 가진다(`data/units/N-12.js` 등, `main.js genProblem(cfg)`는 `cfg.generator`+`cfg.params`만 읽음).
  → 한 유닛에 모드가 여럿이면 (a) 생성기 안에서 rng로 갈라 쓰거나(`nl1_count`가 `roll`로 장면을 섞는 방식) (b) 스레드 레벨(`NL#`의 `levels[].params`)로 나눠 과정 C0 세션 드릴(`data/courses.js` `perSessionDrills`, `@레벨`)에서 부른다.
  **기존 `NL1~NL16`의 레벨 id(1~3)는 `courses.js`가 `@2`,`@3`으로 참조하므로 바꾸지 말 것.** 새 모드는 새 레벨 id(4~)나 새 스레드로 붙인다.
- 채점은 위젯이 `onAnswer(값)`을 부르면 호스트가 `+val===answer`(숫자) 또는 `val.length===answer.length && every(+v===answer[i])`(배열)로 비교한다(`main.js` 3150·4726·5332행). 사용자 정의 검증 함수가 **없다**.
  → 정답이 여럿일 수 있는 열린 활동은 **위젯이 규칙으로 직접 판정한 뒤 정규화한 답(합·개수 등)을 `onAnswer`로 올린다**(`dotToDot`가 다 이으면 `onAnswer(problem.answer)`를 부르는 것과 같은 방식).
- 학습지는 `check-answerable.js`가 `problem.answer`(숫자 또는 배열)를 입력칸에 쳐 넣어 만점이 나와야 통과한다 → 답은 **입력 가능한 숫자/숫자 배열**이어야 하고 위젯 전용 sentinel은 피한다.
- 인쇄: `tex`가 없는 NL 문항은 `exam.js nlVisualHtml(p)`(그림) + `nlPrintAsk(p)`(문구) + `nlAnswerLabel(p)`(정답지 말)로 찍힌다. **새 `widget` 이름은 이 세 함수에 분기를 추가해야 하고, 안 하면 빈 카드가 나간다**(`nlVisualHtml`은 모르는 widget이면 `''`).
- 중복 제거 키 `problemKey()`(`exam.js` 4899행)는 **필드 화이트리스트**만 본다. 새 필드를 안 넣으면 서로 다른 문항이 같은 키가 되어 `NM_UNIQUE_POOL_EXHAUSTED`가 난다 → 각 모드마다 아래 "키 필드"를 화이트리스트에 추가.
- 새 문구는 `data/tts-map.js`(음성 MP3 매핑, `scripts/generate-nm-audio.js`)에 없으면 기기 음성(`_sayWeb`)으로 폴백한다. 유아 단계는 음성이 본체이므로 새 문구 생성 후 오디오 재생성 필요.
- 현재 앱 N-10 = "자료 분류와 표"(`nl10_data`: `sort`/`compare`, 두 종류 바구니 `sortBasket`, 한 종류당 2~6개), N-15 = "문장제와 논리"(`nl15_logic`: `story` 더 받음/덜어냄 `storyCard`+numpad, `sort`).
  교재 10호와 가장 가까운 기존 자산이며, 교재가 요구하는 표(3~5종)·합/차 질문·틀린 곳 찾기는 없다.

## 2. 활동별 상세

### 2·8쪽 숫자 이야기 — 결정 C

- **교재**: 짧은 이야기 속 빈칸 3~4개에 [보기] 2~4개의 수를 골라 채운다(모둠 인원/안경 쓴·안 쓴 수, 사탕 중 빼 놓고 나눠 먹기, 스티커 받은 장수). 정답은 문장 흐름에서 **하나로 정해진다**.
- **앱 현황**: 없음. 가장 가까운 것은 `numberBond`(위 원 전체, 아래 두 원 부분)이지만 이야기 문장 속 빈칸·보기 고르기는 없다.
- **유닛·레벨**: N-10 `practice`를 새 mode로 교체(기존 `nl10_data sort/compare`는 스레드 NL15에 그대로 남아 있어 손실 없음). 새 스레드 `NLG10a`(작업용 이름 — 최종 NL 번호는 통합 시 부여) 레벨 1(빈칸 2·보기 3) / 레벨 2(빈칸 3~4·보기 4).
- **생성기**: `NM_TGEN['nlg10_storyfill'](params{level}, rng)`
- **problem 스키마**
  ```js
  { prompt:{ko,en,zh},            // "이야기의 빈칸에 알맞은 수를 골라 넣어요" (낭독용)
    widget:'slotFill',
    text:{ ko:'우리 모둠은 {0}명이에요. 모자를 쓴 친구가 {1}명, 안 쓴 친구가 {2}명이에요. 쓴 친구가 더 많아요.', en:…, zh:… },
    slots:3,                       // {0}~{2}
    chips:[5,2,3,8],               // 셔플된 보기(정답 수 + 방해 수)
    answer:[5,3,2], answerType:'numbers',   // 빈칸 번호 순서
    tmpl:'whole2' }                // 키 필드
  ```
- **템플릿 3종**(전부 새로 쓴다. 교재 소재와 다르게: 안경→모자, 사탕→딸기 등)
  1. `whole2`: 전체 W = 부분 a + 부분 b, "더 많은 쪽을 먼저 말함" 단서 포함(a>b). 슬롯 {W, a, b}.
  2. `take`: "W개 중 r개를 빼 놓고 둘이 나눠 먹었어요. 한 명은 x개, 다른 한 명은 y개(x가 더 많아요)". 슬롯 {W, r, x, y}, W−r=x+y, x>y. 보기 4개 전부 사용.
  3. `give2`: 합계 W = 두 번 받은 a, b("발표로 받은 것이 더 많아요"). 슬롯 {W, a, b}.
- **수 범위·난이도**: 모든 수 1~9, W≤9. 레벨1은 `whole2`(보기 3 = 정답만, 방해 없음 → 문장 순서와 단서만 읽으면 풀림), 레벨2는 3종 전부 + 방해 수 1개(보기 4).
- **유일해 보장(필수)**: 생성기가 보기의 모든 배정(≤4!)을 전수 검사해 **단서(a>b 등)를 만족하는 배정이 정확히 1개**일 때만 채택한다. 아니면 재추첨. (교재도 흐름으로 하나로 정해지게 쓰여 있어, 앱이 이걸 보장해야 "아무거나 눌러도 정답"이 안 된다.)
- **위젯 `slotFill`(신규) 화면 동작**: 이야기 문장이 줄바꿈 가능한 인라인 텍스트로 나오고 `{i}` 자리에 빈 상자가 놓인다. 아래에 보기 칩(큰 숫자 버튼). 상자를 탭하면 포커스(기본은 가장 앞 빈 상자), 칩을 탭하면 포커스 상자에 들어가고 칩은 흐려진다. 채워진 상자를 탭하면 칩이 돌아간다. 모두 채우면 ✔ 활성 → `onAnswer([v0,v1,…])`. 🔊 버튼은 `NM_SAY`로 이야기 전체를 다시 읽는다(`storyCard`의 replay 버튼과 같은 방식). 오답이면 `shake()`+ 칩 반환(호스트 오답 처리는 기존 위젯과 동일).
- **인쇄**: `nlVisualHtml`에 `slotFill` 분기 — 문장을 그대로 싣고 `{i}`를 12mm 답 상자(□)로 찍고, 문장 오른쪽(또는 아래)에 `[보기]` 둥근 상자에 칩 수를 나열. `nlPrintAsk`는 prompt 그대로. 정답지: `5, 3, 2`(빈칸 순서). `nlAnswerLabel` 필요 없음(배열은 기본 출력).
- **판정**: 배열 완전 일치. 부분 점수 없음.
- **3언어 요령**: 수사 어순이 달라 문장은 3언어를 **각각 새로 쓴다**(번역 아님). en은 "There are {0} kids in our group." 식 짧은 문장, zh는 "我们小组有{0}个人。"
- **소품**: 보기 상자·칩은 UI. 문장 소재는 기존 NM_OBJECTS(딸기·사탕·별·풍선)로 충분 → 새 그림 없음.
- **키 필드(화이트리스트 추가)**: `tmpl`, `chips`, `text`, `slots`.

### 3·9쪽 생활 속의 수학 — 결정 B (+ 3쪽 윷놀이 문항은 D)

- **교재**: 글(설날 / 놀이공원 일기)을 읽고 4~5문항에 숫자로 답한다. 필요한 정보만 골라 쓰는 문항, **함정 정보**(입장료 낸 사람 수, 김밥 줄 수 등) 포함. 읽기량이 많다.
- **앱 현황**: `nl15_logic mode:'story'`(`storyCard` numpad)가 "처음 n개 + 더 받음/줌 → 지금 몇 개" 한 줄 이야기만 한다. 다문장 이야기·정보 고르기 없음.
- **결정**: 기존 `storyCard`에 `layout:'facts'`를 **추가(B)**. 글은 3~4개의 **사실 카드**(그림+한 문장)로 쪼갠다 — 5~7세는 긴 글을 못 읽으므로 음성으로 읽어 주고 카드 그림을 보며 답한다. 3쪽의 윷놀이 규칙문항은 규칙 설명 자체가 읽기 난이도의 대부분이라 **삭제**하고 같은 칸에 "나이 차이"·"세배 횟수 합" 문항으로 대체.
- **유닛·레벨**: 새 모드 `nlg10_facts`를 N-10 `lab` 후보 또는 NL13(이야기 셈과 분류) 신규 레벨 4로. (`nl15_logic`는 키가 이미 `story`/`sort`를 쓰므로 새 키 `nlg10_facts`로 분리 — 기존 모드 동작 불변.)
- **problem 스키마**
  ```js
  { prompt:{…},                         // 질문 한 줄("공연을 본 사람은 모두 몇 명일까요?")
    widget:'storyCard', interaction:'numpad', layout:'facts',
    facts:[ { icon:'🎈', text:{ko,en,zh}, use:true },     // use=true: 정답 계산에 쓰는 정보
            { icon:'🍬', text:{ko,en,zh}, use:true },
            { icon:'🐟', text:{ko,en,zh}, use:false } ],  // 함정(질문과 무관)
    ask:'sum'|'diff'|'pick',           // 키 필드
    answer:6, answerType:'number' }
  ```
- **문항 유형**(4쪽·5쪽 문항을 변형): `pick`(카드에서 한 값을 그대로 읽기), `sum`(두 카드의 수 합), `diff`(두 카드 수의 차). 함정 카드는 레벨2에서만 1장 포함. 수는 전부 1~9, 합 ≤ 9.
- **위젯 변경**: `renderStoryCard`에 `layout==='facts'` 분기 — 카드 3~4장이 세로로 쌓이고(`.nm-sc-fact`: 아이콘 + 짧은 문장), 아래 numpad(`interaction:'numpad'`, 최대 2자리 `numpadState(screen,2)` 기존 그대로). 카드를 탭하면 외곽선 강조(기억 보조용, 판정과 무관). 🔊는 카드 순서대로 낭독.
- **인쇄**: `nlVisualHtml`의 `storyCard` 분기에 `layout==='facts'` 추가 — 사실 카드를 2열 박스로 찍고 하단 `nlAnsBox(단위)`. 질문은 `nlPrintAsk`.
- **판정**: 숫자 하나. 함정 정보를 골라 쓴 오답(예: 합계에 함정 수를 더함)은 그냥 오답.
- **소품**: 놀이공원 소재는 새 그림 부담이 커서 **기존 16종·동물 10종**으로 바꾼다(풍선 타기·사탕 사기 등). 새 소품 없음.
- **키 필드**: `facts`, `ask`.

### 4·10쪽 틀린 부분 찾기 — 결정 C (교재는 자유 서술 E → 선택형으로 전환)

- **교재**: 수 관계가 어긋난 1~2문장에서 틀린 곳을 찾아 쓴다("사탕 5개를 형이 3개 가지면 동생은 3개…"). 4쪽 5문항, 10쪽 6문항(더 많다/적다, 전체 합 오류).
- **앱 현황**: 없음. 자유 쓰기는 자동 채점이 안 된다.
- **변형**: 두 단계 선택. ① 문장에서 **밑줄 친 3곳 중 틀린 곳을 탭** ② 바르게 고친 수를 **3택 칩**에서 고른다. 5~7세라 문장은 한 줄(8~12어절)로.
- **유닛·레벨**: 새 모드 `nlg10_errorfind`, 신규 스레드 레벨(쉬움: 합/남은 수 / 어려움: 더 많다·적다·전체).
- **problem 스키마**
  ```js
  { prompt:{ko:'틀린 곳을 눌러 보고, 맞게 고쳐 봐요',…},
    widget:'errorFind',
    segs:[ {t:{ko:'딸기 ',en:'…',zh:'…'}},
           {part:0, t:{ko:'5개 중',…}}, {t:{…}},
           {part:1, t:{ko:'2개를 먹었더니',…}}, {t:{…}},
           {part:2, t:{ko:'4개가 남았어요.',…}} ],   // part=밑줄 낱말(0..2)
    badPart:2,
    fix:{ choices:[3,4,5], correct:3 },
    answer:3, answerType:'number',                    // = fix.correct
    kind:'rest'|'sum'|'more'|'total' }
  ```
- **오류 생성 규칙**: 먼저 **맞는 상황**을 만들고(예: 5−2=3) 수 한 곳만 ±1~2로 틀리게 바꾼다. 틀린 곳은 반드시 1곳. 고칠 수는 보기 3개(정답 + 틀린 수 + 이웃 수), 수 범위 0~9. `more`(더 많다/적다 방향 오류)는 낱말을 뒤집는 형태라 숫자 답이 안 나오므로 **쓰지 않거나** `fix.choices`를 두 낱말로 하고 `answer`는 0/1 인덱스(`balanceScale`과 같은 규칙) — 1차 구현에서는 **생략**을 권장.
- **위젯 `errorFind`(신규) 화면 동작**: 문장이 줄바꿈 가능하게 나오고 밑줄 3곳이 탭 버튼. 맞는 곳을 탭하면 "여기는 맞아요!"(짧은 말풍선, 호스트에는 아직 알리지 않음), 틀린 곳을 탭하면 그곳이 비어(…) 보기 칩 3개가 아래에 나온다. 칩을 탭하면 `onAnswer(칩값)`. **1단계에서 틀린 곳이 아닌 데를 2번 고르면 `onAnswer(-1)`**(오답 처리, 단계 반복 없음). 이렇게 하면 호스트는 숫자 하나만 본다.
- **인쇄**: 문장에 ①②③ 번호 + 밑줄, 하단 두 답칸 "틀린 곳 □번 → 바른 수 □". 정답지 `nlAnswerLabel`에 `errorFind` 분기: `②번 → 3`(`p.badPart+1`, `p.answer`).
- **판정**: 최종 수 하나(`answer`)만 채점. 틀린 곳 선택은 진행 단계일 뿐.
- **소품**: 없음(문장+기존 소품).
- **키 필드**: `segs`(또는 `kind`+`badPart`+`fix`).

### 5·11쪽 문장제 만들기 — 결정 E (자유 작문) → 선택형으로 대체

- **교재**: 식 또는 그림이 주어지고 어울리는 이야기 문제를 **직접 써 넣는다**(표: 그림/식/문제). 첫 예시만 이야기→식·답.
- **앱 현황**: `nl15_logic story`가 이야기→수 구하기는 한다(A). 반대 방향(식/그림→이야기)은 없다. 참고로 `wp.js` WP6("문제 만들기")가 이미 **식→이야기 3지선다**로 풀었고 원장 승인 문구("영어처럼 고르기")가 있다 — NL 유아 단계는 글이 길면 안 되므로 **그림 중심의 가벼운 판**을 새로 둔다(WP6의 `storyOf` 문장은 유아에겐 길다).
- **대체안(E)**: 두 가지 선택형.
  1. `pic2eq`(그림→식): 그림(꽃 3송이 + 화분 5개 같은 두 줄)을 보고 알맞은 식을 3택에서 고른다. 오답 2개는 연산 기호가 다르거나 수가 하나 다른 식.
  2. `eq2story`(식→이야기): "5−3" 이 주어지고 그림 카드 3장 중 이야기가 맞는 것을 고른다(카드: 그림 + 한 문장 낭독). 오답은 덧셈 이야기, 수가 다른 이야기.
- **유닛·레벨**: 새 모드 `nlg10_pickstory` 레벨1(`pic2eq`) / 레벨2(`eq2story`).
- **problem 스키마**
  ```js
  { prompt:{…}, widget:'choiceCards',
    stem:{ rows:[ {e:'🌼', n:3}, {e:'animal:…또는 토큰', n:5} ] } | { eq:'5 − 3' },   // 제시
    cards:[ { text:{ko:'5 − 3 = 2',…} }, { text:{…} }, { text:{…} } ],              // 보기 3 (pic2eq: 식 / eq2story: pic+text)
    answer:1, answerType:'number', mode:'pic2eq'|'eq2story' }
  ```
- **위젯 `choiceCards`(신규, 범용)**: 카드 3장이 가로로 놓이고(좁으면 세로), 탭 = 즉시 판정(`balanceScale` 접시와 같은 동작: 정답이면 `on` 클래스, 오답이면 `shake`, `onAnswer(index)`). `stem.rows`는 위쪽에 두 줄 그림(개수만큼). 카드 위치는 rng 셔플(정답 번호 고르게).
- **인쇄**: 그림 + ①②③ 보기 → "맞는 것에 ○". 정답지 `nlAnswerLabel`: `choiceCards` → `①`/`②`/`③`(`NL_CIRC[answer]`).
- **판정**: 인덱스 하나.
- **소품**: 꽃(🌼 있음), 화분(`flowerpot`, **신규**), 원숭이(**신규 동물**). 교재 그림을 베끼지 않고 자체 그림. 소재를 기존 토큰으로 바꾸면 신규 소품 없이도 가능(예: 꽃 대신 딸기·별).
- **키 필드**: `stem`, `cards`, `mode`.

### 6쪽 조사하기 — 결정 C

- **교재**: 4×5 격자에 과일 5종(사과·참외·바나나·수박·포도)이 섞여 있다. ① 종류별로 세어 표에 쓴다 ② 많고 적음 ③ 두 종류의 합 ④ 가장 많은 것과 가장 적은 것의 차.
- **앱 현황**: `sortBasket`이 **2종류**를 바구니에 나눠 담고 개수를 세는 것까지만(`nl10_data`/`nl15_logic sort`, 한 종 2~6개). 3종 이상·표·합/차 질문 없음. 표 형식(교재의 핵심)은 앱에 없다.
- **유닛·레벨**: N-10 `lab`(= 교재 "조사/분류" 대응). 새 모드 `nlg10_survey`:
  - 레벨1 `tally3`: 3종·격자 3×3~3×4(≤12칸) → 표 채우기
  - 레벨2 `tally5`: 4~5종·격자 4×4~4×5 → 표 채우기 (칸 수 20이어도 각 종류 ≤9개)
  - 레벨3 `ask`: 표가 이미 채워져 있고 질문 하나(합/차/가장 많은 것) → 숫자
- **problem 스키마**
  ```js
  { prompt:{…}, widget:'surveyGrid',
    cols:5, rows:4,
    cells:['🍎','🍌',…],            // 행 우선, 길이 = cols*rows
    kinds:['🍎','🍌','animal-또는-새토큰…'],  // 표 열 순서
    counts:[5,4,…],                 // 진짜 개수(생성기가 cells에서 센 값)
    askMode:'tally'|'ask',
    ask:{ type:'count'|'sum'|'diff'|'most', a:0, b:2 },   // askMode='ask'일 때
    answer:[5,4,…] | 숫자, answerType:'numbers'|'number' }
  ```
- **제약**: 각 종류 개수는 1~9. `sum` 질문은 두 종류 합 ≤ 9. `diff`/`most`는 **가장 많은 종류와 적은 종류가 유일**하도록 개수를 정한다(동점이면 재추첨). 합계(칸 수) = rows×cols.
- **위젯 `surveyGrid`(신규) 화면 동작**: 위에 과일 격자. 칸을 탭하면 작은 ✓가 붙어 센 칸 표시(판정과 무관, 한 칸 다시 탭 = 해제). 아래 표: 종류별 아이콘 머리글 + 숫자 입력칸. `tally` 모드는 칸마다 `−  숫자  +` 스텝퍼(0~9) → ✔로 `onAnswer([…])`. `ask` 모드는 표가 읽기 전용이고 아래 numpad(1~2자리) → `onAnswer(n)`.
- **인쇄**: 격자 + 표. `tally`는 표 아래 칸 빈 상자, `ask`는 표 값 채우고 질문 문장 + 답칸. 정답지 = 배열 또는 숫자(기본 출력).
- **판정**: `tally` 배열 완전 일치, `ask` 숫자 하나.
- **소품**: 과일 — 사과·바나나·딸기는 기존 NM_OBJECTS. 교재 5종 중 **참외·수박·포도 신규**(실사 PNG 3개). 5종이 부담이면 레벨2는 사과·바나나·딸기·수박·포도로 시작.
- **키 필드**: `cells`, `kinds`, `ask`, `cols`, `rows`.

### 12쪽 분류하기 — 결정 C

- **교재**: 14일 날씨표(맑음/흐림/비, 2×7)에서 종류별 날수, 합쳐 세기(흐림+비), 맑은 날 − 비 온 날.
- **앱 현황**: 없음(3종 분류·합/차 없음).
- **변형**: `nlg10_survey`의 weather 변형. **칸 수를 7~9로 줄인다**(교재 14일은 합이 14라 수 범위 9를 넘는다): 1×7(일주일) 또는 3×3. 세 종류(맑음·흐림·비), 질문: 종류별 날수 / 흐림+비(합 ≤ 9) / 맑음−비(맑음>비).
- **위젯·스키마**: `surveyGrid` 그대로(`kinds:['weather-sun','weather-cloud','weather-rain']`).
- **인쇄**: 날씨 기호는 인쇄에서 단순 선화여도 되도록 원본 아이콘 3개.
- **소품**: 맑음(해)·흐림(구름)·비 3종 **신규**(작화지시서에 sun/cloud 계열은 N-01 이야기 소품 목록에 있으나 `NM_OBJECTS`에는 없음 — 따로 토큰 `weather-sun`/`weather-cloud`/`weather-rain` 등록).

### 7·13쪽 확인학습 — 결정 D (모드 재활용 + 변형)

교재 12문항을 아래로 분해한다. 글이 길거나(곱셈·나눗셈 맛보기) 서술형 작성(문제 만들기)인 것만 변형·대체한다.

| 교재 유형 | 처리 | 모드 |
|---|---|---|
| 구슬 8개 중 1개를 빼 놓고 나머지를 두 손에 나눔(7쪽 1번) | **D** 두 단계 → 한 단계씩 쪼갬 | `nl15_logic` 확장 `twostep` kind `take-split`: 처음 W, 뺌 r, 한쪽 x → 다른쪽 y=W−r−x |
| 9개 중 3개 먹고 남은 수(7쪽 2번), 6명 중 2명 안경(13쪽 2번) | A | 기존 `nl15_logic story`(덜어냄) |
| 5개/1개 가진 두 사람이 **같게** 나누기(7쪽 3번) | **D** 계산 대신 옮기기 조작 | 신규 `nlg10_equalize`, 위젯 `moveEqual` |
| 연필 5+2(7쪽 4번), 구슬 2+4(13쪽 4번 일부) | A | `nl15_logic story`(더 받음) |
| 닭 N마리, 오리는 2마리 더 많다 → 합(7쪽 5번) | **D** 두 단계 | `twostep` kind `more-total` |
| 8권과 5권, 몇 권 더(13쪽 3번) | B | 기존 `wpScene`의 `pair` 모드(두 줄 짝짓기)를 NL에서 재사용하거나 `storyCard`에 `rows` 추가 — 아래 참조 |
| 3개씩 2봉지(13쪽 1번) | **D** 곱셈이 아니라 "묶음 세기" 그림 | `storyCard` `layout:'groups'` |
| 공책 6권을 둘이 똑같이 나눔(13쪽 5번) | **D** 두 접시에 하나씩 나누기 | `nlg10_equalize`(총 6, 두 칸 빈 상태에서 하나씩 놓아 같게) 변형 `share` |
| 그림에서 뺄셈 문제 만들기/문장 읽고 문제 만들기(7쪽 6번, 13쪽 6번) | **E** → 대체 | `nlg10_pickstory`(`eq2story`) |

- **`twostep`(nl15_logic 확장)**: problem은 `storyCard`(`interaction:'numpad'`)이며 `layout:'rows'`(신규): `rows:[{tok:'🍬',n:4,label:{ko,en,zh}}, {tok:'🍬',n:6,…}]`을 위아래로 보여 줌. 질문은 한 줄. 수 범위 합 ≤ 9. 정답 숫자 하나. 인쇄 `nlVisualHtml`의 `storyCard` 분기에 `layout==='rows'` 추가(두 줄 `nlGlyphRows`).
- **`groups`**: `storyCard` 신규 `layout:'groups'`: `groups:[3,3]`(봉지 수 = 배열 길이, 각 봉지 안 개수). 봉지 아이콘 안에 물건. 질문 "모두 몇 개?". 조합: 2×2, 2×3, 2×4, 3×2, 3×3, 4×2 → 합 ≤ 9. 곱셈 기호는 쓰지 않고 "똑같이 모아 세기"로만.
- **`moveEqual`(신규 위젯)**: 위·아래(또는 좌우) 두 접시에 개수 a>b가 놓여 있고 a−b는 짝수. 많은 접시의 물건을 탭하면 하나가 반대쪽 접시로 날아간다. **두 접시가 같아지면** 자동으로 `onAnswer(옮긴 개수)`(= (a−b)/2). 너무 많이 옮겨 역전되면 되돌리기 버튼. `share` 변형은 총 n개가 한쪽에 있고(두 번째 접시 비어 있음) 하나씩 번갈아 나눠 같게 만든 뒤 `onAnswer(한 접시 개수)`.
  - 키 필드: `pans`(두 개수 배열)·`mode`.
- **인쇄**: `moveEqual` → 두 접시 그림 + 답 칸("몇 개를 옮겨요? □개"). `nlAnswerLabel` 불필요.
- **소품**: 사탕·바둑돌(구슬 대용)·딸기(기존), 곰(기존 동물 `bear`), 꿀단지·원숭이(신규, 대체안에서만 선택).

## 3. 이 호가 요구하는 새 위젯 / 새 소품 / 새 인쇄 표현 총정리

### 새 위젯 (`app/widgets.js` `render()` switch에 이름 추가)
| 이름 | 용도 | 비고 |
|---|---|---|
| `slotFill` | 이야기·식 속 빈칸에 보기 칩 넣기 (숫자 이야기, G1-11 세 수 식 만들기와 공용) | 답은 배열, 칩 전수검사로 유일해 보장 |
| `errorFind` | 틀린 곳 탭 → 바른 수 3택 | 답은 바른 수 하나 |
| `choiceCards` | 카드 3택 즉시 판정 (그림→식, 식→이야기, 순위 고르기) | 범용. G1-11 확인학습 "둘째로 큰 수"에도 재사용 |
| `surveyGrid` | 그림 격자 + 표(스텝퍼/읽기전용) | 과일·날씨 공용 |
| `moveEqual` | 접시 간 옮겨 같게 만들기 | D 변형 전용 |

### 기존 위젯 확장
- `storyCard`: `layout:'facts'`(사실 카드), `layout:'groups'`(묶음), `layout:'rows'`(두 줄 비교).
- `nl.js`: `nl15_logic`에 `twostep`(kind `take-split`·`more-total`) 추가(새 키로 분리해도 됨).

### 새 소품(실사 PNG, `app/object-art.js` `NM_OBJECTS` 토큰)
- 과일: `melon`(참외), `watermelon`(수박), `grapes`(포도) — 사과·바나나·딸기는 기존.
- 날씨: `weather-sun`, `weather-cloud`, `weather-rain`.
- (선택) `flowerpot`(화분), 원숭이(동물 11번째), `honeypot`(꿀단지). 모두 대체 소재가 있어 필수는 아님.
- 기존 16종·동물 10종으로 해결되는 것: 사과·딸기·사탕·바둑돌·풍선·별·꽃·곰·오리·토끼.

### 새 인쇄 표현 (`exam.js`)
- `nlVisualHtml`: `slotFill`(문장+빈 상자+보기 상자), `errorFind`(번호 붙은 밑줄 문장+두 답칸), `choiceCards`(그림+①②③ ○표), `surveyGrid`(격자+표 / 표+질문), `moveEqual`(두 접시), `storyCard` 하위 `facts`·`groups`·`rows`.
- `nlAnswerLabel`: `errorFind` → "②번 → 3", `choiceCards` → "①~③".
- `nlPrintAsk`/`NL_PRINT_WORDS`: 새 prompt의 화면 동사("눌러", "탭", "골라")를 인쇄 동사("○표", "써요")로 바꾸는 항목 추가.
- `problemKey` 화이트리스트: `tmpl`,`chips`,`text`,`slots`,`segs`,`badPart`,`fix`,`kind`,`facts`,`ask`,`stem`,`cards`,`mode`,`cells`,`kinds`,`cols`,`rows`,`pans`,`groups`.
- 새 문구 오디오: `scripts/generate-nm-audio.js`로 `data/tts-map.js` 재생성.

### 교재와 일부러 달라지는 점 (원장 확인 용)
- 3쪽 윷놀이 규칙문항 삭제. 12쪽 14일 날씨표를 7~9칸으로 축소(수 범위 9).
- 5·11쪽 문장제 **작문**은 선택형으로 전환(자동 채점 불가).
- 13쪽 묶음 곱셈형은 "똑같이 모아 세기" 그림으로, 같게 나누기는 옮기기 조작으로 낮춤.
