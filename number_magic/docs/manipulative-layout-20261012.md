# 기본 교구 화면 후속 — 2026-10-12

## 요청·범위

원장님 "다음 진행할 것은?"에 ① 다른 교구 화면 점검을 먼저 제안했고, "진행"에 따라 구현합니다.
기준은 넘버스 릴리스 `f17fe98a`, 작업 시작 main `a1c6ee3f`입니다.
브랜치 `codex/numbers-manipulative-layout-20261012`, 결과물은 E:에 저장합니다.

학습 화면의 일은 한 문항을 조작하고 답을 확인하는 것입니다.
안내 → 교구 → 답 확인을 구분하며 PC는 안내 왼쪽·교구 오른쪽, 휴대폰은 안내 위·교구 아래입니다.
기존 종이색·승인 실사 그림·연령/언어별 글꼴은 유지합니다.
짧은 휴대폰 대화는 기존 손글씨를 26px로 표시합니다. 숫자·기호는 그대로 산세리프입니다.
새 장식·이미지·WebGL·애니메이션은 추가하지 않습니다. 이번 범위에 마을·광고·과학은 포함하지 않습니다.

대상은 `g13Rep`(손가락/10칸 짝 맞추기), `numberBond`(모으기), `splitDraw`(가르기 5겉모습),
`hopLine`(수직선 읽기/눈금 선택)입니다. 다른 위젯은 기존 레이아웃을 유지합니다.

## 수정 전 확인

실제 생성기를 사용한 20조건 측정에서 PC 1280×720의 짝 맞추기는 바깥 스크롤 360px,
접시/케이크 가르기는 695/880px가 발생했습니다.
휴대폰 390×844에서 접시/케이크는 232/352px, 모으기는 162px,
수직선 읽기/그리기는 75/114px였습니다. `before/manipulative.json`에 측정/원문/문항을 보관합니다.
원인은 기존 PC zoom 및 dense 자동 배치, 여러 방법을 세로로 모두 쌓는 구조입니다.

## 구현 원칙

- 원래 문항·그림·숫자/보기 순서·배열·연결·줄 수·정답 계약·채점·회차·분량 조절은 유지합니다.
- 기존 첫 안내 음성은 유지하되, 첫 화면부터 실제 현재 문항의 원래 지시를 보입니다.
- PC 확대 zoom을 대상 위젯에만 해제하고, 기존 안내/교구 래퍼를 재사용합니다.
- 여러 가르기 방법은 원래 개수와 예시를 전부 보존합니다. PC에서는 가능한 경우 두 열에 배치합니다.
- 좁은 화면의 긴 활동은 교구 안의 방법 목록만 세로로 스크롤합니다. 안내·확인 버튼은 남습니다.
- 아홉 칸 가로 막대/색칠은 한 줄 배열을 바꾸지 않고 44px 누르기 칸을 유지합니다.
  좁은 화면에서는 해당 줄 안에서 가로로 움직입니다. 페이지 전체의 가로 스크롤은 만들지 않습니다.
- 매우 낮은 가로 창은 읽을 수 있는 기존 스크롤 폴백입니다. 작은 글씨/도형으로 억지 압축하지 않습니다.
- 오류 피드백 한 줄의 자리를 예약하여 오답 때 확인 버튼이 밀리지 않게 합니다.
- 케이크 양초는 승인된 정사각 PNG의 넓은 투명 여백만 화면에서 잘라, 실제 양초 높이를 60px로 표시합니다.
  원본 파일은 수정하지 않으며, 양초 수·케이크 두 개·가르기 방법은 유지합니다. 긴 목록은 교구 내부 스크롤입니다.
- 답이 이미 나온 예시만 비활성화하고, 정답/오답 규칙은 기존 위젯에 맡깁니다.
- Enter/Space 조작, Backspace/Delete로 채운 원·접시·반원의 한 물건 지우기,
  수직선 눈금의 좌우 키 이동을 추가합니다. 숫자 값을 다시 계산하거나 대신 채점하지 않습니다.
- 수직선 10눈금은 좁은 폭에서 44px씩 늘리면 이웃 눈금과 겹칩니다. 기존 위치/폭을 유지하고 키보드 이동을 보완합니다.
  원 안 작은 물건 지우기는 기존 그림 크기와 함께 키보드 되돌리기를 제공합니다.
