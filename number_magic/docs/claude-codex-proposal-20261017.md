### 1. 학부모 진입과 기록

1. 두뇌로를 고른 부모에게는 **과정 1~25 번호만** 묻는다. Level·판본·주차·학습지 번호·앱의 전체 시작 범위를 필수 선택으로 요구하지 않는다. 번호에서 Level을 내부 도출하고, 이미 저장되는 숫자 `selection.bookCourseNumber`와 `step=level-*`를 유지한다. `step`을 곧바로 `course-1`~`course-25`로 바꾸면 기존 저장 선택과 진행 중 진단의 호환 처리가 필요하다. 확인 카드에는 ‘두뇌로 과정 N’과 **앱에서 확인할 주제**를 다른 이름으로 표시한다. 후보가 불확실한 행은 부모에게 전체 앱 목록을 넘기지 말고 짧은 주제 선택이나 학년 경로로 안내한다.
2. 가입 시 저장한 `schoolAge.entryYear`는 **3월 기준 학년의 근거**이지 생년월일·현재 나이가 아니다(`app/main.js`). 화면에는 확인 가능한 학년만 미리 보여 주고 수정할 수 있게 한다. 가입 때 학년을 건너뛴 사용자도 두뇌로 번호만으로 진입할 수 있어야 한다. 현재 `app/placement-ui.js`의 나이 선행 게이트는 이 흐름에 맞춰 바꾼다. ‘잘 모르겠어요’는 학년/나이 정보가 있으면 그 경로, 없으면 간단한 추가 질문으로 간다.
3. 첫 카드의 ‘없어요’를 곧바로 ‘처음 배워요’에 연결하면 교재 없이 이미 공부한 아이도 수 세기부터 검사한다. **‘교재 없이 공부했어요’와 ‘처음 배워요’를 구분**한다. 제안의 대표 교재 카드 바깥에 현재 지원하는 원리셈·창의셈 등 ‘다른 교재’ 진입도 남긴다. 기적의 계산법은 같은 권 번호가 판본마다 겹치고, 구몬·소마셈은 번호 체계가 달라 ‘번호 하나’ 규칙을 일괄 적용하지 않는다. 각 교재에서 식별에 꼭 필요한 것만 묻는다.
4. 주차 1~4는 첫 진입에서 받지 않는다. 시작 버튼 비활성 이유를 바로 옆에 쓰고, 비활성 탭의 선택 표시를 바로잡는다. 6/10/4 구성과 목표 설정은 접을 수 있어도 진단 설명에서 확인 가능하게 둔다. ‘보호자·선생님용’은 이 학부모 제품에 맞춰 ‘보호자용’으로 고치고, ‘교사 검수’를 출시 조건으로 두지 않는다. 모바일 숫자 단추의 누름·초점·선택 상태와 재진입을 검사한다.

### 2. A/B안과 25행 초안표

- **A안은 출발 후보로 채택, B안은 자동 기준으로 사용하지 않는다.** 교재 과정 N을 한다는 사실만으로 앞 과정의 모든 주제를 익혔다고 볼 수 없다. 앱에만 있는 주제를 임의로 건너뛰는 B안 규칙도 근거가 약하다. A안에서도 후보는 ‘지금 확인할 곳’일 뿐이다. 현행 `data/placement-plan.js`는 선택한 앱 단계의 **바로 이전 6·현재 10·바로 다음 4문항**만 고정 출제한다. 비인접 공백은 검사하지 못하고, 결과의 본진도는 `data/placement-paths.js`에서 `selected-not-certified`로 유지한다. 따라서 §3의 ‘20문항 진단으로 확정’과 ‘이전 6문항이 순서 차이의 빈칸을 맡는다’는 표현은 ‘인접 범위 표본을 보고 연습 위치를 제안한다’로 고쳐야 한다.
- 초안 25행을 그대로 자동 기준으로 넣기에는 **후보 선택 규칙이 일관되지 않고 앱 과정 범위가 더 넓은 행**이 있다. 예를 들어 3→C2, 10→C9, 12→C10은 ‘그 과정의 첫 새 주제’보다 선행 공백을 우선한 판단이다. 16→C17, 18→C20, 24→C24는 앱의 현재 10문항에 교재 해당 과정에서 아직 다루지 않은 주제가 섞일 수 있다(`data/courses.js`, `data/placement-plan.js`). Claude의 최종 표에서는 **각 행의 우선 주제, 후보를 당긴 이유, 앱 과정 전체 출제 범위, 미확인 주제, 보류 여부**를 따로 대조해 달라. 위험 행은 후보를 보류하거나 주제별 부분집합 진단을 별도로 설계한다. 과정 번호와 앱 번호가 역행하는 것 자체는 오류가 아니지만, 근거 없이 학습 순서를 인증할 수는 없다.
- 사진 판독 근거인 `sourceVerification`과 **앱 시작 후보의 검증 상태**를 별도 필드로 둔다. 전사됐다는 이유만으로 현행 `data/placement-books.js`의 `verification:'verified'`/`baselineId`를 채우면 대표 주제의 좁은 자동 대응과 과정 전체 동등성을 혼동한다. 후보 전용 데이터/상태로 구현하고, 실제 생성된 20문항을 25행 모두에서 확인한 뒤 공개한다. 주차 원문은 계속 Drive에만 둔다.

### 3. 로드맵 5건 의견

1. **C7/C8 경계 방향에 동의한다.** 다만 `data/stages.js`의 범위만 옮기면 C8~10의 현재 `level1` tier와 `scripts/check-stages.js`, 앱 로드맵이 어긋난다. tier는 문항 시간·문장제 정책에도 쓰이므로 표시 단계와 학습 정책의 관계를 먼저 설계하고 `landing.html`·`about.html` 숫자를 실제 회차·주 수로 다시 계산한다. ‘36건 중 31건 해소’는 현재 스토리 장을 통째 옮기는 가정만으로 재현되지 않는다. 장 이동 뒤 남은 차이를 실제 검사 결과와 첫 학습/의도된 복습 목록으로 제시해 달라.
2. 고등 반복은 **C59의 6~9회차가 1~4회차의 교과 유형·레벨을 반복하는 사례**를 확인했다. 같은 기준의 읽기 전용 집계는 46건으로 제안의 48건과 달라, 먼저 집계 정의를 맞춘다. `scripts/check-session-roles.js`는 현재 C0~37까지만 검사한다. 반복 자리를 바꿀 때는 새 레벨을 기계적으로 올리기보다 실제 출제·풀이·시간과 복습 의도를 확인한다.
3. **C29의 CH5 수정에 동의한다.** 출현은 4회차 한 칸에 그치지 않고 4·6·8·10회차 교과 및 여러 전략 칸에 걸친다. C27 경시 소재가 중1 필수 진도로 보이지 않도록 전체 배치를 검토한다.
4. **C0 창의 전략의 난이도 진행에 동의한다.** 19주 내내 1레벨인 것은 전략 NL5·NL11·NL12이고, 적용 문장제 NL9·NL13·NL15는 이미 1→2→3으로 오른다. 전략의 10주 이후 상향은 각 실제 레벨·생성 문항을 확인하며 적용한다.
5. SB6@8은 C6에 실제 있는 다섯 자리 심화라 C13 이동 방향에 동의하지만, C13의 현재 교과 자리가 차 있어 단순 배열 추가로는 출력에서 빠질 수 있다. **MD50@4는 현행 스레드에 없는 레벨**이므로 별도 문제 생성·정수해·풀이·표시 검사가 필요하다. 진도대응 문서 117~119의 ‘없음’ 표기는 C30 MD50@1~3의 실제 위치를 반영해 고치되, 외부 교재 단계와 정확히 같은 내용이라는 주장은 검증하지 않는다.
