## 이 호의 핵심 개념
- 개수(일곱)와 순서(일곱째) 구분 — 왼쪽·오른쪽·위·아래·앞·뒤 기준으로 몇째인지 찾기
- 양쪽 순서수에서 전체 개수 구하기(왼n째+오른m째 → 전체)
- 수의 크기 비교와 >, < 기호, □에 들어갈 수 찾기
- 화살표 상자(삼각형 꼭짓점)로 세 수의 크기 순서 표현
- 순서대로 쓰기(정렬), 최대·최소·기준 수보다 큰/작은 수 찾기

## 앱으로 옮길 때 주의할 점
- **10칸 줄에 색칠(2·8쪽, 7·13쪽 확인학습)**: 개수 줄과 순서 줄을 나란히 보여주는 동일 컴포넌트 필요. '다섯' vs '다섯째' 혼동이 핵심 오답이므로 텍스트 렌더링(한자어/고유어 수사) 정확성이 중요.
- **순서수와 개수(3·9쪽)**: 왼쪽 n째·오른쪽 m째 두 조건이 맞물리는 칠하기. 칸 수가 주어지지 않는 문항(9쪽 3문항)은 앱에서 칸 수를 고정해 제공하는 편이 안전(원본은 학생이 칸을 직접 그림).
- **화살표 상자(6·12쪽)**: 화살표 그리기(방향 선택 UI), 화살표 따라 수 쓰기(숫자 입력) 두 모드. 약속(화살표가 큰 쪽/작은 쪽)이 학습 대상이라 약속 문구를 앱 UI에 일관되게 표시해야 함.
- **쌓기나무 입체 그림(10쪽, 13쪽 1번)**: G1-1 11쪽과 같은 입체 자산이 필요. 렌더링(Three.js/SVG)과 보이지 않는 블록 개수 정의가 필요.
- **부등호 □ 탐색(5쪽)**: 조건에 맞는 수를 모두 고르는 복수 선택 UI 필요. 정답 판정은 집합 일치.
- **손으로 그리는 활동**: 화살표 그리기(6·12쪽), 9쪽 칸 직접 그려 풀기, 13쪽 ⑤ 사탕 ○ 그리기는 터치 그리기보다 '개수 선택' 같은 입력 방식으로 번역해야 판정이 쉬움.
