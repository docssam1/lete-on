# 고등 새 문제 유형 제작 명세 (2026-09-29)

근거: `docs/high-concept-audit-2026-09-28.md` 설계 v2(원장 승인: 고등 = 공통수학1·공통수학2·대수·미적분Ⅰ 네 단계).
교재(Drive 교과연산 J·K·L)는 **챕터 제목만** 근거로 쓴다 — 본문·문제를 옮기지 않는다. 문제는 전부 새로 만든다.

## 한 유형 = 세 조각

| 조각 | 위치 | 본보기 |
|---|---|---|
| 생성기 | `engine/threads/midNN.js` 의 `NM_TGEN['mdNN_이름'] = function(params, rng){…}` | `engine/threads/mid8.js` MD52 |
| 스레드 | `data/threads.js` 의 `MDNN:{name, gen, prereq, unit, concept, widgets, levels:[3개]}` | `NM_THREADS.MD52` |
| 마법 단원 | `data/units/M-NN.js` (`window.NM_UNITS['M-NN']`) | `data/units/M-52.js` |

번호는 스레드와 단원을 같게 한다: **MD91 ↔ M-91** 부터. (M-89·M-90 은 비워 둔다.)

## 지켜야 할 것

- **답은 정수.** 두 칸 답(실부·허부, 두 근 등)은 기존처럼 배열 + `answerType`(MD80 L2 의 "2다칸" 본보기).
  분수·무리수가 답이 되지 않게 **답을 먼저 고르고 식을 역산**한다(MD52 가 x 를 먼저 고르는 방식).
- 문제는 시드 재현(`rng`만 사용, `Math.random` 금지). 같은 레벨 안에서 문제가 충분히 다양해야 한다
  (`scripts/check-answerable.js`·중복 검사가 걸러낸다).
- `tex` 는 KaTeX, 빈칸은 `\\square`. `solution` 단계(빈칸 `blank`)를 넣는다.
- 세 언어(ko·en·zh) 전부. 고등은 **합니다체**. 교재 문장을 베끼지 않는다.
- 레벨 3개 = 교재 챕터의 소유형 순서(연습 → 실전). 레벨 라벨은 기존처럼 "(연습)"·"(실전)".
- 단원(M-NN)은 M-52 와 같은 구조: practice · discover(story hook/history, stages 2~3개, mathSteps, result) ·
  check · lab/arena 가 있으면 그 형식 그대로. **역사 문단은 확실한 사실만**(모르면 짧게, 지어내지 않음).
- `engine/threads/` 파일은 **bash 문자열 치환으로 고치지 않는다** — 파일 쓰기/편집 도구로만.
- 새 엔진 파일·단원 파일은 그것을 읽는 모든 페이지에 등록: `index.html`·`ws.html`·`drill.html`·`level-test.html`
  (그리고 `grep -rn "M-88.js\|mid16.js"` 로 찾은 곳 전부). Node 검사기는 폴더를 통째로 읽는다.
- 과정 편성(`data/courses.js`)은 **건드리지 않는다** — 리드가 한 번에 바꾼다.

## 검사 (끝나면 전부 통과해야 한다)

`node scripts/check-answerable.js` · `check-unit-lang.js` · `check-tone.js` · 그 밖에 `scripts/check-*.js` 중
스레드·단원을 읽는 것 전부(파일 상단 주석으로 확인). 새 유형마다 레벨별로 30문제씩 뽑아
**답을 손으로 다시 계산하는 검산 스크립트**를 scratch 에 만들어 돌린다(눈으로 믿지 않는다).
