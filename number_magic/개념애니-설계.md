# 개념 애니메이션 설계 — 창의수연 85유닛 + 중고등 62유닛 (2026-08-29)

> 원장 지시: "난 우리 개념에도 필요할 것 같아 — 창의수연이나 중고등 뜨는 고학년 연산에."
> 대상 스킬: `skills/gmap-animated-math-lesson` (GFIELD 자체 제작). **포크하지 않고 확장한다.**

## 1. 왜 — 지금 개념 화면의 실제 상태

**유닛 187개 중 186개가 `mathSteps`, 즉 문자열 배열이다. 그림을 그리는 유닛은 1개뿐이다.**

A-05(100의 보수)의 마법 노트:

```js
mathSteps:['25 + 75 = 100  (짝!)', '40 + 60 = 100  (짝!)', '63 + 37 = 100  (짝!)']
```

그런데 이 전략의 본질은 `25+75+54+46` → `(25+75)+(54+46)`로 **짝을 찾아 묶는 동작**이다.
그 움직임이 곧 마법인데 텍스트 세 줄로는 아이가 머릿속에서 상상해야 한다.

| 구간 | 유닛 | 왜 급한가 |
|---|---|---|
| 창의수연 A·C·H | **85** | 전략 자체가 "펼치고·옮기고·묶는" 동작. 정적 텍스트와 가장 안 맞는다 |
| 중고등 M | **62** | `과정-로드맵.md` §13이 "기호가 바뀌는 순간이 진짜 고비"라 못 박고 **말→그림→내 표기→표준 기호** 순서를 규정했는데, **정작 '그림' 단계가 화면에 없다** — 원칙이 문서에만 있는 상태 |

## 2. 원칙

1. **스킬을 포크하지 않는다.** `skills/gmap-animated-math-lesson`에 archetype을 **보태서** 두 앱
   (boarding-school-math, number_magic)이 같은 스킬을 쓴다. 도형 3종(geometry angle·shape count·
   coordinate plane)은 넘버스와 무관하고, 넘버스가 필요한 **수 펼치기 계열이 스킬에 없다** — 그걸 채운다.
2. **장면을 손으로 그리지 않는다.** 생성기 반환값이 곧 장면 객체다(§4).
3. **`mathSteps` 186개를 버리지 않는다.** 각 줄에 `targetIds`를 달아 그림과 잇는다 — 승격이지 폐기가 아니다.
4. **자기보고를 근거로 삼지 않는다.** 이 저장소는 "맞다고 판단한 뒤" 검사기가 12건을 잡은 전례가 있다
   (HANDOFF). 85개를 눈으로 다 볼 수 없으므로 §6 검사기가 먼저 있어야 한다.

## 4. 데이터 계약 — 장면은 생성기에서 나온다

조사 결과 생성기가 **움직이는 대상을 이미 이름 붙여 내보내고 있다.** 손으로 그릴 필요가 없다.

```
comp100        → {nums, sum, pairCount, target:100}   묶기: nums 중 합이 target인 짝
move10         → {a, b, need, rest}                   이사: need를 b→a, a는 10, b엔 rest
splitHundred   → {a, b, rest, comp}                   쪼개기: 100 한 덩이를 떼어냄
digitShiftSub  → {a, b, before, comp}                 쪼개기/이사
addSubGroup    → {nums, plusSum, minusSum}            묶기: 부호별
addSimilarNums → {a, b, ra, rb, adj}                  보정: 라운드 ra·rb로 계산 후 adj 되돌림
gaussAdd1      → {n, pairSum, pairCount}              무지개
```

유닛당 작업은 **"이 생성기의 어느 필드가 이 archetype의 무엇인가"라는 10줄 안팎의 선언적 매핑**이지
장면 하나를 새로 디자인하는 게 아니다.

### 4-1. ⚠️ 두 생성기 계열의 비대칭 — 이것이 이 작업의 유일한 함정

| | 개수 | 내보내는 것 |
|---|---|---|
| `NM_GEN` (engine/generators.js) | 38 | **이름 붙은 의미 필드** (`need`·`rest`·`comp`·`plusSum`…) |
| `NM_TGEN` (threads/ml.js·adv.js) | 39 | **`steps:[{tex, blank}]`뿐 — 의미 필드가 하나도 없다** |

`ml_x9`가 그 예다. `n`·`n*10`·`answer`를 내부에서 전부 계산하지만 **`n`은 tex 문자열 안에만 있고
밖으로 나오지 않는다.** 이 상태로는 "×10 하고 n을 뺀다"를 그릴 수 없다.

**해법: tex를 파싱하지 말고, 생성기에 `scene:{...}`를 덧붙인다.**
이미 계산해 둔 지역변수를 내보내기만 하면 되므로 생성기당 2~3줄이고 **기존 반환값은 건드리지 않는다**
(문항·정답·인쇄 전부 불변). tex 파싱은 표기가 바뀌는 순간 조용히 깨지므로 금지한다.

```js
/* ml_x9 — 기존 반환에 scene만 추가. answer·steps·tex는 그대로. */
return {
  prompt, tex, answer, answerType:'steps', widget:'steps',
  steps:[…],
  scene:{ archetype:'place-shift', n, shifted:n*10, back:n, result:answer }
};
```

### 4-2. beat 계약

`mathSteps`(또는 `steps`)의 각 줄이 beat 하나가 되고, 각 beat는 자기가 가리키는 객체 id를 명시한다.
G·MAP `scene-contract.md`의 규칙(`draw`·`reveal`·`move`·`highlight`·`count`·`transform`)을 그대로 쓴다.

```
beat 1  highlight  targetIds:[num.25, num.75]   "더해서 100이 되는 짝을 찾아요"
beat 2  move       targetIds:[num.75]           25 옆으로 이동
beat 3  transform  targetIds:[group.1]          두 수가 100 한 덩이로 접힘
```

## 6. 검사기 요건 (1단계에 반드시 포함)

`skills/gmap-animated-math-lesson/scripts/validate_scene_manifest.py`를 확장한다.
**기계가 잡아야 하는 것:**

1. 모든 beat의 `targetIds`가 실재하는 객체를 가리키는가
2. 장면 객체의 수치가 생성기 반환값과 **일치**하는가 (그림이 문제와 다른 수를 그리면 잡는다)
3. 각 계열의 보존식이 성립하는가 — 묶기: 부분합의 합 = 전체합 / 이사: `a+b` 불변 /
   쪼개기: 조각의 합 = 원래 수 / 보정: 되돌린 뒤 정답 일치
4. beat 순서가 전체재생·단계학습에서 동일한가
5. 정답 객체가 답 beat 이전에 드러나지 않는가
6. 3개 언어 필드 존재 + 언어 혼입 없음

**시드 여러 개로 돌린다** — 생성기는 매번 다른 수를 내므로 한 번 맞은 것은 근거가 못 된다.

## 7. 하지 않는 것

- 문제·정답을 바꾸지 않는다. `scene`은 **덧붙이는 필드**이고 기존 반환값은 불변이다.
- 라이선스 원문(교재 스캔·문장)을 장면에 넣지 않는다 — G·MAP `SKILL.md`의 증거 경계 그대로.
- 스킬을 넘버스 전용으로 포크하지 않는다.
- 잠금을 만들지 않는다(자유 선택 원칙).
