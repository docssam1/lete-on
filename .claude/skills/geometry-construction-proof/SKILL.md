# 그림으로 따져 보기 — 기하 논증과 작도

기준 코드는 `fields-classic/question-bank/proof-board.js`(엔진·그림 도구)와 `course2-proofs/g1~g5.js`(권별 논증)다. 문서와 코드가 다르면 **코드가 맞다**. 작도 본보기는 `course2-proofs/g4.js`의 셋: `sssTri`(세 변으로 삼각형, `construct-sss` — 주어진 막대에서 길이를 재어 옮기는 꼴) · `perpBisector`(수직이등분선) · `angleBisector`(각의 이등분선 — 세 변 합동을 근거로 접기). 막대 없이 컴퍼스를 그 자리에서 벌려 긋는 장면은 같은 파일의 `swingArc(f, k, i, c, r, from, to, color)`, 자를 대고 긋는 장면은 `ruleLine(f, k, i, a, b)`을 쓴다. 그림이 한쪽에 몰리면 점들의 테두리를 재어 종이 가운데로 옮기고 크기를 맞춘다(`angleBisector.params`).

## 왜 이렇게 만드나(원장 결정, 2026-11-15)
- 2과정은 1과정보다 발달 단계가 높다. 1과정 판서는 「해 보니 그렇다」, 2과정은 **「왜 반드시 그런가」**를 그림으로 따진다.
- **영상(Manim·mp4)이 아니라 우리 손글씨 판서**로 만든다(「Manim보다 우리 손글씨 식이 낫지 않아?」). 판서도 움직일 수 있고, 장면마다 멈추고 앞뒤로 넘기고, 모양을 바꿔 다시 돌릴 수 있어서다. 홍보 영상 같은 「보여 주기만 하는 것」만 영상으로.
- 깃허브에 쓸 만한 작도 스킬은 없었다(2026-11-15 조사). JSXGraph(MIT/LGPL)는 성숙하지만 화면이 수학 프로그램 모양이라 판서와 이어지지 않는다. 아이가 직접 컴퍼스를 끄는 체험은 emh/cag(MIT)의 조작 방식을 참고할 수 있다(코드를 통째로 가져오지 않는다).

## 논증 한 개의 꼴
```js
{ id, unit, title, vary: "다른 …으로", width?, height?,
  params(seed) { … },                 // seed마다 다른 모양(일반화). 좌표는 여기서 정확히 계산
  scenes: [{ say, line, why, ms }],   // say=아래 설명, line=따져 보기 주장, why=까닭(없으면 생략)
  draw(f, k, p) { … } }               // k = 장면 번호 + 그 장면 진행(0~1). 순수 함수
```
- 권 파일 끝 `PROOFS` 배열에 넣고, `proof.js`의 `BOOKS.<권>.v` 꼬리표를 올린다. 엔진을 고치면 `proof.js`의 `proof-board.js?v=`와 `proof.html`의 `proof.js?v=`·`proof.css?v=`도 올린다.
- `draw`는 k만 보고 그린다(앞뒤로 가도, 움직임 줄이기여도 같은 그림). 장면 i의 진행은 `phase(k, i, a, b)`.
- 한 장면에 **한 동작**. 따져 보기 `line`은 그 장면에서 새로 알게 된 사실 하나, `why`는 그 까닭(정의·이미 보인 사실).

## 그림 도구(`figure()`)
- 선·도형: `seg(a,b,{grow})` · `poly(pts,{draw})` · `path` · `circle` · `dot` · `wedge`/`arc`(각) · `right`(직각) · `ticks`(같은 길이) · `note`.
- 글자: `label(p, text, {write})` — **손글씨(FC Hand)가 기본**, 같은 크기에서 작아 보여 1.3배로 쓴다. `write`(0~1)로 펜이 써 나가듯 드러난다. 고딕이 꼭 필요하면 `font: "sans"`.
- 작도: `arcPath(c, r, from°, to°, {draw})` — 연필 끝이 지나간 만큼의 호 · `compass(c, r, deg)` — 바늘 c, 연필 끝은 c에서 r만큼 deg° 방향, 두 다리 같은 길이 · `ruler(a, b, {side, margin})` — 직선 옆 반투명 자.
- 각은 「수학 방향」(오른쪽 0°, 시계 반대 +). 화면 y는 아래로 커지니 `polar`·`dirDeg`를 써서 계산한다.

## 작도 장면 규칙
1. **주어진 것 먼저**: 주어진 길이는 왼쪽 위에 막대로 놓고 색을 정한다. 그 색이 끝까지 간다(막대 = 컴퍼스로 그은 호 = 완성된 변).
2. **컴퍼스는 진짜로 잰다**: 한 장면 = 막대에서 벌리기(0~0.3) → 중심으로 옮기기(0.3~0.55, 옮기며 연필 방향을 돌림) → 호 긋기(0.55~0.95). 컴퍼스는 그 장면 동안만 보이고 마지막 10%에 사라진다(`live`·`fadeOut`).
3. **호는 짧게, 필요한 곳에만**: 교점 근처 ±20° 정도. 교점이 둘이면 다른 쪽은 그 이야기를 하는 장면에서 긋는다.
4. **좌표는 계산으로 정확하게**: 손으로 그린 느낌은 펜이 그어지는 모습·손글씨·종이 틀로만 낸다. 선을 일부러 흔들지 않는다(같은 길이·같은 각이 눈으로 같아야 논증이 선다).
5. **논증으로 닫는다**: 「그렸다」로 끝내지 말고 ①왜 그 점인가(두 조건을 함께 만족하는 점) ②왜 하나로 정해지는가(다른 교점 → 접으면 겹친다) ③언제 안 되는가(못 그리는 경우를 같은 그림에서 줄이거나 늘여 보인다)까지 장면으로.
6. **「다른 …으로」**: 보통 모양·특수한 모양(정삼각형 등)·아슬아슬한 모양을 섞는다. 모든 seed에서 그림이 틀 안에 들어오는지 확인한다.

## 아이가 직접 해 보는 컴퍼스(`c2-lab.html?tool=compass`, `c2-lab.js compassTool`)
- 점수·정답 판정 없이 해 보기만. 바늘 손잡이(회색)를 끌면 컴퍼스가 통째로 옮겨 가고, 「① 벌리기 · 옮기기」에서 연필 손잡이(노랑)를 끌면 벌어진다. 「② 돌려 긋기」에서는 벌린 길이 그대로 연필이 돌며 호가 남는다.
- B·C·막대 양 끝에 16px 안으로 오면 착 붙는다. 벌린 길이가 막대와 같으면 그 막대 색으로 호를 긋고, 읽기 칸에 「5cm 막대와 같아요」.
- B와 C를 중심으로 그은 두 호가 만나면 교점과 B·C를 이어 삼각형을 칠하고 세 변 길이를 보여 준다. 두 반지름의 합이 BC보다 짧으면 「닿지 않아요」 까닭을 보여 준다(「다른 세 길이로」 마지막 묶음이 그 경우).
- 바늘을 옮겨 연필 끝이 종이 밖으로 나가면 벌린 길이는 두고 방향만 돌려 안으로 넣는다(`keepTipIn`) — 처음엔 이걸 안 해서 연필 손잡이가 화면 밖으로 사라졌다.
- 그림 논증 권 목록(`course2-list.js` `LABS`)에 단원 이름 그대로 칩을 단다.

## 화면 모양
- 그림 칸은 1과정 판서와 같은 종이(`#fbfaf6`) + 초록 점선 틀, 따져 보기의 주장 줄은 손글씨(`proof.css` 맨 끝 블록). 화면 틀은 파란 결 그대로.
- 회사 이름·정답 값은 쓰지 않는다(논증은 답을 말해도 되는 개념 설명이지만, 권별 테스트 문항과 같은 수를 쓰지 않는다).

## 확인 순서
1. `node --check`로 문법.
2. 로컬 서버에서 장면마다 30%·65%·끝을 찍어 본다(Playwright, `proof.html?book=<권>&id=<id>`, 「다른 …으로」를 0·2번 눌러 두 모양 이상). 볼 것: 컴퍼스·글자가 틀 밖으로 나가지 않는지, 호가 교점을 지나는지, 접은 도형이 꼭 겹치는지, 글자가 선에 걸리지 않는지.
3. 이미 있는 다른 논증 몇 개의 끝 장면도 찍어 글꼴 바뀜으로 겹친 곳이 없는지 본다.

## 했던 실수
- 종이 맨 위 막대를 잴 때 컴퍼스 손잡이가 틀 밖으로 나갔다 → 위가 모자라면 손잡이를 아래로(`compass`가 알아서 뒤집는다).
- 글자를 고딕 17px에서 손글씨로 바꾸면 작아 보인다 → 엔진에서 1.3배.
- 권 파일은 `../proof-board.js`를 꼬리표 없이 부르고 `proof.js`는 꼬리표를 붙여 부른다 — 모듈이 둘로 갈려도 되도록, 권 파일은 계산 도구(`P`·`polar`·`phase` 등)만 가져다 쓰고 그리기는 엔진이 넘겨준 `f`로만 한다.
