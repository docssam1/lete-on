# 지필드 교재·시험지·문제은행 디자인

원장 확인(2026-10-23)으로 정한 규칙이다. 실제 시안: 저장소 `fields-classic/question-bank/design-draft/`
(index·exam·covers·unit.html, 배포 주소 `…/fields-classic/question-bank/design-draft/`)와
Claude Design 캔버스 「지필드 교재 디자인 시안」(https://claude.ai/artifact/AasWRPtH6kBfZUSP42K7Mq, 원장 비공개).
새 작업은 이 두 곳의 생김새에서 출발한다. 매번 새로 꾸미지 않는다 — 고정된 틀을 재사용하고 색·번호·내용만 바꾼다.

## 1. 원장이 거른 것 (다시 꺼내지 말 것)
| 거른 것 | 원장 말 | 대신 |
|---|---|---|
| 파랑·하늘색 위주 배색 | 「푸르딩딩한 거 말고」 | 따뜻한 종이색 + 깊은 초록 하나 |
| 굵기 800~900 둥근 고딕 남발 | 「AI로 만든 것 같은 두꺼운 폰트」 | Pretendard 100~700, 제목도 700까지 |
| 언덕·열기구·전면 무늬 같은 그림책 장면 표지 | 「너무 촌스러워」 | 여백 + 큰 제목 + 오브젝트 하나 |
| 큰 카드·그라데이션 배경·이모지 장식 | (시안 원칙) | 얇은 선·정렬·여백 |
| 그림이 문제인데 말로만 쓴 문항(「5로 보입니다」) | 「그림이 없고… 디지털 수인데 그냥 숫자 5」 | 그 문항의 그림을 반드시 그린다(4절) |
| 단원 내지 한 가지만 | 「단원 내지도 다양하게」 | 3안 중 책 성격에 맞춰 고른다 |

## 2. 글꼴
- **화면·메뉴·번호·배점·안내**: Pretendard(`fields-classic/question-bank/assets/fonts/pretendard-var.woff2`, `font-weight: 100 700`으로 선언 — 900이 나오지 않게 상한을 건다).
- **인쇄 본문·문항·단원 제목**: 명조 = Noto Serif KR 400/600/700(본명조와 같은 글꼴). `design-draft/fonts/`에 자체 탑재(OFL, `OFL-NotoSerifKR.txt`). 구글 폰트 CDN에 기대지 않는다 — 인쇄 PC·클라우드 환경에서 막힐 수 있다.
- **표지 제목**: Pretendard 700, 자간 −0.03em, 행간 1.22. (명조 표지는 「촌스럽다」 쪽으로 기운다.)
- 수식은 그 수식 엔진의 전용 글꼴을 그대로 둔다.
- 확인: 렌더 캡처에서 제목을 확대해 실제로 명조/고딕이 나왔는지 본다. `fc-list`에 한글 명조가 없어 조용히 고딕으로 떨어진 전례가 있다.

## 3. 색 (토큰으로만)
| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| 바탕 | `#fdfbf5` 종이 · `#f1ece1` 작업대 · `#f7f2e7` 보조 | 화면 패널·바깥 |
| 글자 | `#2a241c`(화면) · `#191511`(인쇄) · 보조 `#7a6f5c` | |
| 선 | `#e2d9c6` 머리카락 · `#c9bda2` 구분 | 목록 줄·패널 경계 |
| 강조(넓게 한 가지) | 깊은 초록 `#2f6b4a` / 진한 `#1e4631` / 옅은 `#e9f0e7` | 선택·주 단추·교재형 개념 상자 |
| 점처럼 | 감색 `#b4512e`(경고·난이도) · 금색 `#a87c22`/`#d9a62e`(배점·출처·표지 선) | |
- 시험지 본문은 **흑백**(흑백 프린터 기준). 색은 교재형에만 초록 하나 옅게.
- 표지 B안의 바탕색만 권마다 바꾼다(초록 `#16382a`·남색 `#1f2f4a`·와인 `#4a1f2a`·먹 `#2a241c`).

## 4. 본문 쪽 (A4 · 같은 문항 부품, 틀만 바뀜)
**고를 것은 두 가지뿐**: 「1단/2단」, 「시험지/교재」.
- **문항 부품**: 번호(고딕 굵게) + `[N점]`(금색 작게) + 본문(명조) + 그림 + 필요한 문항에 풀이 칸(괘선) + 답 줄(오른쪽 끝).
- **시험지형**: 머리말 = 과정 띠 · 큰 제목(명조) · 이름/반/날짜 줄 · 배점표(문항/점수 2행, 본문 배점에서 자동 집계) · 이중선(4px double). 바닥 = 브랜드 · 쪽 번호.
- **교재형**: 단원 번호 원 + 제목 + 학습 목표 → 개념 상자(옅은 초록, 왼쪽 굵은 띠) → 예제(초록 꼬리표 + 풀이 단계 번호 목록) → 문제 → 「집에서 한 번 더」(점선 상자).
- **세로 채움**: 첫 문항은 머리말 바로 아래에서 시작하고, 남는 높이는 문항 사이 간격으로 고르게 나눠 쪽을 아래까지 채운다(1단: `flex-direction: column; justify-content: space-between`). 2단은 위에서부터 흐른다.
- **쪽 번호**: 넣기/빼기 선택(인쇄 설정 체크박스). **표지에는 어떤 경우에도 쪽 번호 없음.**
- **그림이 문제인 문항은 그림을 그린다**: 거울 시계(바늘만, 숫자 없이 눈금), 반 바퀴 돌릴 시계(빨간 바늘), 뒤집기 글자는 카드 안에, 바둑돌 반복은 **문제 아래 가운데에 크게**(1단 40px, 2단 30px), 디지털 수는 7-세그먼트 카드(실제 카드 「?」 점선 + 거울선 + 비친 카드). 그림은 원본 SVG/도형 — 사진·AI 이미지 금지.
- 여백: 종이 자체 여백 약 15~16mm(56px), `@page { size: A4; margin: 0 }`. 화면 전용 요소는 `@media print`에서 숨긴다.
- 문항이 여러 쪽으로 넘어가면 Paged.js(MIT) 도입을 검토한다(머리말·쪽번호 자동). 아직 도입 전.

## 5. 교재 표지 (시리즈형 — 권마다 색·번호·오브젝트만 바꾼다)
공통: 왼쪽 위 eyebrow(가는 선 + `GFIELD CLASSIC · N과정`, 자간 0.2em) → 큰 제목 2줄 → 부제(작게, 보조색) / 오른쪽 위 권 번호 / 아래 끝 발행처 줄(`지필드 영재교육` · `GOLDEN BELL`, 자간 0.14em). 회사 내부 약칭(FC·필즈)은 쓰지 않는다.
- **A · 흰 바탕 + 광택 도형**: 구·원뿔·정육면체 하나의 묶음(그라데이션 + 위쪽 광택 + 부드러운 그림자), 뒤에 아주 옅은 큰 권 번호. 게임의 광택 3D와 같은 결.
- **B · 딥 그린 + 금 라인**: 단원 핵심을 가는 금선 하나로(예: 마방진 격자 + 한 칸 `15`), 큰 가는 권 번호. 가장 차분·고급.
- **C · 기하 포스터**: 위 절반 여백+제목, 아래 절반 먹색 띠 위 정렬된 도형 2×3. 
- 글자는 항상 진짜 글자(이미지로 굽지 않는다). 외부 템플릿(어도비·캔바)은 **배치 관습만 참고**, 그림은 자체 제작.

## 6. 단원 내지 3안 (책 성격에 따라)
- **A 목차형**(연산·드릴 책): 위 옅은 초록 띠(아래 모서리 둥글게) + 큰 가는 단원 번호 + 과정·권 원 배지 + 명조 단원명 → 소단원 표(번호·이름·공부한 날·확인 동그라미) → 「이 단원의 열쇠말」 상자.
- **B 배움 지도형**(개념서): 초록 사각 번호 + 명조 제목 + 이중선 → 지난/이번/다음 학습 세 칸(이번 단원만 초록 테두리) → 「1분 점검」(감색 왼쪽 띠, 명조 문항 2개).
- **C 포스터형**(심화·사고력): `UNIT 01`(가는 감색, 자간 0.3em) + 큰 명조 제목 + 도입 글 + 오른쪽 위 기호 그림 패널 → 학습 목표 3(검은 원 번호) → 초록 알약 「골든벨 도전 전 · 소단원 N개」.

## 7. 문제은행 화면 (교사용 편집 콘솔)
Tabler·IBM Carbon 목록 설계를 참고한 3칸: **왼쪽 단원 필터**(과정·권 선택, 단원 목록 — 선택은 옅은 초록 + 왼쪽 3px 초록 막대, 난이도·출처 체크) · **가운데 문제 목록**(표 꼴 줄: 번호 · 한 줄 미리보기 · 출처(금색)·유형 · 난이도 점 3개(감색) · 「담기」/「담음 ✓」) · **오른쪽**(미리보기 카드: 명조 본문 + 그림 + 배점·풀이 칸 ± 조절 / 시험지 바구니: 순서·제목·배점·빼기, 합계 · 1단/2단 · 예상 쪽수 · A4 미리보기).
- 머리줄: 이름 + 검색(종이색 칸) + 보조 단추(테두리 없음/있음) + 주 단추 하나(초록, 「시험지 만들기 · N」).
- 터치 영역 44px 이상, 진짜 `<button>`·`<label>`. 폰 폭에서 세 칸이 아래로 쌓인다.

## 8. 만드는 순서 (매번)
1. 이 스킬 + `design-draft/README.md`를 읽는다. 대상(학년·책 성격·용도)을 한 줄로 적는다.
2. 고정 틀에서 고른다(표지 A/B/C · 내지 A/B/C · 본문 1단/2단 · 시험지/교재). 새 방향이 필요하면 **서로 다른 3안**을 만들어 원장에게 고르게 한다 — 기준: 제목 가독성·연령 적합성·시리즈 통일감·인쇄 품질.
3. 내용은 실제 교재 문항으로(지어낸 숫자·통계 금지, 모르는 값은 `[  ]` 자리표시).
4. 확인: 실제 렌더 캡처(PC 1440 · 폰 375 · A4), 글꼴이 실제로 바뀌었는지 확대 확인, 그림이 필요한 문항에 그림이 있는지, 쪽이 세로로 차는지, 인쇄 PDF에서 잘림·겹침이 없는지.
5. 원장이 고르거나 거른 것은 이 스킬의 1절(거른 것)과 해당 절에 바로 적는다 — 다음 작업이 같은 지적을 받지 않게.

## 9. 하지 말 것
- 원장이 고르기 전에 운영 화면(`styles.css`, 인쇄 렌더러)을 통째로 바꾸지 않는다 — 시안에서 고른 뒤 단계적으로.
- 골든벨 정답·라이선스 원문을 시안에 넣지 않는다(공개 저장소). 시안 문항은 공개 문항·자체 제작 문항만.
- 표지를 AI 이미지 한 장으로 만들지 않는다(글자가 틀어진다).
