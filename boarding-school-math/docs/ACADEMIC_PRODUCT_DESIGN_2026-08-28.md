# GFIELD 보딩수학 제품 디자인 기준

## 한 문장 목표

학생은 현재 위치와 오늘 할 학습을 바로 찾고, 교사는 그 판단의 근거와 다음 배정을 바로 확인한다.

## 공개 소개와 실제 제품의 경계

- 공개 소개는 프로그램 선택, 학년·과정 지도, 진단 결과 예시, 공개 상태만 설명한다.
- 학생용은 오늘의 학습, 배정된 진단, 배정된 자료, 경시 준비, 성장 기록을 제공한다.
- 교사용은 학급 근거, 진단 배정, 문제은행·과제 구성, 수업 자료, 분석·리포트, 콘텐츠 검수를 제공한다.
- 학부모용 제품 역할은 만들지 않는다.
- 공개 페이지의 학생·교사 전환은 제품 방향 미리보기이며 실제 권한 경계가 아니다.

## 탐색 구조

```text
공개 홈
├─ 학생용 흐름
├─ 교사용 흐름
├─ 학교 수학·과정 배치
├─ 싱가포르식 숙달·SASMO·Math Kangaroo
├─ AMC 8 → 10 → 12
├─ 교과·문제은행
└─ 진단 기준

학생용
├─ 오늘
├─ 내 실력 지도
├─ 배정된 진단
├─ 배정된 학습·재확인
├─ 경시 도전
└─ 성장 기록

교사용
├─ 학급 근거
├─ 진단 운영
├─ 스킬 지도·그룹
├─ 문제은행·과제 구성
├─ 수업·워크북
├─ 분석·리포트
└─ 콘텐츠 검수
```

## 문제은행 원칙

- 학생은 전체 문항 창고가 아니라 교사가 배정했거나 공개 승인을 받은 자료만 본다.
- 교사는 `course → unit → skill → level → test_type → resource_type` 순서로 자료를 좁힌다.
- 필터 뒤에는 반드시 미리보기, 배정 또는 워크북 구성이라는 실제 다음 행동이 있어야 한다.
- 실제 공개 문항이 없으면 버튼을 가장하지 않고 `검수 대기` 또는 `인증 후 제공`으로 표시한다.
- 문제 화면에서는 수식, 그림, 답안 입력, 진행률이 모든 장식보다 우선한다.

## 시각 언어

- 보딩스쿨의 학술 편집물과 수학 노트를 기준으로 한다.
- 따뜻한 아이보리 종이, 잉크 네이비, 상태용 그린·버건디, 제한된 황동색을 사용한다.
- 제목은 세리프, 조작과 데이터는 산세리프를 사용한다.
- 둥근 SaaS 카드 대신 가는 괘선, 여백, 번호, 표 형식으로 위계를 만든다.
- pill은 상태와 짧은 분류에만 사용한다.
- `샘플`, `데모`, `메타데이터`, `잠금`은 사용자 가치보다 앞에 두지 않는다. 필요한 고지는 해당 행동 근처에 짧게 둔다.

## 효과 사용 정책

- `metal-fx`는 React 18 이상을 전제로 한다. 현재 정적 HTML 제품은 효과 하나를 위해 React로 전환하지 않는다.
- 금속 느낌은 대표 CTA의 정적 1px 테두리에만 사용하고, 상태 의미를 대신하지 않는다.
- Orbs는 실제 채점·생성·불러오기 대기 상태가 생긴 뒤에만 사용한다.
- 문제 뷰어에는 WebGL, 상시 움직이는 구체, 스크롤 쇼 효과를 사용하지 않는다.
- 모든 모션은 `prefers-reduced-motion`에서 정지한다.

## 출시 확인 기준

- 390×844 첫 화면에서 프로그램 목적, 학생용·교사용, 시작 행동이 보인다.
- 홈에서 SASMO, AMC, 교과·문제은행에 각각 한 번의 명확한 경로로 진입한다.
- 학생용·교사용만 존재하고 순서와 명칭이 모든 페이지에서 일치한다.
- 320·390·768px에서 가로 넘침이 없고 핵심 조작은 44px 이상이다.
- 페이지별 색·헤더·버튼·표·필터가 하나의 디자인 시스템을 사용한다.
- K2–G12, SASMO 4목표·6영역, 공식 링크와 공개 권리 경계는 유지한다.
- 실제 문항·학생 데이터·정답·비공개 자산은 공개 페이지로 나오지 않는다.
