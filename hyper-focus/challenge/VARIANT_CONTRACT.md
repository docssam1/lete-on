# 2026년 9월 챌린지 대비 — 유사문항 계약

범위: 이 별도 챌린지 교재의 4회 시험, 본문 20문항과 추가 6문항씩 총 104개 출현. 다른 제품의 원문·문제은행·학생 기록은 가져오지 않는다.

## API

교사용 브라우저 전역 `HFChallengeVariants`, CommonJS `require('./variant-provider.js')`. 학생 화면은 동일 인터페이스의 `remote-variants.js`를 사용하며, 문항은 비공개 서버에서만 받는다. 학생용 `generate`와 `getSource`는 비동기다.

- `list({round?, section?})`: 출현별 `key`, `round`, `section`, `number`, `typeId`, `label`, `eligibility`, `heldReason`, `difficultyNotes`, `fingerprint`.
- `describe({round, section:'main'|'extra', number})`: 한 출현의 상태. section 생략 시 main.
- `getSource(ref)`: 인쇄본과 같은 seed 62001의 읽기 전용 스냅숏. 이를 새 유사문항으로 표시하지 않는다.
- `generate({...ref, difficulty:'easy'|'same'|'hard', seed})`: 성공 시 `{status:'verified', question, source, difficulty}`, 보류 시 `{status:'held', reason, source?}`. seed는 0부터 4294967295까지 정수.
- `explainQuestion(question)`: 기존 core 20유형의 수치·조합·도형 근거 해설. 검산된 question을 입력한다. 학생용 예제에는 자동 노출하지 않는다.

교사용 provider는 bank/supplement, numeric/geometry/core-levels 확장 뒤에 둔다. 해설 함수는 별도 시험 생성 없이 사용할 수 있다. 이 생성기 파일들은 공개 배포 묶음에 포함하지 않는다.

모든 반환 스냅숏은 깊게 동결한다. 동일한 자료 버전·출현·난도·seed의 결과는 동일하며, 문항에는 독립 id와 원출현 fingerprint가 붙는다. 원출현 모형이 바뀌면 새 페이지 로딩에서 다시 판정한다. fingerprint는 내부 변경 검출용이며 암호학적 서명은 아니다.

## 검증 범위

현재 104개 출현 모두 쉽게·같게·어렵게 지원한다. 총 312개 출현/난도 조합이다. 각 유형에서 서로 다른 문제가 무한히 나오는 것은 아니며 비공개 배포용 풀은 중복을 제거한 실제 개수를 공개 메타데이터에 표시한다. 선택한 풀의 문항 수를 초과하면 요청 전에 안내하고 차단한다.

카드 배분과 선호표는 가능한 배치 전수를 확인하여 유일한 답만 채택한다. 가려진 블록·종이 접기·도형 원위치 주사위도 지원하며, 눈에 보이는 개수 세기나 숫자 주사위로 바꾸지 않는다. 접기는 겹친 층과 접는 화살표를 표시하고, 숨은 길쭉블록과 보이는 방향별 블록은 별도 모형으로 검산한다.

추가 문장형 배치: 1회 1번 범위·짝수·제외 조건, 16번 남은 색종이, 17번 나이표와 미래의 합, 2회 6번 귤 역산, 15번 처음 날아간 참새 수, 16번 어떤 수의 기준 관계. 원형의 응답 행동을 보존하며, 심화에서는 알려진 종류·연결할 사람·되돌릴 변화의 수를 늘린다. 실제 설명에 등장한 숫자만 사용해 독립 계산한다.

기존 엔진이 난도를 실제로 바꾸지 않던 19칸은 `variant-core-levels.js`의 별도 구조로 보완했다. 중간 교환값 제시, 고정 카드 자리, 단서 수, 공통 기호를 통한 연결, 전개도 구조 등을 달리한다. 일렬 구슬의 번째 질문은 보인 그림 뒤의 위치만 묻는다. 점 그리기 정답은 1개 이상이고, 심화 주기 개수는 보이지 않은 일치 위치를 포함한다. 암호 질문은 어떤 보기의 답도 직접 복사할 수 없으며, 심화 삼각형의 두 대상은 좌우 차가 달라 중간 관계를 연결해야 한다.

카드 상자 배분의 `resultContract`는 `nested-set`이다. 상자 순서는 고정하되 각 상자 안 카드의 순서 교환은 같은 답이다. 이는 인쇄 답의 동치 규칙이며 새 자동 채점 서비스를 구현했다는 뜻은 아니다.

새 seed가 무한히 서로 다른 사고 구조를 보장하지는 않는다. 일부 기하 유형은 검수된 유한 구조와 위치 변형을 사용한다. 보류 상태를 기본형 생성으로 우회하지 않는다.

`verified`는 명시된 모형과 검수 통과를 뜻한다. 실제 6세 아동 집단의 성적에 따른 통계적 난도 보정이나 목표 정답률 달성을 뜻하지 않는다. 총점 컷 60점의 진단은 별도 진단 모듈의 책임이다.

## 검수

`node hyper-focus/qa/validate_challenge_variants.cjs` 실행. 별도 풀이기가 저장 정답과 무관하게 답을 구하며, 잘못된 정답·모순 조건·여러 답·잘못된 seed·미지원 유형을 대조한다. core 20유형 해설의 숫자 등식도 다시 계산한다.

`--render` 옵션은 실제 브라우저에서 대표 그림을 PNG로 만들고 그림 영역 넘침을 검사한다. 결과: `hyper-focus/output/qa/challenge-variants/`. 화면·인쇄본의 최종 편집 검수는 studio 및 PDF 제작 단계에서도 별도로 수행한다.

v4 부모 통합 검수: 생성 문항 독립 검산 18,720건, 저장 정답을 바꾼 음성 대조 18,720건, core 20유형 해설 720건, 해설 속 숫자 등식 23,010건. 별도 numeric/geometry/core-levels 검사와 다른 에이전트의 경계 재검토를 거쳤다. 구현자 모듈의 승인 대기는 유지하고 provider에서 부모 검수를 반영한 `local-verified`로 표시하며 운영 배포는 여전히 `held`다. 상세 출현별 목록은 math-report.json에 기록한다.
