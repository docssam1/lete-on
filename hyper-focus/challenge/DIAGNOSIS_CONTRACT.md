# 챌린지 진단 계약

## 적용 범위

6세·예비초1 사고력 / 프리미어 대비의 4회 모의고사. 각 회 본문 20문항에 5점씩, 총 100점이며 기준 점수는 60점이다. 추가 연습 6문항은 점수와 강약점 집계에서 제외한다. 소문항이 있는 문제도 해당 번호 전체를 교사가 채점한 뒤 정답 또는 오답을 입력한다. 부분 점수는 지원하지 않는다.

Hyper Focus의 `mock/mock-core.js`에 있는 문항→유형별 집계→오답 유형 선택 흐름과 `diagnosis.html`의 영역별 진단 구조를 이어받는다. 단, 기존의 ‘O가 아닌 모든 값은 오답’ 처리는 사용하지 않는다. 전 회차의 빈 입력은 미채점이다. 기존 진단의 최상위권·실수 원인·예측 문구를 복사하지 않는다. 데이터베이스, 로그인, 다른 제품, 원격 상태는 변경하지 않는다.

## 입력과 식별

- `HFChallengeDiagnosis.describeRound(round)`는 `{round, seed, questions, extra, cutoff, maxScore}`를 반환한다. 현재 본문과 추가 문제를 읽되 수정하지 않는다.
- 문항 메타데이터는 `{occurrenceId, fingerprint, round, number, section, typeId, taxonomy, points}`이다. 원본 정답과 풀이를 메타데이터로 내보내지 않는다.
- `occurrenceId` 예: `challenge-r1-main-01`. 회차·본문/추가·번호의 고정 식별자이며 인지 유형과 구분한다.
- `typeId`는 원본 문제의 생성/선택 ID이다. `taxonomy.typeId`는 같은 인지 유형끼리 집계하기 위한 공통 ID이다. 임의의 새 문제를 원본 ID로 대신하지 않는다.
- `fingerprint`는 지문·그림 HTML·조건·정답의 변경 감지값이다. 보안 해시나 원본 진위 증명은 아니다. 외부 그림 파일의 내용 변경만으로는 변하지 않으므로 그림의 의미가 변경되면 원문 조건/버전도 갱신한다.
- `analyze({round,responses,student?})`: `responses`는 `{occurrenceId,status,fingerprint?}` 배열. 상태는 `correct`, `wrong`, `pending`만 받는다. 저장하거나 불러오는 UI는 fingerprint를 반드시 포함해야 한다. 생략은 현재 메모리에서 새로 입력한 채점에만 허용한다.
- 중복 번호, 타 회차, 추가 연습, 알 수 없는 상태, 다른 fingerprint는 거부한다. 빠진 번호는 미채점이다. 원문이 바뀌면 기존 채점 확인 후 다시 입력한다.
- 학생 이름·유치원만 최대 30/60자로 전달한다. 화면 삽입 시 HTML로 해석하지 말고 텍스트로 출력한다. 엔진은 저장·전송하지 않는다.

## 대영역·소영역·유형

104문항의 지문과 조건을 확인하여 명시적으로 매핑한다. 기존 HF 대영역 이름을 유지하고 규칙을 수와 연산에서 분리한다: 공간 지각, 평면 지각, 수와 연산, 규칙, 논리 추리, 경우의 수, 문제 해결, 지문 이해. 회차마다 실제 출제 수를 집계하며 각 영역을 같은 문항 수로 강제하지 않는다. 분류하지 않은 새 ID는 오류로 중단한다. 기존 ID의 문제 의미를 바꿀 때는 분류도 함께 검토한다.

그룹 `{id,label,total,graded,correct,wrong,pending,rate,status,questionIds,wrongQuestionIds}`를 `groups.areas/subareas/types`에 제공한다. rate는 채점 완료 문항만의 정답률이며 채점 0건이면 null이다.

- 미채점이 남은 그룹: `pending`, 강약점 판단 보류.
- 완료했지만 4문항 미만: `insufficient`, 문항별 결과만 표시.
- 4문항 이상 모두 채점한 그룹: 정답률 75% 이상 `strength`, 50% 미만 `review`, 나머지 `developing`.

위 경계는 이번 회차의 정리 규칙이며 표준화된 능력 척도가 아니다. 낮은 문항 수에서 강점·약점을 단정하지 않는다. 단일 유형의 오답은 ‘이번 유형 재확인’ 근거이지 능력 결함의 증거가 아니다.

## 결과와 처방

`score`는 본문 전체 채점 시에만 숫자, 아니면 null이다. 미완료 결과는 `earnedPoints`와 `possibleScoreRange:[확정 득점,남은 문항을 모두 맞힐 때 점수]`로 나타낸다. 미완료이면 이미 60점이 확보되어도 최종 `cutoffStatus`는 `pending`이다.

`wrongQuestions`와 `practiceSelection`에는 명시적으로 틀렸다고 채점한 본문 문항만 들어간다. 유형별 학습의 난이도 및 변형 가능 여부는 별도 문제은행이 확인한다. 진단 엔진은 검증되지 않은 유사문제를 생성하거나 배포하지 않는다.

`strengthMisses`는 4문항 이상 완료·75% 이상 해결한 대영역 안의 오답이다. ‘다른 문항은 해결했으므로 이 유형의 풀이 확인’이라고 안내한다. 부주의·불안·시간 부족·독해 실패 같은 원인을 추정하지 않는다.

`recommendations`는 각 오답의 번호·유형·구체적인 다음 확인 방법·5점 가능성을 반환한다. 잘 해결한 영역에서 놓친 유형을 먼저 제시하되 학습 성공을 보장하지 않는다. `scorePlan`은 60점에 필요한 추가 정답 수와 해당 오답 목록의 산술적 점수 변화만 제공한다. 현재 시험의 가상 재채점이며 다음 시험 점수 예측이 아니다. 백분위, 합격 확률, 허구의 신뢰도는 제공하지 않는다.

## 검수

`node hyper-focus/qa/validate_challenge_diagnosis.cjs`

4회 전체 104문항 분류, 전부 정답·오답, 55/60/65점 경계, 미채점과 부분 채점, 중복·오류·변경 지문, 오답만 선택, 낮은 표본 판단 보류, 강점 영역의 단일 오답, 원본 불변성을 결정적 입력으로 검사한다. 엔진 검사 통과는 문제 자체의 난이도·그림·단일정답 검수나 공개 승인과는 별개다.
