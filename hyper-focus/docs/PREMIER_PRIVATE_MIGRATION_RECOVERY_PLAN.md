# 프리미어 원본 비공개 전환 및 복구 계획

## 목적

프리미어 모의고사의 문제지 이미지와 검증 답안을 공개 Git 저장소에서 분리하고, 학생 권한을 확인한 뒤 짧은 수명의 주소로만 전달한다. 이 문서는 삭제 지시서가 아니라 별도 승인 작업을 위한 복구 기준이다.

## 현재 안전 기준

- Hyper Focus 수정 범위는 `hyper-focus/**`로 제한한다.
- 기존 `premier/**` 원본과 공개 배포 파일은 이 작업에서 삭제·이동·수정하지 않는다.
- 비공개 배포본은 Git 밖의 승인된 작업 폴더에 생성하고, 로컬 경로는 저장소에 기록하지 않는다.
- 비공개 Supabase 버킷에는 15회분 manifest, 답안, 원본 쪽 이미지만 저장한다.
- 공개 카탈로그에는 회차·문항 수·검수 상태만 두고 문제 원문, 정답, 저장소 경로와 해시를 넣지 않는다.

## 전환 전 필수 확인

1. 활용 8회, 파이널 3회, 최종 4회가 모두 비공개 저장소에 존재한다.
2. 각 회차는 원본 20문항을 유지하고, 검증 완료 문항과 검수 제외 문항을 구분한다.
3. 로컬 inventory의 파일 수·크기·SHA-256과 데이터베이스 자산 메타데이터가 일치한다.
4. 승인된 학생으로 문제지 이미지 열람, 정답 공개 기록, O/X 제출, 영역·유형 진단, 2·3회 재응시를 실검증한다.
5. 비로그인·권한 없음·만료 권한에서는 원본과 답안이 열리지 않는지 확인한다.
6. 모바일·PC·인쇄 화면을 확인한다.
7. GitHub Pages 배포와 Supabase 배포가 모두 정상인 복구 커밋 SHA를 기록한다.

## 별도 승인 후 전환 순서

1. `premier/**` 공개 자산의 전체 목록과 SHA-256 manifest를 만든다.
2. 같은 파일이 비공개 버킷과 G: 보관본에 모두 있으며 해시가 같은지 확인한다.
3. 공개 코드에서 해당 자산을 참조하는 모든 경로를 검색한다.
4. 참조가 비공개 API로 전환된 별도 브랜치를 만들고 브라우저 회귀 검사를 통과시킨다.
5. 사용자에게 삭제 후보 목록, 복구 위치, 예상 배포 영향을 보고하고 명시적 승인을 받는다.
6. 승인된 파일만 좁게 삭제하고 별도 커밋으로 남긴다.

## 복구 절차

- 문제가 생기면 먼저 공개 자산 삭제 커밋만 되돌린다. 학생·응시·진단 데이터는 되돌리지 않는다.
- G: 보관본의 해시가 manifest와 일치할 때만 원본을 복원한다.
- Supabase 자산은 기존 revision을 덮어쓰지 않고 새 revision으로 올린 뒤 데이터베이스의 현재 revision을 전환한다.
- 복구 후 승인 학생, 권한 없는 학생, 비로그인 상태를 다시 검사한다.

## 현재 결론

비공개 전달 경로는 준비하되 `premier/**` 공개 파일 정리는 Hyper Focus 범위 밖의 별도 작업이다. 따라서 현재 병합에서는 원본을 삭제하지 않으며, 위 확인과 사용자 승인이 끝난 뒤 별도 커밋으로만 진행한다.
