# docssam 과학 탐구 랩 — 재설계 규격 (초안, 승인 전)

> 작업 순서는 gajae-code 방식(인터뷰 → 계획 → 승인 → 구현)을 따른다. 이 문서가 "계획"이다.
> 규격 형식은 MengTo `design-first-ui-prompting`(GOAL → FORMAT → LAYOUT → TYPE → COLOR → IMAGERY → COPY → CONSTRAINTS → NEGATIVE).
> 캐릭터 그림(`docssam science.png`)을 아직 못 봤으므로 COLOR·IMAGERY는 그림을 본 뒤 확정한다.

## GOAL
- 콘셉트(사용자 지시 2026-09-19): **"공부하고, 실험하고, 영재원까지."** 개념 학습 → 3D·실제 실험 → 영재원(교육청·대학부설 영재교육원) 대비까지 한 길로 잇는다. docssam이 그 길의 선생님이다.
- 무엇: `/science-lab/` 홈·유닛 전면 재설계 + **문제은행** 신설.
- 누구: 초3~초6 학생(혼자 태블릿·폰으로 봄) + 곁에서 보는 학부모·교사. 영재원을 목표로 하는 아이가 핵심 사용자.
- 성공 기준: ① 아이가 설명 없이 "다음"만 눌러 한 유닛을 끝낸다 ② 이론 화면에서 docssam이 말하는 느낌이 난다 ③ 3D가 폰에서 끊기지 않는다 ④ 문제은행에서 약한 유형이 자동으로 다시 나온다.

### 구조 원칙 — "실험으로 탐구하고, 개념으로 이해하고, 영재원으로 확장한다"
사용자 지시(2026-09-19). 과학교육의 **5E 탐구 순환**(Engage 궁금 → Explore 실험 → Explain 개념 → Elaborate 확장 → Evaluate 점검)을 그대로 쓴다.
핵심은 **순서**다: 개념을 먼저 읽고 실험을 보는 게 아니라, **실험을 먼저 해 보고 그 결과에서 개념을 꺼내고, 그 개념을 새 상황(영재원 문제)에 적용**한다.

**연결 장치 — 같은 데이터가 세 번 나온다.**
- 실험 단계에서 아이가 만든 숫자(예: 두꺼운 뚝배기 10분 뒤 65℃)가
- 개념 카드 안에 그대로 다시 등장하고("네가 본 65℃와 48℃의 차이가 비열이에요"),
- 확장 문제의 조건으로 또 등장한다("같은 뚝배기에 물을 두 배 넣으면 10분 뒤 몇 도쯤일까? 이유를 써 보세요").
  이 되풀이가 "연결된 구조"의 실체다. 화면을 이어 붙이는 게 아니라 **데이터가 단계를 관통**한다.

| 기둥 | 단계 | 지금 자산 |
|---|---|---|
| 실험으로 탐구 | ① 궁금 ② 실험 | scenes/ 15개(해설 모드) → **조작 모드** 추가 필요 / (대기) Drive `실험2` |
| 개념으로 이해 | ③ 개념 | curriculum.js concept / (대기) Drive `이론편` |
| 영재원으로 확장 | ④ 확장 ⑤ 점검 | 문제은행 신설(아래) |

### 홈 = 탐구 지도
- 세로로 구불한 길 위에 정거장 15개(A 1 → B 4 → C 10). 끝낸 정거장은 깃발, 다음 정거장은 docssam이 서서 가리킨다.
- 정거장마다 세 칸 진도(실험·개념·확장)가 보인다. 길 끝은 **영재원 모의 평가**.
- 상단: 로고 + 진도(깃발 n/15). 하단: "이어서 하기" 고정 버튼. PC는 가운데 720px.

### 유닛 = 탐구 순환 5단계 (한 단계 = 한 화면)
| 단계 | 화면 | docssam 역할 | 연결 |
|---|---|---|---|
| ① 궁금 (Engage) | 3D 현상 10초 자동 재생(뚝배기가 식탁에서 끓는 장면) + "왜 그럴까?" 예상 3개 중 고르기 | 질문을 던진다 | 예상이 저장돼 ③에서 다시 보여 준다 |
| ② 실험 (Explore) | **아이가 직접 조작하는 3D**: 변인 하나를 바꾸고(두께 얇게/두껍게) 결과를 본다. 관찰값을 표에 적는다(숫자 입력 또는 눈금 읽기). 해설 재생은 "docssam 설명 보기"로 접어 둔다 | 옆에서 "다른 것도 바꿔 볼까?" 정도만 | 표의 값이 ③·④로 간다 |
| ③ 개념 (Explain) | 실험 표를 위에 두고, 그 아래 개념 카드 3~5장을 한 장씩. 카드마다 "네 실험에서는 …" 문장이 실험값을 인용 | **가장 크게 등장.** 칠판 옆에서 설명 | ①의 예상과 대조: "네 예상은 A였고, 결과는 …" |
| ④ 확장 (Elaborate = 영재원) | 같은 원리를 새 상황에 적용하는 문제 2개(창의적 문제해결·자료 해석) + 탐구 보고서 한 칸(서술형, 채점 기준표) | 반론자·심사위원 역할 | 문제은행에서 출제. 틀린 유형은 약점으로 누적 |
| ⑤ 점검 (Evaluate) | 확인 3문항 + 결과: 다시 풀기 / 다음 정거장 | 축하 | 깃발·배지, 진도 저장 |

**② 실험 조작 모드 — 엔진 확장이 필요하다.** 지금 scenes는 자막 비트를 재생만 한다. 장면 모듈에 `controls: [{id, label, min, max, step, apply(value, objects)}]`와 `readout(objects) → {라벨: 값}`을 추가해, 슬라이더 1~2개로 변인을 바꾸고 결과(온도·거리·개수)를 읽게 한다. 15개 장면 중 수치 모델이 있는 것(뚝배기·팽이·비행기·삼투·씨앗 온도·물줄기)부터 조작 모드를 붙이고, 나머지는 해설 모드로 시작한다.

- 공통: 상단 얇은 진행 점 5개, 하단 고정 "다음" 버튼(1차 CTA 하나만), 좌상단 "지도로".
- 위계: docssam 말풍선(H1급) → 카드 제목 → 본문 → 보조 캡션.

## TYPE SYSTEM
- 제목·말풍선: **Jua**(Google Fonts, 둥근 고딕, 아이 대상 친근함) 400. 대체: "Nanum Square Round", sans-serif.
- 본문: **Pretendard** 400/600, 대체 Noto Sans KR. 본문 16px(폰)·17px(태블릿+), 행간 1.6, `word-break: keep-all`.
- 라벨(단계명·변인 태그): 12px 700, 자간 +0.06em, 대문자 아님(한글).
- 수치(온도·시간): `tabular-nums`.

## COLOR + MATERIAL — 캐릭터를 본 뒤 확정
- 원칙: 캐릭터에서 주색 1개를 뽑아 **악센트 하나만**. 바탕은 그 색의 아주 옅은 톤(순백 아님). 글자는 차콜(순검정 아님).
- 지금 팔레트(크림 #f7f2e8 + 초록 #2f7d6d)는 리딩타운을 따른 것이라 캐릭터와 안 맞으면 버린다.
- 재질: 평평한 면 + 아주 약한 그림자 1단계. 유리·그라데이션·네온 없음.
- 다크 모드: 토큰만 바꿔 동일 구조. 3D 바탕은 밝게 유지.

## IMAGERY / UI STYLE
- 스타일 레인: **playful, character-led** (교과서형 아님, 게임 UI도 아님). 캐릭터가 "선생님"이지 마스코트 장식이 아니다.
- docssam 등장 규칙: 화면당 1회, 말풍선은 항상 캐릭터 입 쪽에서 나온다. 표정 그림이 여러 장이면 인사·설명·질문·칭찬·놀람에 배정, 한 장이면 말풍선 모양(둥근/뾰족/구름)과 크기로 감정을 대신한다.
- 3D: 지금 엔진 유지(원본 도형만). MengTo `build-mobile-threejs-games` 기준을 적용 — 터치 타깃 44px 이상, 세로/가로 회전 시 상태 유지, 저사양 기기는 그림자·입자 수 자동 축소, 감소된 동작 설정이면 즉시 최종 프레임.

## COPY (원칙)
- 말풍선은 한 문장, 25자 안팎. "~해 볼까?" 체(반말 존댓말 혼용 금지 → **~해요** 체로 통일).
- 버튼: "다음", "실험 보기", "지도로", "다시". 설명형 버튼 금지.

## CONSTRAINTS
- FONT: Jua + Pretendard
- STYLE: playful character-led, flat
- MODE: light 기본, dark 지원

## NEGATIVE
- 이모지를 아이콘으로 쓰지 않는다(현재 🎬·✎ 배지 제거).
- 카드 안에 카드 금지. 화면당 CTA 하나.
- 캐릭터 외 외부 일러스트·스톡 이미지 없음.
- 자동 재생 음성 없음(항상 토글).

## 문제은행 (신설, 사용자 지시 2026-09-19)
### 문항 형식 — CARS 창작 문항 규칙을 그대로 잇는다
- 데이터: `data/bank/<unitId>.js` → `[{ id, unit, type, level, stem, choices[4] | answerText, a, why, tags[] }]`
- `type` 5종: **개념 확인** · **자료 해석**(표·그래프 읽기) · **변인 통제**(설계 오류 찾기) · **창의적 문제해결**(영재원 지필 유형: 조건 주고 방법 여러 개 쓰기) · **서술형**(탐구 보고서 문장 쓰기, 자기 채점 기준 제공)
- 객관식은 **정답 위치를 쓰기 전에 배분**(A/B/C/D 균등), 오답은 정답과 같은 구체성(보기 길이 신호 0%). CARS에서 배운 규칙 그대로.
- `level` 1~3. 3 = 영재원 지필 수준.
- 기출 원문(교육청·대학부설 영재원 문제, Drive `영재원기출`·`영재원 모의고사`)은 **git 금지 → Supabase** `question_bank` 테이블. 창작 변형 문항만 git.

### 학습 흐름
- ④ 확장 단계에서 유닛당 2문항 + 서술형 1, ⑤ 점검에서 3문항. 관문 통과 = 점검 2/3.
- **약점 추적**: 틀린 `type`·`tags`를 `profile.bank.weak`에 누적 → 다음 관문에서 같은 태그 문항을 우선 출제(스킬 코치와 같은 원리).
- **영재원 모의 평가**: 길 끝. 25문항 40분 타이머, 유형별 정답률 리포트(부모용), 서술형은 채점 기준표로 자기 채점.
- 오답 노트: 틀린 문항 + 왜 + 관련 유닛 링크. 인쇄 가능(티처 콘솔 패턴 재사용).

### 1차 범위
- 15유닛 × 5문항 = 75문항 창작(정답 분포 검사기 통과) + 모의 평가 1세트(25문항). 기출 연동은 원문 확보 뒤.

## 인터뷰 — 확정에 필요한 답
1. 캐릭터 그림을 대화에 첨부(모양·색 확인용) + 저장소 업로드(github 웹 → `science-lab/assets/`).
2. 표정 그림이 여러 장인가, 한 장인가.
3. 스타일 레인 확인: playful character-led 로 갈지, 더 차분한 교과서형으로 갈지.
4. 홈을 "지도"로 바꾸는 것에 동의하는지(리딩타운과 같은 결).
5. 1차 범위: 15유닛 전부를 새 구조로 옮길지, 1유닛(뚝배기)만 먼저 만들어 보고 정할지. → 권장: **1유닛 먼저**.
6. 영재원 대상: 교육청 영재원 / 대학부설 영재원 중 어느 쪽 지필 유형을 기준으로 할지. 기출 원문을 Supabase에 넣을지(사용자가 보유한 `영재원기출` 폴더).
7. 서술형 채점: 자기 채점(기준표)으로 갈지, 선생님 채점 화면을 둘지.

## 사용성 점검에서 나온 필수 요구 (2026-09-19, `UX-TEST-2026-09-19.md`)
- 3D는 **단계 하나가 화면 전체**. 캔버스가 페이지 스크롤을 막는 구조 자체를 없앤다(터치·휠 모두). 확대는 ±버튼/Ctrl+휠.
- 가로 모드: 3D를 화면 높이에 맞추고 자막·컨트롤은 **오버레이**.
- 컨트롤은 재생·이전·다음 3개, 높이 48px. 음성·속도는 설정 시트. 자막은 고정 높이 말풍선, 대본은 접힘.
- 확인 문제 결과에 **다시 풀기 + 다음 정거장**. 재도전은 보기 섞기.
- 마지막 장면 도달 = 봤음 기록(재생 방식 무관). 단축키는 3D 단계에서만.
- 320px에서 가로 넘침 0 — 빌드 체크에 포함.
