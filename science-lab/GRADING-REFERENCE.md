# 서술형 채점 기준·운영 규칙 — 참고 사이트 분석과 GFIELD 적용안

작성: 2026-09-25 · 상태: **참고 정리** · 원칙: **배점·문항·쪽 구성은 교재가 정한다** · 짝 문서: 「서술형·자유형 공통 채점 계약」 초안

## 0. 무엇을 참고했나, 무엇을 가져오지 않나

- 참고: `yjgosa.vercel.app`(영재학교 2단계 지필 서술형 모의고사, 정식 판매 전). 공개된 무료 문항 1개의 채점 기준표, 이용 안내, 공지, 세트 상세 화면. 로그인 뒤(내 서재·답안 제출) 내부는 보지 못했다.
- **가져오는 것은 형식과 운영 규칙뿐이다.** 그쪽 문항·풀이·채점 기준 문장은 저작물이라 이 저장소에 옮기지 않는다(CARS 원문과 같은 기준). 아래 예시는 전부 우리 문항이다.
- 대상 차이: 그쪽은 **중학생·영재학교 입시**, 우리는 **초등 4학년 교과 + 영재원 확장**이다. 배점 크기와 석차 같은 경쟁 장치는 그대로 가져오지 않는다.

## 1. 채점 기준 형식 — 가장 가져올 만한 것

그쪽 구조: 풀이지 안에 소문항마다 **「채점 요소 | 배점」 표 하나 + 부분점수 규칙 한 줄**. 채점 요소는 과정(중간값·근거)까지 잘게 나누고 1~2점 단위, 흔한 오답마다 따로 감점 규칙을 둔다. 소문항 배점은 쉬운 것 2점에서 서술·반례형 4점으로 올라간다.

이 형식은 앞서 채점 계약 검토에서 나온 구멍 세 개를 한꺼번에 막는다.

| 검토에서 나온 문제 | 이 형식으로 어떻게 풀리나 |
|---|---|
| 채점 기준에 고정 ID가 없어 문장을 고치면 옛 결과와 어긋남 | 요소마다 `id`를 데이터에 적는다 |
| 균등 배분 후 0.5점 반올림하면 합계가 5가 안 됨 | 요소마다 **정수 배점**을 적고 문항 총점 = 요소 배점 합. 반올림이 사라진다 |
| 부분 정답(partial)을 오개념 기록에 어떻게 넣을지 없음 | 부분점수 규칙마다 **오개념 코드(M)**를 붙인다 |

### 우리 데이터 템플릿 (현행 `rubric.required[]`를 확장)

```js
// 예: s41-u03 유사 1세트 14번 — 화강암 알갱이가 큰 까닭 (현행 required 2개를 그대로 요소로)
rubric: {
  version: 's41-u03-v014@1',          // 문장·배점을 고치면 @2로. 옛 결과는 @1 표시를 유지
  total: 2,                           // = criteria 배점 합. 검사기가 확인
  criteria: [
    { id: 'c1', text: '마그마가 땅속 깊은 곳에서 식음', points: 1 },
    { id: 'c2', text: '천천히 식어 알갱이가 크게 자람', points: 1 },
  ],
  partial: [                          // 흔한 오답 → 점수 규칙 + 오개념 연결
    { id: 'p1', when: '빨리 식어서 알갱이가 크다고 씀', cap: 0, m: 'M10' },
    { id: 'p2', when: '과정은 맞는데 암석 이름을 현무암으로 바꿔 씀', deduct: 1, m: 'M10' },
  ],
  sample: '…',                        // 현행 그대로
  pass: '채점 기준을 모두 담으면 정답',  // 현행 그대로(화면 안내 문구)
}
```

- 부분점수 규칙은 두 종류만 둔다. `cap`(이 조건이면 최대 n점) · `deduct`(이 조건이면 n점 감점). 그쪽 규칙도 전부 이 둘로 표현된다.
- `m`이 붙은 규칙이 걸리면 그 오답은 오개념 기록에 **틀림 + 해당 M**으로 들어간다. 규칙에 안 걸린 부분 정답은 **틀림 + 오개념 없음(단순 누락)**으로 센다. 이러면 기존 「서로 다른 문항 2개면 확정」 규칙이 그대로 돈다.
- **배점은 교재에 적힌 그대로 쓴다.** 교재에 배점이 없는 문항만 채점 요소 1개 = 1점으로 둔다. 따로 정할 척도는 없다.

### `grade(input)` 결과와의 연결

- 모델은 **점수를 매기지 않는다.** 요소별 충족 여부와 근거, 걸린 부분점수 규칙 id와 근거만 낸다.
- 점수 = 충족한 요소 배점 합 → `cap`·`deduct` 적용. **서버가 계산**한다.
- 판정은 점수로 정한다: 만점 = correct, 0점 초과 = partial, 0점 = incorrect. 규칙끼리 충돌하거나 근거가 답안에 없으면 `needs_review`.

## 2. 문항 구조·난이도 — 우리 식으로 바꾸기

그쪽: 실생활 상황을 길게 주고 (1)~(4) 소문항이 **계산 → 일반화 → 극한·반례·이유**로 올라간다. 난이도 4단계(하 8문항 60분 ~ 최상 3문항 100분), 과목별 세트 + 종합 + 창의 유형(오류 찾기·주장 평가·추정·실험 설계).

우리 적용:

| 그쪽 | GFIELD 초등판 |
|---|---|
| 계산 → 일반화 → 반례·이유 | **관찰·사실 → 까닭 → 적용·예측** (5E의 실험 → 개념 → 확장과 같은 방향) |
| 난이도 하~최상 + 권장 시간 | 단원 확인(하) · 단원 서술(중) · 영재원형(상). 문항 수·난이도 구성은 교재 그대로 따른다 |
| 창의 유형 5종 | 이미 문제은행 유형에 있는 변인 통제·자료 해석·창의적 문제해결에 **오류 찾기·주장 평가**를 영재원형으로 추가 검토 |
| 그래프 그리기 소문항 | 인쇄 교재에 격자 칸, 사진 채점은 교사 검토로(자동 채점 대상 아님) |

## 3. 운영 규칙 — 가져올 것 / 바꿀 것 / 안 가져올 것

| 그쪽 규칙 | 판단 | 우리 방식 |
|---|---|---|
| 첨삭 1건당 1회 제출, 사진·PDF 20장 상한 | **가져옴** | 과제 1개당 1차 제출 + 고쳐 쓰기 1회. 사진 장 수 = 교재 답안 쪽 수(쪽마다 QR로 식별) |
| 풀이지는 제출하거나 첨삭을 포기해야 열림 | **가져옴** | 채점 모드에서는 예시 답·채점 기준을 **제출 후**에 연다. 지금 화면은 풀기 전에도 「채점 기준 보기」를 펼칠 수 있어 채점 모드와 분리가 필요 |
| 제출 후 7일 안에 소문항별 점수·첨삭 회신 | **바꿈** | AI 초안은 바로 나가고, 교사는 수업 흐름에 맞춰 확인한다. 학생 화면엔 교사 확인 전 상태를 표시 |
| 정오표에 올리고 파일 수정 | **가져옴** | 문항·기준 수정 = `version` 올림 + 정오 기록. 옛 결과는 옛 버전으로 표시하고 재채점 여부는 교사가 고름 |
| 모든 쪽에 구매자 정보 워터마크 | 선택 | 인쇄 교재에는 이미 학생 QR이 들어간다. PDF 판매를 할 때만 검토 |
| 파일을 연 구매자만 별점·체감 난이도, 3명 이상일 때 평균 공개 | 일부 | 학생 체감 난이도만 받아 **교사용 문항 품질 지표**로. 공개 평점은 두지 않음 |
| 포인트 충전(1P=1원)·토스 결제·추천 보상 | 보류 | 결제는 이번 범위 밖. 붙일 때 「충전 때만 결제, 세트 구매는 포인트」 구조가 가장 단순하다는 점만 기록 |
| 검수: 운영자 1명 집필 + 출신 검토자 5명 채점 | **바꿈** | AI 초안 + 교사 검토. 출시 전 표본 대조 게이트(채점 계약 6절)를 그대로 유지 |

## 4. 실행 환경 비교

| | 참고 사이트 | GFIELD 현재 |
|---|---|---|
| 화면 | Next.js 15 (Vercel) | 정적 사이트 (GitHub Pages) |
| 로그인·DB | Supabase, 이메일 링크·카카오, 비밀번호 없음 | Supabase 연결됨, 인증 없음(학생 선택기) |
| 결제 | 토스페이먼츠 v2 위젯 + 서버 주문번호 | 없음 |
| 파일 | Storage 추정 | 없음 |

- **채점은 서버가 필요하다.** API 키를 브라우저에 둘 수 없어서다. 화면을 Next.js로 옮길 필요는 없고, **Supabase Edge Function 하나**에 `grade()`와 점수 계산·검증을 두면 지금 정적 사이트 구조를 유지할 수 있다.

## 5. 채점 계약 초안에 반영할 변경

1. 서술형 결과의 「기본 0~5점, 0.5점 단위, 균등 배분」 → **교재 배점 그대로, 요소별로 나눠 적고 문항 총점 = 합**으로 교체.
2. `matched/missing`의 기준 ID = 데이터의 `criteria[].id`. 모델 출력에 **걸린 부분점수 규칙 id**를 추가.
3. 점수·판정은 서버 계산(1절 규칙). 모델이 낸 점수 필드는 받지 않는다.
4. partial의 오개념 기록 규칙(1절)을 진단 절에 추가.
5. 채점 모드에서 예시 답·기준 공개 시점을 「제출 후」로.
6. 배점은 교재 기준으로 고정. 계약의 「원장 결정 표」에서 배점 척도 항목을 뺀다.
