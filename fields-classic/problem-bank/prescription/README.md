# 필즈 약점 유형 처방전 문제 은행

학생의 진단 오답 유형마다 확정 문제 3개를 인쇄하는 문제 은행입니다.
문제 내용과 정답은 고정하고, 처방전에서는 `유형별로 보기`와 `섞어서 보기`로 표시 방식을 선택합니다.

## 저장 위치

- 문제 데이터와 정답: `prescription-data.js`
- 실제시험 회차·문항·유형 연결표: `source-catalog.js`
- 유형별 그림: `q01/`부터 `q28/`, `q33/`, `q34/`, `q37/`, `q41/`, `q42/`
- 16~24번 그림 생성기: `scripts/generate_assets.py`
- 25번 Geometry 3D 생성기: `scripts/q25_renderer.html`, `scripts/q25_renderer.js`
- 기존 1~14번 확정 생성 원본: `scripts/confirmed_sources/`
- 인쇄 화면: `../../prescription/index.html`
- 진단 결과 연결: `../../mock/index.html`

그림이 필요 없는 2번, 7번, 15번, 29번, 30번, 31번, 32번, 35번, 36번, 38번, 39번, 40번은 문제 문장과 정답만
`prescription-data.js`에 저장합니다.

27번은 문제 화면에는 그림 없이 텍스트 문제로 제공하고, 풀이 그림은 답안 풀이에서만 사용합니다. 원본 유형은 실전 3회 Q10이며,
반으로 자른 조각에서 먹은 조각을 뺀 뒤 남은 조각을 다시 반으로 자르는 구조입니다.
계산은 `(처음 개수×2 - 먹은 조각 수) × 2`로 검산합니다.

28번은 `q28/`의 SVG 3개를 사용합니다. 원본 유형은 실전 3회 Q12이며,
작은 삼각형부터 더 큰 삼각형까지 눈으로 세는 방식으로
크고 작은 삼각형의 개수를 검산합니다.

29번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 3회 Q15이며,
새 기호가 뜻하는 계산 약속을 읽고 그대로 따라 계산합니다.
풀이에는 어려운 연산 용어를 쓰지 않고 앞의 수와 뒤의 수를 말로 설명합니다.

30번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 3회 Q17이며,
숫자 카드로 조건에 맞는 두 자리 수를 모두 정리해서 쓰는 구조입니다.
십의 자리에 올 수 있는 수를 먼저 고르고, 남은 숫자를 뒤에 붙이는 방식으로 풀이합니다.

31번은 그림 없이 텍스트 점수표로 제공합니다. 원본 유형은 실전 4회 Q7이며,
점수표에서 가려진 숫자를 순위 조건으로 찾는 구조입니다.
세 자리 수를 왼쪽 자리부터 비교해 높은 점수와 낮은 점수를 정합니다.

32번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 4회 Q8이며,
숫자 카드로 조건에 맞는 두 자리 수가 몇 개인지 세는 구조입니다.
짝수와 홀수는 끝자리 숫자를 먼저 보고, 앞자리에 올 수 있는 수를 붙여 빠짐없이 셉니다.

33번은 `q33/`의 SVG 3개를 사용합니다. 원본 유형은 실전 4회 Q11이며,
도형 안에서 찾을 수 있는 크고 작은 사각형을 모두 세는 구조입니다.
한 칸짜리부터 두 칸짜리, 더 큰 사각형 순서로 빠짐없이 세도록 풀이합니다.

34번은 `q34/`의 SVG 달력 3개를 사용합니다. 원본 유형은 실전 4회 Q12이며,
특정 요일의 날짜를 모두 찾아 더하는 구조입니다.
같은 요일 날짜가 7씩 늘어나는지 확인하고, 빠진 날짜가 없는지 검산합니다.

35번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 4회 Q19이며,
여러 사람의 키 비교 조건으로 가장 큰 사람과 가장 작은 사람을 찾는 구조입니다.
큰 사람부터 작은 사람까지 이름을 차례로 이어 놓아 답을 확인합니다.

36번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 4회 Q20이며,
사람과 동물을 조건에 맞게 연결하는 구조입니다.
불가능한 동물을 먼저 지우고, 남은 동물을 한 사람씩 연결해 답을 확인합니다.

37번은 `q37/`의 SVG 3개를 사용합니다. 원본 유형은 실전 5회 Q12이며,
도형판을 오른쪽으로 뒤집고 오른쪽으로 반의 반바퀴 돌린 모양을 두 빈칸에 차례로 그리는 구조입니다.
Q04 색종이 접기와 달리 접힌 종이의 구멍 수가 아니라, 도형판의 위치 변화를 차례로 확인합니다.

38번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 5회 Q17이며,
달리기에서 이긴 사람과 진 사람 조건으로 특정 등수를 찾는 구조입니다.
빠른 사람부터 차례로 이름을 이어 놓아 답을 확인합니다.

39번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 6회 Q8이며,
좋아하는 음식을 조건으로 찾는 논리 추리 구조입니다.
먼저 바로 정해지는 사람을 찾고, 좋아하지 않는 음식을 지워 남은 짝을 확인합니다.

40번은 그림 없이 텍스트 문제로 제공합니다. 원본 유형은 실전 6회 Q18이며,
여러 사람이 읽은 책 수를 조건으로 차례로 계산하는 수와 식 문장제 구조입니다.
먼저 바로 구할 수 있는 사람의 책 수를 찾고, 그 값을 다음 조건에 넣어 답을 확인합니다.

41번은 `q41/`의 SVG 3개를 사용합니다. 원본 유형은 실전 3회 Q4이며,
쌓기나무 5개로 만든 도형 보기 중 다른 하나를 찾는 구조입니다.
위에서 본 모양이 같은지 보고, 2층인 곳이 어디인지 비교해 답을 확인합니다.

42번은 `q42/`의 SVG 3개를 사용합니다. 원본 유형은 실전 6회 Q12이며,
삼각형 안의 수가 아래 두 칸의 합이 되도록 1부터 7까지의 수를 한 번씩 배치하는 구조입니다.
이미 정해진 칸에서 옆 칸을 차례로 찾아 답을 확인합니다.

## 운영 원칙

1. 한 유형에는 확정 문제를 정확히 3개 둡니다.
2. 세 문제의 정답을 모두 같게 만들지 않습니다.
3. 정답은 그림에 적은 값이 아니라 계산 또는 완전 탐색으로 검증합니다.
4. 문제 문장, 그림 파일명, 정답, 풀이의 순서를 함께 변경합니다.
5. 새 그림은 기존 `generated/` 폴더가 아니라 이 `prescription/` 폴더에만 저장합니다.
6. 25번은 임시 2D 그림을 사용하지 않고 GitHub의 Geometry World 재질과 조명을 재사용합니다.
7. 섞어서 보기는 새 문제를 생성하지 않고, 검토가 끝난 문제의 표시 순서만 바꿉니다.
8. 문항 선택은 원본 회차·문제 번호를 먼저 기준으로 삼고, 유형 선택은 `source-catalog.js`의 `typeIds` 연결을 사용합니다.

## 그림 다시 만들기

16~24번:

```powershell
python scripts/generate_assets.py
```

25번:

1. 저장소 루트에서 로컬 웹 서버를 엽니다.
2. `scripts/q25_renderer.html?target=4` 형식으로 엽니다.
3. 두 번째 문제처럼 왼쪽 위에 맞춘 모양은
   `&alignment=upper-left`를 추가합니다.
4. 1360 x 900 크기로 각각 `q25_01.png`부터 `q25_03.png`까지 저장합니다.

`confirmed_sources/`는 인수인계 ZIP의 1~14번 확정 원본을 그대로 보관한
참고 자료입니다. 원본 제작 환경의 Linux 글꼴과 `/tmp` 출력 경로를 사용하므로,
다른 운영체제에서 다시 실행할 때는 글꼴과 출력 경로를 먼저 조정해야 합니다.

## 인쇄 주소

```text
fields-classic/prescription/?student=학생이름&types=1,7,14
```

진단 결과의 `약점 처방전 열기` 버튼이 학생 이름과 오답 문항 번호를
자동으로 이 주소에 전달합니다.
