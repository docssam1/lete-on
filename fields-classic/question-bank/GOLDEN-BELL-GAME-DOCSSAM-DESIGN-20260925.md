# 골든벨 체험 게임과 독쌤 대본

상태: 1권 4단원, 7체험, 21도전의 화면 체험에 적용. 2권 이후는 원본 활동과 답안 대조 뒤 단원별로 별도 구현한다. 음성 생성과 배포는 이 단계에서 하지 않는다.

## 한 도전의 흐름

1. 원본 활동과 같은 사고 행동을 요구하는 새 고정 도전의 조건을 먼저 보여 준다.
2. 독쌤은 말풍선으로 한 번에 하나의 행동만 안내한다. 그림과 조작 버튼이 실제 행동을 수행한다.
3. 조작 중에는 현재 상태를 설명하되, 정답 배치나 완성 그림을 대신 보여 주지 않는다.
4. 틀리면 실패한 조건을 다시 보게 한다. 맞으면 실제 수·방향·자리로 확인한 근거를 보여 준다.
5. 마지막 도전 뒤에만 연결 문제로 이동한다. 체험의 완료 상태는 원본 문제 성적이나 답안 승인에 기록하지 않는다.

말풍선은 `golden-bell-hands-on-guide.js`의 `start`, `progress`, `retry`, `success` 네 상태를 따른다. 질문과 조건이 말풍선보다 먼저 읽히도록 배치한다. 대본의 숫자는 현재 게임 상태에서만 계산하고, 미래 도전의 정답은 넣지 않는다. 음성이 없어도 모든 피드백을 읽고 조작할 수 있어야 한다.

## 풀이 과정을 행동으로 (원장 지시 2026-10-23)

원장: 「교사용 지도서나 골든벨 풀이 과정을 꼭 참고하고 게임 만들어야 돼」 「행동 과정을 생각해」.
게임은 **정답만 맞히는 화면이 아니라, 그 레슨 `explanation.steps`(골든벨 풀이)의 단계를 아이가 손으로 한 번씩 하는 화면**이어야 한다.
- 먼저 레슨의 `explanation.steps`를 읽고, 단계마다 「아이가 누르거나 옮기는 행동 하나」를 정한다. 단계를 건너뛰는 시행착오(한 개씩 옮겨 보다 맞히기)는 막는다.
- 다음 단계 행동은 앞 단계가 끝나야 열린다. 결과 확인 단추도 마지막 단계 전에는 잠근다.
- 틀린 행동은 옮기지 않고 결과를 미리 말해 준다(「k개를 주면 이번엔 B가 …개 더 많아요」) — 예측하고 확인하는 습관.
- 1권 「같아지도록 옮기기」를 이 방식으로 바꿨다(풀이: 차이 구하기 → 한 개 옮기면 차이가 2 줄므로 차이를 둘로 나누기 → 덧셈으로 확인).

## 확장과 검수

- 2권 이후는 제목만 보고 게임을 만들지 않는다. 교사용 원문 활동의 조건, 학생 행동, 그림, 공식 답을 먼저 대조한다. 한 단원에 의미 있는 체험 1~2개를 고르고, 조작이 필요 없는 유형은 억지 게임으로 바꾸지 않는다.
- 각 도전은 조건 데이터, 판정, 화면, 종이 문제, 답안의 안정 ID를 공유한다. 학생 문제 그림에는 완성 답을 넣지 않는다.
- 수학 검산, 오답/복수해 판정, 데스크톱·390px 조작, 키보드, 동작 축소, 실제 A4 네 모드 PDF, 정답 누출을 각각 검사한다. 화면 통과를 인쇄 통과로 간주하지 않는다.
- 독쌤 음성은 나중에 사용자가 지정한 본인 녹음과 정확한 녹취를 기준으로 별도 제작한다. `promo/anssem-hs` 자료는 음성 단계에서만 검토한다. 현재 체험에는 자동 재생과 음성 버튼이 없다.
