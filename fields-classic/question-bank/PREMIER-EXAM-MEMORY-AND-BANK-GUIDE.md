# 프리미어 시험·모의고사 문제은행 제작 가이드

이 문서는 필즈 더 클래식에서 검증한 **원본 기억 방식**과 **문제은행 제작 방식**을
프리미어 시험에 옮겨 적용하기 위한 인수인계 문서다. 목적은 원본 시험·모의고사·교재를
그대로 복제하는 것이 아니라, 각 문항의 실제 사고 구조를 확인한 뒤 같은 구조의 새 문제를
안전하게 생성하고 시험지로 구성하는 것이다.

## 1. 지켜야 할 결과

학생과 교사가 쓰는 화면은 다음 세 가지여야 한다.

1. **시험지별**: 원본 선발시험, 실전 모의고사, 파이널 모의고사를 고르고 문항 번호를 체크한다.
2. **교재·단원별**: 교재의 단원과 개념·유형·연습·심화 단계를 고른다.
3. **유형별**: 대분류 → 중분류 → 세부 유형을 고른다.

어느 경로에서 골라도 결과는 같은 형식의 시험지다. 문제 본문에는 문항 번호, 지문, 필요한 그림,
답칸만 보인다. 정답·풀이·유사문제 힌트는 별도 답안지 또는 교사용 화면에서만 연다.

## 2. 원본 기억 스킬: 먼저 찾아서 확인하고, 기억으로 만들지 않는다

### 2.1 원본 저장 원칙

- 원본 PDF, PPTX, 답안지, 해설 대본, 교재는 비공개 Drive 또는 비공개 저장소에 둔다.
- 공개 GitHub에는 원본 전체 페이지 이미지, OCR 전문, 원본 PDF를 올리지 않는다.
- 공개 코드에는 생성기, 직접 만든 SVG·CSS 도형, 유형 메타데이터, 검수 기록만 둔다.
- 원본 파일의 개인 PC 절대 경로는 코드와 공개 문서에 넣지 않는다.

### 2.2 메모리 카탈로그

프로젝트마다 `.source-memory/source-memory.json`을 따로 둔다. 이 파일에는 원문을 복사하지 않고
다음만 기록한다.

| 기록 | 예시 |
| --- | --- |
| 출처 식별 | `premier-final-02`, 프리미어 파이널 모의고사 2회 |
| 원본 종류 | 선발시험 / 실전 모의고사 / 파이널 모의고사 / 교재 / 답안 / 대본 |
| 안정 위치 | 원본 파일명, 페이지·슬라이드·문항 번호·영상 시간 |
| 상태 | `draft`, `verified`, `stale`, `excluded` |
| 근거 | `premier-final-02 | 문제지 p.4, 8번 그림` |
| 결정 | 기존 유형 재사용 / 새 세부 유형 / 제외 사유 |

원본을 확인할 때는 항상 다음 순서를 지킨다.

1. 카탈로그에서 시험지명·문항 번호·유형 후보를 찾는다.
2. 기존 감사 기록과 확정 답안을 먼저 읽는다.
3. 필요한 원본 페이지·슬라이드·대본 시간만 연다.
4. 문제지와 답안지를 같은 문항 번호로 대조한다.
5. 일치하지 않거나 판단이 안 되면 `draft` 또는 `stale`로 남기고 문제은행을 잠근다.

OCR·파일명·대본은 원본을 찾기 위한 보조 수단이다. 그림 위치, 접는 방향, 저울 기울기,
표의 행과 열처럼 답을 바꾸는 정보의 증거로 OCR만 사용하면 안 된다.

### 2.3 모의고사도 원본 시험과 똑같이 취급한다

실전·파이널 모의고사는 "연습 문제"라는 이유로 단원명만 붙여 한 유형으로 합치지 않는다.
각 회차의 각 문항을 원본 시험과 같은 표준으로 기록한다.

- `프리미어 실전 1회 15번`
- `프리미어 파이널 2회 8번`
- `프리미어 최종 점검 21번`

같은 이름이라도 그림·조건·묻는 값·풀이 순서가 다르면 새 세부 유형이다. 예를 들어,
기호 양팔저울과 동물 양팔저울은 둘 다 저울이지만 **질문 구조와 그림 조건이 다르면 분리**한다.
학생 화면에서는 같은 대분류 아래에 자연스럽게 보이되, 내부 생성기와 검수는 따로 관리한다.

## 3. 문항을 유형으로 옮기는 절차

문항마다 아래 표를 먼저 작성한다. 이 표가 없으면 생성기를 만들지 않는다.

| 항목 | 필수 기록 |
| --- | --- |
| 출처 | 시험·모의고사·교재 이름, 회차, 문항 번호, 원본 위치 |
| 대분류 | 수와 연산 / 규칙과 관계 / 논리와 문제해결 / 도형과 공간 |
| 중분류 | 예: 양팔저울, 색종이 접기, 반복 규칙, 쌓기나무 |
| 세부 유형 | 실제 풀이 동작이 드러나는 이름 |
| 주어진 것 | 숫자, 표, 그림, 조건 문장, 선택지 |
| 물어보는 것 | 수, 순서, 개수, 도형, 위치 중 무엇인지 |
| 풀이 흐름 | 아이가 거치는 생각 순서 |
| 정답 | 답안지와 직접 대조한 답 |
| 그림 구조 | 표 크기, 화살표, 방향, 시점, 기울기, 색, 빈칸 위치 |
| 난이도 기준 | 원본보다 쉽게 / 같게 / 어렵게 바꾸는 구조 규칙 |

### 세부 유형을 나누는 기준

다음 중 하나라도 다르면 기존 유형에 억지로 붙이지 않는다.

- 그림 구조가 다르다: 세로 표와 삼각형 표, 반 접기와 대각선 접기
- 묻는 값이 다르다: 전체 개수와 숨은 개수, 가장 무거운 것과 가장 가벼운 것
- 풀이 흐름이 다르다: 직접 비교와 중간 물건을 지우는 비교
- 답의 유일성을 만드는 조건이 다르다: 조건 배치, 참말·거짓말, 순서 문제

특히 **모의고사에서 이미 같은 유형 ID가 쓰였다는 이유만으로 생성기를 재사용하지 않는다.**
새 회차의 원본 구조를 기존 검증 문항과 1:1로 대조하고, 재현될 때만 재사용한다.

## 4. 생성기와 그림 제작 규칙

### 4.1 한 데이터에서 문제·그림·답을 만든다

생성기는 다음 값을 함께 반환한다.

```text
prompt       문제 지문
visual       그림을 그리는 구조화 데이터
answer       코드로 계산한 정답
solution     학년 수준 풀이
reference    기준 시험·모의고사·교재 문항
difficulty   쉽게 / 같게 / 어렵게
```

그림의 수, 동물, 저울 방향, 표 값은 `visual`에서 그리고, 답은 같은 데이터에서 계산한다.
그림만 따로 바꾸거나 지문만 따로 바꾸면 선·조건·정답이 서로 어긋난다.

### 4.2 난이도는 숫자 크기가 아니라 풀이 구조로 조절한다

| 수준 | 바꾸는 방법 |
| --- | --- |
| 쉽게 | 조건 하나를 줄이고, 마지막 단계에 빈칸을 둔다. |
| 같게 | 원본과 같은 조건 수·그림 구조·풀이 단계를 유지한다. |
| 어렵게 | 학년 범위 안에서 조건 하나를 더하거나 빈칸을 중간에 둔다. |

큰 수만 넣거나 설명을 길게 해서는 "어렵게"가 아니다. 유아·초1 범위에서는 순열·조합·제곱·방정식 같은 용어와 풀이를 사용하지 않는다.

### 4.3 그림 방식

- 표, 수 카드, 저울, 선, 화살표, 색종이: HTML/CSS 또는 SVG
- 인쇄에서 선명해야 하는 도형: SVG 우선
- 쌓기나무: 검증된 Geometry/Cube Town 생성기와 렌더러 재사용
- 실제 동물·교구 그림: 프로젝트 안에서 허가된 자산만 사용
- 원본 교재 페이지: 공개 저장소에 두지 않으며, 필요할 때 권한 있는 뷰어에서만 표시

저울의 경우에는 무거운 쪽의 저울판·물건이 실제로 아래로 내려가야 한다. 이름, 동물, 받침대,
저울선이 겹치거나 카드 밖으로 나가지 않는지 PC·모바일에서 함께 검사한다.

## 5. 단일 정답과 답 노출 방지

1. 완성된 정답 상태를 먼저 만들고, 문제에 필요한 값만 가린다.
2. 가능한 배치·순서·조건을 모두 검사할 수 있으면 전수 확인해 답이 하나인 경우만 남긴다.
3. 생성기 계산과 다른 방식으로 답을 다시 계산한다.
4. `NaN`, 빈 지문, 빈 그림, 0개 조건, 여러 정답, 학년 밖 수는 버리고 다시 생성한다.
5. 객관식은 정답만 길거나 진하거나 가운데에 오지 않게 한다. 오답은 실제 실수에서 만든다.
6. 문제 본문·그림 제목·캡션에는 풀이와 정답 힌트를 넣지 않는다.

정답과 해법 키포인트는 승인된 답안지, 진단 결과, 교사용 화면에만 표시한다.

## 6. 문제은행 화면 규칙

### 선택 화면

- 시험지별: 모의고사 회차를 열고 **문항 번호 단위**로 체크한다.
- 교재 단원별: 권 → 단원 → 개념·유형·연습·심화 → 세부 유형을 체크한다.
- 유형별: 대분류 → 중분류 → 세부 유형을 체크한다.
- 마우스를 유형에 올리면 대표 문항 미리보기를 보여 주되, 원본 페이지를 그대로 노출하지 않는다.
- 원본 대조 또는 생성기 검수가 끝나지 않은 항목은 보이되 선택할 수 없게 한다.

### 시험지 화면

- 선택 기준에 따라 생성된 문제를 한 장의 시험지 카드로 보여 준다.
- 문항에는 번호, 지문, 필요한 그림, 답칸만 둔다.
- `정답 확인`, 힌트, 풀이, 답은 문제 본문에 넣지 않는다.
- 답안 보기와 풀이 핵심은 별도 답안지로 연다.
- 학생 이름 워터마크는 화면·인쇄에 대각선 3줄 정도로 넣는다.
- 모바일은 한 장씩 세로로 보기, 인쇄는 A4에서 잘림 없이 나오게 한다.

## 7. 공개 전 검수 순서

각 새 시험 또는 모의고사마다 아래 순서를 끝까지 지킨다.

1. 원본 문제지·답안지·필요하면 해설 대본을 문항 번호별로 대조한다.
2. 감사 문서에 문항별 유형 연결, 원본 위치, 답, 보류 사유를 남긴다.
3. 기존 생성기 재사용 여부를 구조 기준으로 판단한다.
4. 새 유형은 생성기·렌더러·독립 정답 검산을 만든다.
5. 쉬움·같게·어려움마다 최소 1,000회 생성해 답·유일성·그림·문장을 검사한다.
6. 여러 유형을 섞어 실제 시험지 수만큼 생성한다.
7. PC, 모바일, A4 인쇄에서 카드 겹침·선 꼬임·그림 잘림·답 노출이 없는지 확인한다.
8. 통과한 문항만 `sourceMatched: true`, `verified: true`로 열고, 나머지는 잠근다.

## 8. 프리미어 프로젝트 권장 파일 구조

```text
premier-question-bank/
  .source-memory/
    source-memory.json              # 원본 위치와 검증 근거만 저장
  source-audits/
    premier-selection-audit.md      # 원본 선발시험 문항 대조
    premier-practice-01-audit.md    # 실전 모의고사 1회
    premier-final-01-audit.md       # 파이널 모의고사 1회
  source-data.js                    # 시험·문항·유형 연결과 잠금 상태
  generators.js                     # 새 문제와 정답 계산
  renderers.js                      # SVG/HTML 그림 렌더
  answer-verifiers/                 # 생성기와 다른 계산의 검산 코드
  app.js                            # 선택·시험지·답안지 화면
```

## 9. 다른 작업자에게 전달할 작업 순서

1. 프리미어 원본을 카탈로그에 **식별 정보만** 등록한다.
2. 선발시험과 모든 실전·파이널 모의고사를 회차별 감사 문서로 나눈다.
3. 문항 하나씩 원본 그림·조건·답을 대조해 세부 유형을 정한다.
4. 기존 유형과 같아 보이면 반드시 기존 검증 문항을 열어 구조를 비교한다.
5. 생성기·독립 검산·렌더러를 함께 만든다.
6. 선택 화면에서는 확인된 문항만 체크 가능하게 한다.
7. 생성된 결과는 시험지 형식으로만 보여 주고, 답은 분리한다.
8. 검수 결과와 보류·제외 결정을 카탈로그와 감사 문서에 남긴다.

## 10. 금지 사항

- 원본을 보지 않고 대본·OCR·기억만으로 유형을 확정하기
- 비슷한 이름의 기존 생성기를 그대로 연결하기
- 원본 교재·시험지 페이지를 공개 GitHub에 올리기
- 문제 본문에 답이나 풀이 힌트를 넣기
- 답이 여러 개인 문제를 열기
- 난이도를 숫자만 크게 해 조절하기
- 미검수 문항을 `verified`로 일괄 변경하기
- 기존 진단·처방 상품의 생성기를 새 문제은행 작업 중에 임의로 수정하기

이 가이드의 핵심은 하나다. **원본 위치가 확인되고, 사고 구조와 정답이 검증된 문항만,
새 문제로 생성해 시험지에 넣는다.**
