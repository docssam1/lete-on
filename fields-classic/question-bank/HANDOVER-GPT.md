### Geometry 공용 코드의 문제은행 세분화

- Geometry 학습지의 PN·SQ 코드는 발급 코드 호환성을 위해 유지한다.
- 문제은행에서는 PN을 `색칠된 면 전체 수`와 `n면이 색칠된 낱개 수`, SQ를
  `n번째 개수`, `개수로 몇 번째 찾기`, `다음 단계 증가량`으로 나눴다.
- `worksheetOptions`로 질문 구조만 고정하며 그림·계산·정답 엔진은 한 벌만 쓴다.
  같은 세부 유형 안에서 계단·십자·정사각형 등 모양이 달라지는 것은 정상이다.
- 새 다섯 세부 유형은 세 난이도별 1,000회씩 **15,000문항**을 별도 재검산했고,
  요청하지 않은 질문 구조가 섞인 경우와 답 오류가 모두 0건이었다.
- 기존 Geometry 학습지·발급 코드의 재현성을 지키기 위해 옵션 없는 13코드는
  기준 커밋 `a0681d5`와 **12,000개 시드**를 비교했고 모두 동일했다.
- 일반 SQ에서 삼각 계단은 제외한다. 파이널 원본과 대조된 삼각 계단은
  `cube-step-sequence` 전용이며, 다른 SQ 유형과 다시 섞지 않는다.

### 원본 재대조 전 개방 금지인 반복 ID

- 초1 2·3·4차의 `shape-sum-table`, `cryptarithm`, `vertical-addition`,
  `multiplication-matrix`, `ratio-distribution`은 같은 ID가 여러 문항에 임시로 반복된다.
- 이 문항들은 현재 `verified: false`이거나 생성기가 없어 전부 잠겨 있다. **같은 ID라는
  이유만으로 기존 생성기를 연결하거나 `verified`를 일괄 변경하지 않는다.** 원본 한 문항씩
  그림·조건·질문·답을 대조한 뒤 구조가 다르면 새 세부 유형 ID로 나눈다.
- 실전·파이널에서 같은 ID가 반복되는 것은 실제로 같은 구조가 재출제된 경우가 많지만,
  새 회차를 추가할 때도 문항 번호별 1:1 대조 규칙은 그대로 적용한다.

## 1. 이 물건이 무엇인가

한국 영재·사고력 학원 **필즈 더 클래식**의 6~7세 선발시험 대비 문제은행이다.
실제 선발시험지·실전 모의고사·1과정 교재를 **문항 단위로 원본과 대조한 뒤**, 같은 구조의
문제를 무한히 만들어 내는 생성기를 붙인다. 대조가 끝나지 않은 문항은 화면에 보이되
**선택할 수 없게 잠근다.**

파는 것은 문제 자체가 아니라 **"실제 출제와 같은 구조"라는 보증**이다. 그래서 이 프로젝트의
거의 모든 규칙은 "확인되지 않은 것을 열지 않는다"로 수렴한다.

### 화면 구성 (세 가지 진입)

1. **시험 종류별** — 시험지를 고르고 문항 번호를 체크한다
2. **시기별** — 6세 12월~초1 1월까지 9구간
3. **유형별** — 대분류 > 중분류 > 세부 유형 체크 트리

## 2. 절대 규칙 (어기면 상품이 망가진다)

1. **문항 번호별로 원본 그림·조건·답안을 모두 대조한다.** 요약본이나 기억으로 하지 않는다.
2. **제목이 비슷해도 구조가 다르면 다른 세부 유형을 만든다.** 이 규칙이 이 프로젝트에서
   가장 자주 깨졌다(아래 4절 참고).
3. 생성기는 **답을 코드로 계산**한다. 난이도는 숫자 범위가 아니라 **조건 수와 구조**로 조절한다.
4. **원본 대조 + 난수 검산이 끝난 문항만** `verified: true` / `sourceMatched: true`로 연다.
5. Golden Bell, 연산 테스트, 2권 이후 교재 뒤 리뷰는 제외한다.
6. `fields-classic/prescription/`과 `fields-classic/problem-bank/prescription/`의 기존 진단
   유사문제는 **건드리지 않는다**(별도 상품).
7. **파이널 4회 = 실전 4회, 파이널 최종 = 실전 3회**로 문항·그림·수치가 같다. 중복본을 다시
   연결하지 말 것. 서재에 `준비중` 자리만 둔다.

### 검산의 원칙 — 자기보고는 근거가 아니다

**생성기가 계산한 답을 그대로 믿지 않는다.** 답을 **구조가 다른 방법으로 다시 계산**해서
일치할 때만 연다. 이 방식이 거의 모든 유형에서 실제 결함을 잡았다.

| 유형 | 생성 방식 | 검산 방식(다른 구조) |
| --- | --- | --- |
| 성냥개비 | 4 + 3(n−1) 공식 | 변을 좌표 집합에 넣어 중복 제거하고 센다 |
| 바둑돌 | 넓이 공식 | 격자를 실제로 칠해서 한 칸씩 센다 |
| 과녁 조합 | 규칙 추론 | 모든 짝을 만들어 합을 집합에 모은다 |
| 색종이 조각 수 | — | 세 해상도(401·509·643) flood fill이 전부 일치할 때만 |
| 색종이 구멍 수 | — | 2^접기로 가정하지 않고 실제로 되접어 서로 다른 구멍을 센다 |
| 배치·추리 | 정답에서 역산 | 전수 열거로 **답이 유일한지**까지 확인 |

난수 검산은 **쉬움·같게·어려움 각각 1,000회 이상**을 기본으로 한다.

## 4. 가장 중요한 교훈 — "이름만 같은 유형" 덫

이 프로젝트에서 **가장 많이, 가장 조용히 발생한 사고**다. 반드시 읽을 것.

생성기가 이미 있으면 "된 것"처럼 보인다. 그런데 그 생성기는 **7세 1차의 어떤 문항**에 맞춰
만들어진 것이고, 다른 시험지가 같은 유형 id를 쓰면서 **구조가 다른 문항**에 붙는다.

- **파이널 2회**: 생성기가 있던 6문항을 대조했더니 **6개 전부 구조가 달랐다.**
- **파이널 3회**: 같은 검사를 했더니 6개 중 **5개가 잘못**돼 있었다(3개는 구조 불일치,
  2개는 유형 id 오기).

### 그래서 반드시 이렇게 한다

새 시험지의 문항이 기존 유형에 연결돼 있으면, **그 연결을 의심부터 한다.**

1. 그 유형이 쓰인 **모든 시험지**를 훑어 **어느 문항이 그 생성기의 검증 기준이었는지** 찾는다.
2. 새 시험지 원본의 **구조와 확정 답**이 그 기준에서 재현되는지 **수치로 돌려 본다.**
3. 안 되면 **새 세부 유형으로 분리한다.** 기존 생성기를 고쳐 두 문항을 겸하게 만들지 않는다.

이름 비교만으로는 절대 안 잡힌다. 실제로 잡힌 예:
`edge-sum-grid`(네 원 사각형)에 삼각형 최대합 문제가, `symbol-sum-grid`(3×3)에 4×4 문제가,
차가 n+1로 늘어나는 바둑돌 생성기에 차가 늘 0 또는 1인 문제가 붙어 있었다.

### 만들면서 걸린 것 (같은 실수를 반복하지 않도록)

- **참말·거짓말 추리가 3,000번에 18번밖에 성립하지 않았다.** "1등이 아니야" 같은 약한 말만
  쓰니 조건을 만족하는 순서가 **중앙값 48가지**나 남아 누구의 등수도 정해지지 않았다.
  → 등수를 콕 집는 말을 섞고, **등수가 하나로 정해지는 사람 중에서** 물을 사람을 고르게 해
  9%대로 올렸다. **순서가 여러 가지여도 되고 묻는 사람의 등수만 하나면 된다**(원본도 순서는
  두 가지, 답은 하나였다).
- **이름을 가·나·다로 붙였더니 "나: 가는 나보다 바로 뒤에 들어왔어"** 가 나왔다. 이름 '나'와
  대명사 '나'가 겹쳐 읽을 수가 없다. → 실제 이름으로 교체.
- **조사가 틀렸다.** "예린는", "서연가", "닭와 토끼", "사탕는", "10장가", "형을(를) 있는 학생".
  → 받침을 계산하는 헬퍼 `hasBatchim`/`topicOf`/`subjectOf`/`withOf`/`objectOf`를 넣었다.
  **"형을(를) 있는" 같은 문장은 조사만으로 안 된다** — 문장 전체를 시나리오마다 적어 둔다.
  문장을 훑는 검사기도 만들었는데, `있는`·`없는`·`기르는` 같은 **동사 어미 '-는'을 조사로
  오인**하니 걸러야 한다.
- **별 개수가 0인 줄**이 나왔다. 그 줄을 통째로 비우면 끝이라 문제가 되지 않는다.
- **viewBox만 있는 SVG가 카드 폭까지 늘어났다.** 색종이 이식 때와 **같은 실수를 반복**했다.
  `width:100%; max-width:...; height:auto`를 반드시 준다.
- **조건이 까다로운 생성기는 뽑기에 실패하면 `null`을 준다.** `app.js`가 한 번만 호출하고
  있어서 **빈 문항 카드가 나갈 수 있었다.** 최대 400회 재시도하도록 고쳤다.

### 문항을 여는 절차

```js
// source-data.js — 유형 등록
type("matchstick-growth", "pattern", "도형 규칙", "이어 붙인 성냥개비 도형에 필요한 개수",
     { generator: "matchstickGrowth", sourceMatched: true })

// source-data.js — 시험지의 문항별 verified 플래그
].map((typeId, index) => ({ ...question(index + 1, typeId),
     verified: [0, 1, 5, ...].includes(index) }))
```

**열리는 조건 = `verified`(문항) AND `sourceMatched`(유형) AND 생성기 존재.**
셋 다여야 체크박스가 활성화된다. 교재 탭은 `textbookSource`가 있으면 열리지만,
**시험지 탭은 문항별 `verified`를 별도로 요구한다. 이 게이트는 절대 완화하지 않는다.**

```js
}
```

`meta`는 장식이 아니다. **검산기가 답을 독립적으로 다시 계산할 때 쓰는 입력**이다.
검산에 필요한 값이 `meta`에 없으면 검산은 문자열 비교로 전락한다.

### 확인 명령

```bash
node --check generators.js && node --check app.js && node --check source-data.js
# 브라우저 확인은 Playwright + /opt/pw-browsers/chromium 사용
```

## 8. 이 프로젝트에서 반복적으로 틀린 것 모음

같은 실수가 여러 번 났다. 착수 전에 한 번 읽으면 시간을 아낀다.

1. **이름만 같은 유형에 연결** — 11번 발생. 4절 참고.
2. **viewBox만 있는 SVG가 컨테이너 폭까지 늘어남** — 2번 발생.
3. **한국어 조사** — 이름·사물을 무작위로 뽑으면 반드시 깨진다.
4. **답이 문제에 그대로 노출** — 달력 문항에서 목표 날짜가 남은 줄에 보였고, 날짜 문항에서
   `after === ago`면 시험 날짜가 오늘이 되어 답이 드러났다. **난수 검산에 "답 노출" 항목을
   반드시 넣는다.**
5. **답의 유일성 미확인** — 겹친 색종이 순서가 1,000회 중 994회 실패했다. 조건을 "z순서상
   **바로 위** 종이와 겹침"으로 바꿔 0회가 됐다.
6. **정답이 늘 최장 보기** — 4지선다를 만들 때 정답에만 한정어구가 붙는다. (CARS 쪽 교훈이지만
   문제은행 4지선다에도 그대로 적용된다.)
7. **본인의 오진** — "화살표 호가 종이 밖으로 부푼다"고 보고했다가 좌표로 재보니 아니었다.
   **눈으로 본 것도 수치로 확인한 뒤에 고친다.**

## 9. 교육과정 학습맵 계층

`learning-map.js`는 기존 문제은행 위에 교육과정 탐색 정보를 얹는 별도 계층이다. 문제를 만드는 기준은 계속 `source-data.js`의 GFIELD 대영역·중영역·세부 유형과 원본 대조 기록이다.

- 공개 자료: `DECK6/korean-elementary-learning-map`
- 고정 버전: `kr-full-depth-v0.4`
- 고정 커밋: `3ef0563084aa2a9baaa47da2c1ec0ebf5d7edc5c`
- 라이선스와 표시 원칙: `LEARNING-MAP-NOTICE.md`

초1~2 수학 87개 토픽을 10개 상위 묶음으로 정리했다. 관련성이 분명한 중분류는 `교육과정 관련`, 마방진·복면산·논리 추리처럼 국가 성취기준 하나에 정확히 넣기 어려운 유형은 `사고력 확장`으로 표시한다.

절대 규칙:

1. 학습맵을 이유로 기존 `typeId`, 유형명, 생성기, 난이도, 정답을 바꾸지 않는다.
2. `관련 위치`는 공식 1:1 대응이나 학생 진단이 아니다.
3. 연결이 애매하면 추측하지 말고 `사고력 확장`으로 남긴다.
4. 진단 모의고사와 처방 시스템에는 이 계층을 연결하지 않는다.
5. 학습맵 버전을 바꾸면 전체 유형 매핑 검사와 브라우저 미리보기 검사를 다시 한다.
