# 골든벨 체험 포함 교재 인쇄 설계

작성일: 2026-09-22. 상태: **설계 제안이며 미구현, 실제 PDF 미검수**.
확인 브랜치: `codex/golden-bell-semantic-workbook`.
이번 작업은 이 문서 하나만 작성한다. 기존 dirty 변경, 구현 파일, 원본 자료는 보존하며 커밋과 푸시는 하지 않는다. 다른 프로그램과 제외 자료는 검사하지 않는다. 비공개 파일 경로, 실제 공식 답, 개인정보는 기록하지 않는다.

## 2. 교재 구성과 모드

권 표지 1쪽 -> 단원 개념표지 -> 체험 종이판 -> 교재 문제와 개별 답칸 -> 추가 연습 -> 다음 단원 순서로 학생 묶음을 구성한다. 답안과 풀이는 별도 후반 묶음이다. 개념표지에는 개념명, 핵심 문장, 칼라 개념 그림, 해당 체험명/번호를 넣는다. 출제된 문제의 해답 그림을 개념 예시로 재사용하지 않는다.

| 사용자 모드 | 기존 값 | 향후 출력 계약 |
| --- | --- | --- |
| 문제만 | `study` | 표지/개념, 체험 조건과 빈 기록칸, 문제와 소문항별 빈 답칸, 추가 연습. 출제 문항의 정답/풀이/완성 그림은 제외한다. 기존 스토리보드의 verify 및 답 노출 프레임을 선별하는 별도 검증이 필요하다. |
| 답안 | `answers` | 동일 번호의 답, 풀이 단계, 풀이 그림, 체험 판정 조건과 대표 예시. 학생 문제 묶음은 중복하지 않는다. |
| 빠른 정답 | `quick` | 동일 번호와 최소 판정 정보. 배치/색칠형은 작은 좌표 격자 또는 배치도, 복수해 체험은 대표 예시 및 허용 조건. 긴 풀이는 제외한다. |
| 함께 | `both` | 문제만 묶음 전부 + 필요 시 빈 면 + 답안 묶음 전부. 문제 사이에 답안을 끼워 넣지 않는다. |

문제 선택/단원 선택은 네 모드 모두 같은 manifest를 사용한다. 답안이 준비되지 않으면 답안 포함 모드는 중단하고 명확히 알린다. 미검증 체험은 빈 답으로 내보내거나 임의 답을 만들지 않고 선택에서 잠근다.

### 양면 답안 앞면 정책

기존 `addDuplexAnswerBlank(root, book, mode)`는 `both`에서 첫 `answers-` 페이지 전의 페이지 수가 홀수일 때 빈 면을 넣는다. 즉 학생 묶음이 5쪽이면 6쪽을 비우고 답안은 7쪽, 학생 묶음이 6쪽이면 바로 7쪽에서 시작한다. 빈 면도 실제 PDF 쪽수에 포함한다.

신규 체험 답안은 `answers-hands-on-*`처럼 기존 접두어를 유지하거나 명시적인 답안 역할로 함께 탐지해야 한다. 모든 콘텐츠 분할/압축이 끝난 뒤 빈 면을 넣고 `renumberPrintPages`를 마지막에 호출한다. 독립 출력물의 PDF 1쪽이 앞면이고 긴 변 넘김 양면이라는 전제다. 다른 문서에 합칠 때는 선행 쪽수를 별도 입력받기 전까지 앞면을 보장하지 않는다.

## 3. 단원당 1~2체험과 21도전 정책

현재 모델 적용 범위는 **1권의 4개 단원**이다. 전체 과정의 모든 단원에 체험이 준비되었다는 뜻이 아니다. 그 밖의 단원은 대응 모델/검수 필요로 남긴다. 단원은 lesson 하나가 아니라 `HANDS_ON_UNITS`의 묶음이며, 같은 단원의 여러 lesson을 출력해도 체험을 반복 삽입하지 않는다.

| 단원 / unit ID | 체험 번호 / activity ID | 연결 lesson | 도전 번호 | 종이 대응물과 기록칸 |
| --- | --- | --- | --- | --- |
| 도형 움직이기 / `movement` | T01 / `turn-clock` | `clock-turning` | D01~D03 | 출발 바늘 시계, 방향 화살표, 1/4바퀴 이동 기록칸, 최종 바늘을 그릴 빈 시계. 방향/회전량/끝 위치를 각각 기록한다. |
| 도형 움직이기 / `movement` | T02 / `mirror-tiles` | `mirror-reflection` | D04~D06 | 원본 4x4 격자, 가로/세로 거울선, 주어진 칸과 학생 색칠 영역. 거울까지 거리 짝을 표시할 짧은 기록칸. |
| 색종이 접기 / `folding` | T03 / `fold-once` | `fold-one-cut` | D07~D09 | 시작 종이, 접는 방향, 접힌 종이의 자를 칸, 펼침 예상 빈 4x4 격자. 접는 선과 자르는 선을 구분한다. |
| 색종이 접기 / `folding` | T04 / `fold-twice` | `fold-two-cut` | D10~D12 | 시작 -> 첫 접기 -> 둘째 접기 -> 자르기 조건 그림, 역순 펼침 기록과 최종 빈 격자. 충분한 전폭 작업 공간. |
| 마방진과 가쿠로 퍼즐 / `equal-sums` | T05 / `cross-sums` | `equal-line-placement` | D13~D15 | 중앙 고정 수와 네 빈 자리의 십자판, 중복 없이 쓸 카드, 가로/세로 식과 합을 따로 쓰는 칸. |
| 수 추리와 논리 추리 / `logic` | T06 / `line-order` | `relative-order-running` | D16~D18 | A~D 카드, 앞/뒤가 명시된 네 자리, 각 조건 점검칸. 이름 등 실사용자 데이터는 사용하지 않는다. |
| 수 추리와 논리 추리 / `logic` | T07 / `share-equally` | `book1-equalize-transfer` | D19~D21 | A/B 시작 묶음, 옮기는 방향, 옮긴 수/이후 양쪽 수/차이 기록표와 두 식의 빈칸. |

단원별 체험 수는 2/2/1/2이며 각 체험에 현재 `rounds` 순서대로 3도전이 있다. 위 D번호는 **제안한 인쇄 전역 번호**이지 현재 코드 필드가 아니다. 화면 표시는 계속 도전 1/3~3/3과 대응한다.

- 내부 식별자는 `bookId/unitId/activityId/roundIndex`로 고정한다. `roundIndex`는 0부터, 인쇄 도전 표시는 1부터다. T/D 매핑은 버전이 있는 manifest에 고정하여 필터링해도 재번호하지 않는다.
- 교재 문항의 `sourceNo`, 추가 연습 번호, 체험 T/D번호는 분리한다. 도전 하나의 여러 기록칸은 D01-a/b처럼 연결하며 별도 도전으로 세지 않는다.
- 도전 1/2/3을 자동으로 쉬움/보통/어려움이라 부르지 않는다. 현재 배열 순서이며 난도 상승은 검증되지 않았다.
- 종이 공통 단계는 1 조건 읽기 -> 2 예상/조작 -> 3 결과 기록 -> 4 이유 설명이다. 답안에는 대응 검증 단계를 둔다. 단계 번호와 도전 번호를 혼용하지 않는다.
- 기본 교재는 선택한 단원당 모든 체험과 각 3도전을 포함한다. 축약 출력은 명시적 선택일 때만 허용하며 선택된 D번호를 표지에 표시하고 21도전 전체라 부르지 않는다.
- 단원 전체 인쇄는 unit ID로 중복 제거한다. lesson 단독 인쇄는 해당 lesson에 직접 연결된 체험을 우선한다. 직접 연결이 없으면 단원 공통 체험 선택을 명시적으로 제공하고 관련 없는 체험을 자동 배정하지 않는다.

### 판정 보존의 주의점

시계는 끝 위치만으로 판정하면 한 바퀴와 제자리의 차이를 잃는다. 현재 `activityCheck`처럼 방향을 포함한 회전량도 기록해야 한다. 거울의 좌표는 `[x,y]`이고 셀 인덱스는 `y*4+x`다. 인쇄 행/열 표시는 1부터 변환하되 좌표를 뒤집지 않는다.

접기는 `round.model.folds` 순서와 컷 위치를 그대로 사용하고 펼치기는 역순이다. 시작/중간 조건 그림은 제공하되 완성 펼침도는 학생 문제에 노출하지 않는다. 접기/자르기 수행 확인과 예상 칸 답을 구별한다. 실제 가위 작업 대신 그리기로 수행할 수 있게 하고, 오려 쓰는 부록은 단면 출력으로 분리한다.

십자 합과 줄 세우기는 단일 정답이라고 가정하지 않는다. 카드 중복 금지/합 동일/모든 조건 충족을 판정 기준으로 하며 대표 배치와 다른 유효 배치도 허용한다. 나누어 옮기기는 최종 양의 같음과 전체 수 보존을 함께 확인한다. 화면의 `solved`, `checked`, `history`, 학습 성적이나 사용자의 실제 풀이 흔적은 인쇄 데이터에 포함하지 않는다.

## 4. 제안 데이터 계약과 연결 함수

아래 이름/필드는 **향후 제안**이며 현재 구현된 API가 아니다.

| 제안 계약 | 필수 필드 / 규칙 |
| --- | --- |
| `WorkbookManifest` | `schemaVersion`, `bookId`, `selectedLessonIds`, `mode`, `colorMode`, `units`, `items`, `answerStartOnFront`. 한 번 확정한 선택/순서를 네 모드가 공유한다. |
| `PaperActivity` | `unitId`, `activityId`, `activityNo`, `lessonId`, `kind`, `rounds`. 현재 `HANDS_ON_ACTIVITIES[id].lesson`을 `lessonId`로 명시적으로 매핑한다. |
| `PaperChallenge` | `key`, `roundIndex`, `challengeNo`, `prompt`, `givenVisual`, `steps`, `responses`, `layout`. 모델의 조건만 복사하며 화면 state와 분리한다. |
| `PaperResponse` | `id`, `label`, `type`(number/text/drawing/grid/order/equation), `unit`, `minHeightMm`, 필요 시 `rows/cols`. 하나의 요구 결과마다 독립 칸을 둔다. |
| `PaperLayout` | `span`(1 또는 2), `keepTogether`, `minVisualMm`, `splitPoints`, `role`. `role`은 concept/question/practice/hands-on/answer/blank 중 하나다. |
| `PaperAnswer` | 동일 `key`, `responseIds`, `validationKind`, `acceptedRule`, `solutionSteps`, `solutionVisual`, `verificationStatus`. 승인된 답안 경로에서만 결합한다. 공개 manifest에 답/풀이 payload를 넣지 않는다. |

`buildHandsOnPaperManifest(bookId, selectedLessons)`는 `unitForLesson`과 두 상수를 읽고 중복 제거/번호 매핑을 한다. `renderHandsOnPaper(challenge, { mode, colorMode })`는 정적인 칼라 그림과 응답칸을 만든다. 화면 렌더러를 그대로 호출하면 버튼, 정답 피드백, 현재 상태가 섞이므로 별도 순수 어댑터를 제안한다. 모델의 원래 배열은 변경하지 않는다.

`printLessons` 연결 순서는 manifest 확정 -> 기존 표지/개념/문제/추가 연습과 체험 페이지 구성 -> 승인된 답안 결합 -> 폰트/이미지 준비 -> `compactGoldenBellPrint` -> 양면 빈 면 -> `renumberPrintPages` -> 인쇄다. 기존 `printLessonPage`의 lesson 단위 생성만으로는 단원 체험 중복을 막기 어려우므로 상위 조합 단계에서 unit별 한 번만 삽입한다.

기존 `data-print-book`, `data-print-lesson`, `data-print-part`를 유지하고 신규 `data-print-unit`, `data-print-activity`, `data-print-challenge`, 안정적인 item key를 추가한다. 제안 part는 `hands-on-T01-D01`, 답안은 `answers-hands-on-T01-D01`이다. 레이아웃의 `exerciseFamily/exerciseNodes`가 이를 인식하게 하는 변경은 추후 별도 승인이 필요하다. 답안과 학생용의 family는 서로 합치지 않는다.

## 5. A4 페이지 분할

- 현재 188mm 폭/265mm 높이 측정 기준과 실제 인쇄 CSS를 출발점으로 삼는다. 본문 2열, 간격 6mm를 제안하며 열당 약 91mm다. 실제 안쪽 패딩/제본 여백을 적용한 최종 폭은 PDF로 다시 측정한다.
- 짧은 문제는 한 장 4~6개, 중간 크기 그림 문제는 2~4개를 초기 목표로 삼는다. 고정 개수 할당이 아니라 문제+그림+개별 답칸+최소 필기 공간의 실측 높이로 결정한다.
- 시계/거울/카드 배치는 기본 반폭, 두 번 접기는 기본 전폭이다. 4x4 응답 격자는 한 변 40mm 이상, 시계는 지름 40mm 이상, 단답칸 높이 8mm 이상, 이유 쓰기는 최소 두 줄/14mm를 제안한다. 초등 본문은 11pt를 출발값으로 삼고 수용량 때문에 무조건 축소하지 않는다.
- 문제와 모든 소문항 답칸은 원칙적으로 한 묶음이다. 제목만 전 페이지에 남기지 않는다. 길면 먼저 전폭 -> 다음 쪽 -> 의미 있는 단계 경계에서 계속 페이지 순으로 처리한다. 계속 페이지는 동일 D번호와 단계 번호를 반복한다.
- 공통 그림과 그것을 참조하는 문항은 함께 이동한다. 이동이 불가능하면 공통 그림을 계속 페이지에 명시적으로 반복하며 다른 문항으로 오인되지 않게 한다. 소문항의 공유 그림을 임의로 잘라내지 않는다.
- 개념표지, 절취 부록, 학생/답안 경계는 압축에서 보호한다. 체험 도전끼리는 같은 단원/학생 역할 내에서만 합치며 독립 조건 그림과 답칸을 유지한다. 빈 공간을 채우기 위해 다음 단원이나 답안을 끼우지 않는다.
- 기존 `contentFits`의 푸터 전 8px 안전 간격을 유지하고 중첩 요소의 overflow도 별도 검사한다. 새 체험이 한 장에 안 들어가면 명시적 분할 또는 준비 실패를 반환한다. `overflow:hidden`, 글씨 강제 축소로 잘림을 숨기지 않는다.

## 6. 칼라 그림과 흑백 판독

칼라가 기본이다. 실제 조건을 보여 주는 벡터 그림과 격자를 사용하고 화면 애니메이션의 우연한 중간 프레임은 인쇄하지 않는다. 칼라 그림의 주어진 부분/조작 대상/학생 기록을 서로 다른 색과 선 종류로 구분한다.

흑백 대응은 단순 회색 변환에 맡기지 않는다. 주어진 칸은 빗금+윤곽선, 학생 답칸은 빈 테두리, 거울선은 굵은 이중선, 접는 선은 파선, 자르는 선은 실선과 짧은 라벨로 구분한다. 색 이름만으로 문제 조건을 설명하지 않는다. 화살표에는 방향 라벨, 카드에는 숫자/문자, A/B 묶음에는 문자 표식을 병기한다.

최종 크기에서 주요 선 0.3mm 이상을 출발 기준으로 제안한다. 인쇄 배경 옵션이 꺼져도 조건/격자/답칸이 사라지면 실패다. `print-color-adjust: exact`는 보조 수단일 뿐이다. 칼라 PDF와 흑백 PDF, 실제 흑백 종이 출력 각각에서 판독을 확인해야 한다.

## 7. 실제 PDF 검수표 제안

아래 항목은 모두 **미실행**이다. 코드 분석/HTML 스크린샷만으로 통과 처리하지 않는다. 추후 승인된 검수에서는 고정된 브라우저와 A4 100% 조건으로 실제 PDF를 저장하고 페이지를 렌더해 전수 확인한다. 검수용 이름/날짜는 공란으로 둔다.

| 검수 항목 | 대상 / 방법 | 통과 기준 | 현재 |
| --- | --- | --- | --- |
| 도전 완전성 | 1권 전체 manifest와 PDF의 T/D번호 대조 | 4단원, 7체험, 21도전; 누락/중복 0 | 미실행 |
| 단원 선택 | 각 단원, lesson 단독, 여러 lesson 선택 | 2/2/1/2 체험 정책 및 중복 제거; 선택 외 도전 0 | 미실행 |
| 네 모드 x 두 색상 | `study/answers/quick/both` x 칼라/흑백 총 8조합 PDF | 모드별 포함/제외가 계약과 일치 | 미실행 |

| 실제 분할 | PDF 모든 쪽 및 가장 긴 지문/다중 답칸/접기 쪽 확대 | 잘림/겹침/고립 제목/불필요한 빈 쪽 0, 필기 공간 확보 | 미실행 |

| 칼라/흑백 판독 | 칼라, 회색 출력, 배경 인쇄 해제, 실제 흑백 1부 | 색 없이 조건과 답칸 판독 가능, 얇은 선/연한 표식 소실 0 | 미실행 |

## 8. 후속 승인 단위

1. 1권 4단원/7체험/21도전 manifest와 학생/답안 분리 계약을 승인한다.
2. 정적 종이 어댑터와 번호/레이아웃 연결을 별도 구현한다. 다른 프로그램은 수정하지 않는다.
3. 실제 PDF 8조합 및 양면/흑백 실물을 검수한 뒤 해당 범위만 완료 판정한다.

이번 산출물은 설계 문서뿐이다. 구현, 테스트 통과, PDF 생성, 배포, 커밋 또는 푸시를 완료했다고 표시하지 않는다.
