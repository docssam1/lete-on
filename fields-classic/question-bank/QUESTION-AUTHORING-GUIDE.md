# 필즈 더 클래식 문항 제작 기법

이 문서는 6세 후반부터 초등학교 1학년까지 사용하는 필즈 더 클래식 문제은행의 문항 제작 원칙을 정리한 실무 매뉴얼이다. 단순히 숫자만 바꾼 문제를 많이 만드는 것이 아니라, 원본 문항의 사고 과정과 그림 구조를 보존하면서 정답이 정확한 문제를 반복 생성하는 것이 목표다.

## 1. 가장 중요한 원칙

1. 원본 문항의 지문, 조건, 그림, 물어보는 값, 정답을 한 묶음으로 확인한다.
2. 이름이 비슷해도 풀이 과정이 다르면 다른 세부 유형으로 분리한다.
3. 정답은 문구에 직접 써 두지 않고 생성 코드가 조건에서 다시 계산한다.
4. 그림에 표시한 값과 정답 계산에 사용한 값은 하나의 데이터에서 나온다.
5. 원본 대조, 난수 검산, 실제 화면 검수를 모두 통과하기 전에는 문제은행에서 선택할 수 없게 한다.
6. 아이가 배우지 않은 용어와 계산법을 풀이 편의를 위해 끌어오지 않는다.

## 2. 원본 문항을 분석하는 방법

문항마다 다음 항목을 기록한다.

| 항목 | 기록 내용 |
| --- | --- |
| 출처 | 시험지명, 시험 시기, 문항 번호, 원본 페이지 |
| 대분류 | 수와 연산, 규칙과 관계, 논리와 문제해결, 도형과 공간 |
| 중분류 | 수 배열, 반복 규칙, 조건 배치, 색종이 접기 등 |
| 세부 유형 | 실제 풀이 구조가 드러나는 구체적인 이름 |

학원·교재 스타일은 세부 유형의 소유자가 아니다. 같은 풀이 구조가 필즈, 소마, 시매쓰 등 여러 자료에서 확인되면 유형을 복제하지 않고 하나의 유형에 `academyStyleIds`를 여러 개 붙인다. 스타일 필터는 여러 값을 동시에 선택하는 합집합 방식이며, 같은 유형 ID와 생성기는 결과에서 한 번만 사용한다. 출처가 하나 더 확인됐다는 이유만으로 중복 유형을 만들지 않는다.
| 주어진 것 | 숫자, 카드, 사람 수, 그림의 배치, 조건 문장 |
| 물어보는 것 | 빈칸의 수, 몇 번째, 개수, 합, 도형 등 |
| 풀이 규칙 | 아이가 실제로 거쳐야 하는 생각의 순서 |
| 정답 | 답안지와 직접 대조한 값 |
| 그림 구조 | 표 크기, 칸 수, 접는 방향, 화살표 경로, 입체 방향 |

같은 중분류라도 아래는 서로 다른 세부 유형이다.

- 앞에서의 순서와 사이 사람 수 / 뒤에서의 순서와 사이 사람 수
- 네 수 카드의 변의 합 / 세 수를 두 번 모으는 피라미드
- 단순 반복 모양 / 피아노 건반 왕복 / 바둑돌 개수 차
- 색종이 구멍 수 / 대각선 접기 / 번호표를 접어 자른 수의 합
- 쌓기나무 전체 개수 / 숨은 쌓기나무 / 앞·옆·위 모양 / 구멍 난 쌓기나무

## 3. 유아·초1에 맞는 지문 쓰기

### 문장 원칙

- 한 문장에는 한 가지 행동만 넣는다.
- 조건이 여러 개면 문장 속에 이어 쓰지 말고 글머리표로 나눈다.
- 먼저 상황을 말하고 마지막 문장에 무엇을 구하는지 쓴다.
- `구하시오`와 `구해 보세요` 중 프로그램 전체에서 하나의 말투를 일관되게 사용한다.
- `경우의 수`, `순열`, `조합`, `제곱`, `변수`, `방정식` 같은 학년 밖 용어를 사용하지 않는다.
- 제곱 규칙도 `7×7`이나 `7²` 대신 `가로 7줄에 7개씩`처럼 눈으로 셀 수 있게 설명한다.
- 곱셈을 배우기 전 단계라면 묶어 세기나 반복 덧셈으로 풀이한다.
- 음수, 분수, 불필요하게 큰 수는 원본 학습 범위에 있을 때만 사용한다.

### 좋은 지문 예

`검은 돌과 흰 돌을 그림과 같은 규칙으로 놓았습니다. 8번째 모양에서 검은 돌과 흰 돌의 수는 몇 개 차이 날까요?`

### 피해야 할 지문 예

`일반항을 추론하여 제8항에서 두 집합의 원소 개수 차를 계산하세요.`

### 보기와 조건 만들기

- 아이가 지문만 읽고 상황을 머릿속에 다시 만들 필요가 없도록 필요한 표나 그림을 함께 둔다.
- `[보기]`가 규칙을 설명하는 문항이면 생성 문제에도 `[보기]`를 반드시 포함한다.
- 문제 해결에 쓰이지 않는 장식 그림은 넣지 않는다.
- 그림에 이미 적힌 조건을 지문에 중복해 문제가 두 개처럼 보이게 하지 않는다.
- 한 화면과 한 인쇄 카드 안에는 하나의 질문만 둔다.

## 4. 정답을 눈치채지 못하게 하는 방법

### 객관식 보기

- 정답 보기만 설명이 길거나 문장이 정확하면 안 된다.
- 모든 보기의 문장 구조, 단위, 글자 수를 비슷하게 맞춘다.
- 정답만 유일하게 그림이 크거나 진하거나 가운데에 오지 않게 한다.
- 오답은 무작위 숫자가 아니라 실제로 나올 수 있는 실수에서 만든다.

대표적인 오답 근거:

- 한 단계를 덜 계산한 값
- 더하기와 빼기 순서를 바꾼 값
- 앞에서와 뒤에서를 바꾼 순서
- 반복 마디의 시작점을 한 칸 잘못 잡은 결과
- 접은 횟수나 대칭 위치를 하나 빠뜨린 결과

### 단답형

- 유아·초1의 입력 답은 가능하면 한 자리 수, 두 자리 수, 짧은 단위 또는 도형 이름으로 끝낸다.
- 긴 설명을 입력해야 정답이 되는 문항은 만들지 않는다. 긴 내용은 풀이에서만 보여 준다.
- 같은 세트에서 모든 문항의 정답이 같아지지 않게 한다.
- 문제를 새로 만들 때 정답의 위치와 값이 한쪽으로 몰리지 않는지 검사한다.
- `모두 15개가 됩니다`처럼 정답을 유추하게 하는 문장을 지문이나 그림 제목에 넣지 않는다.

## 5. 난이도 조절 방법

난이도는 원본을 기준으로 `이 문제보다 쉽게`, `이 문제와 같게`, `이 문제보다 어렵게`로 표시한다. 단순히 수를 크게 만드는 것은 난이도 조절이 아니다.

### 쉽게

- 원본과 같은 규칙을 유지한다.
- 조건 수를 하나 줄인다.
- 반복 마디나 화살표 경로를 짧게 한다.
- 빈칸을 마지막 단계에 둔다.
- 그림의 일부 값을 더 많이 보여 준다.
- 받아올림·받아내림이 없는 값으로 구성한다.

### 같게

- 원본과 조건 수, 그림 구조, 풀이 단계 수를 같게 한다.
- 사람 이름, 수, 색, 방향만 바꾼다.
- 원본에서 요구한 사고 과정을 그대로 거쳐야 풀리게 한다.

### 어렵게

- 학년 범위는 유지하면서 조건을 하나 추가한다.
- 빈칸을 중간 단계로 옮긴다.
- 앞·뒤 또는 가로·세로 조건을 함께 사용한다.
- 반복 경로나 접기 단계를 한 단계 늘린다.
- 주어진 값을 조금 줄이되 답이 하나로 정해지게 한다.

### 절대 금지

- 큰 수만 사용해 어렵게 보이기
- 아직 배우지 않은 곱셈·나눗셈·제곱·문자식을 풀이에 사용하기
- 조건이 부족해 정답이 여러 개인 문제
- 어려운 단계에서만 글이 지나치게 길어지는 문제

## 6. 생성기 설계 기법

문제 생성기는 `문제 데이터 생성`과 `그림 렌더`를 분리한다.

```text
난이도 선택
  -> 조건에 맞는 난수 생성
  -> 정답 계산
  -> 유일한 답인지 검사
  -> 지문·그림 데이터·정답·풀이 반환
  -> 화면 또는 인쇄용 그림 렌더
```

각 생성 결과는 최소한 다음 값을 가진다.

- `prompt`: 문제 지문
- `visual`: 그림을 그리는 데 필요한 구조화 데이터
- `answer`: 코드로 계산한 정답
- `solution`: 학년 수준에 맞는 풀이
- `source`: 기준 시험지와 문항 번호
- `difficulty`: 원본 대비 쉬움·같게·어려움

### 유일한 답 보장

- 먼저 정답이 존재하는 완성 상태를 만든 뒤 일부를 빈칸으로 가린다.
- 가능한 배치를 모두 검사할 수 있는 유형은 후보를 검사해 답이 하나인 문제만 사용한다.
- 답이 없거나 두 개 이상이면 버리고 새로 생성한다.
- 0, 음수, 너무 큰 값, 겹치는 구멍처럼 학습 범위를 벗어나는 결과도 버린다.

### 정답 검산

- 생성된 값으로 정답을 별도의 계산식에서 다시 계산한다.
- 그림에 표시된 수의 합, 차, 순서가 정답 계산 데이터와 같은지 검사한다.
- 각 난이도에서 최소 1,000회 이상 난수 검산한다.
- `undefined`, `NaN`, 빈 지문, 빈 그림, 빈 답이 한 번이라도 나오면 공개하지 않는다.
- 여러 유형을 동시에 20문제 이상 생성해 카드 겹침과 화면 오류도 확인한다.

## 7. 이미지와 도형 제작 기준

### 어떤 방식을 사용할지

- 표, 수 카드, 선, 화살표, 색종이, 바둑돌: HTML/CSS 또는 인라인 SVG
- 인쇄 시 선명해야 하는 도형: SVG 우선
- 접기 과정과 곡선 화살표: SVG 또는 Canvas
- 쌓기나무와 공간 문제: 기존 Geometry/Cube Town의 Three.js 렌더러 재사용
- 실제 교재 표지나 사진 자료: 승인된 원본 이미지 사용
- PNG는 원본 문서 미리보기나 복잡한 래스터 자료에만 사용한다.

### 그림 원칙

- 그림은 문제의 조건을 정확히 전달해야 한다.
- 표의 행·열, 화살표 방향, 접는 선, 잘린 위치를 원본과 대조한다.
- 같은 도형은 같은 크기와 선 두께를 사용한다.
- 숫자와 도형이 겹치지 않게 한다.
- 확대와 A4 인쇄에서도 선과 글자가 깨지지 않게 한다.
- 모바일과 PC에서 지문과 그림이 카드 밖으로 밀리지 않게 한다.
- 의미 없는 네모 반복이나 장식용 캐릭터를 문제 그림으로 사용하지 않는다.
- 쌓기나무는 시험 유형과 관련된 시점·개수·숨은 블록이 정확해야 하며 단순 색칠 활동으로 바꾸지 않는다.

## 8. 풀이 작성 방법

- 정답만 다시 말하지 말고 아이가 따라갈 수 있는 순서로 쓴다.
- 한 단계에 한 가지 생각만 설명한다.
- 전문 용어 대신 `먼저`, `그다음`, `마지막으로`를 사용한다.
- 곱셈을 배우지 않았다면 `4개씩 3줄이므로 4+4+4`처럼 설명한다.
- 가능한 경우 그림에 표시한 값과 같은 순서로 풀이한다.
- 유사문제의 수가 바뀌면 풀이의 숫자도 같은 데이터에서 자동으로 바뀌어야 한다.
- 풀이와 해법 키포인트는 답안 및 진단지에서 사용하고 문제 본문에는 노출하지 않는다.

## 9. 저작권 있는 원본 문서 저장 기법

워터마크는 유출 경로를 확인하는 장치이지 저작권 보호를 완전히 보장하는 장치가 아니다. 원본 접근 권한과 저장 위치를 먼저 제한해야 한다.

### 권장 저장 구조

```text
비공개 Google Drive/필즈 더 클래식 문제은행 원본/
  01_실제선발시험/
    시험지/
    답안지/
  02_필즈더클래식_1과정/
    교재/
    권별_단원테스트/
  03_실전모의고사/
    시험지/
    답안지/
    해설대본/
```

### 저장 원칙

- 원본 PDF·PPTX·답안은 권한이 제한된 Drive 또는 비공개 저장소에 둔다.
- 공개 GitHub에는 원본 PDF·PPTX와 원본 전체 페이지 이미지를 올리지 않는다.
- 원본 페이지 이미지가 제품에 필요하면 비공개 저장소에서 로그인 확인 후 불러온다.
- 공개 저장소에는 생성기 코드, 유형 메타데이터, 직접 제작한 도형 템플릿만 둔다.
- 원본 파일명, 시험 시기, 문항 번호를 별도 목록으로 관리하되 학생 개인정보는 기록하지 않는다.
- 운영 코드에는 `C:\`, `E:\`, `G:\` 같은 개인 PC 절대 경로를 넣지 않는다.
- 원본 파일을 교체할 때 파일명만 믿지 말고 문서 페이지 수와 문항 번호를 다시 확인한다.
- 저장소가 공개인지 비공개인지 확인하기 전에는 원본 렌더 이미지를 병합하지 않는다.

### 뷰어와 워터마크

- 원본은 로그인과 상품 권한을 확인한 사용자에게만 보여 준다.
- 화면 워터마크는 사용자 이름 또는 승인 정보가 보이도록 대각선 3줄 정도로 배치한다.
- 인쇄할 때에도 별도의 워터마크가 반드시 포함되어야 한다.
- 학생 이름과 승인번호를 URL에 평문으로 오래 남기지 않는다.
- 캡처를 완전히 막을 수 있다고 안내하지 않는다. 접근 통제와 개인화 워터마크를 함께 사용한다.

- [ ] 원본 문제지와 답안지를 같은 문항 번호로 확인했다.
- [ ] 지문, 조건, 그림, 정답이 모두 원본 구조와 맞다.
- [ ] 세부 유형이 다른 문제와 잘못 합쳐지지 않았다.
- [ ] 유아·초1이 모르는 용어와 계산법이 없다.
- [ ] 문제 본문에 정답 힌트나 풀이 문구가 없다.
- [ ] 객관식 정답만 길거나 눈에 띄지 않는다.
- [ ] 정답이 하나이며 단위와 답 형식이 정확하다.
- [ ] 그림의 수와 정답 계산에 사용한 수가 같다.
- [ ] 쉬움·같게·어려움이 수 크기만 다른 구성이 아니다.
- [ ] 난이도별 1,000회 이상 검산했다.
- [ ] PC·모바일·A4 인쇄 화면에서 겹침과 잘림이 없다.
- [ ] 원본 저작물이 공개 저장소에 노출되지 않는다.
- [ ] 검수 전 문항은 선택 불가 상태다.

## 11. 실패 사례에서 얻은 기준

- 세 문제의 정답을 모두 같게 만드는 것은 문제은행이 아니다.
- 원본의 `[보기]`를 빼면 규칙을 추측해야 하는 다른 문제가 된다.
- 그림 안에 문제 지문을 다시 넣으면 질문이 두 개 겹쳐 보일 수 있다.
- 마방진, 표의 합, 복면산은 눈으로 계산한 답을 믿지 말고 코드로 모든 줄을 검산한다.
- 접기 문제는 접힌 선 위에 구멍을 놓거나 대칭 위치가 겹치면 실제 구멍 수가 달라질 수 있다.
- 순서 문제는 앞·뒤 기준과 전체 인원을 바꾸면 정답이 달라지므로 조건을 함께 생성해야 한다.
- 2D 아이소메트릭 그림을 3D 쌓기나무 문제라고 대체하지 않는다.
- 기존 렌더러가 있으면 새 그림을 임의로 만들지 않고 검증된 렌더러와 자산을 재사용한다.
