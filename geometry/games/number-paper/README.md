# 숫자 색종이 공방

종이를 직접 만지는 활동이다. 사용자가 처음의 문제집 같은 화면을 지적하여,
칸 선택 → 정답 확인 → 합 입력 흐름을 접기 → 가위질 → 펼치기 → 조각 모으기로 교체했다.
입체감·광택은 종이 앞뒷면과 접힌 겹, 잡고 움직이는 조각에 적용한다.

1. 종이의 움직일 면을 잡아 반으로 접고, 옆으로 한 번 더 접는다.
2. 가위로 빗금 영역을 자른다. 인접한 절단 칸 사이에는 가짜 절단선을 만들지 않는다.
3. 마지막 접기부터 역순으로 한 겹씩 펼쳐 잘린 결과를 발견한다.
4. `잘린 조각 모으기` 또는 `남은 종이 모으기`에서 해당 종이를 바구니로 옮긴다.
   네 변으로 연결된 종이는 통째로 움직인다. 자르지 않은 칸을 낱장으로 떼지 않는다.
5. 기본 난이도는 모인 수의 합을 보여 준다. `도전 · 계산`은 조각을 모두 담은 뒤 합을 직접 입력하고 확인한다.
   맞히면 합과 완성 표시를 보여 주고 다음 종이로 진행한다.

색종이 오른쪽에는 접는 기준선 가운데에 짧은 곡선 화살표로 현재 접는 방향을 표시한다.
자른 뒤에는 펼친 모양을 먼저 예상하고, 접은 선을 대칭축으로 삼아 거꾸로 해결한다.
펼치기 안내는 반대 방향의 ②→① 순서로 바뀐다. 작은 설명용 종이 그림은 사용하지 않는다.
화살표는 결과 모양을 미리 보여 주지 않으며, 예상 자체를 별도 채점하거나 기록하지 않는다.
자르기·수집·계산 단계에서는 방향 화살표를 숨긴다.

기본 난이도는 조작 활동 완료를 기록한다. 도전 난이도는 수집 중 합을 숨기고,
모든 조각을 담은 뒤 정수 합의 일치를 확인한다. 틀리면 조각과 입력을 유지한다.
도움 요청 전에는 합을 공개하지 않으며, 요청 뒤에는 단계별 계산 도움에 결과가 나타난다.
계산 단계의 별도 `도와줘요` 버튼은 쉬운 10 짝꿍부터 묶는 과정을 보여 준다.
5+5·6+4 같은 온전한 짝을 먼저 찾고, 이어서 합이10인 여러 수를 묶는다. 딱 맞는 묶음이 없을 때만
필요한 만큼 수의 양을 나눠 옮긴다. 종이 자체를 찢는 동작과는 구별한다.
10칸 틀을 채워 `10으로 묶기`를 누르면 한 묶음이 생기고, 마지막에는 몇십과 남은 수를 더한다.
도움을 받아도 답을 자동 입력하거나 완료 처리하지 않는다. 입력·도움 단계·도움 사용 여부를 보존한다.
정오 점수·감점·시간 제한은 없으며 공식 성적이나 성취도 판정으로 사용하지 않는다.
현재 조작이 재미있는지는 사용자/어린이 실제 플레이 검수 전이다.

- 활동별 내부 창작 20모양, 총 40모양. 한 회차 다섯 장, `다른 종이도 만들기`로 네 묶음을 순환한다.
- 드래그의 대안으로 종이·가위·조각을 탭하거나 네이티브 버튼에서 Enter/Space를 누를 수 있다.
- 반대로 끌거나 바구니 밖에 놓으면 원래 자리로 돌아간다. 다시 시작하기로 새 종이를 꺼낸다.
- 기본 진행은 기존 `progress.number-paper.paperPlay`, 도전은 별도 `paperPlayChallenge`에 저장한다.
  계산 입력과 완료 상태도 복원하며 저장된 정답 완료 여부는 현재 카드의 합으로 다시 검증한다.
  이전 퀴즈 필드와 다른 게임의 프로필은 덮어쓰거나 삭제하지 않는다.
- 4언어를 지원한다. 동작 줄이기 설정에서는 접기·이동을 즉시 완료한다.
- 현재 혼자 하는 활동이며 기존 2~4명 배틀과는 별도다.

## 학습 범위와 구현

가로 후 세로로 두 번 접는 4×4 숫자 종이다. 기존 학습지와
`shared/number-paper-model.js`의 칸 대응·합 계산을 공유한다. 숫자·그림·문항은 내부 창작이다.
원본 33장 전체 반영, 대각선 접기, 겹침 순서, 맨 위 수까지 지원한다고 주장하지 않는다.

| learner-fit 기준 | 적용 |
| --- | --- |
| language | 한 번에 한 조작을 짧게 안내한다. 긴 문제와 설명 패널을 없앴다. |
| representations | 원래 좌표의 한 종이가 앞뒷면을 뒤집고, 잘린 부분을 같은 좌표로 펼친다. |
| prerequisites | 기본은 종이 잡기·자르기·모으기부터 시도한다. 도전은 바구니 숫자를 모두 더하는 연산이 필요하다. |
| reasoning-load | 접기 두 번, 절단, 역순 펼치기, 수집을 차례로 한다. 한 번에 다섯 장이다. |
| response-mode | 물리 조각을 직접 조작한다. 도전은 수집 후 정수 합을 입력한다. 드래그·탭·키보드 대안을 제공한다. |

`activity-model.js`는 단계·절단의 중간 상태·연결된 조각·진행 복원을 관리한다.
`activity-render.js`는 같은 모델에서 종이 면·경첩·구멍·가위 영역·조각을 그린다.
`app.js`는 포인터 제스처, 키보드 대안, 취소 가능한 동작과 저장을 연결한다.
`calculation.js`는 도전의 계산 단계·정답 확인·완료 조건·저장 복원을 관리한다.
`activity.css`는 작업대·입체 종이·바구니를 그린다. 외부 3D 엔진이나 유료 API는 없다.
이전 정적 렌더러·스타일·언어 파일은 기존 검산과 변경 이력을 위해 남겨 두었으며 현재 페이지는 불러오지 않는다.

## 검산과 검수

```sh
node geometry/games/number-paper/core.selftest.mjs
node geometry/games/number-paper/activity.selftest.mjs
node geometry/games/number-paper/calculation.selftest.mjs
node geometry/games/number-paper/calculation-help.selftest.mjs
```

기존 검사는 운영 반사 공식을 호출하지 않고 종이 겹을 옮겨 40문항과 학습지 632조건을 비교한다.
이전 퀴즈의 2,621,440개 칸 집합·합 유일성 검사도 수학 모델 회귀 검사로 유지하며 현재 응답 UI로 해석하지 않는다.
활동 검사는 독립 겹 이동 120단계, 모든 부분 절단의 펼침, union-find 조각 분할,
313상태 전이·복원, 잘못된 동작과 4언어 1,252장면을 검산한다.

CUA 브라우저에서 보이는 처음 숫자와 빗금 위치로 독립 계산해 40개 고유 모양을 실제 조작으로 완주했다.
실제 좌표 드래그 접기·가위·조각 담기와 키보드 완주, 부분 절단/수집 저장 복원, 접기 도중 재시작을 확인했다.
1024×768·667×375의 4언어, 844×390의 2언어, 390×844의 4언어에서 최종 112상태를 확인했다.
가로 넘침·종이 잘림·44px 미만 버튼이 없으며 세로폰은 세로 스크롤을 허용한다.
근거는 기존 비공개 검수 폴더 `game-number-paper-20261017/activity/`에 있다.

정보 보존을 검사했다. 브라우저에서 잘린 조각5장·남은 종이5장을 계산 완료하고 기본1장을 회귀 검수했다.
