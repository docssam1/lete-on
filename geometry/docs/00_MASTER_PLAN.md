# GFIELD Cube Game 전체 설계

## 1. 목표

GFIELD Cube Game은 어린이가 실제 교구를 만지는 것처럼 블록을 집고, 놓고, 돌려 보고, 수를 적으며 공간 감각과 수 감각을 익히는 게임 모음이다.

이번 범위는 아래 두 게임이다.

1. 똑같이 쌓기
2. 쌓기나무 개수 세기

`쌓기나무 개수 세기`에는 두 가지 유형이 있다.

- A형: 각 자리의 높이를 더해 전체 개수 세기
- B형: 전체에서 보이는 개수를 빼서 보이지 않는 개수 세기

개발할 때는 똑같이 쌓기, A형, B형을 별도 폴더와 별도 문제 데이터로 만든다. 나중에 GFIELD Geometry World에 통합할 때 A형과 B형을 `쌓기나무 개수 세기`의 유형 선택 화면으로 묶는다.

## 2. 확정 범위

- 똑같이 쌓기: 최대 `3 x 3 x 4`
- 개수 세기: 최대 `4 x 4 x 4`, 정답 범위 `0~64`
- 언어: 한국어, 중국어 간체, 일본어, 영어
- 입력: 마우스, 손가락 터치, 키보드
- 렌더링: Three.js 3D
- 문제 수: 모든 레벨은 기본 5문제
- 진행: 문제를 완성하면 자동 채점하고 성공 연출 뒤 다음 단계로 이동
- 건너뛰기: 모든 문제에 `다음 문제` 버튼 제공
- 저장: 게임별 최고 별과 마지막 열린 레벨을 브라우저에 저장

### 레벨 수

| 통합 게임 | 개발 모듈 | 레벨 | 문제 수 |
|---|---|---:|---:|
| 똑같이 쌓기 | `copy-build` | 6 | 30 |
| 개수 세기 A형 | `count-heights` | 5 | 25 |
| 개수 세기 B형 | `count-hidden` | 6 | 30 |

개수 세기의 A형과 B형 진행 기록은 따로 저장한다. 한 유형을 먼저 끝내야 다른 유형이 열리는 방식으로 잠그지 않는다.

## 3. 게임 공통 흐름

```text
게임 선택 -> 레벨 선택 -> 문제 소개 -> 놀이 -> 자동 채점
-> 짧은 성공 연출 -> 다음 학습 단계 또는 다음 문제 -> 레벨 결과
```

- 문제를 틀려도 점수를 깎는 표현은 쓰지 않는다.
- 힌트를 쓰지 않고 바로 해결하면 `Great job!`을 보여 준다.
- 힌트를 썼거나 여러 번 고친 뒤 해결하면 `Good job!`을 보여 준다.
- 레벨 결과는 1~3별로 표시한다.
- 한 문제에서 막히면 다음 문제로 넘어갈 수 있다. 건너뛴 문제는 레벨 끝에서 다시 풀 수 있다.

## 4. 화면 공통 구조

데스크톱에서는 문제 모양과 놀이판을 좌우로 둔다. 모바일에서는 문제 모양, 놀이판, 블록 더미 또는 답 입력 순으로 세로 배치한다.

공통 화면 요소는 다음만 유지한다.

- 상단: 게임 이름, 레벨, 문제 진행 점
- 중앙: 3D 문제 장면과 3D 놀이 장면
- 장면 바로 아래: 현재 게임에 필요한 도구
- 하단: 처음부터, 시점, 다음 문제
- 오른쪽 아래: 작은 docssam 캐릭터와 한두 줄 말풍선

설명용 카드와 긴 문장을 계속 늘리지 않는다. 아이가 해야 할 행동은 장면, 빨간 놓기 자리, 짧은 말풍선으로 알려 준다.

## 5. 진짜 게임처럼 보이기 위한 원칙

- 자동 생성한 듯한 임의 모양보다 사람이 고른 문제 모양을 먼저 사용한다.
- 블록은 같은 재질, 모서리, 그림자, 조명을 공유한다.
- 블록을 들면 살짝 올라오고, 놓으면 짧게 눌렸다 돌아오며, 제거하면 바닥으로 떨어진다.
- 성공 연출은 1초 안에 끝낸다. 화면 전체를 가리는 큰 창을 띄우지 않는다.
- 말풍선은 대화창처럼 길게 만들지 않는다. 한 번에 한 행동만 말한다.
- 유리 효과, 과한 그라데이션, 둥근 카드의 반복, 의미 없는 장식은 사용하지 않는다.
- 숫자, 별, 진행 점, 조작 버튼은 게임 전체에서 같은 위치와 모양을 쓴다.
- 출시 버전 음성은 브라우저 기계음 대신 언어별로 미리 만든 자연스러운 음성 파일을 사용한다.

## 6. 폴더 구조

세 개발 모듈은 각각 단독으로 열어도 동작해야 한다. 통합 화면에서는 두 개의 게임 카드만 보여 주고, 개수 세기 카드를 연 뒤 A형과 B형을 고른다.

```text
cube-section/
  shared/
    three-viewer.js
    block-model.js
    block-materials.js
    drag-controller.js
    number-input.js
    locale.js
    progress.js
    audio.js
    game-shell.css
  games/
    copy-build/
      index.html
      app.js
      styles.css
      levels.js
      i18n.js
    count-heights/
      index.html
      app.js
      styles.css
      levels.js
      i18n.js
    count-hidden/
      index.html
      app.js
      styles.css
      levels.js
      i18n.js
  assets/
    character/
    audio/ko/
    audio/zh/
    audio/ja/
    audio/en/

```

현재 `index.html`, `app.js`, `styles.css`는 똑같이 쌓기 원형으로 보존한다. 공통 모듈 분리는 기능이 그대로 동작하는 것을 확인하면서 한 파일씩 진행한다.

## 7. 공통 좌표와 블록 데이터

- `x`: 왼쪽에서 오른쪽
- `y`: 아래에서 위
- `z`: 앞에서 뒤
- 모든 좌표는 정수 격자 좌표다.
- 블록의 기준점은 블록이 차지하는 영역의 왼쪽, 아래, 앞 모서리다.

```js
const piece = {
  id: "p1",
  kind: "cube",
  size: [1, 1, 1],
  position: [0, 0, 0],
  rotationY: 0,
  color: "wood"
};
```

직육면체도 같은 형식을 쓴다.

```js
const longBlock = {
  id: "p2",
  kind: "cuboid",
  size: [1, 2, 1],
  position: [1, 0, 0],
  rotationY: 0,
  color: "wood"
};
```

`size`는 단위 칸 기준이다. `rotationY`는 `0`, `90`, `180`, `270`만 허용한다. 한 블록이 차지하는 모든 단위 칸을 계산해 충돌과 정답을 검사한다.

## 8. 공통 문제 형식

```js
const problem = {
  id: "copy-l1-01",
  game: "copy-build",
  level: 1,
  board: [3, 4, 3],
  camera: "isometric",
  pieces: [],
  rules: {},
  answer: {},
  textKey: "problem.copy.l1.01"
};
```

- 문제 파일에는 화면 문장을 직접 넣지 않고 번역 키만 넣는다.
- 모든 문제는 고유한 `id`를 가진다.
- 정답을 화면에서 읽어 다시 계산하지 않는다. 문제 데이터의 `answer`를 기준으로 채점한다.
- 문제를 불러올 때 좌표 범위, 공중에 뜬 블록, 블록 충돌, 정답 값 오류를 먼저 검사한다.

## 9. 다국어 규칙

- 게임별 `i18n.js`에 같은 키를 네 언어로 모두 넣는다.
- 빠진 번역이 있으면 출시 검사에서 실패하게 한다.
- 버튼은 짧게 쓰고, 설명은 말풍선 한두 줄을 넘기지 않는다.
- 숫자는 모든 언어에서 아라비아 숫자를 사용한다.
- 음성 파일 이름은 `{언어}-{문장키}.mp3`로 통일한다.

## 10. 다음 Codex가 지켜야 할 작업 방식

1. 한 번에 한 게임 또는 한 공통 모듈만 수정한다.
2. 기존 똑같이 쌓기 동작을 확인한 뒤 공통 파일을 분리한다.
3. 문제 데이터와 화면 로직을 같은 파일에 섞지 않는다.
4. 문제를 무작위로 만들지 말고 먼저 레벨당 5문제를 직접 작성한다.
5. 데스크톱과 모바일에서 드래그, 탭, 회전을 모두 검사한다.
6. 마우스 좌표로 블록을 고르지 말고 Three.js 레이캐스팅과 넓은 놓기 면을 사용한다.
7. 모든 텍스트 파일은 UTF-8로 유지한다.
8. 기능을 끝내기 전 디자인을 전면 변경하지 않는다.
9. 새 게임은 자기 폴더의 `index.html`로 단독 실행되어야 한다.
10. 완료 조건을 모두 통과하지 않으면 다음 게임으로 넘어가지 않는다.

## 11. 구현 순서

1. 현재 파일의 한글, 중국어, 일본어 인코딩과 번역 표시를 먼저 검사한다.
2. 공통 Three.js 장면과 진행 상태를 `shared`로 분리한다.
3. 똑같이 쌓기 레벨 1~3을 현재 기능으로 완성한다.
4. 직육면체, 다른 조각, 색 레벨을 추가한다.
5. 쌓기나무 개수 세기를 별도 게임으로 만든다.
6. 보이지 않는 쌓기나무의 벽 없는 유형을 만든다.
7. 벽 있는 유형을 추가한다.
8. 네 언어 음성, 모바일 검사, 문제 데이터 검사를 마무리한다.
