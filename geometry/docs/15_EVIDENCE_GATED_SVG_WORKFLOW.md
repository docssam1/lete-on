# Geometry SVG 제너레이터 증거 관문

이 문서는 Geometry World의 새 문항·학습지·개념 설명을 만들거나 기존 SVG를 고칠 때 적용하는
프로젝트 규칙이다. 다음 두 스킬에서 이 프로젝트에 필요한 부분만 결합한다.

- `skills/concept-whiteboard-lesson/SKILL.md`
- `evidence-gated-learning-pipeline`:
  `https://github.com/docssam1/source-to-memory/tree/main/skill/evidence-gated-learning-pipeline`

기존 게임 구조를 모두 애니메이션으로 바꾸는 문서가 아니다. 절차의 순서 자체가 학습 내용일 때만
화이트보드 장면을 사용하며, 일반 문항 SVG에는 근거·수학·가시성·렌더 관문만 적용한다.

## 1. 작업 계약

코드를 쓰기 전에 아래 항목을 짧게 기록한다.

- 작업 ID와 문항 유형
- 학습자 단계: `킨더`, `키즈`, `Pre`, `입문`, `초급`, `중급`
- 같은 단계 안의 난이도: `하`, `중`, `상`
- 학습자가 하는 실제 행동: 계산, 그리기, 접기, 회전, 세기, 고르기, 설명하기
- 선수 지식과 허용 표기
- 원본 또는 사용자 결정의 정확한 위치
- 공개하면 안 되는 원본·답안·개인 경로
- 단일값, 순서, 집합, 범위, 활동형 중 정답 계약
- 수정 가능한 파일과 승인 경계
- 완료 조건과 실제 검증 명령

단계는 그림이나 수가 커졌다는 이유만으로 올리지 않는다. 추론 단계, 조건 결합, 숨은 정보,
역추론, 표현 전환, 오답 유사도를 기준으로 한다. 세부 기준은
`geometry/docs/14_STAGE_DIFFICULTY_PROFILE.md`를 따른다.

모든 학습자용 문항은 `learner-fit` 관문을 가져야 한다. 검수 기록에는 정확한 학습자 단계와
다섯 기준 `language`, `representations`, `prerequisites`, `reasoning-load`, `response-mode`를
모두 적는다. "아이에게 적절함" 같은 한 줄 평가는 통과 근거가 아니다.

## 2. 중복 작업 방지

새 렌더러나 생성기를 만들기 전에 다음 순서로 찾는다.

1. 현재 작업 트리, Git 기록, 이 인수인계서와 설계 문서를 확인한다.
2. 같은 유형과 별칭을 `rg`로 검색한다.
3. 기존 문제 모델, 독립 계산기, SVG 렌더러, 브라우저 검사, 인쇄 검사를 찾는다.
4. `.source-memory/source-memory.json`이 있으면 메타데이터를 먼저 조회한다.
5. 계약이 같은 기존 구현을 이어 쓰고, 이름만 다른 복제 구현을 만들지 않는다.

2D 도형과 학습지의 기본 렌더러는 `geometry/worksheet/render.js`의 `GW_RENDER`다.

- `project`: 등각 좌표 계산
- `fmt`: 좌표 정밀도 제한
- `polygon`: 점 목록으로 면 생성
- `wrapSvg`: 안정된 `viewBox`와 비율 적용
- `renderIso`, `renderIsoCoords`: 높이 지도와 단위 블록 좌표 렌더링

기존 함수로 표현할 수 없을 때만 같은 파일의 DOM 없는 문자열 빌더 방식으로 작은 도움 함수를
추가하고, 기존 함수가 부족한 이유를 코드나 설계 기록에 남긴다.

## 3. 모델과 그림을 분리한다

SVG 문자열을 먼저 쓰지 않는다. 데이터가 다음 흐름을 따라야 한다.

```text
원본 위치·사용자 결정
  -> 의미 모델(points, segments, cells, faces, folds, blocks, labels, viewpoint)
  -> 독립 정답 계산 또는 전체 후보 열거
  -> SVG 좌표와 경로 계산
  -> 게임·학습지 렌더
  -> 화면·인쇄·접근성·공개 검증
```

필수 규칙:

- 정답을 좌우하는 점, 선, 면, 가림, 접힌 위치를 눈대중 좌표로 두지 않는다.
- SVG의 점과 선은 의미 모델에서 계산한다.
- `viewBox`, `preserveAspectRatio`, 라벨 여백도 모델의 경계 상자에서 정한다.
- 쌓기나무의 시선은 문항 데이터다. 기본 시선 코드는 `iso-plus-x-plus-z-v1`이다.
- 직접 세기에서는 필요한 윗면과 높이가 보이지 않으면 문항을 제외한다.
- 숨은 블록, 구멍, 색, 접힌 면이 둘 이상으로 해석되면 설명으로 덮지 말고 문항을 잠근다.
- 문제 화면에는 답 선, 완성선, 정답 색, 필요 이상의 강조를 넣지 않는다.
- 생성기의 답을 다시 읽어 정답 검사에 쓰지 않는다. 독립 계산기나 전체 후보 열거를 사용한다.

SVG에 `data-points`, `data-segments`, `data-viewpoint`, `data-*` 모델 정보를 남기면 브라우저 검사가
그림과 문제 데이터의 일치를 다시 확인할 수 있다. 공개에 불필요한 원본 경로나 답안은 넣지 않는다.

## 4. 절차형 개념 설명을 쓰는 조건

`concept-whiteboard-lesson`은 순서가 학습 내용인 경우에만 사용한다.

적용 예:

- 쌓기나무의 층을 먼 곳부터 세는 순서
- 주사위를 한 칸씩 굴리며 바뀌는 면 추적
- 색종이를 접고 자른 위치를 역순으로 펼치는 절차
- 큰 삼각형에서 길이 1, 2, 3, ...인 밑변 선분을 차례로 모아 더하기
- 점판에서 조건을 확인하며 선을 하나씩 추가하기

정적 사실, 단순 정의, 완성 그림만 보면 되는 문항에는 사용하지 않는다.

화이트보드 장면 규칙:

1. 빈 판에서 시작한다.
2. 한 beat에는 새 대상 하나만 그린다.
3. 이미 만든 것을 다시 보게 할 때만 `highlight`를 쓰고 다음 beat에서 지운다.
4. 좌표는 장면 모델에서 계산하며 장면 manifest에 손 좌표를 넣지 않는다.
5. `objects`는 안정된 의미 ID를 가지고, `beats`는 실제 풀이 순서와 같다.
6. 자막은 한국어·영어·중국어의 화면 문장, 인쇄 설명, 음성 문자열의 기준이다.
7. 재생·일시정지·처음부터·속도·자막·모션 축소를 제공한다.
8. 풀이 보기는 첫 오답 뒤에만 연다. 처음부터 보이는 버튼이나 대기 시간 해제는 쓰지 않는다.
9. 마지막 정지 장면은 애니메이션 없이 A4에 인쇄해도 풀이 순서를 설명해야 한다.

색과 움직임만으로 의미를 전달하지 않는다. 음성이 꺼져도 자막과 도형으로 이해할 수 있어야 한다.

## 5. 필수 관문

| 관문 ID | 확인 방법 | 통과 조건 |
|---|---|---|
| `source-scope` | 원본 위치·사용자 결정 대조 | 문항 행동, 도형 위상, 방향, 답 형식이 근거와 일치 |
| `math-model` | 독립 계산·불변식 검사 | 모델이 조건과 정답을 정확히 표현 |
| `answer-contract` | 가능한 답 전체 열거 | 단일정답은 유효 답 1개, 복수·활동형은 계약대로 인정 |
| `observability` | 고정 시선과 가려짐 검사 | 화면 정보만으로 계약된 답을 구할 수 있음 |
| `learner-fit` | 단계별 별도 검수 | 다섯 기준을 모두 기록하고 해당 단계에 적합 |
| `svg-geometry` | 모델과 SVG의 점·선·면 대조 | 좌표, 연결, 겹침 순서, 라벨, `viewBox`가 일치 |
| `gaze` | beat별 스크린샷 육안 검사 | 절차형 장면은 한 beat에 새 초점 1개 |
| `render-pc` | 실제 브라우저 캡처 | 잘림, 겹침, 빈 그림, 오답 노출 없음 |
| `render-mobile` | 390px와 실제 조작 검사 | 가로 넘침 없고 터치 대상과 글자가 읽힘 |
| `render-a4` | 실제 PDF 렌더·페이지 이미지 검사 | 페이지 분리, 여백, 필기 공간, 최종 정지 장면 정상 |
| `accessibility` | DOM·키보드·텍스트 검사 | SVG 설명, 키보드 조작, 색 외 의미 전달 존재 |
| `negative-control` | 검사 대상을 일부러 한 번 깨기 | 각 핵심 검사가 실제로 실패한 뒤 원복됨 |
| `regression` | 관련 게임·학습지 검사 재실행 | 공유 모델·렌더러의 기존 동작 유지 |
| `release-readback` | 원격 SHA·배포 화면 확인 | 승인된 결과가 실제 공개 위치에서 열림 |

필수 관문은 `pass`, `fail`, `blocked`, `pending`으로 기록한다. 필요한 관문 하나라도 통과하지 않으면
완료라고 말하지 않는다.

## 6. Negative control

검사가 초록색이라는 사실만으로는 부족하다. 다음 중 해당하는 것을 의도적으로 한 번 깨고 검사가
실패하는지 확인한 뒤 원복한다.

- 점 하나를 한 칸 이동해 도형 위상을 틀리게 한다.
- 모델과 SVG의 숫자 하나를 다르게 한다.
- 주사위 방향 또는 쌓기나무 시선 코드를 바꾼다.
- 답 후보를 하나 더 유효하게 만들어 단일정답 검사를 실패시킨다.
- `viewBox`를 줄여 라벨이 잘리게 한다.
- 절차형 beat에 대상 두 개를 동시에 추가한다.
- A4에서 카드가 페이지 사이에 갈라지게 한다.

보고서에는 무엇을 깨뜨렸고 어떤 검사가 실패했는지 적는다. 깨진 상태의 파일은 커밋하지 않는다.

## 7. 상태와 공개

작업, 근거, 공개 상태를 한 단어로 섞지 않는다.

- 작업: `pending`, `in-progress`, `complete`, `blocked`
- 근거: `draft`, `verified`, `conflict`, `stale`, `superseded`, `excluded`
- 공개: `locked`, `eligible`, `approved`, `published`, `revoked`

테스트 통과는 공개 승인과 다르다. `eligible`은 필수 관문 통과, `approved`는 사용자의 공개 승인,
`published`는 원격 커밋과 실제 배포 화면 확인까지 끝난 상태다.

반복되는 작업에는 저장소의 `.evidence-pipeline/pipeline.json`을 사용한다. 원본 본문이나 개인 경로를
ledger에 복사하지 않고 출처 record ID, 테스트, 캡처, 결정 위치만 기록한다. 새 제너레이터를 실제로
시작할 때 해당 학습자 단계와 문항 유형으로 ledger 항목을 만들며, 빈 형식만 미리 대량 생성하지 않는다.

## 8. 재개 체크포인트

토큰이나 시간이 부족해지기 전에 다음을 인수인계서에 갱신한다.

- 정확한 저장소, 브랜치, 현재 커밋과 미커밋 여부
- 작업 계약과 명시적 제외 범위
- 출처 record ID와 검증 상태
- 완료한 산출물과 관문별 증거
- `pending`, `locked`, `excluded`, `superseded` 항목과 이유
- 다음에 실행할 한 가지 작업과 정확한 검증 명령
- 이미 수행한 외부 작업과 아직 필요한 사용자 승인

오래된 채팅 요약보다 현재 결정적 검사, 정확한 출처 위치, 승인된 답·설계, 현재 인수인계서를 우선한다.

## 9. 제너레이터 완료 보고 형식

```text
작업 ID:
학습자 단계 / 난이도:
학습 행동 / 정답 계약:
원본·결정 record ID:
재사용한 모델·렌더러:
독립 정답 검산:
learner-fit 다섯 기준:
PC / 모바일 / A4:
Negative control:
회귀 검사:
공개 상태와 원격 SHA:
남은 잠금 사유:
```

"SVG를 만들었다"는 완료 조건이 아니다. 모델, 답, 시선, 학습자 적합성, 화면·인쇄, 실제 공개가
각자의 근거로 확인되어야 한다.
