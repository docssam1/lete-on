# 게임 2-B: 보이지 않는 쌓기나무 세기

## 1. 학습 목표

겉에서 보이는 쌓기나무와 안쪽에 가려진 쌓기나무를 구분하고 아래 식으로 보이지 않는 개수를 구한다.

```text
전체 개수 - 보이는 개수 = 보이지 않는 개수
```

이 유형은 `벽이 없는 경우`와 `벽이 있는 경우`를 한 레벨 묶음으로 제공한다.

## 2. 보이는 쌓기나무의 정확한 뜻

쌓기나무 하나의 면이 허용된 관찰 방향 중 한 방향에서 바깥까지 막힘없이 이어지면 `보이는 쌓기나무`다. 허용된 어느 방향에서도 보이지 않으면 `보이지 않는 쌓기나무`다.

- 위 방향은 항상 관찰할 수 있다.
- 바닥 아래에서는 보지 않는다.
- 벽이 없는 문제는 앞, 뒤, 왼쪽, 오른쪽, 위에서 본다.
- 뒤쪽 벽이 있으면 뒤에서는 볼 수 없다.
- 두 벽이 있는 모서리 문제는 벽 바깥 방향에서는 볼 수 없다.

카메라의 현재 각도로 보이는지에 따라 정답이 바뀌면 안 된다. 문제를 만들 때 허용된 모든 방향의 합집합으로 보이는 블록을 확정한다.

## 3. 문제 흐름

1. 3D 모양을 돌려 보며 전체 구조를 관찰한다.
2. 보인다고 생각하는 쌓기나무를 탭해 표시하며 센다.
3. `전체`, `보이는`, `보이지 않는` 세 칸에 수를 넣는다.
4. 세 값이 식과 정답을 모두 만족하면 자동 성공한다.
5. 성공 뒤 반투명 보기로 내부의 숨은 쌓기나무를 보여 준다.

식 영역은 다음처럼 한 줄로 유지한다.

```text
[전체 __] - [보이는 __] = [보이지 않는 __]
```

## 4. 벽이 없는 유형

- 장면을 자유롭게 돌릴 수 있다.
- 단단한 직육면체에서는 안쪽 블록이 핵심이다.
- 계단 모양에서는 여러 방향으로 돌려 봐야 보이는 블록을 빠뜨리지 않는다.
- 정답 공개 때 겉 블록을 살짝 벌려 내부 블록을 보여 준다.

## 5. 벽이 있는 유형

- 벽은 실제 3D 면으로 렌더링한다.
- 벽 뒤로 카메라가 넘어가지 않도록 회전 범위를 제한한다.
- 한쪽 벽, ㄱ자 두 벽 순으로 난이도를 올린다.
- 벽은 반투명 전환 버튼을 제공하지만, 사용하면 힌트 1회로 기록한다.
- 벽을 투명하게 해도 정답에서 `보이는 방향` 정의는 바뀌지 않는다.

## 6. 레벨 구성

| 레벨 | 유형 | 최대 크기 | 문제 특징 |
|---|---|---|---|
| 1 | 벽 없음 | 3x3x2 | 단단한 직육면체, 전체와 겉 구분 |
| 2 | 벽 없음 | 3x3x3 | 계단과 일부 빈칸, 여러 방향 관찰 |
| 3 | 벽 없음 | 4x4x4 | 큰 직육면체와 복합 입체 |
| 4 | 벽 1개 | 3x3x3 | 뒤 벽에 붙인 계단 모양 |
| 5 | 벽 2개 | 4x4x3 | 모서리에 붙인 모양 |
| 6 | 벽 1~2개 | 4x4x4 | 불규칙 계단, 전체-보이는 전략 완성 |

각 레벨은 5문제다. 레벨 1~3은 벽 없는 묶음, 레벨 4~6은 벽 있는 묶음으로 레벨 선택 화면에서 구분한다.

## 7. 문제 데이터

정답 논쟁이 생기지 않도록 문제 파일에 전체, 보이는 블록 ID, 보이지 않는 블록 ID를 모두 저장한다. 개발용 검사기가 좌표로 다시 계산해 두 값이 같은지 확인한다.

```js
const problem = {
  id: "hidden-l4-01",
  game: "count-hidden",
  level: 4,
  board: [3, 3, 3],
  walls: ["back"],
  viewDirections: ["top", "front", "left", "right"],
  cubes: [
    { id: "c001", position: [0, 0, 0] },
    { id: "c002", position: [0, 1, 0] }
  ],
  answer: {
    total: 2,
    visibleIds: ["c001", "c002"],
    hiddenIds: []
  }
};
```

실제 문제는 `c001`처럼 고유 ID를 가진 모든 정육면체 좌표를 저장한다. 한 좌표에 두 블록이 있거나 공중에 뜬 블록이 있으면 문제 검사에서 실패한다.

## 8. 보임 계산 규칙

각 블록과 각 허용 방향에 대해 같은 줄에 더 바깥쪽 블록이 있는지 확인한다.

```text
어느 한 방향이라도 막히지 않음 -> visible
모든 허용 방향이 다른 블록 또는 금지된 벽 방향으로 막힘 -> hidden
```

아래 방향은 계산하지 않는다. 벽 방향은 `viewDirections`에서 제외한다. 화면 채점은 미리 계산된 ID 목록을 사용하고, 계산 함수는 문제 데이터 검사에 사용한다.

## 9. 탭해서 보이는 블록 세기

- 화면에서 실제로 노출된 블록을 누르면 작은 순번표가 붙는다.
- 같은 블록을 다시 누르면 선택을 취소한다.
- 장면을 돌려도 순번표는 블록에 붙어 있어야 한다.
- 현재 카메라에서 완전히 가려진 블록은 선택할 수 없다.
- 여러 방향에서 같은 블록을 다시 눌러 중복으로 세지 않도록 ID로 관리한다.

## 10. 힌트 단계

1. 식의 어느 칸부터 구할지 말풍선으로 알려 준다.
2. 아직 세지 않은 보이는 블록 중 하나를 짧게 반짝인다.
3. 마지막 힌트에서 겉 블록을 반투명하게 해 내부 위치를 보여 준다.

힌트가 정답 숫자를 바로 말하지는 않는다.

## 12. 완료 조건

- 6개 레벨이 각각 5문제를 가진다.
- 벽 없는 문제의 카메라는 자유 회전된다.
- 벽 있는 문제의 카메라는 벽 뒤로 넘어가지 않는다.
- 같은 블록을 다른 시점에서 눌러도 한 번만 센다.
- 전체, 보이는, 보이지 않는 세 답과 뺄셈 관계를 모두 검사한다.
- 정답 후 숨은 블록 위치를 아이가 이해할 수 있게 보여 준다.
- 모든 문제에서 저장된 정답과 자동 보임 계산 결과가 일치한다.
