# GFIELD Geometry UX Design System

GFIELD Geometry 화면은 일반적인 AI 생성 대시보드나 마케팅 랜딩 페이지처럼 보이지 않아야 한다. 학습 목적, 실제 교구, 검수한 문제 그림이 화면의 중심이며 장식은 그 구조를 돕는 범위에서만 사용한다.

## 1. 화면 성격

### 문제은행과 학습지

- 사용자는 교사와 학부모다. 조용하고 밀도 높은 작업대처럼 구성한다.
- 설정 순서와 종이 미리보기가 한눈에 구분되어야 한다.
- 외곽 카드 안에 다시 카드를 반복해서 넣지 않는다.
- 실제 생성되는 문제를 미리보기에 사용한다. 별도의 장식용 예시를 만들지 않는다.
- 데스크톱은 선택 작업대와 종이 미리보기를 나란히 두고, 모바일은 같은 순서를 세로로 유지한다.

### 마을과 영역 소개

- 사용자는 아이와 보호자다. 실제 게임 캡처, 캐릭터, 교구 재질이 먼저 보여야 한다.
- 큰 홍보 문구보다 게임 이름, 난이도, 실제 플레이 장면을 우선한다.
- 영역은 열린 전시대처럼 나누고, 섹션 카드 안에 게임 카드를 중첩하지 않는다.
- 게임 캡처는 동일한 시점, 프레임, 밝기 기준으로 관리한다.

## 2. GFIELD 시각 언어

- 기본 재료: 밝은 원목, 인쇄용 종이, 얇은 기술선, 교구의 실제 색.
- 기본 색: 딥 네이비, GFIELD 그린, 종이색, 원목색. 한 화면의 주 강조색은 하나만 쓴다.
- 모서리: 조작 요소와 카드 모두 2~6px. 특별한 이유 없이 큰 알약 모양을 쓰지 않는다.
- 그림자: 표면의 높이를 설명할 정도로만 사용한다. 광범위한 푸른 발광과 장식용 빛 번짐은 쓰지 않는다.
- 아이콘: 익숙한 기호 또는 프로젝트의 기존 아이콘을 사용한다. 기능을 이모지로 대신하지 않는다.
- 글자: 화면 제목보다 문제·게임 이름과 상태가 빨리 읽혀야 한다. 작은 카드 안에 큰 전시용 글자를 넣지 않는다.

## 3. 특수 효과 사용 규칙

- 액체 금속과 포일 느낌은 주요 입구 또는 현재 선택 상태 한 곳에만 쓴다.
- WebGL 금속 효과를 넣기 전 정적 CSS 대체 표현이 먼저 완성되어야 한다.
- 애니메이션 구(Orbs)는 일반 배경 장식으로 사용하지 않는다. 실제 대기나 진행 상태를 전달할 때만 검토한다.
- 상태 변화는 120~260ms, 화면 진입은 400~700ms를 기준으로 한다.
- `prefers-reduced-motion`에서는 이동과 반복 애니메이션을 제거한다.

## 4. 상호작용 원칙

- 선택, 해제, 비활성, 완료 상태를 색 하나에만 의존하지 않는다.
- 눌린 버튼은 즉시 형태나 깊이가 바뀌어 연속 터치를 막는다.
- 선택 가능한 유형이 없는 상태도 빈 화면으로 두지 않고 현재 조건에서 할 수 있는 다음 행동을 분명히 표시한다.
- 모바일은 최소 터치 영역 44px를 기준으로 하되, 카드 전체를 불필요하게 버튼처럼 보이게 만들지 않는다.
- 데스크톱과 모바일은 같은 정보 구조를 사용하고 배치만 바꾼다.

## 5. 금지 패턴

- 같은 크기의 둥근 카드가 페이지 전체에 반복되는 구성
- 보라색·파란색 그라데이션과 발광 구를 정체성 없이 사용하는 구성
- 실제 콘텐츠보다 큰 마케팅 히어로
- 카드 안의 카드, 섹션 전체를 떠 있는 카드로 만드는 방식
- 서로 다른 게임 캡처의 시점·배율·재질이 제각각인 상태
- 기능 설명을 장문의 화면 문구로 대신하는 방식

## 6. 적용과 검수

1. 실제 데스크톱 1440×900과 모바일 390×844에서 캡처한다.
2. 가로 넘침, 잘린 글자, 홀로 남은 카드, 과도한 빈 공간을 확인한다.
3. 키보드 포커스와 터치 상태를 확인한다.
4. 실제 문제 생성과 게임 링크를 한 번 이상 실행한다.
5. 효과를 끈 상태와 모션 감소 상태에서도 기능과 위계가 유지되는지 확인한다.

## 참고 원칙

- Meng To Skills: 명세가 분위기보다 우선하며, 한 번에 1~2개의 변화만 검증한다.
- Beautiful UI: 프리미티브는 재사용하되 도메인에 맞게 다시 설계한다.
- Liquid Metal: 선택된 핵심 표면에만 제한하고 정적 대체 표현을 유지한다.
