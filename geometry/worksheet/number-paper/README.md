# 숫자 색종이 생각 학습지

게임의 `내 종이 학습지`에서 현재 회차의 같은 다섯 문항과 순서를 전달한다.
독립적으로 열면 활동·5/10/20문항, 두 활동 합쳐 최대40문항을 선택한다.
기존 `worksheet/paper-fold/`는 보존하며 새 학습지는 숫자 색종이 공방의40개 내부 창작 모양만 사용한다.

문제지는 처음 숫자 종이·접기 방향·접어 자를 칸을 제시한다. 학생은 펼친 결과를 예상하여
잘린 칸에 ×를 표시하거나 남은 칸을 칠한 뒤, 바구니 숫자의 합을 구한다.
답을 미리 표시하지 않는다. 풀이에서는 마지막 접기부터 역순으로 펼친 중간 결과와
바구니에 담을 칸, 수의 목록과10만들기를 제시한다. 합이10보다 작으면 그대로 더한다.
게임과 같은 물리 모델·문항·10만들기 계획을 사용하며 공식 성적·성취도 평가는 하지 않는다.

인쇄 범위는 문제만, 정답과 풀이만, 둘 다, 빠른 정답의 네 가지다.
기본은 문제만이다. A4 한 쪽에 두 문항을 배치하며 활동을 섞어 한 쪽을 채우지 않는다.
문제와 풀이를 함께 출력할 때 풀이를 새 페이지에 두고, 양면 옵션은 문제 쪽 수가 홀수이면
빈 면을 추가해 풀이가 새 종이에서 시작하게 한다. 빈 면을 제외한 모든 쪽에GFIELD 표시와 쪽 번호를 둔다.
벡터SVG를 사용하므로 문항 그림을 낮은 해상도 비트맵으로 확대하지 않는다.

`ids`는 현재 게임의 문항 ID 목록이며 검증 후 순서 그대로 사용한다. 잘못된 ID·중복·빈 선택은
오류로 표시하고 인쇄를 막는다. 활동/개수를 명시적으로 바꾸면 전달된 목록을 지우고 새 목록을 고른다.
학습지는 게임 저장 기록을 쓰거나 진행을 바꾸지 않는다. 이름 입력은 URL이나 저장소에 남기지 않는다.

## 검증과 PDF

```sh
node geometry/worksheet/number-paper/workbook.selftest.mjs
node geometry/worksheet/number-paper/export-pdf-plan.mjs --output /path/to/output/pdf
python3 geometry/worksheet/number-paper/pdf-export.py --plan /path/to/output/pdf/print-plan.json --font /path/to/korean.ttf
python3 geometry/worksheet/number-paper/pdf-qa.py --directory /path/to/output/pdf
```

PDF 검수는 브라우저와 같은 문항·페이지 계획·벡터SVG를 내보내 ReportLab으로 실제PDF를 만든다.
이 검수 PDF와 브라우저 인쇄 미리보기의 레이아웃은 각각 확인한다. 네이티브 프린터 설정을 자동 제어하지 않는다.
PDF 생성에는 ReportLab과 적법한 한글TrueType글꼴, 검수에는 pdfplumber/pypdf/Pillow 및pdftoppm이 필요하다.
코드에 글꼴을 복사하지 않는다. 브라우저는 기존SUIT와 시스템 한글·중문·일문 글꼴을 사용한다.

한국어PDF6종49쪽: 활동별20문항 문제지·풀이집4종40쪽, 현재5장 양면 묶음7쪽, 빠른 정답2쪽.
전체 페이지를 렌더하고 글자 경계·번호·빈 면·정답·빈 응답 격자·벡터 여부를 확인한다.
웹 미리보기는4언어·4인쇄 범위·데스크톱/세로폰/작은 가로 화면으로 별도 검수한다.
기존 PDF의 첫 이미지 선명도 문제가 이 신규 학습지로 수정되었다고 해석하지 않는다.

최종 PDF·검수 기록은 기존Geometry Google Drive, 코드·버전과 기술 기록은GitHub,
현재 검수에 필요한 자료·임시 렌더는 로컬 작업 위치에 둔다.
