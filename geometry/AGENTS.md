# Geometry Project Working Rules

이 문서는 `geometry/` 아래의 게임, 학습지, 문제은행, 맵 작업에 적용한다.

## 모델과 추론 강도

- 단순 문구, CSS, 작은 UI 수정: 빠른 코딩 모델, 낮음~중간 추론.
- 여러 파일 수정, 데이터 연결, 기존 기능 유지: 최신 Codex 코딩 모델, 중간~높음 추론.
- 수학 문항 제작, 정답 계산, 난이도 설계, 원본 대조: 사용 가능한 가장 정확한 모델, 높은 추론. 구현과 검수를 분리하고 다른 계산 방법으로 재검산한다.
- 병합, 배포, 대규모 구조 변경: 최신 고성능 코딩 모델, 높은 추론. `git status`, diff, 테스트, 실제 브라우저 검증 후 실행한다.
- 모델을 직접 바꿀 수 없으면 시작 전에 권장 모델과 추론 강도를 알리고 현재 모델에서 검증을 강화한다.

## 작업 시작 전

1. 현재 브랜치, `git status`, 최근 커밋을 확인한다.
2. 기존 코드, 설계 문서, 원본 자료를 먼저 읽고 추측으로 구현하지 않는다.
3. 기존 사용자 변경과 무관한 미추적 파일은 그대로 둔다.
4. `git reset`, `git clean`, 임의의 브랜치 변경, 사용자 변경 삭제를 하지 않는다.

## 수학 문항과 원본 검수

- 원본 문항은 문제번호별로 유형, 구조, 조건, 그림, 정답을 1:1 대조한다.
- 이름이 비슷하다는 이유만으로 기존 생성기를 연결하지 않는다.
- 정답 유일성은 독립 계산 또는 가능한 경우 전수 열거로 확인한다.
- 생성형 문항은 고정 예시뿐 아니라 여러 난수 시드로 자동 검산한다.
- 난이도는 숫자 크기만이 아니라 조건 수, 추론 단계, 보기 구조, 시각적 가림 정도로 조절한다.
- 유아·초등 문항에는 순열, 조합, 제곱 등 학년 밖 표현을 쓰지 않는다.
- 그림에서 정보가 가려지거나 답이 여러 개가 되는 문항은 공개하지 않는다.
- 실패하거나 불확실한 문항은 `검수 대기`로 잠그고 사용자 화면에 출제하지 않는다.

## 구현과 화면 검수

- 기존 데이터 계약, 저장 기록, 음성, 다국어, PWA 동작을 보존한다.
- 그림 문항과 게임은 실제 브라우저에서 데스크톱과 모바일을 모두 확인한다.
- 모바일은 세로·가로, 웹뷰 안전 영역, 터치 목표, 텍스트 넘침, 버튼 겹침을 점검한다.
- Three.js 화면은 비어 있지 않은지, 시점과 프레이밍이 맞는지, 상호작용 후에도 정상인지 확인한다.
- 커밋 전 문법 검사, 자동 검산, `git diff --check`, 변경 diff 검토, 화면 회귀 검사를 수행한다.

## 커밋, 병합, 배포

- 큰 작업은 검증 가능한 단계별 커밋으로 나눈다.
- 커밋에는 이번 작업 파일만 포함하고 사용자 변경을 섞지 않는다.
- 사용자 승인 없이 `main`에 병합하거나 운영 배포하지 않는다.
- 병합 또는 배포 전 브랜치 상태, 전체 diff, 테스트 결과, 브라우저 결과를 다시 확인한다.

## 완료 기준과 보고

코드 작성만으로 완료 처리하지 않는다. 다음 항목이 모두 통과해야 완료다.

- 원본 대조
- 정답 유일성
- 난수 검산
- 데스크톱·모바일 화면 표시
- 기존 기능 회귀 검사

마지막 보고에는 반드시 다음을 적는다.

1. 완료 항목
2. 검증 결과
3. 남은 `검수 대기` 또는 잠금 문항
4. 커밋 SHA
