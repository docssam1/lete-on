# 시험지 조립·교체·순서 편집 명세

## 목적

문제은행의 승인 문항을 찾아 시험지에 넣고, 선택한 문항을 쌍둥이·유사문항으로 바꾸고, 끌어서 순서를 조정한다. 편집은 원문 문항을 수정하지 않고 시험지의 `배치(placement)`만 변경한다.

## 화면 구조

- 왼쪽 후보 영역: 단원 요약, 새 문제, 쌍둥이·유사, 내 문제, 개념 자료
- 범위 변경: 학교급→학년·학기→대단원→소단원의 트리에서 여러 범위를 추가·해제
- 오른쪽 선택 영역: 현재 시험지 문항, 삭제, 교체, 순서 끌기
- 상단 정렬: 유형 오름차순, 난이도 오름차순, 객관식 우선, 무작위, 사용자 순서
- 보기 모드: 문제만, 문제+정답, 문제+해설+정답
- 요약: 총 문항, 배점, 단원, 세부유형, 난도, 객관/주관 비율

## 데이터 원칙

```text
canonical question
  └─ exam placement
       placementId
       itemId
       itemVersionId
       order
       score
       selectionKind
       replacementHistory
```

- 끌어서 이동: `order`만 바꾼다.
- 문항 교체: 같은 `placementId`에서 `itemId`만 바꾸고 이전 ID와 교체 사유를 기록한다.
- 삭제: 시험지 배치만 지우며 문항 DB 원문은 삭제하지 않는다.
- 번호: 저장된 배열 순서로 1번부터 다시 매긴다. 문항 ID와 번호를 동일시하지 않는다.
- 정답·해설 보기: 화면 권한 상태일 뿐 시험지 초안에 정답 원문을 복사하지 않는다.
- 모든 초안에는 양의 `revision`을 저장하고, 추가·삭제·교체·이동·정렬·범위 변경 때 증가시킨다. 저장 API는 현재 revision이 일치할 때만 변경을 받아야 한다.
- 문항 번호, 답안 번호, 해설 번호, 분석지 번호는 각각 계산하지 않고 `createDraftProjection`의 같은 배치 투영을 사용한다.

## 교체 후보 규칙

교체 후보는 다음을 모두 통과해야 한다.

1. 목표 과정과 교육과정 범위가 일치한다.
2. 학년→대단원→소단원→세부유형 분류가 검증됐다.
3. 답안이 원답 대조와 독립 검산을 통과했다.
4. 그림 문항은 도형 감사와 인쇄·모바일 표시 검사를 통과했다.
5. 사용자 공개 승인을 받았다.
6. 이미 선택된 동일 문항과 중복되지 않는다.
7. 가능한 답 후보를 독립적으로 검사한 단일정답 감사가 완료됐다.

`쌍둥이`는 같은 핵심 조건과 풀이 구조를 유지한다. `유사`는 같은 세부유형 안에서 조건 결합이나 표현을 바꾸되 목표 난도와 시험 범위를 벗어나지 않는다.

쌍둥이·유사 교체는 화면의 표시 이름만으로 허용하지 않는다. 서버가 원문 문항과 후보 문항의 문항군, 세부유형, 풀이 구조, 난도 관계를 검증한 중립 `replacementEvidence`가 필요하다. 이 근거는 원문이나 답을 포함하지 않으며 현재 문항·문항 버전과 후보 문항·문항 버전에 결속한다.

## 범위 추가·변경

- 선택 범위는 교육과정 노드 경로의 목록으로 저장한다.
- 상위 노드를 선택하면 그 아래 소단원·세부유형을 포함한다.
- 범위를 추가·해제하면 후보 목록과 유형·난도 통계를 다시 계산한다.
- 이미 시험지에 담은 문항은 자동 삭제하지 않는다.
- 새 범위와 대조해 `유지 가능`, `범위 밖`, `분류 확인 필요`로 나눈다.
- `범위 밖` 문항은 시험 확정 전에 같은 세부유형의 승인 문항으로 교체하거나 사용자가 명시적으로 제거해야 한다.
- `분류 확인 필요` 문항은 분류가 끝날 때까지 시험 확정을 막는다.

## 끌기·정렬 규칙

- 직접 끌면 정렬 상태를 `사용자 순서`로 바꾼다.
- 자동 정렬 뒤에도 사용자가 다시 끌어 조정할 수 있다.
- 무작위 정렬은 같은 시드에서 같은 순서를 재현해야 한다.
- 이동·교체 후 문항 번호, 답안 번호, 해설 번호, 분석지 번호를 함께 다시 계산한다.
- 인쇄용 2열 4문항 배치는 문항 번호 순서를 기준으로 하되, 큰 그림은 페이지 넘김 경고를 낸다.

## 개념 자료

개념 자료는 채점 대상 문항과 다른 블록으로 저장한다. 문항 수·총점·정답률에는 포함하지 않고, 인쇄 위치와 관련 문항 ID만 기록한다.

## 현재 구현 범위

`data/exam-editor-core.js`에 초안 생성, revision 증가, 문항 버전 결속, 범위 변경·대조, 문항 추가·삭제·교체, 끌기 순서 변경, 다섯 가지 정렬, 세 가지 보기 모드, 문항 통계, 단일 번호 projection, 최종 확정 전 재검사를 구현했다.

서버에는 다음 보호 계층이 연결되어 있다.

- `server/exam-editor-registry.js`: 공개 승인·분류·답안·단일정답·그림 검수를 통과한 현재 문항 버전만 후보로 제공한다.
- `server/exam-draft-store.js`: 초안 revision을 비교한 뒤 잠금 파일, 임시 파일 flush, 원자 교체로 저장한다.
- 후보 검색 응답은 중립 문항 ID, 버전, 교육과정 경로, 세부유형, 난도, 입력 방식, 그림 필요 여부만 반환한다.
- 쌍둥이·유사 교체는 클라이언트가 보낸 판정값을 사용하지 않는다. 서버의 비공개 근거 ID를 다시 읽어 현재 배치 문항·버전과 후보 문항·버전을 대조한다.
- 최종 readiness는 저장된 문항 버전과 현재 레지스트리를 다시 비교하고, 하나의 projection으로 문제·답안·풀이·분석지 번호를 만든다.

실제 범위 트리와 좌우 패널·드래그 UI는 이 API 위에 연결한다. 화면에서 보이는 후보 수나 교체 가능 표시만으로 공개 가능 여부를 판단하지 않는다.
