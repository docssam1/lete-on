# 모의고사 응시 화면 정리 (2026-11-07)

학생이 시험지·풀이를 읽다가 O/X를 표시하고 결과를 저장하는 흐름을 정리했다. 기존 화면은 모든 쪽이 길게 이어지고, 모바일 채점 화면에서 문제로 돌아가기와 저장 위치를 찾기 어려웠다.

## 변경

- 시험지·정답/풀이·학습분석지는 같은 위치의 선택 버튼으로 전환한다. 없는 자료의 버튼은 숨기며 기존 보호 API로만 받는다.
- 화면에서는 한 쪽씩 보고 이전/다음·쪽 선택·150/200% 확대를 사용한다. 자료별 읽던 쪽을 유지한다. 문항 번호와 쪽 번호를 임의로 연결하지 않는다.
- PC는 옆에 O/X 패널, 모바일은 하단 ‘페이지 보기 / O/X 자가채점’ 버튼을 둔다. 표시 개수·다음 미확인·저장을 가까이에 유지한다.
- 표시 변경은 기존 판본별 탭 임시 저장을 사용한다. 저장 전 미확인 개수를 확인하고, 실패하면 표시를 보존해 재시도할 수 있다. 최종 저장 형식은 기존 `self-check`와 O/X/빈 문자열이다.
- 결과는 O/X/미확인·영역·문항별 결과로 표시한다. 오답/미확인 필터와 정답·풀이로 돌아가는 버튼을 추가했다. 자가채점과 공식 성적을 구분한다.
- 자체 Pretendard, 본문 16px, 제목 22~28px, 최대 굵기 700, 44px 이상 조작 영역을 사용한다. 선택·키보드 초점·저장 중·실패 상태를 구분한다.
- ‘전체 인쇄’는 확대/현재 쪽과 관계없이 선택한 자료 전체를 A4로 출력한다. 이미지가 다 준비되기 전에는 인쇄를 막고 실패 시 다시 불러온다.

기존 18회·670문항, 범위·시간·PDF 원본·수식·그림·워터마크, 서버 API와 회차별 권한·서명 검증은 보존한다. DB·실제 학생 기록·교사 승인 로직을 변경하지 않는다. 추가 라이브러리나 유료 API는 사용하지 않았다.

## 적용 지침

frontend-design, gfield-design-system, ui-ux-pro-max(고정 영역·진행·저장 피드백), ux-writing을 적용했다. 인쇄 회귀 검증에는 PDF 지침을 적용했다. 기존 스킬 지도와 앞선 과정 선택 개편에 이어진 작업이다.

## 검증과 한계

- 브라우저 통합 검사 10개 통과: 1440/768/390/320px, 문서/쪽/확대, O/X 임시 복원·지우기·미확인·결과 필터, 실패/재시도, 만료·권한 거부, 요청 순서 역전, 키보드·초점·44px 조작 영역·폰트.
- 18개 실제 공개 회차의 메타데이터를 PC/모바일 36화면에 넣어 제목·문항 수·시간·가로 넘침을 확인했다.
- 기존 채점·보호·공식 범위 관련 계약 검사 31개 통과.
- 합성 시험지/풀이/분석지의 인쇄 결과 3/2/1쪽을 PDF로 재개방해 A4·모든 쪽 번호·UI 제외를 확인하고 렌더링했다. 실제 승인 PDF를 재생성한 것은 아니다.
- 학생 흐름 검사는 합성 API 응답과 합성 페이지로 진행한다. 운영 학생 계정·DB 쓰기·실제 제출을 만들지 않는다. 공개 배포 파일은 검수한 파일과 해시로 대조하고, 공개 호스팅에서도 같은 합성 응답으로 UI를 재검사한다. 서버 종단 간 재검증과 구분한다.
